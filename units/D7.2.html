    연습문제 5개 바로가기

    표시 없는 본문은 원본 정리 파일의 내용 · 보충은 원본에 없어 더한 설명 · 가상 예시는 지어낸 상황 · 연결은 다른 단원과의 관계 · 확인 필요는 그대로 확정하지 않은 부분

    탐지는 로그를 모으는 데서 끝나지 않습니다. 원본의 핵심 문장은 수집은 탐지가 아니고, 경보는 대응이 아니다입니다. 로그를 모으기만 하면 탐지 통제가 아니고, 경보가 울려도 처리할 사람과 절차가 없으면 대응이 아닙니다. 이 단원은 공식 개요 7.2가 드는 IDPS, SIEM, 지속적 모니터링과 튜닝, 유출 모니터링, 로그 관리, 위협 인텔리전스, UEBA를 하나의 탐지 체계로 엮어 봅니다.

    2침입 탐지·방지 (IDPS)

    구분동작배치·성격
    IDS탐지·경보만아웃오브밴드(복제), 탐지 통제
    IPS탐지 후 차단인라인, 예방 통제

    IPS는 인라인이므로 오탐이 서비스 중단으로 이어집니다. 그래서 도입 초기에는 탐지 전용 모드로 운영하며 튜닝한 뒤 차단을 켭니다. IPS는 단일 실패점이자 성능 병목이 될 수 있어 장애 시 통과(fail-open)와 차단(fail-close) 중 하나를 결정해야 합니다.

    배치보는 것못 보는 것
    NIDS/NIPS세그먼트 경계, 다수 호스트암호화 트래픽 내용, 호스트 내부 동작
    HIDS/HIPS복호화 후 상태, 파일 변경, 프로세스 동작전체 조망(단말 수만큼 관리 부담)
    탐지 방식원리강점 / 약점
    시그니처 기반알려진 패턴 일치정확 / 제로데이 탐지 불가
    이상 기반정상 기준선과의 편차신규 공격 탐지 / 오탐 많음, 학습 기간에 이미 침해되어 있으면 공격을 정상으로 학습
    상태 프로토콜 분석프로토콜 규격 위반규격 일탈 탐지 / 구현 복잡
    휴리스틱·행위행위 조합 평가변형 대응 / 해석 어려움

    회피 기법: 암호화(TLS 검사는 중간 복호화가 필요하고 프라이버시·법적 문제를 낳음), 단편화·재조립 차이, 느린 공격(low and slow), 정상 서비스 악용(널리 쓰이는 클라우드 서비스를 C2로 써서 평판으로 구분 불가).

    연결IDS/IPS의 네트워크 관점은 D4.2 네트워크 구성요소의 2절, 예방·탐지 통제의 분류는 D1.9 위험 관리에서 다룹니다.

    원본 연습문제 · D7.2-Q01

    오탐이 IDS 보다 IPS 에서 더 큰 운영상 결과를 낳는 이유는?

    1. IPS 가 더 많은 로그를 저장하므로 오탐이 디스크 공간을 더 빨리 소비한다.
    2. IPS 는 인라인에 위치해 트래픽을 차단하므로 오탐이 정상 서비스를 중단시킨다.
    3. IDS 와 달리 IPS 는 배치 후 튜닝할 수 없다.
    4. IPS 는 SIEM 에 보고하지만 IDS 는 보고하지 않는다.
    정답과 해설 보기

    정답 B. IDS 는 복제 트래픽을 받아 탐지와 경보만 하므로 오탐의 비용은 분석 시간이다. IPS 는 트래픽 경로상에 인라인으로 배치되어 차단까지 하므로 오탐이 곧 정상 서비스 중단이 된다. 그래서 도입 초기에는 탐지 전용 모드로 운영하며 튜닝한 뒤 차단을 활성화한다.

    • A · 로그 저장량은 오탐의 운영 결과와 무관하다.
    • C · IPS 도 튜닝할 수 있으며 튜닝이 필수다.
    • D · 둘 다 SIEM 에 로그를 보낼 수 있다.

    3지속적 모니터링과 튜닝

    원본은 탐지 체계는 설치하고 끝나는 것이 아니다라고 말합니다. 환경과 공격이 바뀌므로 계속 조정해야 합니다.

    경보 피로 (Alert Fatigue)

    오탐이 많으면 분석가가 경보를 무시하거나 일괄 종결하고, 실제 침해가 그 안에 묻힙니다. 경보 건수, 오탐률, 평균 처리 시간, 미처리 잔량, 일괄 종결 비율을 지표로 관리하고, 규칙 정밀화, 환경 맥락 반영(알려진 스캐너·백업 작업 제외), 우선순위화, 자동 보강, 반복 작업 자동화로 대응합니다.

    원본이 강조하는 구분: “경보를 줄이기 위해 규칙을 끈다”와 “정밀화한다”는 다릅니다. 전자는 탐지 공백을 만들므로, 끌 때는 무엇을 못 보게 되는지 기록합니다.

    원문 사례 — 경보 피로가 묻은 침해. 일 평균 4,200건의 경보를 분석가 3명이 처리했고 68%가 일괄 종결되었습니다. 사후 조사에서 실제 침해 경보가 일괄 종결 묶음에 들어 있었습니다.

    탐지 커버리지와 기준선

    • MITRE ATT&CK 기법 단위로 매핑해 어떤 기법을 탐지할 수 있는지 측정합니다.
    • 침해 공격 시뮬레이션으로 실제 탐지 여부를 검증합니다.
    • 로그 소스 상태 모니터링: 로그가 끊기면 탐지가 조용히 멈춥니다. 로그 수신 중단 자체를 경보 대상으로 둡니다.
    • 이상 기반 탐지의 정상 기준선은 조직 변화(신규 시스템, 업무 패턴, 원격 근무)를 반영해 갱신합니다.

    원문 사례 — 로그가 끊긴 것을 아무도 몰랐다. 핵심 서버군의 로그가 4개월간 SIEM에 들어오지 않았습니다. 포워더가 업데이트 뒤 멈췄고 수신 중단 경보가 없어 아무도 몰랐습니다.

    가상 예시정상 예약 작업에서 같은 경보가 매일 수천 건 나오자 운영자가 “이 규칙을 통째로 끄자”고 합니다. 먼저 어떤 경로와 자산에서 반복되는지, 원래 무엇을 잡으려던 규칙인지 적습니다. 승인된 예약 작업의 계정·호스트·시간대 조합만 예외로 두고 규칙은 남기면, 같은 행위가 다른 계정이나 시간대에서 일어날 때는 여전히 잡힙니다. 조정 뒤에는 그 기법을 다시 시뮬레이션해 탐지가 살아 있는지 확인합니다.

    연결침해 공격 시뮬레이션은 D6.2 보안 통제 테스트의 9절, 지속적 모니터링(ISCM)과 지표는 D6.3 보안 프로세스 데이터의 7절, ATT&CK은 D3.7 암호 분석 공격에서 다룹니다.

    원문 위치: D7.2.md §3 지속적 모니터링과 튜닝, §7 사례 1, 사례 2 · 공식 개요 7.2 “Continuous monitoring and tuning”

    4SIEM

    여러 출처의 로그를 수집·정규화·상관분석해 경보를 만드는 체계입니다.

    구성 요소요점
    수집에이전트, 포워더, 신디케이션, API
    정규화공통 스키마로 변환. 이 단계가 품질을 결정 — 필드 매핑이 틀리면 상관 규칙이 작동하지 않음
    보강 enrichment자산·사용자·위협 인텔리전스·지리 정보. “10.1.2.3에서 접속”이 “결제 서버에 재무팀 계정이 접속”이 되면 판단이 가능
    상관분석여러 이벤트를 연결해 의미를 만듦
    경보·사례 관리경보를 조사 단위로 묶어 처리
    보존조사와 규제 요구에 맞춘 기간
    단일 이벤트들결합하면
    VPN 로그인 성공 + 같은 계정이 출입증으로 건물 내 활동자격증명 도용 가능성
    다수 계정 인증 실패 + 같은 출처 IP비밀번호 스프레이
    권한 상승 + 비정상 시간 접속 + 대량 조회내부자 또는 계정 탈취

    한계: 쓰레기를 넣으면 쓰레기가 나온다(로그 품질과 커버리지), 비용이 수집량에 비례(탐지 목적에 따라 수집 대상 선택), 규칙만으로는 미지의 공격을 못 잡음(UEBA·헌팅이 보완), 운영 인력이 없으면 작동하지 않음.

    보충로그 관리 플랫폼과 SIEM은 하는 일이 다릅니다. 로그 관리는 신뢰성 있는 수집·저장·검색·보존에 집중하고, SIEM은 그 위에서 정규화·보강·상관분석·경보를 만듭니다. 그리고 SIEM 규칙을 더하기 전에 그 규칙이 쓰는 필드가 어느 시스템에서 생성되고 실제로 수집되는지부터 확인해야 합니다. 필드가 비어 있으면 규칙이 실행되어도 사람·장비·행동을 연결할 수 없습니다.

    연결물리·논리 로그 상관분석 사례는 D5.1 물리적·논리적 접근 통제의 3절, 비밀번호 스프레이는 D5.6 인증 시스템의 8절에서 다룹니다.

    원본 연습문제 · D7.2-Q11

    SIEM 은 로그 관리 플랫폼과 어떻게 다른가?

    1. 공급업체 이름만 다른 같은 제품 범주다.
    2. 로그 관리는 신뢰성 있는 수집과 저장, 검색, 보존에 집중하고 SIEM 은 정규화와 출처 간 상관분석, 규칙이나 이상에 대한 경보, 사건 처리 흐름을 더한다.
    3. SIEM 이 로그 관리 플랫폼보다 로그를 더 오래 보관한다.
    4. 로그 관리는 애플리케이션 로그에만, SIEM 은 네트워크 로그에만 적용된다.
    정답과 해설 보기

    정답 B. 둘은 목적이 다르고 흔히 함께 쓰인다. 로그 관리는 "빠뜨리지 않고 모으고 필요할 때 찾는다" 가 목표이고 SIEM 은 "서로 다른 출처의 사건을 엮어 의미를 만든다" 가 목표다. SIEM 은 상관분석 비용이 커서 보존 기간이 짧은 경우가 많고, 장기 보존은 저렴한 로그 저장소에 두는 구성이 일반적이다. 보존 기간이 구분 기준은 아니다.

    • A · 목적과 기능이 다르다.
    • C · 보존 기간은 구성에 따라 다르며 구분 기준이 아니다.
    • D · 로그 출처로 구분되지 않는다.

    5로그 관리

    무엇을 기록할 것인가

    • 인증: 성공과 실패 모두
    • 권한 변경과 특권 사용
    • 설정·정책 변경
    • 데이터 접근: 특히 민감 데이터의 대량 조회
    • 시스템·보안 도구 상태 변경: 보안 에이전트 중지, 로깅 비활성화는 공격의 전형적 선행 행위
    • 애플리케이션 보안 이벤트: 인가 거부, 입력 검증 실패

    비밀번호, 토큰, 개인정보 원문은 기록하지 않습니다. 로그 자체가 유출 대상이 됩니다.

    원문 사례 — 보안 에이전트 중지가 선행 신호였다. 공격자는 권한 획득 직후 엔드포인트 보안 에이전트를 중지하고 로그 전송을 비활성화했습니다. 이 변경은 로그에 남았지만 경보가 정의되어 있지 않았습니다. 에이전트 중지, 서비스 비활성화, 감사 정책 변경을 최우선 경보로 등록했습니다.

    단계요건
    생성필요한 이벤트가 실제로 기록되는가
    수집중앙으로 신뢰성 있게 전달되는가
    보호변조·삭제를 막는가
    보존조사·규제 요구 기간을 덮는가
    분석실제로 검토되고 경보가 정의되었는가
    폐기보존 기간 후 안전하게 삭제되는가

    무결성 보호: 원격 중앙 전송(공격자는 로그부터 지운다), 추가 전용(append-only)·불변 저장, 전송 중 암호화와 인증, 접근 통제와 접근 기록(로그 조회도 기록), 그리고 시각 동기화(상관분석과 증거 가치의 전제).

    보존 기간 설계

    체류 시간이 수개월인 사례가 흔해서 90일 보존으로는 초기 침입을 추적할 수 없습니다. 규제·계약 요구와 비용을 함께 보고, 고비용 분석 저장과 저비용 장기 보관을 계층화합니다. 동시에 개인정보가 포함된 로그는 과다 보존도 위반이므로, 보존과 삭제 의무가 충돌하면 법무 검토가 필요합니다.

    원문 사례 — 90일 보존이 막은 조사. 침해가 5개월 전 시작된 것으로 보였지만 보존은 90일이었고, 초기 침입 경로와 접근 범위를 확정하지 못한 채 규제 기관에 신고해야 했습니다. 인증·관리 이벤트 로그는 저비용 계층에 13개월, 분석용 고비용 계층은 90일로 계층화했습니다.

    연결증거로서의 로그와 시각 동기화는 D7.1 조사의 2절·6절, 인증 로그 항목은 D5.6 인증 시스템의 8절, 로그 검토를 통제 시험으로 보는 관점은 D6.2 보안 통제 테스트의 4절에서 다룹니다.

    원본 연습문제 · D7.2-Q06

    타임라인 복원 결과 공격자가 권한을 획득한 직후 엔드포인트 보안 에이전트를 중지하고 로그 전송을 비활성화했다. 이 변경은 로그에 남았으나 경보는 없었다. 무엇을 우선해야 하는가?

    1. 보안 에이전트 중지, 서비스 비활성화, 감사 정책 변경은 공격의 전형적 선행 행위이므로 최우선 경보로 등록한다.
    2. 에이전트 상태 복원을 위해 모든 단말을 매일 밤 재부팅하도록 요구한다.
    3. 엔드포인트 보안 제품을 다른 공급자 것으로 교체한다.
    4. 엔드포인트 로그의 보존 기간을 늘린다.
    정답과 해설 보기

    정답 A. 공격자는 탐지와 기록을 먼저 무력화하려 하므로 보안 에이전트 중지와 로깅 비활성화, 감사 정책 변경은 공격의 전형적 선행 행위다. 이 변경은 대개 로그에 남으므로 경보만 정의하면 조기 탐지가 가능하다.

    • B · 야간 재부팅은 가용성을 해치고 공격 탐지와 거리가 멀다.
    • C · 제품 교체는 경보 정의 부재와 무관하다.
    • D · 보존 연장은 이미 기록된 이벤트의 경보 부재를 해결하지 않는다.

    로그 출처가 동기화된 시각을 사용해야 하는 이유는?

    6유출 모니터링 (Egress Monitoring)

    전통적 경계 방어는 들어오는 것에 집중했지만, 데이터 유출과 명령·제어는 나가는 방향입니다. 감시 대상은 데이터 유출(대량 업로드, 비정상 목적지·시간), C2 통신(주기적 비컨, 비정상 도메인, DNS 터널링), 정책 위반(승인되지 않은 클라우드 저장소, 개인 메일), 알려진 악성 인프라로의 연결입니다.

    기법요점
    DLP콘텐츠 검사로 민감 데이터 전송 탐지·차단. 네트워크·엔드포인트·클라우드에 배치
    프록시·SWG모든 외부 접근을 중개해 검사·기록
    DNS 모니터링가장 비용 효율이 높은 유출 탐지 수단. DNS 터널링, DGA 도메인, 신규 등록 도메인
    비컨 탐지일정한 주기와 크기로 반복되는 연결 패턴
    대역폭·세션 이상평소와 다른 양과 목적지
    TLS 검사내용을 보려면 필요하지만 프라이버시·법적 검토 선행, 인증서 고정 때문에 깨지는 서비스 있음

    암호화와 정상 서비스 악용으로 내용 기반 탐지가 어려워지면서 메타데이터 기반 행위 분석의 비중이 커졌습니다.

    원문 사례 — DNS로 드러난 유출. DLP와 프록시는 깨끗했지만, DNS 질의 로그에서 한 단말이 한 도메인에 비정상적으로 긴 하위 도메인 이름으로 초당 수십 건 질의하는 패턴이 나왔습니다. DNS 터널링을 통한 유출이었습니다. DNS 로그 전량 수집과 질의 길이·빈도·엔트로피 기반 규칙을 추가했습니다.

    연결DLP와 데이터 보호는 D2.6 데이터 보안 통제, DNS 보안은 D4.1 네트워크 아키텍처에서 다룹니다.

    원문 위치: D7.2.md §3 유출 모니터링, §7 사례 3 · 공식 개요 7.2 “Egress monitoring”

    7위협 인텔리전스와 위협 헌팅

    위협 인텔리전스는 단순 데이터가 아니라 맥락과 판단이 더해진 위협 정보입니다.

    수준내용소비자
    전략적위협 환경, 동향, 위험경영진
    운영적특정 공격자의 캠페인, 의도보안 관리
    전술적TTP(전술·기법·절차)탐지 설계
    기술적IOC(지표)자동 차단·탐지

    IOC(해시, IP, 도메인, URL)는 쉽게 바뀌어 수명이 짧고, TTP(행동 방식)는 바꾸기 어려워 탐지 가치가 깁니다. 고통의 피라미드(Pyramid of Pain): 해시·IP는 공격자가 쉽게 바꾸고, TTP를 탐지하면 공격자가 가장 고통스럽습니다. 원본은 IOC 중심에서 TTP 중심 탐지로 옮겨 가는 것을 성숙화 방향으로 봅니다.

    피드 운영: 적합성(우리 산업·기술 스택과 무관한 지표는 소음), 적시성과 수명(오래된 IOC는 오탐, 만료 관리), 자동 차단의 위험(신뢰도에 따라 차단·경보·기록 구분), 공유 표준(STIX 표현, TAXII 전송, NIST SP 800-150).

    원문 사례 — 외부 피드 자동 차단이 만든 장애. 외부 피드의 IP 목록을 검증 없이 자동 차단에 연결했다가, 피드에 들어 있던 공용 CDN 주소 하나가 차단되어 다수 업무 서비스가 멈췄습니다. 자동 차단은 고신뢰 지표로 한정하고, 중간 신뢰는 경보, 저신뢰는 기록으로만 쓰고, IOC 만료 관리를 도입했습니다.

    위협 헌팅

    경보를 기다리지 않고 가설을 세워 능동적으로 침해 흔적을 찾는 활동입니다. 가설 수립 → 데이터 조회 → 분석 → (발견 시) 사고 대응 / (미발견 시) 탐지 규칙 추가. 전제는 충분한 로그 커버리지이고, 가설은 위협 인텔리전스의 TTP, ATT&CK 기법, 환경의 취약 지점, 과거 사고에서 나옵니다.

    원본은 헌팅의 산출물이 침해 발견보다 새로운 탐지 규칙과 가시성 공백 식별인 경우가 더 흔하고 더 가치 있다고 말합니다. “발견하지 못함”도 결과이지만, “없다”가 아니라 “이 데이터 범위에서 이 기법의 흔적을 찾지 못했다”로 기록합니다.

    원문 사례 — 헌팅의 산출물은 탐지 규칙. 특정 ATT&CK 기법 가설로 조사했지만 흔적을 찾지 못했고, 그 과정에서 해당 기법을 탐지할 로그가 애초에 수집되지 않고 있음을 발견했습니다.

    연결ATT&CK과 위협 모델링은 D1.10 위협 모델링·D3.7 암호 분석 공격에서 다룹니다.

    원문 위치: D7.2.md §3 위협 인텔리전스, §7 사례 5, 사례 8 · 공식 개요 7.2 “Threat intelligence (e.g., threat feeds, threat hunting)”

    8UEBA

    사용자와 엔티티의 행위 기준선을 학습해 편차를 탐지합니다. 규칙은 “알려진 나쁜 것”을 찾고, UEBA는 “이 주체에게 비정상인 것”을 찾습니다. 서버, 서비스 계정, 기기도 대상이며, 서비스 계정의 행위 기준선은 사람보다 안정적이어서 편차 탐지가 효과적입니다.

    강점약점
    내부자 위협, 자격증명 도용, 서서히 진행되는 활동. 시그니처 없는 행위학습 기간에 이미 침해되어 있으면 공격을 정상으로 학습. 조직 변화가 대량 오탐. 점수가 왜 높은지 설명하기 어려움(조사·징계에서 문제). 근로자 프라이버시(고지, 정책, 비례성)

    운영 원칙: UEBA 점수를 단독 근거로 조치하지 않고 다른 증거와 결합합니다.

    원문 사례 — UEBA 학습 기간의 함정. 3개월 학습 뒤 조사에서 침해가 학습 기간 전부터 진행 중이었고, 공격자의 접근 패턴이 정상 기준선에 포함되어 있었습니다. 학습 전 침해 점검, 기준선 주기적 재검토, UEBA 점수 단독 사용 금지를 원칙으로 세웠습니다.

    보충새로 시작한 일괄 작업이 기존 패턴을 벗어나 큰 전송량 경보를 낼 수 있습니다. 시간·계정·대상 흐름을 정상 변경 기록과 대조한 뒤 조사 여부를 정합니다. 행동 이상은 확인이 필요한 신호이지 결론이 아니며, 규칙을 조정했다면 그 조정 때문에 놓치게 되는 다른 신호는 없는지도 확인합니다.

    연결근로자 모니터링의 법적 요건은 D7.1 조사의 9절과 D1.4 법률·규제·컴플라이언스, 서비스 계정 관리는 D5.5 프로비저닝 생애주기의 7절에서 다룹니다.

    원문 위치: D7.2.md §3 UEBA, §7 사례 7 · 공식 개요 7.2 “User and Entity Behavior Analytics (UEBA)”

    9종합 이해 확인

    종합 · 자작 상황 문제 (실제 시험 문제 아님)

    관제 점검 결과다. ㉠ 핵심 서버군 로그가 4개월간 SIEM에 들어오지 않았는데 아무도 몰랐다. ㉡ 일 4,200건 경보 중 68%가 일괄 종결된다. ㉢ 외부 피드 IP를 검증 없이 자동 차단에 연결했다. ㉣ 로그 보존이 90일이다. 가장 적절한 대책 묶음은?

    1. ㉠ 로그 소스별 수신 상태 모니터링, 수신 중단 자체를 경보로 / ㉡ 규칙 정밀화·맥락 반영·보강·우선순위화, 끈 규칙은 공백 기록 / ㉢ 신뢰도별로 차단·경보·기록 구분, IOC 만료 관리 / ㉣ 인증·관리 이벤트는 저비용 계층에 장기 보존(개인정보 과다 보존은 법무 검토)
    2. ㉠ SIEM 교체 / ㉡ 경보가 많은 규칙을 모두 끔 / ㉢ 피드를 하나 더 추가 / ㉣ 모든 로그 무기한 보존
    3. ㉠ 분기마다 수동 확인 / ㉡ 분석가에게 더 빨리 처리하라고 지시 / ㉢ 그대로 / ㉣ 30일로 단축해 비용 절감
    4. ㉠ IPS로 교체 / ㉡ IDS를 끔 / ㉢ 모든 외부 IP 차단 / ㉣ 로컬에만 보관
    정답과 해설 보기

    정답 A. ㉠ 3절(로그가 끊기면 탐지가 조용히 멈춘다), ㉡ 3절(끄는 것과 정밀화는 다르다 — B가 틀린 이유), ㉢ 7절(자동 차단의 위험), ㉣ 5절(체류 시간 > 보존 기간이면 조사 불가, 단 과다 보존도 위반 — B의 “무기한”이 틀린 이유).

    중앙 수집기에 먼저 도착한 기록이 먼저 발생한 것은 아닐 수 있습니다. 장비 시각·시간대·수집 지연을 확인해 발생과 도착을 나누고, 맞추기 어려운 범위를 기록합니다.

    11핵심 요약

    1. 수집 → 상관분석 → 탐지 → 대응 → 튜닝. 수집은 탐지가 아니고, 경보는 대응이 아니다. MTTD, MTTR, 체류 시간.
    2. IDS = 탐지(아웃오브밴드), IPS = 차단(인라인, 오탐 = 서비스 중단). 탐지 모드로 튜닝 후 차단. NIDS(조망) + HIDS(맥락).
    3. 시그니처(정확, 제로데이 불가) / 이상 기반(신규 탐지, 오탐, 오염된 기준선). 회피: 암호화, 단편화, low and slow, 정상 서비스 악용.
    4. 튜닝: 경보 피로, 끄기 ≠ 정밀화(끄면 공백 기록), ATT&CK 커버리지, 로그 수신 중단을 경보로, 기준선 갱신.
    5. SIEM: 수집, 정규화(품질 결정), 보강, 상관분석, 사례 관리, 보존. 쓰레기 입력 = 쓰레기 출력, 운영 인력 필수.
    6. 로그: 인증 성공·실패, 권한·설정 변경, 데이터 접근, 보안 도구 중지(선행 신호). 비밀번호·토큰 기록 금지. 원격 전송, append-only, 시각 동기화. 보존은 체류 시간을 고려해 계층화, 과다 보존도 위반.
    7. 유출 모니터링: DLP, 프록시, DNS(가장 비용 효율적), 비컨, TLS 검사(법적 검토). 메타데이터 행위 분석.
    8. 인텔리전스: 전략·운영·전술·기술. IOC(수명 짧음) → TTP(수명 김), 고통의 피라미드. 자동 차단은 신뢰도별로. STIX/TAXII.
    9. 헌팅: 가설 기반 능동 탐색. 산출물은 주로 탐지 규칙과 가시성 공백. “이 범위에서 찾지 못했다”로 기록.
    10. UEBA: “이 주체에게 비정상”. 서비스 계정에 효과적. 오염된 학습, 설명 가능성, 프라이버시. 단독 근거 금지.
    원문 위치: D7.2.md §8 CISSP 시험 관점, §9 핵심 암기 요약. 원본의 출제 단정 표현은 판단 기준으로 바꿔 적었습니다.

    12주요 용어 (Glossary)

    영어 원어와 한국어 뜻 · English–Korean

    IDS / IPS — Intrusion Detection System / Intrusion Prevention System · 침입 탐지 시스템 / 침입 방지 시스템

    탐지·경보만 하는 시스템과 탐지 후 차단까지 하는 시스템.

    NIDS / HIDS — Network Intrusion Detection System / Host-based Intrusion Detection System · 네트워크 기반 침입 탐지 / 호스트 기반 침입 탐지

    네트워크 기반과 호스트 기반 침입 탐지.

    Signature-based / Anomaly-based Detection · 서명 기반 탐지 / 이상 기반 탐지

    알려진 패턴 일치 탐지와 정상 기준선 편차 탐지.

    Inline / Out-of-band · 통신 경로 내 / 통신 경로 밖

    트래픽 경로상 배치와 복제 트래픽 수신 배치.

    SIEM (Security Information and Event Management) · 보안 정보·이벤트 관리

    로그를 수집·정규화·상관분석해 경보를 생성하는 체계.

    Normalization · 정규화

    서로 다른 로그 형식을 공통 스키마로 변환하는 과정.

    Enrichment · 보강

    이벤트에 자산·사용자·위협 정보를 결합해 판단 가능하게 만드는 과정.

    Correlation · 상관분석

    여러 이벤트를 연결해 단일 이벤트에 없는 의미를 도출하는 분석.

    Alert Fatigue · 경보 피로

    과다한 경보로 분석가가 경보를 무시하게 되는 현상.

    MTTD / MTTR — Mean Time to Detect / Mean Time to Respond or Recover · 평균 탐지 시간 / 평균 대응·복구 시간

    평균 탐지 시간과 평균 대응·복구 시간.

    Dwell Time · 체류 시간

    공격자가 탐지되지 않고 환경에 머문 기간.

    Egress Monitoring · 유출 모니터링

    조직에서 나가는 트래픽을 감시해 유출과 명령·제어를 탐지하는 활동.

    DLP (Data Loss Prevention) · 데이터 유출 방지

    민감 데이터의 전송을 콘텐츠 검사로 탐지·차단하는 통제.

    DNS Tunneling · DNS 터널링

    DNS 질의에 데이터를 실어 보내는 유출·통신 기법.

    Beaconing · 비컨

    감염 단말이 명령·제어 서버에 주기적으로 접속하는 패턴.

    IoC — Indicator of Compromise · 침해 지표

    해시, IP, 도메인 같은 구체적 침해 지표. 수명이 짧다.

    TTP (Tactics, Techniques, Procedures) · 전술·기법·절차

    공격자의 행동 방식. 바꾸기 어려워 탐지 가치가 길다.

    STIX / TAXII — Structured Threat Information Expression / Trusted Automated Exchange of Intelligence Information · 위협 정보 표현 형식 / 위협 정보 교환 프로토콜

    위협 정보의 표현 형식과 전송 프로토콜.

    Threat Hunting · 위협 헌팅

    경보를 기다리지 않고 가설 기반으로 침해 흔적을 찾는 능동적 활동.

    UEBA (User and Entity Behavior Analytics) · 사용자·엔티티 행위 분석

    사용자와 엔티티의 행위 기준선 편차를 탐지하는 분석.

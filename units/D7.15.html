    Address personnel safety and security concerns · ISC2 CISSP Exam Outline(2024-04-15 발효) 7.15

    주요 용어 바로가기 · Glossary

    연습문제 5개 바로가기

    표시 없는 본문은 원본 정리 파일의 내용 · 보충은 원본에 없어 더한 설명 · 가상 예시는 지어낸 상황 · 연결은 다른 단원과의 관계 · 확인 필요는 그대로 확정하지 않은 부분

    도메인 7의 마지막 단원은 사람을 다룹니다. 원본은 단원 전체의 원칙을 첫 줄에 둡니다. 인원 안전이 자산, 데이터, 가용성보다 우선한다. 그리고 이 단원에는 두 축이 있습니다. 사람이 해를 입지 않게 하는 인원 안전(safety), 사람을 경로로 한 침해를 막는 인원 보안(security). 둘은 자주 충돌하며, 원본이 꼽는 전형적 실패는 자산을 지키려다 사람을 위험에 두는 설계입니다. 공식 개요 7.15는 출장, 보안 교육(내부자 위협, 소셜 미디어, 2FA 피로), 비상 관리, 강압을 듭니다.

    1인원 안전과 인원 보안

    축내용
    인원 안전 safety사람이 해를 입지 않게
    인원 보안 security사람을 경로로 한 침해를 막음

    판단 순서안전과 다른 목표가 충돌하는 상황이라면 ① 사람이 다치거나 갇힐 위험이 있는가 → 있다면 그것이 먼저(비상구는 안에서 열림, 강압 시 순응) ② 그 결정으로 생기는 보안 공백은 무엇인가 → 대피 후 재진입 통제, 감시 유지, 조용한 경보처럼 안전을 해치지 않는 방식으로 메운다. 안전을 희생해서 보안을 지키는 설계는 선택지에 두지 않습니다.

    원본 연습문제 · D7.15-Q11

    비상 상황의 결정에서 자산 보호와 인명 안전이 상충할 때 우선하는 것은?

    1. 인명 안전이 항상 우선한다. 그래서 비상 탈출 같은 통제는 접근 통제와 충돌하더라도 사람이 나갈 수 있게 해야 한다.
    2. 자산은 측정 가능한 가치를 가지므로 자산 보호.
    3. 그때 당직 관리자가 결정하는 쪽.
    4. 기록은 재생성할 수 없으므로 데이터 무결성.
    정답과 해설 보기

    정답 A. 화재와 같이 사람이 위험할 때는 해당 비상 절차에 따라 대피와 인원 보호를 먼저 수행합니다. 출입 설계에서는 안전한 퇴실을 확보하고, 소화 설비에는 인체 영향과 시설 안전 기준을 고려합니다. 자산 손실은 복구와 보험으로 다룰 수 있지만 인명은 그렇지 않다.

    • B · 자산 가치는 인명보다 우선하지 않는다.
    • C · 상황별 판단이 아니라 확립된 원칙이다.
    • D · 데이터도 인명보다 우선하지 않는다.
    원문 위치 · D7.15-Q11
    문제 목록으로 돌아가기

    2출장 (Travel)

    위험내용
    기기 절취와 압수분실, 도난, 국경 검사와 일시 보관
    적대적 환경숙소·공공 장소에서의 기기 접근, 객실 금고의 신뢰성 한계
    네트워크공공 와이파이, 가짜 AP, 호텔 네트워크
    충전 포트데이터 전송이 가능한 공공 충전 포트
    관찰·표적화화면 엿보기, 대화 도청, 특정 산업·직급 표적
    개인 안전·법적 차이치안, 재해, 의료 접근성 / 암호화 수출입 규제, 데이터 접근 요구, 구금 위험

    통제: 데이터 최소화(가장 효과적), 출장 전용 기기(최소 구성, 종료 후 초기화), 전체 디스크 암호화와 전원 종료, VPN 강제와 분할 터널링 금지, 셀룰러 테더링 선호, 전원 어댑터나 데이터 차단 케이블로 충전, 프라이버시 스크린, 피싱 저항성 MFA, 원격 초기화, 귀국 후 초기화 또는 검사, 출장 전 브리핑, 비상 연락과 체크인, 여행 추적(프라이버시와 균형), 임원 보호.

    원본의 핵심: 출장 보안은 기술이 아니라 “무엇을 가져가지 않을 것인가”다. 기기에 없는 데이터는 탈취될 수 없습니다.

    원문 사례 — 데이터 최소화가 막은 손실. 고위험 지역 출장 정책을 출장 전용 기기와 데이터 최소화로 바꾼 뒤, 출장자 기기를 숙소에서 분실했지만 기기에는 업무 데이터가 없었고 접근은 VPN과 MFA를 거쳐야 해 손실은 기기 자체뿐이었습니다.

    원문 사례 — 공공 충전 포트. 공항 공공 충전 포트에 업무용 스마트폰을 연결했는데, 귀국 후 점검에서 기기에 관리 프로파일이 추가되어 있었습니다.

    연결VPN과 분할 터널링은 D4.3 안전한 통신 채널, FDE의 한계는 D7.5 자원 보호의 5절, MFA는 D5.2 식별·인증 전략의 2절에서 다룹니다.

    원문 위치: D7.15.md §3 출장, §7 사례 1, 사례 2 · 공식 개요 7.15 “Travel”

    3내부자 위협 (Insider Threat)

    공식 개요는 보안 교육과 인식에서 내부자 위협, 소셜 미디어 영향, 2FA 피로를 명시합니다(교육 체계 전반은 D1.12 인식·교육·훈련).

    유형동기와 특성
    악의적 내부자금전, 보복, 이념, 포섭
    부주의한 내부자실수, 절차 우회, 편의
    침해된 내부자자격증명 탈취로 공격자가 내부자로 활동

    원본은 악의적 내부자가 가장 어려운 이유를 이렇게 설명합니다. 정당한 접근 권한을 갖고 정상 업무 시간에 정상 경로로 활동하므로 시그니처 기반 탐지가 작동하지 않습니다.

    프로그램 구성요점
    최소권한과 알 필요성가장 근본적. 권한이 없으면 할 수 없음
    직무 분리·이중 통제, 직무 순환·강제 휴가혼자 전 과정 불가, 장기 부정 탐지
    접근 검토, UEBA, 유출 모니터링(DLP, 외부 저장소, 대량 인쇄)권한 누적과 이상 행위
    퇴사 전후 집중 모니터링퇴사 통보 후 유출이 집중됨
    물리·논리 상관분석, 익명 신고 경로동료의 신고
    지원 프로그램재정 곤란·불만·스트레스가 동기. 처벌 중심이 아닌 지원 접근이 예방 효과

    윤리적·법적 경계: 프라이버시(모니터링 범위·고지·비례성), 차별 금지(특정 집단 프로파일링), 행위 분석 점수는 조사 단서이지 단독 근거가 아님, 조사 전 법무·인사 참여, 투명성(모니터링 사실 고지가 억제 효과와 법적 요건을 함께 충족).

    원문 사례 — 퇴사 통보 후 데이터 유출. 퇴사를 통보한 직원이 2주 인수인계 기간에 대량의 설계 문서를 개인 클라우드로 올렸는데, 평소 권한 범위 안이었고 업무 시간 중이었습니다. 퇴사 통보 후 집중 모니터링 기간을 두고, 외부 저장소 업로드를 DLP로 탐지하고, 고위험 역할은 통보 시점에 권한 범위를 줄였습니다.

    원문 사례 — 지원 접근이 예방한 내부자 사건. 감시 중심 프로그램은 1년간 탐지 성과가 미미하고 직원 불만만 늘었는데, 재정 곤란·불만·스트레스에 대한 지원 경로와 결합하자 두 건의 자발적 상담이 생겨 잠재 사건으로 커지기 전에 해소되었습니다.

    연결권한 원칙과 직무 순환은 D7.4 기본 보안 운영 개념, UEBA와 유출 모니터링은 D7.2 로깅·모니터링의 6·8절, 퇴사 처리는 D5.5 프로비저닝 생애주기의 4절, 조사 절차는 D7.1 조사의 9절에서 다룹니다.

    원본 연습문제 · D7.15-Q04

    퇴사를 통보한 직원이 2주의 인수인계 기간에 이미 보유한 접근 권한으로 업무 시간 중 대량의 설계 문서를 개인 클라우드 저장소로 업로드했다. 이 패턴을 해소하는 통제는?

    1. 인수인계 필요와 무관하게 통보 즉시 모든 접근을 차단한다.
    2. 통보 후 집중 모니터링 기간을 설정하고 외부 저장소 업로드에 데이터 유출 방지를 적용하며 고위험 역할은 통보 시점에 권한 범위를 축소한다.
    3. 직원에게 추가 비밀 유지 협약 서명을 요구한다.
    4. 사내 네트워크에서 개인 기기 사용을 금지한다.
    정답과 해설 보기

    정답 B. 퇴사 통보 후 데이터 유출이 집중된다는 것이 알려진 패턴이다. 권한 범위 내의 정상 시간 활동이므로 통보 후 집중 모니터링 기간을 설정하고 외부 저장소 업로드를 유출 방지로 탐지하며 고위험 역할은 통보 시점에 권한 범위를 축소해야 한다.

    • A · 즉시 전면 차단은 인수인계를 불가능하게 만들고 역할별 판단이 필요하다.
    • C · 서면 협약은 억제 효과가 제한적이고 탐지를 제공하지 않는다.
    • D · 클라우드 업로드는 개인 기기 없이도 가능하다.

    4소셜 미디어 영향

    조직 위험내용
    정보 노출업무 사진의 화면, 화이트보드, 배지, 설비 — 의도하지 않은 노출이 대부분
    조직 구조 노출직함, 보고 체계, 기술 스택 → 표적 피싱의 재료
    채용 공고의 과다 정보사용 중인 제품과 버전
    위장 계정, 포섭 접근임원·채용 담당자 사칭, 가짜 채용 제안
    평판·물리 안전발언의 조직 입장 해석, 출장·재택 위치와 일정 노출
    개인 신원 정보보안 질문 답의 재료(어머니 성, 반려동물, 출신 학교)

    대응: 예시 중심 정책(“조심하라”가 아니라), 실제 사례 교육, 공식 창구 지정, 채용 공고 검토, 임원 보호와 사칭 계정 모니터링, 보안 질문 지양.

    원본의 경계: 직원의 개인 소셜 미디어를 조직이 통제할 수는 없다. 통제 대상은 업무 정보의 노출이며 개인 표현과 구분해야 합니다. 과도한 통제는 법적 문제와 반발을 낳습니다.

    원문 사례 — 사진에 담긴 노출. 직원이 올린 사무실 사진 배경에 모니터의 고객 목록, 화이트보드의 네트워크 다이어그램, 배지 번호가 선명하게 담겨 있었습니다. 실제 사례 이미지로 보여 주는 교육, 민감 구역 촬영 제한, 화이트보드 지우기 습관으로 대응했습니다.

    원문 사례 — 채용 공고가 제공한 정찰 정보. 채용 공고에 보안 제품과 버전, 클라우드 구성, 레거시 시스템이 상세히 적혀 있어 침투 테스트 팀이 이를 정찰의 주 출처로 썼습니다. 제품명 대신 범주로 일반화하고 공고를 보안 검토 대상에 넣었습니다.

    연결사회공학의 원리는 D1.12 인식·교육·훈련, 보안 질문이 MFA가 아닌 이유는 D5.2 식별·인증 전략의 2절에서 다룹니다.

    원본 연습문제 · D7.15-Q08

    침투 테스트 팀이 조직의 채용 공고를 주 정찰 출처로 사용했다. 공고가 보안 제품명과 버전, 클라우드 구성, 레거시 시스템을 상세히 기재했기 때문이다. 적절한 통제는?

    1. 채용 공고 게시를 중단하고 채용 대행사에만 의존한다.
    2. 지원자가 공고를 보기 전에 비밀 유지 협약에 서명하도록 요구한다.
    3. 공격자를 오인시키기 위해 의도적으로 거짓 기술 세부를 게시한다.
    4. 공고의 기술 세부를 일반화해 제품명과 버전 대신 범주를 기재하고 공고 검토를 보안 검토 범위에 포함한다.
    정답과 해설 보기

    정답 D. 채용 공고는 누구나 볼 수 있는 공개 정찰 자료다. 제품명과 버전은 알려진 취약점 조회로 바로 이어지므로 범주 수준으로 일반화하고 공고 검토를 보안 검토 대상에 포함시켜야 한다.

    • A · 공고 중단은 채용 자체를 어렵게 만든다.
    • B · 공개 공고에 비밀 유지 협약은 적용할 수 없다.
    • C · 허위 정보는 지원자를 오인시키고 신뢰를 해친다.

    52FA 피로 (MFA Fatigue / Push Bombing)

    수법: 탈취한 비밀번호로 로그인을 반복 시도해 사용자에게 푸시 알림을 대량 발송합니다. 사용자가 짜증·혼란·“시스템 오류겠지”라는 판단으로 승인하면 접근이 성립합니다. 헬프데스크 사칭 연락과 결합되는 경우가 많습니다(“인증 요청을 승인해 주세요”).

    대응내용
    번호 매칭화면의 숫자를 앱에 입력해야 승인. 무심한 탭 방지
    추가 맥락 표시로그인 위치, 앱, IP
    속도 제한과 자동 차단반복 요청 시 차단·경보
    피싱 저항성 인증FIDO2와 패스키가 근본 해결 — 푸시 승인 자체가 없음
    탐지다수 거부 후 승인, 단시간 다수 요청
    교육“예상하지 못한 인증 요청은 거부하고 신고한다”, “헬프데스크는 인증 승인을 요청하지 않는다”
    신고 경로거부만으로는 조직이 공격을 모름 → 거부 후 신고

    관련 수법: SIM 스와핑(SMS 우회), 실시간 피싱 중계(AiTM)(TOTP와 푸시 모두 우회, FIDO2가 대응), MFA 재등록 사회공학.

    원문 사례 — 2FA 피로 공격 성공. 공격자가 야간에 푸시를 반복 발송해 사용자가 잠결에 승인했고, 이후 헬프데스크를 사칭해 다른 사용자도 공략했습니다. 번호 매칭, 위치·앱 표시, 단시간 다수 요청 차단, 위 두 교육 메시지로 대응하고 FIDO2 전환을 추진했습니다.

    원문 사례 — 거부만 하고 신고하지 않은 경우. 여러 사용자가 의심스러운 푸시를 거부했지만 신고하지 않아 조직은 공격이 진행 중임을 몰랐고, 결국 한 사용자가 승인해 침해가 일어났습니다. 거부 이벤트 자체를 경보 대상으로 등록했습니다.

    연결MFA 수단의 강도와 FIDO2 원리, 헬프데스크 재등록 우회는 D5.2 식별·인증 전략의 2절과 4절에서 다룹니다.

    6비상 관리 (Emergency Management)

    구성요소요점
    대피 계획경로, 집결 지점, 인원 점검 담당. 장애인과 방문자 포함
    대피 훈련훈련하지 않은 계획은 혼란을 만듦
    인원 점검누가 안전한가. 출입 기록이 재실 인원 파악의 근거
    대피소(shelter-in-place)밖이 더 위험할 때(화학 유출, 외부 위협, 기상)
    응급 처치·AED, 비상 소통, 외부 기관 연계소방, 경찰, 의료
    역할과 대리자, 사후 지원층별 담당, 심리 지원, 가족 소통

    특수 상황: 의료 응급, 적대적 침입자(지역 지침에 따른 절차와 훈련), 작업장 폭력(위협 평가, 보고 경로, 접근 권한 즉시 차단), 감염병(재택 전환, 인력 가용성 저하).

    보안과의 접점

    • 대피 중 보안 공백: 건물이 비는 동안 자산 노출 → 대피 후 재진입 통제.
    • 비상 시 fail-safe 문이 열리면 보안 구역이 개방됩니다.
    • 허위 경보를 이용한 침입: 화재 경보를 울려 대피시킨 뒤 침입.
    • 비상 상황의 보안 우회가 영구화되는 것.

    원문 사례 — 허위 화재 경보를 이용한 침입. 공격자가 화재 경보를 작동시켜 건물을 대피시킨 뒤 혼란 중 제한 구역에 들어갔고, fail-safe 문은 모두 열려 있었습니다. 대피 후 재진입 통제, 대피 중 핵심 구역 감시 유지, 경보 원인 확인 절차를 추가했습니다. 문을 잠그는 것이 아니라 안전을 해치지 않는 방식으로 공백을 메운 것입니다.

    보충현장 안전 확인과 업무 복구 승인에는 서로 다른 정보가 필요합니다. 인원 상태가 확인된 경로와, 시설을 다시 써도 된다는 판단을 각각 기록하면 복구 책임자가 무엇을 기다려야 하는지 분명해집니다. 병원처럼 환자가 있는 시설에서는 “대피”와 “환자 이송·대피소 유지”의 판단이 별도로 필요합니다.

    연결fail-safe 문과 출입 기록은 D7.14 물리적 보안, BC 훈련은 D7.13 7절, DR의 인원 원칙은 D7.11 재해 복구 프로세스의 3절에서 다룹니다.

    7강압 (Duress)

    사람이 위협 하에 강제로 행동하도록 요구받는 상황입니다.

    통제 수단내용
    강압 코드정상과 다른 코드를 입력하면 겉으로는 정상 동작하면서 조용히 경보
    강압 경보고정식, 휴대식, 발 스위치
    안전 확인 문구통화 중 특정 문구로 강압 상황을 알림
    체크인 절차정기 확인이 없으면 이상 신호
    감시 연동경보 시 해당 구역 카메라 자동 표시

    원본의 핵심 원칙: 강압 통제의 원칙은 “순응하라”다. 사람의 생명이 자산보다 우선하므로 저항하지 말고 요구에 따르면서 조용히 경보를 보내는 것이 설계 목표입니다.

    • 은밀성: 가해자가 눈치채면 피해자가 위험해집니다. 확인 음이나 화면 표시가 없어야 합니다.
    • 오작동 방지와 진짜 경보를 놓치지 않을 균형.
    • 대응 절차: 즉시 현장 진입이 아니라 상황 평가와 외부 기관 연계가 우선인 경우가 많습니다.
    • 훈련: 코드를 기억하지 못하면 쓸모없고, 훈련 사실이 외부에 알려지면 효과가 떨어집니다.
    • 이중 효과 방지: 강압 코드가 실제로 금고를 열어 주되 경보가 가야 합니다. 열리지 않으면 가해자가 폭력을 씁니다.
    • 적용 대상: 현금 취급, 단독·야간 근무, 접수, 고위험 지역 출장, 임원.

    논리적 강압: 암호 강제 제공 요구(지역별 법적 의무가 다름), 부인 가능 암호화(실효성과 법적 위험이 논쟁적), 그리고 한 사람이 혼자 모든 것을 열 수 없게 하는 접근 설계(이중 통제, 지식 분할)가 강압에 대한 구조적 방어입니다.

    원문 사례 — 강압 코드가 작동하지 않은 설계. 현금 취급 지점에서 직원이 강도 상황에 강압 코드를 입력했지만 금고가 열리지 않도록 설계되어 있었고, 가해자가 폭력을 썼습니다.

    원문 사례 — 혼자 열 수 없게 만든 구조적 방어. 금고와 암호 키에 이중 통제와 지식 분할을 적용해, 한 직원이 강압 상황에 놓였을 때 혼자서는 열 수 없었고 가해자가 얻을 수 있는 것이 제한되었습니다.

    가상 예시야간 응급실 접수 담당자에게 발 스위치 강압 경보를 주었는데, 경보를 받은 보안팀이 어디로 어떻게 대응해야 할지 정해져 있지 않았다고 합시다. 강압 신호는 받는 쪽의 절차(누가 받는가, 현장 진입 전에 무엇을 확인하는가, 언제 경찰에 연락하는가)와 함께 설계되어야 운영 통제가 됩니다. 신호만 있고 대응이 없으면, 은밀하게 보낸 경보가 아무 일도 일으키지 못합니다.

    연결이중 통제와 지식 분할은 D7.4 기본 보안 운영 개념의 3절, 감시 연동은 D7.14 물리적 보안의 4절에서 다룹니다.

    원본 연습문제 · D7.15-Q01

    현금 취급 지점에 강압 코드를 도입했으나 강압 코드 입력 시 금고가 열리지 않도록 구성되어 있었다. 실제 강도 상황에서 직원이 강압 코드를 입력했고 금고가 열리지 않아 가해자가 폭력을 사용했다. 설계상의 오류는?

    1. 가해자가 도망가도록 강압 코드가 경보음을 발생시켜야 했다.
    2. 강압 통제는 요구를 충족시키면서 조용히 경보를 보내야 한다. 지배 원칙은 순응하고 사람을 보호하는 것이다.
    3. 현금 취급에 강압 코드를 아예 사용하지 않아야 했다.
    4. 직원이 요구를 거부하고 저항하도록 교육받아야 했다.
    정답과 해설 보기

    정답 B. 강압 통제의 핵심 원칙은 순응하라다. 사람의 생명이 자산보다 우선하므로 강압 코드는 겉으로는 요구를 충족시키면서 조용히 경보를 보내야 한다. 요구가 충족되지 않으면 가해자가 폭력을 사용해 피해자가 위험해진다. 또한 확인 음과 화면 표시가 없어야 은밀성이 유지된다.

    • A · 경보음은 은밀성을 깨뜨려 피해자를 더 위험하게 만든다.
    • C · 강압 코드는 현금 취급 지점의 표준 통제다.
    • D · 저항 유도는 생명을 위험에 두는 잘못된 설계다.

    9종합 이해 확인

    종합 · 자작 상황 문제 (실제 시험 문제 아님)

    인원 보안 점검 결과다. ㉠ 고위험 지역 출장자가 평소 업무 노트북을 그대로 가져간다. ㉡ 여러 직원이 의심스러운 푸시 알림을 거부만 하고 신고하지 않았다. ㉢ 현금 취급 지점의 강압 코드는 금고를 열지 않도록 되어 있다. ㉣ 화재 경보 대피 후 제한 구역 재진입 통제가 없다. 가장 적절한 대책 묶음은?

    1. ㉠ 출장 전용 기기와 데이터 최소화, 귀국 후 초기화 / ㉡ “거부하고 신고”, 거부 이벤트 경보, 번호 매칭·FIDO2 / ㉢ 강압 코드는 요구를 충족하면서 조용히 경보 / ㉣ 대피 후 재진입 통제와 대피 중 핵심 구역 감시
    2. ㉠ 노트북 암호 강화만 / ㉡ 푸시 알림 끔 / ㉢ 강압 코드 입력 시 경보음 / ㉣ 비상구를 fail-secure로
    3. ㉠ 출장 금지 / ㉡ 거부한 직원 칭찬만 / ㉢ 강압 코드 폐지 / ㉣ 화재 경보 비활성화
    4. ㉠ 그대로 / ㉡ SMS OTP로 교체 / ㉢ 금고 이중 잠금으로 직원도 못 열게 하고 경보 없음 / ㉣ 경비 증원만
    정답과 해설 보기

    정답 A. ㉠ 2절(가져가지 않는 것이 핵심), ㉡ 5절(거부만으로는 탐지가 안 됨), ㉢ 7절(순응, 은밀한 경보 — B의 경보음은 은밀성을 깸), ㉣ 6절(안전을 해치지 않으면서 공백을 메움 — B의 비상구 fail-secure는 인원 안전 위반).

    먼저 비상 계획에 따라 사람과 현장의 안전을 확인합니다. 재진입 승인 여부와 업무 중단 상태를 구분해 보고한 다음 안전한 방식으로 대체 운영과 복구를 진행합니다.

    11핵심 요약

    1. 인원 안전 > 자산·데이터·가용성. 두 축: 안전(해를 입지 않게)과 보안(사람을 경로로 한 침해). 자산을 지키려다 사람을 위험에 두는 설계가 전형적 실패.
    2. 출장: 데이터 최소화(가장 효과적), 출장 전용 기기, 전원 종료, VPN·분할 터널링 금지, 충전 포트 주의, 귀국 후 초기화.
    3. 내부자: 악의적·부주의·침해된. 악의적 내부자는 정당한 권한·정상 경로. 최소권한이 가장 근본, 퇴사 전후 집중 모니터링, 지원 접근, 투명성, 점수는 단서일 뿐.
    4. 소셜 미디어: 사진 속 화면·배지, 조직 구조, 채용 공고, 사칭, 보안 질문 재료. 통제 대상은 업무 정보 노출이지 개인 표현이 아니다.
    5. 2FA 피로: 푸시 대량 발송 + 헬프데스크 사칭. 번호 매칭, 맥락 표시, 속도 제한, FIDO2가 근본 해결. “거부하고 신고”, 헬프데스크는 승인을 요청하지 않는다. AiTM은 TOTP·푸시 모두 우회.
    6. 비상 관리: 대피(장애인·방문자), 인원 점검(출입 기록), 대피소, 외부 기관. 허위 경보 침입 → 대피 후 재진입 통제.
    7. 강압: 강압 코드·경보·확인 문구. 원칙은 순응, 은밀성, 열어 주되 경보, 대응은 평가 먼저. 이중 통제·지식 분할이 구조적 방어.
    8. 인적 보안 생애주기: 채용 심사, 계약·NDA, 재직 관리, 퇴사 처리, 공급자·계약 인력도 같은 수준.
    원문 위치: D7.15.md §8 CISSP 시험 관점, §9 핵심 암기 요약. 원본의 출제 단정 표현은 판단 기준으로 바꿔 적었습니다.

    12주요 용어 (Glossary)

    영어 원어와 한국어 뜻 · English–Korean

    Clean Device · 출장 전용 기기

    최소 구성으로 준비해 출장 후 초기화하는 기기. 고위험 지역에 적합하다.

    Shoulder Surfing · 화면 엿보기

    어깨 너머로 화면이나 입력을 관찰하는 수법.

    Juice Jacking · 충전 포트 악용

    공공 충전 포트의 데이터 라인을 통한 공격.

    Insider Threat · 내부자 위협

    악의적, 부주의한, 침해된 내부자에 의한 위협.

    Compromised Insider · 침해된 내부자

    자격증명이 탈취되어 공격자가 내부자로 활동하는 상태.

    MFA Fatigue / Push Bombing · 2FA 피로

    푸시 알림을 대량 발송해 사용자의 무심한 승인을 유도하는 공격.

    Number Matching · 번호 매칭

    화면의 숫자를 앱에 입력하게 해 무심한 승인을 막는 방식.

    AiTM (Adversary-in-the-Middle) · 공격자 중간 개입

    가짜 사이트가 인증 코드를 실시간 중계하는 피싱. TOTP 와 푸시를 우회한다.

    SIM Swapping · SIM 스와핑

    통신사를 속여 번호를 이전해 SMS 기반 인증을 우회하는 공격.

    Shelter-in-place · 피난처 대기

    밖으로 나가는 것이 더 위험할 때 건물 내에 머무는 대응.

    Accountability / Headcount · 인원 점검

    대피 후 누가 안전한지 확인하는 활동.

    Duress Code · 강압 코드

    정상 동작을 유지하면서 조용히 경보를 발생시키는 코드.

    Panic Button · 비상 경보 장치

    강압이나 위협 상황에서 경보를 발생시키는 장치.

    Duress Word · 안전 확인 문구

    통화 중 강압 상황을 알리는 사전 합의된 문구.

    Dual Control / Split Knowledge · 이중 통제 / 지식 분할

    혼자서 열 수 없게 만드는 통제. 강압에 대한 구조적 방어다.

    연습문제 5개 바로가기

    표시 없는 본문은 원본 정리 파일의 내용 · 보충은 원본에 없어 더한 설명 · 가상 예시는 지어낸 상황 · 연결은 다른 단원과의 관계 · 확인 필요는 그대로 확정하지 않은 부분

    자원 보호는 정보가 담긴 매체와, 저장·전송·사용이라는 데이터의 세 상태를 보호하는 일입니다. 원본은 두 가지를 강조합니다. 하나는 암호화는 접근 통제를 대체하지 않는다는 것, 정당한 권한으로 복호화된 데이터를 읽는 공격자에게 암호화는 효과가 없습니다. 다른 하나는 매체 관리의 실패는 정책이 아니라 “아무도 그 매체의 존재를 몰랐다”에서 나온다는 것입니다.

    1데이터의 세 상태와 매체

    상태위치주된 보호 수단
    저장 at rest디스크, 테이프, 백업, 객체 저장소암호화 + 접근 통제 + 물리 보호
    전송 in transit네트워크TLS, IPsec, 상호 인증
    사용 in use메모리, CPU격리, 메모리 보호, 기밀 컴퓨팅

    원본은 암호화가 막는 것을 분명히 합니다. 매체 분실, 디스크 탈취, 전송 가로채기입니다. 정당한 경로로 들어온 사용자나 그 계정을 탈취한 공격자는 암호화의 영향을 받지 않습니다. 매체는 데이터의 물리적 담체이고, 데이터 분류가 매체 취급 수준을 결정합니다.

    연결데이터 상태별 보호는 D2.6 데이터 보안 통제, 데이터 분류는 D2.1 자산 식별과 분류에서 다룹니다.

    원문 위치: D7.5.md §2 · 공식 개요 7.5 “Apply resource protection”, “Data at rest / data in transit”

    2매체 관리

    매체의 범위

    • 이동식 매체: USB, 외장 디스크, 광학 매체, 메모리 카드
    • 백업 매체: 테이프, 백업 디스크
    • 내장 저장장치: 서버·단말·모바일의 디스크와 플래시
    • 종이: 인쇄물, 출력물, 수기 기록 — 가장 자주 빠지는 범주
    • 폐기 대상 장비: 복합기·프린터 내부 디스크, 네트워크 장비 설정 메모리, 의료·산업 장비
    • 클라우드 저장소: 물리 매체는 통제 밖이지만 논리적 삭제와 암호화는 고객 책임

    원문 사례 — 복합기 내부 디스크. 리스 만료된 복합기를 반납한 뒤 점검에서 내부 디스크에 수년간의 스캔·인쇄·팩스 이미지가 저장되어 있었음이 확인되었습니다. 장비 반납 전 정화를 자산 폐기 절차의 필수 단계로 넣었습니다.

    가상 예시병원이 초음파 장비를 교체하며 리스사에 반납한다고 합시다. 장비 내부 저장장치에 환자 영상과 식별 정보가 남아 있을 수 있습니다. 의료기기는 제조사 서비스 절차 없이 저장장치를 다루기 어려운 경우가 많으므로, 구매·리스 계약 단계에서 반납 전 데이터 삭제 방법과 증빙 제공을 정해 두는 편이 현실적입니다. 매체 관리의 범위를 “IT 자산”으로만 잡으면 이런 장비가 빠집니다.

    연결자산 인벤토리는 D2.3 안전한 프로비저닝, 자산 보존과 폐기 시점은 D2.5 자산 보존 (EOL·EOS)에서 다룹니다.

    원본 연습문제 · D7.5-Q11

    매체 관리에 속하는 실무는?

    1. 담긴 데이터의 분류에 따라 매체에 표식을 붙이고 위치와 보관 책임을 추적하며 재사용이나 폐기 전에 정화하는 일.
    2. 애플리케이션의 세션 시간 초과 설정.
    3. 애플리케이션이 사용하는 암호 알고리즘 선정.
    4. 조직의 사용 정책 작성.
    정답과 해설 보기

    정답 A. 매체 관리는 물리적 저장 매체의 생애주기를 다룬다. 표식이 없으면 취급자가 민감도를 알 수 없고, 위치 추적이 없으면 분실을 인지하지 못하며, 정화 없이 재사용하면 이전 데이터가 남는다. 알고리즘 선정과 세션 설정은 다른 영역이다.

    • B · 애플리케이션 설정 영역이다.
    • C · 암호 솔루션 선정 영역이다.
    • D · 정책 수립 영역이다.

    원본 연습문제 · D7.5-Q08

    리스 기간이 만료된 복합기를 반납했다. 이후 검토에서 내부 디스크에 수년간의 스캔과 인쇄, 팩스 이미지가 보존되어 있었음이 확인되었다. 자산 폐기 절차에 추가해야 할 것은?

    1. 기기 반납 전에 인쇄 대기열을 삭제하도록 하는 요건.
    2. 인쇄 대기열에 있는 동안에만 문서를 암호화하는 것.
    3. 반납 전 모든 기기의 내부 저장장치 정화를 의무화하고 디스크 반환 또는 파괴에 대한 계약 조항을 두는 것.
    4. 분류된 문서의 스캔을 금지하는 정책.
    정답과 해설 보기

    정답 C. 복합기와 프린터, 네트워크 장비, 의료와 산업 장비의 내부 저장장치도 매체다. 반납이나 폐기 전 정화를 자산 폐기 절차의 필수 단계로 넣고 리스 계약에 디스크 반환 또는 파괴 조항을 포함시켜야 한다.

    • A · 대기열 삭제는 저장된 이미지를 지우지 않는다.
    • B · 대기열 구간 암호화는 저장된 이력을 보호하지 않는다.
    • D · 스캔 금지는 업무를 제약하며 근본 해결이 아니다.

    3잔류 데이터와 객체 재사용

    • 데이터 잔류(data remanence): 삭제했다고 생각한 데이터가 매체에 남아 있는 현상.
    • 삭제와 포맷은 데이터를 지우지 않습니다. 파일 시스템의 포인터만 제거하거나 메타데이터만 초기화합니다.
    • 객체 재사용(object reuse): 이전 사용자의 데이터가 남은 저장 공간이 다른 주체에게 할당되는 문제. 메모리와 디스크 모두에 적용됩니다.
    • 슬랙 공간과 미할당 영역에 잔존 데이터가 남습니다(포렌식이 이를 이용).

    연결잔류의 원리는 D2.4 데이터 생애주기의 6절, 포렌식에서의 활용은 D7.1 조사의 5절에서 다룹니다.

    4매체 정화 — Clear, Purge, Destroy

    수준방법재사용
    Clear 소거덮어쓰기 등 논리적 제거조직 내 동일 등급 재사용
    Purge 제거암호 소거, 블록 소거, 디가우징조직 외부 반출 가능
    Destroy 파괴분쇄, 소각, 용융재사용 불가

    선택 기준은 매체 재사용 범위와 데이터 분류입니다.

    매체적합한 방법
    HDD덮어쓰기 효과적. 디가우징은 자기 매체에만 유효하며 디가우징 후 디스크는 사용 불가
    SSD·플래시덮어쓰기를 신뢰할 수 없음(웨어 레벨링, 과잉 프로비저닝). 디가우징 무효. 암호 소거나 제조사 블록 소거, 또는 파괴
    광학 매체덮어쓸 수 없으므로 파괴
    테이프덮어쓰기, 디가우징, 파괴
    모바일 기기기기 전체 암호화 상태에서 키 삭제(암호 소거)
    종이교차 절단 분쇄 또는 소각. 직선 절단은 복원 가능성

    암호 소거와 폐기 증빙

    암호 소거(Cryptographic Erase)는 암호화해 저장한 상태에서 키만 안전하게 삭제합니다. 전제는 처음부터 암호화되어 있었고 키 삭제가 확실해야 한다는 것입니다. 대용량에도 즉시 수행되어 SSD에 적합하고, 클라우드에서는 사실상 유일한 확정적 삭제 수단입니다. 키 사본이 어딘가 남아 있으면 무효입니다.

    폐기 증빙: 외부 위탁 시 파괴 증명서, 고등급 매체는 입회 또는 영상 기록, 그리고 매체 식별자 대조. 원본은 대조 없는 위탁이면 매체가 중간에 사라져도 알 수 없다고 경고합니다.

    원문 사례 — SSD를 덮어쓰기로 정화한 실패. 폐기 예정 노트북 200대를 3회 덮어쓰기로 정화해 재판매업체에 넘겼는데, 샘플 검증에서 일부 기기의 이전 데이터 조각이 복원되었습니다. 전체 디스크 암호화를 기본 적용하고 폐기 시 암호 소거를 수행하며, 외부 반출 기기는 추가로 블록 소거나 물리 파괴를 적용했습니다.

    원문 사례 — 디가우징한 디스크를 재사용하려 한 경우. 디가우징한 디스크를 재사용 풀로 반환했더니 전부 동작하지 않았습니다. 디가우징은 서보 정보까지 지워 디스크를 쓸 수 없게 만듭니다.

    원문 사례 — 대조 없는 파괴 위탁. 파괴를 외부 업체에 맡기고 증명서만 받았는데, 감사에서 보낸 매체 목록과 파괴된 매체 식별자를 대조한 기록이 없었습니다. 식별자 단위 인수인계와 대조를 의무화했습니다.

    확인 필요NIST SP 800-88은 2025년 9월 Rev. 2로 개정되어 Rev. 1을 대체했습니다. 세 방법(Clear·Purge·Destroy)의 틀은 유지된 것으로 알려져 있지만 매체별 기법 설명과 디가우징의 위상에 변화가 있다는 2차 자료가 있습니다. 개정 내용과 출처는 D2.4 7절의 확인 필요 상자에 정리했습니다. 이 절의 매체별 방법은 원본(Rev. 1 기준)을 따릅니다.

    보충Clear는 일반적인 접근으로는 데이터를 얻기 어렵게 하고, Purge는 실험실 수준의 복구 시도에도 대응하며, Destroy는 매체를 다시 쓸 수 없게 만듭니다. 적합한 자기 매체에 적용한 디가우징은 Purge 기법이지만 결과적으로 디스크가 동작하지 않게 되므로, “재사용할 것인가”라는 질문이 방법 선택을 먼저 가릅니다.

    원본 연습문제 · D7.5-Q01

    솔리드 스테이트 드라이브를 사용하는 노트북 200대를 3회 덮어쓰기로 정화해 재판매업체에 매각했다. 이후 표본 검증에서 이전 데이터 조각이 복원되었다. 사용해야 했던 방법은?

    1. 플래시 매체에서는 덮어쓰기를 신뢰할 수 없으므로 암호 소거나 블록 소거, 또는 물리 파괴.
    2. 3회가 아니라 7회 덮어쓰기.
    3. 어떤 저장 매체에서든 데이터를 제거하는 디가우징.
    4. 빠른 포맷 후 파티션 테이블 제거.
    정답과 해설 보기

    정답 A. SSD 는 웨어 레벨링과 과잉 프로비저닝 영역 때문에 논리 주소에 쓴 데이터가 물리적으로 다른 블록에 저장되고 이전 블록이 남는다. 따라서 덮어쓰기 횟수를 늘려도 신뢰할 수 없다. 전체 디스크 암호화를 전제로 한 암호 소거, 장치의 블록 소거, 또는 물리 파괴가 적절한 방법이다.

    • B · 횟수를 늘려도 접근되지 않는 물리 블록은 지워지지 않는다.
    • C · 디가우징은 자기 매체에만 유효하며 플래시에는 무효다.
    • D · 포맷과 파티션 제거는 데이터를 지우지 않는다.

    5저장 데이터 보호 (Data at Rest)

    암호화 계층보호 대상보호하지 못하는 것
    전체 디스크(FDE)디스크 탈취, 분실부팅·로그인된 시스템의 OS 접근
    파일·폴더선택적 보호다른 파일, 메타데이터
    DB 투명 암호화(TDE)데이터 파일과 백업DB 권한을 가진 접근
    열·필드 수준특정 민감 필드권한 있는 애플리케이션
    애플리케이션 계층DB 관리자까지 차단애플리케이션 침해

    원본의 정리: 각 계층은 다른 위협을 막는다. FDE는 노트북 분실에 효과적이지만 켜져 있고 로그인된 시스템에서는 효과가 없습니다. TDE는 데이터 파일 탈취를 막지만 DB 접근 권한이 있는 사람에게는 평문이 보입니다. DB 관리자가 운영은 하되 민감 열을 평문으로 볼 수 없어야 한다면, 애플리케이션 계층 암호화와 관리자가 접근할 수 없는 별도 KMS의 키가 답입니다.

    백업 데이터와 물리 보호

    • 백업도 원본과 같은 분류를 받습니다. 원본은 암호화하고 백업은 평문으로 두는 모순이 흔합니다.
    • 백업 매체의 이동과 외부 보관이 분실 위험을 만듭니다.
    • 백업 접근 권한이 데이터 접근 권한을 우회할 수 있습니다. 백업 운영자가 전체를 복원해 읽을 수 있으면 접근 통제가 무의미합니다.
    • 랜섬웨어 대비: 분리된 자격증명, 불변 저장, 오프라인 사본.
    • 물리 보호: 데이터센터 접근 통제, 잠금 캐비닛과 금고, 환경 통제(테이프는 온습도·자기장에 민감), 보관 장소의 지리적 분리.

    원문 사례 — 원본은 암호화, 백업은 평문. 운영 DB에는 TDE를 적용했지만 백업 파일은 평문으로 외부 보관소에 보내졌고, 운송 중 테이프 하나가 분실되었습니다.

    원문 사례 — FDE가 막지 못한 유출. 전사에 FDE를 적용했지만 한 직원이 로그인된 노트북을 카페에 두고 자리를 비운 사이 데이터가 복사되었습니다. 화면 자동 잠금 시간 단축과 이석 시 잠금 교육으로 대응했습니다.

    가상 예시외부 보관소의 암호화 백업이 무결성 검사는 통과했는데, 원래 키 서비스가 종료되어 복구 환경에서 읽을 수 없다고 합시다. 암호화된 백업은 데이터·키 버전·키 서비스 접근 경로가 함께 있어야 복구됩니다. 복구 시험에는 “파일이 온전한가”뿐 아니라 “그 시점의 키로 복호화되는가”가 포함되어야 합니다.

    연결데이터 접근과 키 접근의 분리 사례는 D5.1 물리적·논리적 접근 통제의 3절, 백업 검증 지표는 D6.3 보안 프로세스 데이터의 4절, 데이터센터 물리 보안은 D7.14 물리적 보안에서 다룹니다.

    원본 연습문제 · D7.5-Q04

    데이터베이스 관리자가 데이터베이스를 운영할 수는 있어야 하지만 민감 열 값을 평문으로 읽을 수는 없어야 한다는 요구사항이 있다. 이를 충족하는 접근은?

    1. 관리자가 접근할 수 없는 별도 키 관리 서비스에 키를 두는 애플리케이션 계층 암호화.
    2. 데이터베이스에 대한 모든 클라이언트 연결에 TLS 활성화.
    3. 데이터베이스 서버에 대한 전체 디스크 암호화.
    4. 데이터베이스 파일에 대한 투명 데이터 암호화.
    정답과 해설 보기

    정답 A. 투명 데이터 암호화와 전체 디스크 암호화는 데이터 파일 탈취를 막지만 데이터베이스에 접근 권한이 있는 관리자에게는 투명하게 복호화되어 보인다. 애플리케이션 계층에서 암호화하고 키를 별도 관리 서비스에 두어 관리자에게 키 접근 권한을 주지 않으면 평문을 볼 수 없다. 데이터 접근 권한과 키 접근 권한의 분리가 핵심이다.

    • B · TLS 는 전송 보호이며 저장 데이터 열람과 무관하다.
    • C · FDE 는 디스크 탈취 대비이며 운영 중 접근을 막지 않는다.
    • D · TDE 는 DB 권한 있는 접근에 투명하다.
    원문 위치 · D7.5-Q04
    문제 목록으로 돌아가기

    6전송 데이터 보호 (Data in Transit)

    수단특징
    TLS가장 보편적. 서버 인증 + 기밀성 + 무결성
    mTLS양쪽 인증. 서비스 간 통신의 기본
    IPsec네트워크 계층. 사이트 간 연결, 레거시 프로토콜 보호
    SSH관리 접속과 파일 전송
    애플리케이션 계층 암호화중간 지점을 신뢰할 수 없을 때 종단 간 보호
    흔한 실패결과
    인증서 검증 미비중간자 공격 노출. 클라이언트 코드에서 검증을 끄는 것이 전형적 실수
    레거시 프로토콜 허용다운그레이드 공격
    내부망은 안전하다는 가정내부 침해 후 횡적 이동과 자격증명 수집이 쉬움
    구간 암호화로드밸런서에서 복호화 뒤 평문 전달 구간이 노출 지점
    메타데이터 노출누가 누구와 언제 얼마나 통신했는지는 드러남
    URL·쿼리에 민감 데이터TLS로 보호되어도 로그, 브라우저 이력, 리퍼러에 남음

    비정형 경로도 전송입니다. 이메일(기본적으로 종단 간 암호화 아님), 파일 전송(FTP는 평문 → SFTP·FTPS), 물리 운송(암호화·봉인·추적), API와 웹훅(외부 통합 경로가 유출 경로).

    원문 사례 — 내부망 평문 가정. 내부 서비스 간 통신을 평문으로 운영하다가 한 서버가 침해되자 공격자가 내부 트래픽을 수집해 서비스 계정 자격증명과 개인정보를 대량 확보했습니다. 서비스 간 mTLS를 적용하고 네트워크 위치를 신뢰 근거로 삼지 않았습니다.

    연결TLS와 안전한 통신 채널은 D4.3 안전한 통신 채널, 제로 트러스트는 D3.1 안전한 설계 원칙, 인증서 검증은 D3.6 암호 솔루션에서 다룹니다.

    원문 위치: D7.5.md §3 전송 데이터 보호, §7 사례 8

    7사용 중 데이터 (Data in Use)

    메모리에 복호화된 상태로 있는 데이터는 보호가 가장 어렵습니다. 권한을 가진 공격자가 프로세스 메모리를 덤프하면 자격증명과 복호화 키가 드러납니다.

    • 프로세스 격리와 권한 분리
    • 메모리 내 보관 시간 최소화: 쓰고 즉시 지움
    • 키를 HSM에 두고 연산도 HSM 안에서: 평문 키가 메모리에 나오지 않음
    • 기밀 컴퓨팅: 하드웨어 기반 신뢰 실행 환경에서 처리해 OS·하이퍼바이저로부터도 격리
    • 동형 암호와 보안 다자 연산: 암호화 상태에서 연산(성능 제약 큼)
    • 토큰화와 가명화: 민감 값을 대체 값으로 바꿔 처리 구간에서 평문이 필요 없게(결제 환경)

    보충파일이 암호화된 디스크에 있어도, 정상 권한으로 열면 프로그램은 값을 처리합니다. 그래서 사용 중 보호는 암호화보다 “필요한 범위만 보여 주기”에 가깝습니다. 화면 표시 범위, 메모리 접근, 내보내기·복사 통제, 처리 환경의 격리, 사본이 기록되는 위치를 함께 봅니다.

    연결신뢰 실행 환경과 하드웨어 보안은 D3.4 시스템 보안 기능, 토큰화·가명화는 D2.6 데이터 보안 통제에서 다룹니다.

    원문 위치: D7.5.md §3 사용 중 데이터

    8키 관리가 결정한다

    원본의 결론: 암호화 통제의 실효성은 키 관리가 결정한다.

    • 키가 데이터와 같은 곳에 있으면 암호화는 무의미합니다. 디스크를 가져가면 키도 함께 갑니다.
    • 키 접근 권한과 데이터 접근 권한을 분리합니다.
    • 키 생애주기: 생성, 배포, 보관, 사용, 교체, 보관 해제, 파기.
    • 키 교체 뒤에도 과거 데이터 복호화를 위해 이전 키를 보관하므로 버전 관리가 필요합니다.
    • 키 백업과 복구: 키를 잃으면 데이터도 영구히 잃고, 동시에 키 백업이 공격 표면입니다.
    • HSM과 KMS: 키 보호와 사용 감사.
    • 클라우드 키 관리 모델: 공급자 관리 키, 고객 관리 키(CMK), 고객 보유 키(BYOK/HYOK). 통제 수준이 올라갈수록 운영 책임도 커집니다.
    • 암호 소거의 전제가 키 관리입니다.

    연결키 관리 생애주기와 HSM은 D3.6 암호 솔루션에서 다룹니다.

    원문 위치: D7.5.md §3 키 관리가 결정한다

    9종합 이해 확인

    종합 · 자작 상황 문제 (실제 시험 문제 아님)

    자원 보호 점검 결과다. ㉠ 폐기 노트북(SSD)을 3회 덮어쓰기 후 매각했다. ㉡ 운영 DB는 TDE, 백업은 평문으로 외부 보관된다. ㉢ 파괴 위탁 업체에서 증명서만 받는다. ㉣ 내부 서비스 간 통신이 평문이다. 가장 적절한 대책 묶음은?

    1. ㉠ 덮어쓰기 7회로 늘림 / ㉡ 백업 보관소 변경 / ㉢ 증명서 양식 개선 / ㉣ 방화벽 추가
    2. ㉠ FDE 기본 적용 후 암호 소거(또는 파괴) / ㉡ 백업도 같은 분류로 암호화, 운송 봉인·추적, 백업 접근 권한 분리 / ㉢ 매체 식별자 단위 인수인계와 대조, 고등급은 입회 / ㉣ 서비스 간 mTLS, 네트워크 위치를 신뢰 근거로 쓰지 않음
    3. ㉠ 디가우징 / ㉡ TDE로 충분 / ㉢ 위탁 중단 / ㉣ 내부망이므로 유지
    4. ㉠ 포맷 / ㉡ 백업 중단 / ㉢ 사진만 받음 / ㉣ VPN 하나로 전체를 감쌈
    정답과 해설 보기

    정답 B. ㉠ 4절(SSD 덮어쓰기는 신뢰 불가, 디가우징도 무효 — C가 틀린 이유), ㉡ 5절(백업도 같은 분류), ㉢ 4절(식별자 대조), ㉣ 6절(내부망 평문 가정).

    11핵심 요약

    1. 세 상태: 저장(암호화+접근 통제+물리), 전송(TLS·IPsec·상호 인증), 사용(격리·기밀 컴퓨팅). 암호화는 접근 통제를 대체하지 않는다.
    2. 매체 범위: 이동식, 백업, 내장, 종이(가장 자주 빠짐), 복합기·의료·산업 장비 내부 저장, 클라우드.
    3. 생애주기: 인벤토리(추적 안 되면 분실도 모름), 라벨(외부 이동 시 등급 노출 주의), 이동(운송 중 분실이 가장 흔함), 재사용 전 정화, 폐기 증빙.
    4. 잔류: 삭제·포맷은 지우지 않는다. 객체 재사용.
    5. Clear(내부 재사용) / Purge(외부 반출) / Destroy(재사용 불가). SSD는 덮어쓰기·디가우징 불신 → 암호 소거. 디가우징 후 HDD는 사용 불가. 광학은 파괴, 종이는 교차 절단. SP 800-88 Rev. 2 개정(D2.4).
    6. 폐기 증빙: 증명서 + 매체 식별자 대조 + 고등급 입회.
    7. 저장 암호화 계층: FDE(분실), TDE(파일 탈취), 앱 계층(DBA 차단) — 각각 다른 위협. 백업도 같은 분류, 백업 권한이 데이터 권한을 우회할 수 있음.
    8. 전송: 인증서 검증, 레거시 제거, 내부망 평문 가정 금지(mTLS), 구간 암호화, URL의 민감 데이터.
    9. 사용 중: HSM 내부 연산, 기밀 컴퓨팅, 토큰화.
    10. 키 관리가 실효성을 결정: 키와 데이터 분리, 버전 관리, 키 백업, CMK/BYOK/HYOK.
    원문 위치: D7.5.md §8 CISSP 시험 관점, §9 핵심 암기 요약. 원본의 출제 단정 표현은 판단 기준으로 바꿔 적었습니다.

    12주요 용어 (Glossary)

    영어 원어와 한국어 뜻 · English–Korean

    Media Management · 매체 관리

    정보를 담은 매체의 취득부터 폐기까지 생애주기를 통제하는 활동.

    Data Remanence · 데이터 잔류

    삭제했다고 생각한 데이터가 매체에 남아 있는 현상.

    Object Reuse · 객체 재사용

    이전 사용자의 데이터가 남은 저장 공간이 다른 주체에게 할당되는 문제.

    Clear / Purge / Destroy · 소거 / 제거 / 파괴

    NIST SP 800-88 의 세 가지 정화 수준.

    Degaussing · 디가우징

    강한 자기장으로 자기 매체의 데이터를 제거하는 방법. 자기 매체에만 유효하다.

    Cryptographic Erase · 암호 소거

    암호화된 데이터의 키만 안전하게 삭제해 복호화 불가능하게 만드는 방식.

    Wear Leveling · 웨어 레벨링

    플래시 저장장치가 쓰기를 분산하는 기법. 덮어쓰기 기반 정화를 신뢰할 수 없게 만든다.

    Over-provisioning · 과잉 프로비저닝

    SSD 가 예비로 보유하는 영역. 논리 주소로 접근되지 않아 데이터가 잔존한다.

    Certificate of Destruction · 파괴 증명서

    매체 파괴를 위탁한 경우 수행 사실을 입증하는 문서.

    FDE (Full Disk Encryption) · 전체 디스크 암호화

    디스크 전체를 암호화하는 방식. 분실과 탈취에 효과적이다.

    TDE (Transparent Data Encryption) · 투명 데이터 암호화

    데이터베이스가 데이터 파일을 투명하게 암호화하는 기능.

    Confidential Computing · 기밀 컴퓨팅

    하드웨어 기반 신뢰 실행 환경에서 처리해 OS 와 하이퍼바이저로부터 격리하는 기술.

    Tokenization · 토큰화

    민감 값을 대체 값으로 바꾸어 처리 구간에서 평문을 없애는 기법.

    BYOK / HYOK — Bring Your Own Key / Hold Your Own Key · 고객 키 가져오기 / 고객이 키 보유

    고객이 키를 제공하거나 자체 보유하는 클라우드 키 관리 모델.

    Key Rotation · 키 교체

    키를 주기적으로 교체하는 것. 과거 데이터 복호화를 위한 버전 관리가 필요하다.

    연습문제 5개 바로가기

    표시 없는 본문은 원본 정리 파일의 내용 · 보충은 원본에 없어 더한 설명 · 가상 예시는 지어낸 상황 · 연결은 다른 단원과의 관계 · 확인 필요는 그대로 확정하지 않은 부분

    방화벽, 스위치, 라우터, IDS, NAC, 엔드포인트 에이전트. 네트워크를 이루는 구성 요소마다 볼 수 있는 것과 볼 수 없는 것이 다릅니다. 원본의 출발점은 한 문장입니다. 네트워크 구성 요소의 보안은 “어느 계층에서 무엇을 볼 수 있는가”로 결정된다. 이 단원은 각 장비가 무엇을 근거로 판단하는지, 그래서 무엇을 놓치는지를 다룹니다.

    1방화벽 유형

    유형(계층)판단 기준한계
    패킷 필터 (3·4)IP·포트·프로토콜연결 상태를 모른다
    상태 기반 Stateful (3·4)연결 상태 추적내용은 보지 못한다
    애플리케이션/프록시 (7)내용 검사느림, 프로토콜별 구현 필요
    차세대(NGFW) (3~7)앱 식별·사용자·IPS 통합복잡도·비용
    WAF (7)웹 공격 패턴웹 전용

    상태 기반 방화벽은 연결 테이블을 유지해 내부에서 나간 요청에 대한 응답만 허용합니다. 패킷 필터는 이를 못 해서 응답 포트를 넓게 열어야 했습니다.

    원문 사례 — 상태를 모르는 방화벽. 레거시 패킷 필터가 내부에서 나간 요청의 응답을 받으려고 1024~65535 포트를 전면 개방하고 있었고, 공격자가 그 범위로 직접 접속해 내부 서비스에 닿았습니다. 상태 기반 방화벽으로 바꾸자 세션 테이블에 기록된 유효한 응답만 통과해 그 범위를 닫을 수 있었습니다.

    프록시, 베스천 호스트, DMZ

    • 프록시는 양쪽 연결을 중계합니다. 클라이언트와 서버가 직접 연결되지 않아 내부 구조가 숨겨지고, 내용 검사와 캐싱이 가능합니다. 포워드 프록시는 내부 사용자의 외부 접근을, 리버스 프록시는 외부 요청을 내부 서버로 중계합니다(부하 분산, TLS 종단).
    • 베스천 호스트(Bastion Host)는 외부에 노출되어 강화된 호스트입니다. 공격면을 최소화합니다.
    • DMZ / 스크린드 서브넷은 외부 공개 서비스를 내부망과 분리된 구간에 둡니다. 외부에서 DMZ로는 접근할 수 있지만 DMZ에서 내부망으로의 접근은 제한됩니다.

    보충유형 표를 위에서 아래로 읽으면 “방화벽이 점점 많은 것을 보게 된 역사”입니다. 패킷 필터는 봉투의 주소만, 상태 기반은 “이 편지가 우리가 보낸 편지의 답장인가”까지, 프록시·NGFW·WAF는 편지 내용까지 봅니다. 많이 볼수록 정밀하지만 느려지고 복잡해집니다. 그래서 실제 네트워크는 하나만 쓰지 않고 경계에는 상태 기반·NGFW, 웹 서버 앞에는 WAF를 겹쳐 둡니다(D3.1 안전한 설계 원칙의 심층 방어 사례). DMZ 규칙의 핵심은 방향입니다. 외부에서 DMZ로는 열고, DMZ에서 내부로는 닫습니다. DMZ 서버가 털리는 것을 전제로 그다음을 막는 설계입니다.

    원본 연습문제 · D4.2-Q01

    레거시 패킷 필터 방화벽이 아웃바운드 요청의 응답을 받기 위해 인바운드 1024~65535 포트를 개방해야 한다. 이 필요를 없애는 방화벽 기능은?

    1. 애플리케이션 페이로드에 대한 심층 패킷 검사.
    2. 외부 인터페이스에서의 네트워크 주소 변환.
    3. 세션 테이블로 연결 상태를 추적하는 상태 기반 검사.
    4. 방화벽의 규칙 처리 처리량 증가.
    정답과 해설 보기

    정답 C. 상태 기반 방화벽은 연결 테이블을 유지해 내부에서 나간 요청에 대응하는 응답만 허용한다. 패킷 필터는 각 패킷을 독립적으로 보기 때문에 응답을 받으려면 넓은 포트 범위를 미리 열어 두어야 했고 그 자체가 공격 경로가 되었다.

    • A · DPI 는 내용 검사이며 상태 추적과 별개 기능이다.
    • B · NAT 는 주소 변환이며 보안 통제가 아니다.
    • D · 성능 향상은 포트 개방 필요를 없애지 못한다.

    2IDS와 IPS

    구분위치동작
    IDS경로 밖(수동, out-of-band)탐지·경보
    IPS경로 안(인라인)탐지·차단

    원본은 IPS는 인라인이라 오탐이 곧 서비스 중단이 된다고 경고합니다. 그래서 차단 정책은 신중히 적용하고 모니터 모드로 시작하는 것이 일반적입니다(D2.6 데이터 보안 통제의 DLP와 같은 원리).

    탐지 방식원리장단점
    시그니처 기반알려진 패턴 대조정확하지만 미지의 공격 탐지 불가
    이상 기반 Anomaly정상 기준선에서의 이탈신종 탐지 가능, 오탐 많음
    휴리스틱·행위 기반행위 패턴 분석중간
    • NIDS/NIPS — 네트워크 기반. 세그먼트 전체를 보지만 암호화 트래픽은 보지 못한다
    • HIDS/HIPS — 호스트 기반. 복호화된 내용과 시스템 활동을 보지만 호스트마다 배포해야 한다
    • 허니팟/허니넷 — 공격자를 유인해 관찰한다. 원본은 이것이 enticement(유인)라 적법하다고 설명한다

    원문 사례 — 암호화 트래픽을 보지 못한 NIDS. NIDS가 세그먼트 전체를 감시했지만 대부분의 트래픽이 TLS로 암호화되어 내부에서 외부 C2로 나가는 통신을 탐지하지 못했습니다. 조직은 HIDS/EDR을 병행해 호스트에서 복호화된 활동을 보고, TLS 종단 프록시로 검사 지점을 만들고, 목적지·빈도·인증서 특징 같은 메타데이터 기반 탐지를 더했습니다.

    판단 순서탐지 수단을 고르거나 탐지 실패를 분석할 때 ① 그 트래픽이 암호화되어 있는가(그렇다면 네트워크 장비는 내용을 못 본다 → 호스트 기반이나 종단 지점 검사) ② 알려진 공격인가 새 공격인가(시그니처 vs 이상 기반) ③ 차단까지 해야 하는가, 오탐 시 업무가 멈춰도 되는가(IPS vs IDS) 순서로 봅니다.

    용어 주의원본 D1.5와 D7.7은 Entrapment/Enticement의 한국어 표기가 서로 반대로 되어 있습니다. 이 교재는 Enticement = 유인(이미 범행 의도가 있는 사람에게 기회를 노출, 적법), Entrapment = 함정교사(의도 없는 사람을 범행으로 끌어들임, 위법)로 통일합니다.

    연결IDS/IPS·허니팟의 운영과 조정은 D7.7 탐지·예방 수단, 로그와 경보 분석은 D7.2 로깅·모니터링, 유인과 함정교사의 법적 구분은 D1.5 조사 유형에서 다룹니다.

    원본 연습문제 · D4.2-Q24

    시그니처 기반 탐지와 이상 기반 탐지를 올바르게 대비한 설명은?

    1. 이상 기반 탐지는 시그니처 갱신과 튜닝의 필요성을 없앤다.
    2. 둘 다 탐지를 시작하기 전에 학습 기간이 필요하다.
    3. 시그니처 기반은 알려진 패턴을 일치시켜 오탐이 적지만 신종 공격을 놓치고 이상 기반은 신종 활동을 표시할 수 있으나 기준선이 필요하고 오탐이 더 많다.
    4. 시그니처 기반은 미지의 공격을, 이상 기반은 알려진 공격만 탐지한다.
    정답과 해설 보기

    정답 C. 시그니처 기반은 알려진 것에 강하고 모르는 것에 무력하다. 이상 기반은 평소와 다른 것을 찾으므로 신종에 가능성이 있지만 무엇이 평소인지 학습해야 하고, 업무 변화가 오탐으로 잡힌다. 기준선을 침해된 상태에서 학습하면 공격을 정상으로 배우는 문제도 있다.

    • A · 이상 기반도 지속적인 튜닝이 필요하다.
    • B · 시그니처 기반은 학습 기간이 필요하지 않다.
    • D · 역할이 뒤바뀌었다.

    매체의 물리 보안

    • 배선실·관로 통제
    • 케이블 경로 보호 — 노출 구간 최소화
    • TEMPEST — 전자기 방출로 정보가 새는 것을 막는 기준. 차폐실(Faraday cage), 저방출 장비
    • 미사용 포트 비활성화

    원문 사례 — 구리 구간의 탭. 구리 케이블 구간에서 비접촉 유도 탭으로 트래픽이 도청되었습니다. 천장 배선 경로가 통제되지 않은 공용 구역을 지나고 있었습니다. 그 구간을 광섬유로 바꾸고 관로를 통제 구역으로 옮겼습니다.

    보충원본 사례의 제목은 “광케이블 구간의 탭”이지만 본문은 구리 구간이 도청되어 광섬유로 바꾼 이야기여서, 이 교재는 본문에 맞춰 제목을 적었습니다. 또 광섬유도 도청이 “불가능”한 것은 아닙니다. 피복을 벗기고 섬유를 구부려 빛의 일부를 빼내는 방식은 선을 끊지 않으므로, 손실이 작으면 감시 장비 없이는 알아차리기 어렵습니다(일반 지식에 근거한 보충). 그래서 광섬유로 바꾼 뒤에도 관로 통제와 신호 손실 감시, 필요하면 전송 구간 암호화를 함께 둡니다.

    가상 예시공장 설비까지 통신 구간을 연장하는데, 대형 모터와 전기 설비에서 오는 간섭이 있고 여러 업체 직원이 드나드는 배선 구역을 지납니다. 매체만 바꾸면 끝나는 문제가 아닙니다. 간섭에는 광섬유나 차폐 케이블이 답이지만, 배선 구역에 아무나 접근할 수 있다면 탭이나 절단 위험이 남으므로 관로를 통제 구역으로 옮기거나 잠금을 걸고, 그래도 경로를 믿을 수 없다면 전송 구간을 암호화합니다.

    연결배선실과 관로 통제는 D3.9 사이트·설비 보안 통제, 물리 경로 이중화는 D3.8 사이트·설비 설계 원칙, 전송 구간 암호화는 D4.3 안전한 통신 채널에서 다룹니다.

    원문 위치: D4.2.md §3 전송 매체, §7 사례 4 · 공식 개요 4.2 “Transmission media (e.g., physical security of media, signal propagation quality)”

    42계층 스위치 보안

    원본의 핵심은 같은 브로드캐스트 도메인 안에서는 라우터와 방화벽을 거치지 않는다는 것입니다. 그래서 2계층 공격은 상위 계층 통제를 우회합니다.

    공격수법통제
    ARP 스푸핑위조 ARP 응답으로 트래픽 가로채기동적 ARP 검사(DAI)
    DHCP 스푸핑가짜 DHCP 서버로 게이트웨이·DNS 조작DHCP 스누핑
    MAC 플러딩MAC 표를 넘치게 해 허브처럼 동작하게포트 보안(MAC 수 제한)
    VLAN 호핑트렁크 자동 협상·이중 태깅 악용자동 협상 끄기, 네이티브 VLAN 분리
    STP 조작위조 BPDU로 경로 변경BPDU 가드, 루트 가드

    DHCP 스누핑과 동적 ARP 검사는 짝이다

    • DHCP 스누핑 — 스위치가 DHCP 교환을 관찰해 신뢰 포트에서만 DHCP 응답을 허용하고, 어느 포트에 어떤 IP·MAC이 할당되었는지 바인딩 표를 만든다
    • 동적 ARP 검사 — 그 바인딩 표를 근거로 ARP 응답의 IP·MAC 쌍이 맞는지 검증한다

    원본은 DHCP 스누핑이 없으면 동적 ARP 검사가 근거로 쓸 정보가 없다고 설명합니다. 그래서 DHCP 스누핑을 먼저 켜고 동적 ARP 검사를 적용하며, 고정 IP 환경에서는 수동 바인딩을 등록합니다. 업링크와 정당한 DHCP 서버 방향만 신뢰 포트로 두고 사용자 포트는 모두 비신뢰로 둡니다.

    보충VLAN은 하나의 물리 스위치를 별개의 브로드캐스트 도메인으로 나눠, 서로 다른 VLAN 사이의 통신이 라우터나 방화벽을 거치게 만듭니다. 그 자체가 암호화나 인증은 아닙니다. D4.1 네트워크 아키텍처의 판단 기준대로 VLAN은 브로드캐스트를 나누지만 보안 경계로는 부족하므로, 민감 구간은 라우팅 경계에 방화벽을 둡니다.

    원본 연습문제 · D4.2-Q13

    공격자가 위조된 수천 개의 출처 MAC 주소로 스위치에 프레임을 쏟아붓는다. 의도된 효과와 그에 대응하는 통제는?

    1. DHCP 주소 풀을 소진시키는 것이며 통제는 DHCP 스누핑이다.
    2. MAC 주소 표를 넘치게 해 스위치가 허브처럼 프레임을 범람시켜 스니핑이 가능해지게 하는 것이며 통제는 포트당 MAC 주소 수를 제한하는 포트 보안이다.
    3. 스패닝 트리 루트 브리지를 변경하는 것이며 통제는 루트 가드다.
    4. 스위치 전력 예산을 소진시키는 것이며 통제는 전력 제한이다.
    정답과 해설 보기

    정답 B. MAC 주소 표가 가득 차면 스위치는 목적지를 찾을 수 없어 프레임을 모든 포트로 범람시키고 허브처럼 동작한다. 그 결과 같은 세그먼트의 공격자가 다른 사용자의 트래픽을 수집할 수 있다. 포트 보안으로 포트당 학습 가능한 MAC 수를 제한하면 표가 넘치기 전에 위반 포트를 차단한다.

    • A · 주소 풀 소진은 DHCP 고갈 공격이며 수법이 다르다.
    • C · 루트 브리지 변경은 위조 BPDU 를 쓰는 별개 공격이다.
    • D · 전력 예산은 PoE 관련 사안이다.
    원문 위치 · D4.2-Q13

    원본 연습문제 · D4.2-Q36

    스위치에서 VLAN 이 달성하는 것은?

    1. 각 포트에 가용한 대역폭을 늘린다.
    2. 같은 VLAN 내 포트 간 트래픽을 암호화한다.
    3. 네트워크 접근을 부여하기 전에 기기를 인증한다.
    4. 하나의 물리 스위치를 별개의 브로드캐스트 도메인으로 나눈다. 그래서 서로 다른 VLAN 의 포트는 라우팅이나 정책 지점을 거치지 않고 통신할 수 없다.
    정답과 해설 보기

    정답 D. VLAN 은 논리적 분할 수단이다. 서로 다른 VLAN 사이의 통신은 3계층을 거치므로 그 지점에 접근 통제를 둘 수 있다. 다만 같은 VLAN 안의 통신은 통제되지 않으므로 측면 이동을 막으려면 마이크로세그멘테이션이 필요하다. 암호화와 기기 인증(802.1X)은 별개 기능이다.

    • A · 대역폭을 늘리지 않는다.
    • B · VLAN 은 암호화를 제공하지 않는다.
    • C · 기기 인증은 802.1X 의 역할이다.

    5NAC — 네트워크 접근 제어

    쉬운 설명

    NAC(Network Access Control)는 네트워크에 연결하려는 기기를 검증하고 정책에 따라 접근을 허용합니다. 핵심 기술은 IEEE 802.1X입니다.

    요소역할
    Supplicant접속하려는 기기(클라이언트)
    Authenticator스위치·AP (통로 역할)
    Authentication ServerRADIUS 서버 (실제 인증 판단)

    인증 전에는 포트가 차단되고 인증 성공 후에만 통신이 허용됩니다. EAP로 다양한 인증 방식을 받아들입니다.

    상태 검사와 결과

    NAC는 기기의 상태(Posture)도 검사합니다. 운영체제 패치 수준, 안티멀웨어 설치·갱신, 디스크 암호화, 승인된 기기인지(인증서, MAC). 결과는 통과 → 정상 VLAN, 미흡 → 격리 VLAN에서 치유, 실패 → 차단 또는 게스트 VLAN입니다.

    배포 방식특징
    에이전트 기반상세 검사 가능, 설치 필요
    에이전트리스설치 불필요, 검사 깊이 제한
    사전 인증(pre-admission)접속 전 검사
    사후 인증(post-admission)접속 후 행위 기반 통제

    한계: MAB

    원본은 MAC 주소 기반 통제가 스푸핑에 약하고, 802.1X와 인증서 기반이 더 강하다고 설명합니다. 프린터·IoT처럼 802.1X를 지원하지 않는 기기에는 MAB(MAC Authentication Bypass)를 쓰는데, 이것이 우회 경로가 됩니다.

    원문 사례 — MAB로 우회된 NAC. 802.1X를 전면 적용했지만 프린터와 IP 카메라에는 MAB를 허용했고, 공격자가 프린터의 MAC 주소를 위조해 진입했습니다. MAB 대상 기기를 전용 VLAN으로 격리해 통신 범위를 제한하고, 프로파일링으로 기기 종류를 교차 확인하게 보완했습니다.

    보충NAC는 세 가지를 따로 묻습니다. 누가(사용자 신원), 어떤 기기로(기기 신원), 지금 어떤 상태로(패치·암호화) 접속하는가. 직원 인증이 성공해도 기기가 필수 상태를 충족하지 못하면 업무망 대신 격리 구역에 둘 수 있습니다. 병원 네트워크라면 의료 장비 대부분이 802.1X를 지원하지 않아 MAB 대상이 되기 쉽습니다. 그래서 장비 종류별 전용 구역과 허용 통신 목록이 MAB의 약점을 메우는 핵심이 됩니다.

    연결RADIUS·EAP 같은 인증 시스템은 D5.6 인증 시스템, 기기 인증과 인증서는 D5.2 식별·인증 전략·D3.6 암호 솔루션, 의료·IoT 기기의 구조적 약점은 D3.5 아키텍처별 취약점에서 다룹니다.

    원문 위치: D4.2.md §3 NAC, §7 사례 3 · 공식 개요 4.2 “Network Access Control (NAC) systems (e.g., physical and virtual solutions)”

    6엔드포인트 보안

    원본은 엔드포인트를 최종 방어선이자 가장 많은 침해가 시작되는 지점이라고 부릅니다.

    계층수단
    예방안티멀웨어, 애플리케이션 허용 목록, 호스트 방화벽, 패치
    탐지·대응EDR, HIDS/HIPS, 로그 수집
    데이터 보호전체 디스크 암호화, DLP, 매체 통제
    구성강화, 최소권한, 표준 이미지

    EDR(Endpoint Detection and Response)은 전통적 안티바이러스가 시그니처 기반 차단에 그친 것과 달리 행위를 계속 기록하고 조사·대응을 지원합니다. 프로세스 생성·네트워크 연결·파일 변경을 기록하고, 이상 행위 탐지와 위협 헌팅, 원격 격리·프로세스 종료·포렌식 수집을 합니다. XDR은 엔드포인트·네트워크·클라우드 신호를 통합합니다.

    애플리케이션 허용 목록은 승인된 것만 실행합니다. 차단 목록보다 강력하지만 운영 부담이 크며, 원본은 고위험 시스템이나 레거시 자산에 효과적이라고 설명합니다.

    연결표준 이미지와 강화는 D2.3 안전한 프로비저닝, 레거시 자산의 허용 목록은 D2.5 자산 보존 (EOL·EOS), 위협 헌팅은 D1.10 위협 모델링·D7.2 로깅·모니터링, 포렌식 수집은 D7.1 조사에서 다룹니다.

    원문 위치: D4.2.md §3 엔드포인트 보안 · 공식 개요 4.2 “Endpoint security (e.g., host-based)”

    7인프라 운영

    원본의 한 줄은 보안은 운영 안정성 위에 선다입니다.

    • 이중 전원 — 이중 PSU, 서로 다른 전원 경로
    • 보증과 지원 계약 — 장애 시 교체·대응 시간(SLA)
    • 예비 부품 — 중요 장비의 콜드 스페어
    • 펌웨어 관리 — 네트워크 장비 펌웨어에도 취약점이 있다
    • 구성 백업 — 장비 설정의 정기 백업과 버전 관리
    • EOL/EOS 추적
    • 용량 관리 — 포화가 곧 가용성 사고

    네트워크 장비 자체의 보안 설정도 필요합니다. 기본 자격증명 변경과 관리 계정 개별화, 미사용 서비스·포트 끄기, 대역 외 관리, 로그 중앙 수집, NTP 시간 동기화, 설정 변경 승인 절차.

    원문 사례 — 설정 백업이 없던 장비 장애. 코어 스위치가 하드웨어 고장으로 교체되었는데 설정 백업이 없어 수작업 복구에 6시간이 걸렸습니다. 장비 설정의 정기 백업과 버전 관리를 자동화했습니다.

    보충복구 능력은 장비를 사는 시점에 상당 부분 정해집니다. 이중 전원이 실제로 서로 다른 전원에 꽂혀 있는지, 예비 장비가 필요한 시간 안에 도착하는 지원 계약인지, 새 장비에 승인된 설정을 바로 복원할 수 있는지를 함께 시험해야 합니다. 셋 중 하나만 빠져도 사례처럼 복구가 몇 시간씩 늘어납니다.

    연결전원 이중화는 D3.9 사이트·설비 보안 통제, 구성 관리는 D2.3 안전한 프로비저닝·D7.3 구성 관리, EOL/EOS는 D2.5 자산 보존 (EOL·EOS), 대역 외 관리는 D4.1 네트워크 아키텍처, 장비 형상 관리는 D3.10 정보시스템 생애주기에서 다룹니다.

    원문 위치: D4.2.md §3 인프라 운영, §7 사례 5 · 공식 개요 4.2 “Operation of infrastructure (e.g., redundant power, warranty, support)”

    8종합 이해 확인

    종합 · 자작 상황 문제 (실제 시험 문제 아님)

    점검 결과다. ㉠ 경계 방화벽이 응답을 받으려고 고번호 포트 전체를 열어 두었다. ㉡ NIDS가 암호화된 C2 통신을 놓쳤다. ㉢ 프린터용 MAB 예외로 위조 기기가 업무 VLAN에 들어왔다. ㉣ 코어 스위치 교체 후 설정 복구에 6시간이 걸렸다. 가장 적절한 대책 묶음은?

    1. ㉠ 상태 기반 방화벽 / ㉡ EDR·종단 프록시·메타데이터 탐지 병행 / ㉢ MAB 기기를 전용 VLAN에 격리하고 프로파일링 / ㉣ 설정 자동 백업과 버전 관리
    2. ㉠ 포트를 더 연다 / ㉡ NIDS 시그니처 추가 / ㉢ NAC 해제 / ㉣ 예비 장비 추가 구매만
    3. ㉠ 패킷 필터 추가 / ㉡ IPS로 교체 / ㉢ 프린터 MAC 고정 / ㉣ 장비 교체 주기 단축
    4. ㉠ DMZ 제거 / ㉡ 암호화 금지 / ㉢ 802.1X 해제 / ㉣ 문서화만
    정답과 해설 보기

    정답 A. ㉠ 1절(원문 사례 1), ㉡ 2절(네트워크 장비는 암호화된 내용을 못 본다 — 시그니처를 늘리거나 IPS로 바꿔도 같은 문제), ㉢ 5절(MAC은 위조 가능), ㉣ 7절(원문 사례 5).

    NAC는 왜 방화벽이나 단말 보안의 역할을 모두 대신할 수 없나요?

    설명 확인하기

    NAC는 접속 시 신원과 단말 상태를 바탕으로 어느 네트워크에 들일지 판단합니다. 방화벽은 연결 흐름을 집행하며, 단말 보안은 기기 위의 실행과 상태를 보호합니다.

    10핵심 요약

    1. 구성 요소의 보안은 어느 계층에서 무엇을 볼 수 있는가. 허브 1 / 스위치 2(MAC) / 라우터 3(IP) / 방화벽 3~7 / 프록시 7.
    2. 방화벽: 패킷 필터(상태 모름) → 상태 기반(응답만 허용) → 프록시(내용) → NGFW(앱·사용자·IPS) / WAF(웹).
    3. 포워드 프록시(내부→외부), 리버스 프록시(외부→내부 서버, TLS 종단). 베스천 호스트 = 강화된 노출 호스트. DMZ → 내부 접근 제한.
    4. IDS = 경로 밖·탐지, IPS = 인라인·차단(오탐 = 서비스 중단). 시그니처(정확, 신종 못 잡음) vs 이상 기반(신종, 오탐 많음). NIDS는 암호화 트래픽을 못 본다.
    5. 매체: 광섬유가 가장 안전(EMI 면역, 탭 시 신호 손실). 감쇠·크로스토크·EMI. TEMPEST.
    6. 2계층: ARP 스푸핑→DAI, DHCP 스푸핑→DHCP 스누핑(DAI의 근거), MAC 플러딩→포트 보안, VLAN 호핑→자동 협상 끄기, STP→BPDU 가드.
    7. NAC = 802.1X(Supplicant / Authenticator / RADIUS) + 상태 검사(통과·격리·차단). MAB는 우회 경로 → 전용 VLAN.
    8. 엔드포인트: 예방(허용 목록) + EDR(행위 기록·조사·대응) + 디스크 암호화 + 강화.
    9. 인프라: 이중 전원, 지원 계약, 예비 부품, 펌웨어, 설정 백업, EOL 추적, 용량.
    원문 위치: D4.2.md §8 CISSP 시험 관점, §9 핵심 암기 요약. 원본의 출제 단정 표현은 판단 기준으로 바꿔 적었습니다.

    11주요 용어 (Glossary)

    영어 원어와 한국어 뜻 · English–Korean

    Stateful Firewall · 상태 기반 방화벽

    연결 상태를 추적해 유효한 세션의 패킷만 허용하는 방화벽.

    Proxy · 프록시

    클라이언트와 서버 사이에서 연결을 중계하는 장치. 포워드는 내부→외부, 리버스는 외부→내부 요청을 중계한다.

    Bastion Host · 베스천 호스트

    외부에 노출되어 특별히 강화된 호스트. 공격면을 최소화한다.

    DMZ (Demilitarized Zone) / Screened Subnet · 외부 노출 서비스를 분리한 완충 구역 / 필터링된 서브넷

    외부 공개 서비스를 내부망과 분리해 두는 구간.

    IDS / IPS — Intrusion Detection System / Intrusion Prevention System · 침입 탐지 시스템 / 침입 방지 시스템

    탐지와 경보만 하는 수동 시스템과, 인라인에서 탐지·차단까지 하는 시스템.

    Signature-Based / Anomaly-Based Detection · 서명 기반 탐지 / 이상 기반 탐지

    알려진 패턴 대조 방식과 정상 기준선 이탈 탐지 방식.

    NIDS / HIDS — Network Intrusion Detection System / Host-based Intrusion Detection System · 네트워크 기반 침입 탐지 / 호스트 기반 침입 탐지

    네트워크 기반과 호스트 기반 침입 탐지 시스템.

    Attenuation · 감쇠

    거리에 따른 신호 약화. 케이블 길이 제한의 원인이다.

    Crosstalk · 크로스토크

    인접 선로 간 신호 간섭.

    TEMPEST · 장비의 비의도적 전자파 방출 보안

    전자기 방출을 통한 정보 유출을 막기 위한 기준과 대책.

    NAC — Network Access Control · 네트워크 접근 제어

    연결하려는 기기를 검증하고 정책에 따라 접근을 허용하는 체계.

    IEEE 802.1X · 포트 기반 네트워크 접근 제어 표준

    포트 기반 네트워크 접근 제어 표준. Supplicant, Authenticator, Authentication Server 로 구성된다.

    Posture Assessment · 상태 점검

    접속 기기의 패치·백신·암호화 상태를 검사하는 과정.

    Quarantine VLAN · 격리 VLAN

    정책 미충족 기기를 치유 전까지 격리하는 네트워크 구간.

    MAB — MAC Authentication Bypass · MAC 주소 기반 대체 접근 확인

    802.1X 를 지원하지 않는 기기를 MAC 주소로 인증하는 우회 방식. 스푸핑에 취약하다.

    EDR / XDR — Endpoint Detection and Response / Extended Detection and Response · 엔드포인트 탐지 및 대응 / 확장 탐지 및 대응

    엔드포인트 행위를 기록해 탐지·조사·대응을 지원하는 체계와, 이를 네트워크·클라우드까지 확장한 것.

    Application Allowlisting · 애플리케이션 허용 목록

    승인된 프로그램만 실행을 허용하는 통제.

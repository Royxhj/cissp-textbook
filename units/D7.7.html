    연습문제 5개 바로가기

    표시 없는 본문은 원본 정리 파일의 내용 · 보충은 원본에 없어 더한 설명 · 가상 예시는 지어낸 상황 · 연결은 다른 단원과의 관계 · 확인 필요는 그대로 확정하지 않은 부분

    공식 개요 7.7의 제목은 탐지·예방 수단을 “운영하고 유지(Operate and maintain)”하라는 것입니다. 원본은 이 단어에 무게를 둡니다. 통제는 설치되었을 때가 아니라 유지될 때 효과를 낸다. 패치되지 않은 보안 장비, 만료된 라이선스, 꺼진 에이전트, 갱신되지 않은 규칙, 처리되지 않는 경보는 모두 “있지만 작동하지 않는 통제”입니다. 이 단원은 여덟 가지 수단을 각각의 한계와 유지 요건과 함께 봅니다.

    2방화벽

    유형판단 기준
    패킷 필터주소, 포트, 프로토콜
    상태 기반연결 상태 포함
    애플리케이션 프록시프로토콜 내용 검사
    차세대(NGFW)애플리케이션 식별, 사용자 신원, 위협 정보
    웹 애플리케이션(WAF)HTTP 요청 내용
    • 네트워크 방화벽은 경로를, WAF는 요청 내용을 통제합니다. NGFW가 WAF를 대체하지 않습니다.
    • 마지막 규칙은 암묵적 거부입니다.
    • 송신(egress) 규칙이 누락되는 경우가 많습니다. 나가는 것을 전부 허용하면 C2와 유출이 자유롭습니다.

    운영과 유지

    규칙 누적: 임시 허용이 영구화되어 수년 뒤 수천 개 규칙 중 무엇이 왜 있는지 아무도 모릅니다. 대응은 규칙별 히트 카운트를 근거로 한 주기적 정리, 규칙마다 요청자·사유·승인·만료일 문서화(만료일 없는 규칙이 누적의 원인), 변경 통제, 설정 백업과 롤백, 고가용성과 장애 시 동작(fail-open/fail-close) 결정입니다.

    원문 사례 — 아무도 모르는 방화벽 규칙 4,200개. 10년간 규칙 4,200개가 누적되었고, 히트 카운트 분석에서 1,900개가 1년간 한 번도 적용되지 않았고, 일부는 전 대역 허용이었으며, 요청자와 사유 기록이 없는 규칙이 다수였습니다.

    원문 사례 — 송신 규칙이 없던 방화벽. 인바운드는 엄격했지만 아웃바운드는 전면 허용이어서, 침해 후 공격자가 임의 포트로 C2를 세우고 데이터를 내보냈습니다. 필요한 목적지·포트만 허용하는 송신 정책과 프록시 경유를 강제했습니다.

    보충검사 장비가 멈추면 어느 연결을 끊고 어느 연결을 계속 허용할지 미리 정해야 합니다. 병원처럼 연결 중단이 진료 중단으로 이어지는 곳에서는 무조건 fail-close가 답이 아닐 수 있습니다. 업무 안전과 “관찰할 수 없는 상태”의 위험을 함께 검토해 비상 동작을 정하고, 실제로 전환·복귀가 예상대로 되는지 시험합니다.

    연결방화벽 유형은 D4.2 네트워크 구성요소의 1절, 규칙 기반 접근 통제와 암묵적 거부는 D5.4 인가 메커니즘의 5절, 유출 모니터링은 D7.2 로깅·모니터링의 6절에서 다룹니다.

    원문 위치: D7.7.md §3 방화벽, §7 사례 1, 사례 2 · 공식 개요 7.7 “Firewalls (e.g., next generation, web application, network)”

    3IDS / IPS 운영

    탐지 방식과 배치는 D7.2 로깅·모니터링의 2절에서 다뤘고, 여기서는 유지 관점입니다.

    • 시그니처 갱신: 갱신이 멈춘 IDS는 과거 공격만 봅니다.
    • 튜닝: 오탐을 줄이면서 탐지력을 유지합니다.
    • 배치 지점 검증: 네트워크 변경 후 IDS가 보지 못하는 구간이 생깁니다.
    • 용량 관리: 처리 한계를 넘으면 조용히 패킷을 버립니다. 처리율과 드롭률을 모니터링합니다.
    • IPS 차단 규칙은 업무 영향 위험이 있으므로 변경 관리 대상입니다.

    원문 사례 — IDS가 보지 못한 구간. 네트워크 재구성 후 트래픽 경로가 바뀌어 IDS가 주요 구간을 보지 못했고, 6개월간 그 구간 경보가 0건이었는데 아무도 이상하게 여기지 않았습니다. 원본은 경보가 없는 것과 안전한 것은 구분되지 않는다고 말합니다. 네트워크 변경 시 탐지 배치 검증을 필수로 넣고, 탐지 장비별 트래픽 수신량과 경보 발생 추세를 모니터링했습니다.

    보충같은 규칙을 탐지 모드와 차단 모드로 쓸 수 있어도 결과는 다릅니다. 오탐이 기록만 남기는지, 정상 업무를 멈추는지에 따라 변경의 검증 수준과 되돌리기 조건을 다르게 정합니다.

    원본 연습문제 · D7.7-Q17

    IDS 와 IPS 의 기본적인 차이는?

    1. IDS 는 의심 활동을 탐지해 보고하고 IPS 는 차단까지 할 수 있는 위치에 놓인다. 그래서 IPS 의 오탐은 정당한 트래픽을 중단시킬 수 있다.
    2. IDS 는 시그니처가 필요하고 IPS 는 필요하지 않다.
    3. IDS 는 네트워크에서, IPS 는 호스트에서 동작한다.
    4. IPS 는 암호화된 트래픽에서만 동작한다.
    정답과 해설 보기

    정답 A. 둘의 탐지 방식은 같을 수 있고 차이는 배치와 권한이다. IDS 는 복사된 트래픽을 보며 알려 주고, IPS 는 경로 안에 있어 차단할 수 있다. 차단 능력의 대가로 오탐이 업무 중단이 되고 장비 자체가 단일 실패점이 될 수 있다.

    • B · 둘 다 시그니처와 이상 기반을 쓸 수 있다.
    • C · 둘 다 네트워크형과 호스트형이 있다.
    • D · 암호화 여부와 무관하다.

    4허용 목록과 차단 목록

    방식원리특성
    허용 목록 allowlist명시 허용만 실행·통신기본 거부. 강력하지만 운영 부담
    차단 목록 blocklist명시 차단만 금지기본 허용. 쉽지만 미지 대응 불가

    원본은 허용 목록이 본질적으로 더 안전하다고 말합니다. 알려지지 않은 악성코드도 목록에 없으므로 실행되지 않습니다. 적용 영역은 앱 실행 제어, 스크립트 실행, 네트워크 목적지, 이동식 매체, 매크로입니다.

    구현 방식특성
    경로 기반우회 쉬움
    해시 기반정확하지만 업데이트마다 갱신
    서명 기반발행자 인증서 기준. 실무적 균형

    운영 부담이 실패 원인이므로, 감사 모드로 먼저 운영해 실행되는 것을 모은 뒤 강제 모드로 전환하고, 변화가 적고 위험이 높은 환경(서버, 산업 제어, 키오스크, 특권 단말)부터 적용합니다.

    원본이 짚는 흔한 우회: 허용된 인터프리터나 시스템 유틸리티로 악성 코드를 실행합니다. 그래서 허용된 프로그램의 자식 프로세스와 스크립트 실행도 함께 통제합니다.

    원문 사례 — 허용 목록의 인터프리터 우회. 앱 허용 목록을 적용했지만 공격자가 허용된 스크립트 인터프리터로 악성 코드를 실행해, 실행 파일 없이 공격이 진행되었습니다.

    가상 예시의료 영상 판독 워크스테이션이나 검사 장비의 제어 PC는 설치 소프트웨어가 거의 바뀌지 않고 패치는 제조사 검증이 필요해 늦어지기 쉽습니다. 이런 단말은 허용 목록이 운영 부담 대비 효과가 가장 큰 곳입니다. 다만 장비 제조사의 업데이트 절차와 목록 갱신을 연결해 두지 않으면, 정식 업데이트가 차단되는 장애가 생깁니다.

    원본 연습문제 · D7.7-Q01

    애플리케이션 허용 목록이 알려지지 않은 악성코드에 대해 차단 목록보다 본질적으로 더 강한 이유는?

    1. 허용 목록이 차단 목록보다 정의를 더 자주 갱신한다.
    2. 허용 목록은 파일 내용을 검사하고 차단 목록은 파일 이름만 확인한다.
    3. 허용 목록은 기본 거부이므로 명시적으로 승인되지 않은 것은 실행되지 않으며 처음 보는 악성코드도 포함된다.
    4. 허용 목록은 커널 모드에서, 차단 목록은 사용자 모드에서 동작한다.
    정답과 해설 보기

    정답 C. 차단 목록은 기본 허용이므로 목록에 없는 악성코드는 그대로 실행된다. 허용 목록은 기본 거부이므로 목록에 없다는 사실만으로 차단되며 알려지지 않은 악성코드도 막힌다. 대가는 업데이트마다 목록을 갱신해야 하는 운영 부담이다.

    • A · 갱신 빈도가 아니라 기본값의 방향이 차이의 본질이다.
    • B · 두 방식 모두 해시나 서명 기반으로 구현될 수 있다.
    • D · 실행 모드는 본질적 차이가 아니다.

    5샌드박싱

    격리된 환경에서 실행해 행위를 관찰합니다. 미지 파일·메일 첨부·URL 검사와 악성코드 동적 분석에 쓰이며, 메일 게이트웨이, 웹 프록시, 엔드포인트, 분석 전용 환경에 배치합니다. 격리가 불완전하면 샌드박스 탈출이 가능합니다.

    회피 기법내용
    환경 인식가상화 흔적, 적은 메모리·CPU, 마우스 움직임·사용자 파일 부재를 감지하면 악성 행위를 하지 않음
    시간 지연분석 시간보다 길게 대기
    조건 트리거특정 도메인 가입, 언어 설정, 날짜에만 동작
    사용자 상호작용 요구클릭이나 암호 입력을 기다림

    대응은 샌드박스를 실제 환경처럼 꾸미고, 관찰 시간을 늘리고, 정적 분석·평판·엔드포인트 행위 탐지를 함께 쓰는 것입니다. 원본의 결론은 샌드박스 통과는 안전을 의미하지 않는다입니다.

    원문 사례 — 샌드박스를 통과한 악성코드. 메일 게이트웨이 샌드박스가 첨부를 “악성 아님”으로 판정했지만 단말에서 실행된 뒤 랜섬웨어가 동작했습니다. 분석해 보니 악성코드가 가상화 흔적과 사용자 파일 부재를 감지해 샌드박스 안에서는 무해하게 동작했습니다.

    원문 위치: D7.7.md §3 샌드박싱, §7 사례 5 · 공식 개요 7.7 “Sandboxing”

    6허니팟, 허니넷, 허니토큰

    구분범위
    허니팟단일 미끼 시스템
    허니넷미끼 네트워크 전체
    허니토큰미끼 자격증명·파일·레코드

    저상호작용은 서비스를 흉내만 내 안전하지만 정보가 적고, 고상호작용은 실제 시스템이라 상세히 관찰할 수 있지만 침해되어 공격 발판으로 쓰일 위험이 있습니다.

    가치: 탐지 신호의 품질이 매우 높습니다. 정상 업무가 미끼에 접근할 이유가 없으므로 접근 자체가 거의 확실한 이상 신호이고 오탐이 극히 적습니다. 특히 허니토큰은 비용이 낮고 실용적입니다. 내부 정찰도 미끼를 만나면서 드러납니다.

    원문 사례 — 허니토큰이 잡은 자격증명 탈취. 사용되지 않아야 할 미끼 서비스 계정 자격증명을 설정 파일에 심어 두고 사용 시도를 경보로 걸었더니, 어느 날 그 계정으로 인증 시도가 발생해 자격증명 탈취와 내부 정찰이 즉시 탐지되었습니다.

    원문 사례 — 격리되지 않은 고상호작용 허니팟. 연구용 허니팟에 송신 통제를 적용하지 않아, 침해된 허니팟이 외부 시스템 공격의 발판이 되었습니다.

    주의점: 고상호작용 허니팟은 격리와 송신 통제 필수, 방치된 허니팟은 그 자체가 취약 자산, 실제 데이터를 넣지 않음. 그리고 법적 경계입니다.

    확인 필요원본 D7.7은 “유인(entrapment)과 함정(enticement)”이라고 영문을 반대로 짝지었습니다. 이 교재의 용어 기준과 일반적 용법은 Enticement = 유인(이미 범의가 있는 침입자에게 머물 기회를 제공, 일반적으로 허용), Entrapment = 함정교사(없던 범의를 유발, 문제가 됨)입니다. 원본의 요지(“없던 범의를 유발하면 문제”)는 그대로이며 영문 짝만 바로잡았습니다. 구체적 허용 범위는 관할 법에 따라 다르므로 법무 검토가 필요합니다.

    연결유인과 함정교사의 법적 구분은 D1.5 조사 유형, 같은 용어 주의는 D4.2 네트워크 구성요소에서도 다뤘습니다.

    원본 연습문제 · D7.7-Q06

    심어 둔 미끼 자격증명의 사용에 대한 경보가 일반적으로 매우 낮은 오탐률을 갖는 이유는?

    1. 미끼 자격증명이 실제 자격증명보다 더 강한 암호로 보호된다.
    2. 인증 시스템이 미끼 자격증명을 더 높은 우선순위 이벤트로 취급한다.
    3. 미끼 자격증명은 업무 시간에만 유효하다.
    4. 어떤 정상 업무 프로세스도 그 자격증명을 사용할 이유가 없으므로 사용 자체가 거의 확실한 이상 신호다.
    정답과 해설 보기

    정답 D. 미끼는 정상 업무에서 쓰이지 않도록 설계되므로 사용 시도가 발생하면 누군가 설정 파일이나 저장소를 뒤져 자격증명을 수집했다는 뜻이다. 정상 트래픽과 구분하기 위한 기준선 학습이 필요 없어 오탐이 극히 적은 고품질 신호가 된다.

    • A · 암호 강도와 오탐률은 무관하다.
    • B · 우선순위 설정은 결과이며 원인이 아니다.
    • C · 유효 시간은 신호 품질의 근거가 아니다.

    유형제공 범위

    한계와 책임 경계내용
    조직 맥락 부족무엇이 정상 업무인지 외부는 모름. 맥락과 자산 중요도 전달은 조직 책임
    책임은 이전되지 않음위탁해도 최종 책임은 조직(위험 수용 결정, 결과 책임)
    대응 권한의 범위어디까지 조치할 수 있는가. 서버 격리 권한? 사전 합의와 승인 경로
    에스컬레이션심각도별 연락 경로와 시간을 SLA로
    가시성 공백공급자가 보지 않는 영역은 아무도 보지 않음
    종료 시 전환탐지 규칙과 이력이 조직에 남는가
    공급자 침해다수 고객 환경 접근 권한 → 공급자 침해가 조직 침해로 전이

    원문 사례 — MDR의 대응 권한이 불명확했던 사례. 격리 조치 권한 범위를 합의하지 않아, 사고 때 공급자는 조직 승인을 기다리고 조직은 공급자가 조치했다고 생각해 초기 2시간 동안 아무 조치도 이루어지지 않았습니다. 심각도별 자동 조치 범위와 승인 필요 범위를 구분했습니다.

    연결공급자 관리와 책임은 D1.11 공급망 위험 관리, SLA는 D7.4 기본 보안 운영 개념의 6절에서 다룹니다.

    원본 연습문제 · D7.7-Q12

    어떤 조직이 모니터링을 관리형 보안 서비스 공급자에게 외주한다. 전가할 수 없는 책임은?

    1. 공급자가 수행하는 24시간 경보 선별.
    2. 공급자가 할 수 있는 탐지 규칙 조정.
    3. 결과에 대한 책임. 위험 수용 수준 결정, 무엇을 사고로 볼지 정의, 억제 조치 승인, 그리고 문제가 생겼을 때 규제기관과 고객에게 답하는 일.
    4. 공급자가 호스팅하는 모니터링 플랫폼 유지.
    정답과 해설 보기

    정답 C. 실행은 외주할 수 있지만 책임은 남는다. 무엇을 사고로 볼지와 어디까지 조치를 허용할지는 조직의 위험 수용 수준에서 나오는 결정이므로 공급자가 정할 수 없다. 침해가 발생했을 때 규제기관과 고객은 조직에 묻는다. 그래서 계약에 대응 권한과 상향 보고 기준, 통지 의무를 명시하고 공급자의 성과를 조직이 검증해야 한다.

    • A · 운영 업무는 외주 가능하다.
    • B · 규칙 조정은 조직 승인 아래 외주 가능하다.
    • D · 플랫폼 운영은 외주 가능하다.

    8안티멀웨어

    탐지 방식은 시그니처, 휴리스틱·행위, 평판, ML 분류, 그리고 행위 기록·사후 조사·격리까지 포함하는 EDR입니다.

    • 커버리지: 에이전트 미설치 자산이 공백. 설치율과 정상 동작률을 지표로.
    • 에이전트 상태: 꺼진 에이전트, 오래된 정의 파일, 통신 실패. 보안 에이전트 중지는 공격의 선행 행위.
    • 예외 목록: 성능을 위해 추가한 제외 경로가 공격자의 은닉 장소가 됩니다. 최소화하고 문서화·주기 검토.
    • 중앙 관리와 경보 연동: 로컬 알림만으로는 탐지 체계가 아닙니다.

    한계: 파일 없는 공격과 정상 도구 악용(living off the land)에 약합니다. 그래서 EDR, 행위 탐지, 허용 목록이 보완합니다.

    10운영과 유지의 공통 요건

    요건내용
    커버리지 측정자산 대비 통제 적용률. 누락이 공백
    상태 모니터링꺼짐·만료·통신 실패 탐지
    갱신시그니처, 규칙, 정의, 모델, 라이선스
    튜닝환경 변화 반영, 오탐 관리
    효과 검증실제로 탐지·차단하는가(BAS)
    경보 처리절차와 잔량 관리
    예외 관리최소화와 주기 검토
    변경 통제차단 규칙 변경은 가용성 영향
    수명 관리지원 종료 제품 교체

    원본의 결론: “도구는 있는데 작동하지 않는다”가 가장 흔한 상태다. 통제 인벤토리를 만들고 각 통제의 커버리지·상태·효과를 측정하는 것이 운영의 출발점입니다.

    가상 예시서비스 담당자가 탐지 규칙이 정상 파일 배포를 경고한다고 보고했고, “보안 제품이니 모든 차단을 강제하고 예외를 허용하지 말자”는 제안이 나왔습니다. 경보와 차단을 운영 변경으로 다루면 판단이 달라집니다. 어떤 배포 경로와 서명이 걸렸는지 확인하고, 그 조합만 범위를 좁혀 예외로 두되 만료일과 재검토를 붙이고, 차단 강화는 변경 관리 절차로 영향 범위를 시험한 뒤 적용합니다.

    연결침해 공격 시뮬레이션은 D6.2 보안 통제 테스트의 9절, 예외 관리는 D6.4 결과 분석과 보고의 4절, 변경 관리는 D7.9 변경 관리에서 다룹니다.

    11종합 이해 확인

    종합 · 자작 상황 문제 (실제 시험 문제 아님)

    탐지·예방 수단 점검 결과다. ㉠ 방화벽 규칙 4,200개 중 1,900개가 1년간 미적용이며 아웃바운드는 전면 허용이다. ㉡ 네트워크 재구성 후 한 구간 IDS 경보가 6개월간 0건이다. ㉢ 앱 허용 목록을 적용했는데 스크립트 인터프리터는 자유롭게 실행된다. ㉣ MDR 계약에 격리 권한 범위가 없다. 가장 적절한 대책 묶음은?

    1. ㉠ 규칙을 그대로 두고 장비 교체 / ㉡ 0건이므로 안전 / ㉢ 차단 목록으로 전환 / ㉣ 공급자가 알아서 판단
    2. ㉠ 히트 카운트로 정리, 규칙마다 사유·승인·만료일, 송신 정책 수립 / ㉡ 배치 지점 검증과 장비별 수신량 모니터링 / ㉢ 인터프리터·스크립트·자식 프로세스까지 통제 / ㉣ 심각도별 자동 조치·승인 범위와 에스컬레이션 합의
    3. ㉠ 모든 규칙 삭제 / ㉡ IPS로 교체 / ㉢ 허용 목록 폐기 / ㉣ MDR 해지
    4. ㉠ 아웃바운드 규칙만 추가 / ㉡ 시그니처만 갱신 / ㉢ 경로 기반 목록 추가 / ㉣ 책임도 공급자에게 이전
    정답과 해설 보기

    정답 B. ㉠ 2절(규칙 누적, 송신 규칙), ㉡ 3절(경보 없음 ≠ 안전), ㉢ 4절(허용된 인터프리터 우회), ㉣ 7절(대응 권한 사전 합의). D의 “책임 이전”은 7절에서 보듯 불가능합니다.

    12핵심 개념을 내 말로 설명하기

    복습

    같은 규칙을 IDS와 IPS에서 쓰더라도 배포 판단이 달라지는 이유는 무엇인가요?

    설명 확인하기

    IDS의 잘못된 탐지는 대체로 경보를 남기지만 IPS가 같은 정상 흐름을 차단하면 업무가 멈출 수 있습니다. 차단 전 영향과 예외를 시험하고 되돌리는 조건을 정합니다.

    13핵심 요약

    1. 통제는 설치가 아니라 유지될 때 효과. “있지만 작동하지 않는 통제”가 가장 흔하다.
    2. 방화벽: 패킷 필터 → 상태 기반 → 프록시 → NGFW, WAF는 요청 내용(NGFW가 대체 못 함). 암묵적 거부, 송신 규칙. 규칙 누적 → 히트 카운트, 사유·승인·만료일.
    3. IDS/IPS 운영: 시그니처 갱신, 튜닝, 배치 지점 검증, 용량(조용한 드롭). 경보 없음 ≠ 안전.
    4. 허용 목록 > 차단 목록(미지 악성코드도 실행 안 됨). 서명 기반이 균형. 감사 모드 → 강제. 변화 적고 위험 높은 곳부터. 인터프리터 우회 주의.
    5. 샌드박스: 환경 인식·시간 지연·조건 트리거로 회피. 통과 ≠ 안전, 엔드포인트 탐지와 병행.
    6. 허니팟/허니넷/허니토큰: 오탐 극히 적은 고품질 신호. 고상호작용은 격리·송신 통제. Enticement = 유인, Entrapment = 함정교사.
    7. 제3자(MSSP·MDR·SOCaaS): 맥락 전달은 조직 몫, 책임은 이전되지 않음, 대응 권한 사전 합의, 공급자 침해 전이.
    8. 안티멀웨어: 커버리지·상태·예외 목록(은닉 장소). 파일 없는 공격엔 EDR·행위 탐지.
    9. ML/AI: 설명 가능성, 기준선 오염, drift, 적대적 회피, 과신. 다른 증거와 결합, 사람 검토 유지.
    10. 공통: 커버리지, 상태, 갱신, 튜닝, 효과 검증, 경보 처리, 예외, 변경 통제, 수명.
    원문 위치: D7.7.md §8 CISSP 시험 관점, §9 핵심 암기 요약. 원본의 출제 단정 표현은 판단 기준으로 바꿔 적었습니다.

    14주요 용어 (Glossary)

    영어 원어와 한국어 뜻 · English–Korean

    NGFW (Next-Generation Firewall) · 차세대 방화벽

    애플리케이션 식별, 사용자 신원, 침입 방지, 위협 정보를 통합한 방화벽.

    WAF (Web Application Firewall) · 웹 애플리케이션 방화벽

    HTTP 요청을 검사해 웹 애플리케이션 공격을 차단하는 통제.

    Implicit Deny · 암묵적 거부

    명시적으로 허용되지 않은 모든 트래픽을 거부하는 마지막 규칙.

    Egress Filtering · 송신 필터링

    외부로 나가는 트래픽을 통제하는 규칙. 누락되기 쉽다.

    Rule Hit Count · 규칙 히트 카운트

    각 방화벽 규칙이 적용된 횟수. 미사용 규칙 정리의 근거다.

    Allowlist / Blocklist · 허용 목록 / 차단 목록

    명시 허용만 허용하는 방식과 명시 차단만 금지하는 방식.

    Audit Mode · 감사 모드

    허용 목록을 차단 없이 관찰만 하며 목록을 수집하는 단계.

    Sandboxing · 샌드박싱

    격리된 환경에서 실행해 행위를 관찰하는 분석 방식.

    Sandbox Evasion · 샌드박스 회피

    분석 환경임을 탐지하면 악성 행위를 하지 않는 기법.

    Honeypot / Honeynet / Honeytoken · 유인 시스템 / 유인 네트워크 / 유인 데이터

    미끼 시스템 / 미끼 네트워크 / 미끼 자격증명·파일.

    Low / High Interaction · 저/고 상호작용

    서비스를 흉내만 내는 방식과 실제 시스템을 쓰는 방식.

    Entrapment / Enticement · 유인 / 함정

    없던 범의를 유발하는 것과 이미 범의가 있는 자에게 기회를 제공하는 것.

    MSSP / MDR / SOCaaS — Managed Security Service Provider / Managed Detection and Response / Security Operations Center as a Service · 관리형 보안 서비스 제공자 / 관리형 탐지·대응 / 서비스형 보안관제센터

    운영·모니터링 위탁 / 탐지와 대응 포함 / 관제 기능 전반 서비스.

    Living off the Land · 시스템의 정상 도구를 이용하는 공격 방식

    시스템에 이미 있는 정상 도구로 공격을 수행하는 기법.

    EDR (Endpoint Detection and Response) · 엔드포인트 탐지 및 대응

    단말 행위를 기록해 탐지·조사·격리를 제공하는 체계.

    Concept Drift · 개념 변화

    환경 변화로 모델 성능이 저하되는 현상.

    Adversarial Evasion · 적대적 회피

    모델을 우회하도록 입력을 조작하는 공격.

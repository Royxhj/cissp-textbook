    연습문제 7개 바로가기

    표시 없는 본문은 원본 정리 파일의 내용 · 보충은 원본에 없어 더한 설명 · 가상 예시는 지어낸 상황 · 연결은 다른 단원과의 관계 · 확인 필요는 그대로 확정하지 않은 부분

    보호해야 할 데이터와 그 등급을 알았으면, 이제 실제로 어떤 통제를 어느 수준으로 걸지 정해야 합니다. 표준의 통제 목록을 통째로 복사하면 해당 없는 것까지 떠안고, 필요한 조정은 빠집니다. 이 단원은 통제를 고르고 다듬는 과정(표준 선정, 스코핑, 테일러링)과 대표적인 데이터 보호 수단(암호화·토큰화·마스킹·가명화, DLP, DRM, CASB)을 다룹니다.

    1통제 선택의 흐름과 데이터 상태

    왜 필요한가

    원본은 통제 선택을 “무엇을 보호해야 하는가”에서 시작해 “어떤 통제를 어느 수준으로 적용할 것인가”로 내려가는 과정으로 설명합니다. 그리고 통제는 카탈로그에서 그대로 복사하는 것이 아니라 추리고 조정하는 것이라고 강조합니다.

    분류 + 규제 + 위험 평가
    →
    표준 선정어떤 통제 집합
    →
    스코핑해당되는 것만
    →
    테일러링우리 환경에 맞게
    →
    구현과 검증

    데이터 상태별 통제

    공식 개요 2.6의 첫 세부 항목이 데이터 상태(in use, in transit, at rest)입니다.

    상태주요 통제
    저장 중 At rest저장 암호화(디스크·DB·파일), 접근 통제, 백업 암호화
    전송 중 In transitTLS, IPSec/VPN, 안전한 파일 전송, 인증서 검증
    사용 중 In use메모리 보호, 기밀 컴퓨팅, 화면 마스킹, 세션 통제

    세 상태를 모두 덮어야 한다는 점은 D2.2 자산 취급 요구사항에서 다뤘습니다. 이 단원의 초점은 어떻게 고르는가이고, 원본이 드는 선택 기준은 데이터 분류 등급 + 위협 모델 + 규제 요구 + 비용입니다. 분류가 낮은 데이터에 고비용 통제를 걸면 낭비이고, 반대면 보호 공백입니다.

    보충세 상태는 순서대로 한 번씩 지나가는 단계가 아니라 동시에 존재할 수 있습니다. 사용자가 브라우저로 문서를 열면 서버의 저장본, 네트워크로 가는 사본, 화면에 표시되는 값이 한꺼번에 있습니다. 디스크 암호화는 저장본을, TLS는 전송 구간을 지키지만, 화면에 뜬 내용을 복사할 수 있는지는 애플리케이션 권한과 DRM 같은 다른 통제의 몫입니다. 통제를 고를 때 “이 통제는 어느 상태를 지키는가”를 꼭 붙여 생각하면 빈 곳이 보입니다.

    연결등급은 D2.1 자산 식별과 분류, 등급별 취급 규칙은 D2.2 자산 취급 요구사항에서 정했습니다. 위협 모델은 D1.10 위협 모델링, 비용 대비 효과 판단은 D1.9 위험 관리의 통제 가치 계산에서 다뤘습니다.

    원문 위치: D2.6.md §2, §3 데이터 상태별 통제 선택 · 공식 개요 2.6 “Data states (e.g., in use, in transit, at rest)”

    2표준 선정

    무엇을 보고 고르는가

    공식 개요의 Standards selection은 어떤 통제 집합을 기준으로 삼을지 정하는 단계입니다. 원본이 드는 고려 요소입니다.

    1. 법적·규제 요구 — 선택이 아니라 의무인 것부터(HIPAA, GDPR 등)
    2. 계약상 요구 — PCI DSS처럼 계약으로 강제되는 것
    3. 산업 관행 — 동종 업계의 기대 수준
    4. 조직의 위험 프로파일 — 위협 환경과 자산 특성
    5. 인증 필요성 — 대외 신뢰를 입증해야 하면 ISO 27001처럼 인증 가능한 표준
    표준성격
    NIST SP 800-53상세한 통제 카탈로그
    ISO/IEC 27001 / 27002ISMS 요구사항과 실행 지침, 인증 가능
    CIS Controls우선순위가 매겨진 실무 통제
    PCI DSS카드 산업, 계약 의무
    NIST CSF결과 중심 프레임워크

    여러 요구가 겹치면 통합 매핑을 합니다. 하나의 통제가 여러 표준의 요구를 동시에 충족하도록 설계해 중복 작업을 줄입니다.

    보충통합 매핑의 실제 모습은 이렇습니다. “접근 권한을 분기마다 검토한다”는 통제 하나를 만들고, 그것이 ISO 27001 부속서 A의 어떤 항목, PCI DSS의 어떤 요구, 고객 계약의 어떤 조항을 충족하는지 표로 연결해 둡니다. 그러면 감사가 세 번 와도 같은 증거(검토 기록)를 세 번 쓰면 됩니다. 표준마다 별도 통제를 만들면 같은 일을 세 번 하고, 셋 중 하나는 결국 형식만 남습니다.

    연결각 프레임워크의 성격은 D1.3 보안 거버넌스, 법률과 계약상 의무의 차이(PCI DSS는 법이 아니라 계약)는 D1.4 법률·규제·컴플라이언스에서 다뤘습니다. 인증 심사와 감사의 수행은 D6.5 보안 감사에서 다룹니다.

    원문 위치: D2.6.md §3 표준 선정 · 공식 개요 2.6 “Standards selection” · 기존 문제 주제(표준 선정 순서)

    3스코핑

    쉬운 설명

    스코핑(Scoping)은 통제 집합 중 우리에게 해당되는 것만 추리는 작업입니다. 무선 네트워크가 없으면 무선 관련 통제는 범위 밖이고, 클라우드를 쓰지 않으면 클라우드 통제는 적용되지 않습니다.

    원본은 제외는 근거와 함께 문서화해야 한다고 강조합니다. “해당 없음”을 기록 없이 남기면 감사에서 통제 누락과 구분되지 않습니다.

    범위는 설계할 수 있다

    원본이 드는 좋은 예가 PCI DSS의 범위 축소입니다. 카드 데이터를 처리하는 시스템만 범위에 들어가므로, 네트워크 분할로 범위를 줄이면 비용과 노력이 크게 줄어듭니다.

    원문 사례 — 범위 축소로 비용을 줄인 경우. 카드 결제를 처리하는 조직이 전체 네트워크를 PCI DSS 범위로 두고 있어 수백 대 서버 모두에 고강도 통제와 분기 스캔이 필요했습니다. 네트워크 분할로 카드 데이터 환경을 격리하고 토큰화를 도입해 다른 시스템은 토큰만 갖게 하자 범위가 수십 대로 줄었습니다. 원본의 결론은 스코핑은 사후 작업이 아니라 설계 전략이라는 것입니다.

    보충범위 축소가 통하는 이유는 D2.1 자산 식별과 분류의 자산 분류 원칙과 같습니다. 민감한 데이터가 닿는 시스템은 그 등급의 통제를 받아야 하므로, 민감한 데이터가 닿는 곳을 줄이면 무거운 통제를 받아야 할 곳도 줄어듭니다. 다만 범위 밖이라고 선언하려면 정말로 분리되어 있다는 근거(분할 시험 결과 등)가 있어야 합니다. 경계가 새는데 범위만 줄이면 서류상 안전이 됩니다.

    원본 연습문제 · D2.6-Q01

    조직이 통제 카탈로그를 검토하면서 무선 인프라를 운영하지 않는다는 이유로 무선 네트워크 통제를 제외했다. 이 활동을 가장 잘 설명한 것은?

    1. 테일러링
    2. 스코핑
    3. 위험 수용
    4. 인증
    정답과 해설 보기

    정답 B. 스코핑은 통제 집합 중 조직에 적용되는 것만 추리는 작업이다. 적용 대상이 아닌 통제를 제외하는 것이 스코핑이며, 적용 대상 통제를 조직 환경에 맞게 강화·완화·보완하는 것이 테일러링이다. 제외는 반드시 근거와 함께 문서화해야 감사에서 누락과 구분된다.

    • A · 테일러링은 적용하기로 한 통제를 어떻게 조정할지 정하는 단계다.
    • C · 위험 수용은 통제하지 않고 위험을 감수하는 결정이다.
    • D · 인증은 제3자가 준수를 검증하는 절차다.
    원문 위치 · D2.6-Q01
    문제 목록으로 돌아가기
    원본 연습문제 · D2.6-Q07

    가맹점이 PCI DSS 요구사항 적용 대상 시스템 수를 줄여야 한다. 가장 효과적인 조치 조합은?

    1. 컴플라이언스 팀에 모든 서버에 대한 관리자 접근 권한 부여.
    2. 감사 단순화를 위한 카드 데이터 보존 기간 연장.
    3. 모든 시스템에 대한 취약점 스캔 빈도 증가.
    4. 카드 데이터 환경을 격리하는 네트워크 분할과 토큰화의 결합.
    정답과 해설 보기

    정답 D. PCI DSS 범위에는 카드 데이터를 저장·처리·전송하는 시스템이 포함된다. 네트워크 분할로 카드 데이터 환경을 격리하고 토큰화로 다른 시스템은 토큰만 보유하게 하면 범위가 크게 줄어 비용과 노력이 절감된다. 스코핑은 사후 작업이 아니라 설계 전략이다.

    • A · 광범위한 관리자 접근은 범위를 넓히고 최소권한에 반한다.
    • B · 보존 연장은 범위와 위험을 모두 키운다.
    • C · 스캔 빈도는 범위를 줄이지 않고 오히려 부담을 늘린다.

    4테일러링

    쉬운 설명

    테일러링(Tailoring)은 스코핑으로 추린 통제를 조직 환경에 맞게 조정하는 작업입니다.

    조정 유형내용
    강화 strengthen기준보다 높은 수준 적용
    완화 reduce위험이 낮아 수준을 낮춤
    보완 compensating적용할 수 없을 때 동등한 대체 통제
    매개변수 지정“주기적으로”를 “분기 1회”로 구체화
    추가 supplement카탈로그에 없는 조직 고유 통제 추가

    스코핑과의 차이

    작업묻는 것예
    스코핑적용 대상인가, 아닌가무선이 없으니 무선 통제 제외
    테일러링적용하되 어떻게 조정하는가비밀번호 변경 주기를 조직 위험에 맞춰 지정, 적용 불가한 통제를 보완 통제로 대체

    원본은 모든 조정이 위험 기반 근거와 함께 문서화되어야 하고 권한 있는 사람의 승인이 필요하다고 정리합니다.

    판단 순서통제 목록을 다듬는 상황을 만나면 ① 이 통제가 우리 환경에 해당하는 대상이 있는가(없으면 스코핑으로 제외, 근거 기록) ② 해당한다면 그대로 쓸 수 있는가(쓸 수 있으면 매개변수만 지정) ③ 그대로 쓸 수 없으면 강화·완화·보완 중 무엇인가 ④ 근거와 승인이 있는가 순서로 봅니다. 지문이 “제외했다”면 스코핑, “조정했다·대체했다·구체화했다”면 테일러링입니다.

    가상 예시결제를 외부 결제 대행사에 위탁한 온라인 상점이 있습니다. 상점이 카드번호를 저장하지 않더라도 결제 화면이 어떻게 연동되는지에 따라 PCI DSS 요구 일부가 상점에 남습니다. 먼저 결제 흐름을 따라가며 어디까지 요구가 적용되는지 정하는 것이 스코핑이고, 적용 범위 안의 통제를 상점 환경에 맞게 값과 구현을 정하는 것이 테일러링입니다. 마지막으로 대행사가 수행하는 통제와 상점이 수행하는 통제를 나누고, 각각 어떤 증거로 확인할지 정합니다.

    연결테일러링의 ‘보완’은 D2.5 자산 보존 (EOL·EOS)에서 교체할 수 없는 레거시 시스템에 쓴 보완 통제와 같은 개념입니다. 위험 기반 근거는 D1.9 위험 관리, 승인과 예외 절차는 D1.6 정책·표준·절차·지침에서 다뤘습니다. 원본은 NIST SP 800-53B(통제 베이스라인과 테일러링 지침)와 SP 800-37(RMF)의 Select 단계를 관련 표준으로 듭니다.

    CISSP 관점원본은 스코핑과 테일러링을 바꿔 서술한 선택지를 함정으로 지목합니다. 판단 기준은 하나입니다. 대상에서 빼는 것이면 스코핑, 대상으로 남긴 것을 고치는 것이면 테일러링. 그리고 둘 다 근거 문서와 승인이 있어야 합니다.

    원문 위치: D2.6.md §3 테일러링, §4 Tailoring·Compensating Control, §5 첫 표, §6 NIST SP 800-53B·800-37 · 공식 개요 2.6 “Scoping and tailoring” · 기존 문제 주제(스코핑과 테일러링 구분)

    5데이터 보호 기법: 암호화, 토큰화, 마스킹, 해싱

    쉬운 설명

    민감한 값을 보호하는 방법은 “원래 값으로 되돌릴 수 있는가, 어떻게 되돌리는가”로 구분하면 정리됩니다.

    기법무엇을 하나복원
    암호화 Encryption키 없이 읽을 수 없게 변환키로 완전 복원
    토큰화 Tokenization민감 값을 의미 없는 토큰으로 대체하고 대응 관계를 별도 토큰 금고(vault)에 보관. 토큰과 원본 사이에 수학적 관계가 없다금고 조회로만 복원
    마스킹 Masking표시할 때 일부를 가림(****-****-****-1234). 저장된 원본은 그대로일 수 있다표시 수준 통제
    해싱 Hashing입력을 고정 길이 값으로 단방향 변환복원 불가

    원본은 토큰화가 카드 데이터 보호에 널리 쓰이며 PCI DSS 범위 축소에도 활용된다고 설명합니다(3절의 사례).

    보충토큰화가 범위를 줄일 수 있는 이유는 “수학적 관계가 없다”는 성질 때문입니다. 암호화된 카드번호는 키만 있으면 풀리므로 그것을 가진 시스템도 여전히 카드 데이터를 다룬다고 볼 수 있지만, 토큰은 금고 없이는 아무 의미가 없습니다. 그래서 무거운 통제는 금고 하나에 집중하면 됩니다. 마스킹은 반대로 저장된 원본을 그대로 두는 경우가 많아, 화면 노출은 줄여도 데이터베이스가 유출되면 원본이 나갑니다. 해싱은 비밀번호 저장에 쓰이지만, 비밀번호 검증값을 저장할 때는 일반 해시를 그대로 쓰지 않고 솔트와 계산 비용을 더한 비밀번호 전용 방식을 쓰도록 NIST SP 800-63B-4가 요구합니다(“Passwords SHALL be salted and hashed using a suitable password hashing scheme”, 솔트 32비트 이상).

    연결암호화와 해시의 원리, 솔트와 키 유도 함수는 D3.6 암호 솔루션, 비밀번호 저장 방식과 인증 시스템 구현은 D5.6 인증 시스템, 비밀번호 해시를 노리는 공격(사전 대입, 레인보 테이블)은 D3.7 암호 분석 공격에서 다룹니다. 개발·테스트 환경에 운영 데이터를 쓰지 말고 마스킹·합성 데이터를 쓰라는 원칙은 D2.4 데이터 생애주기에서 봤습니다.

    원본 연습문제 · D2.6-Q18

    토큰화가 하는 일은?

    1. 가역적 알고리즘으로 데이터를 그 자리에서 암호화한다.
    2. 민감한 값을 민감하지 않은 대체값으로 바꾸고 원값은 별도의 보호된 금고에 보관한다. 그래서 대체값만 필요한 시스템은 실제 값을 보유하지 않는다.
    3. 저장 요구를 줄이기 위해 데이터를 압축한다.
    4. 원값을 영구히 파괴한다.
    정답과 해설 보기

    정답 B. 토큰화의 핵심은 대체값이 수학적으로 원값과 연결되지 않는다는 점이다. 암호화는 키가 있으면 어디서든 복호화되지만 토큰은 금고를 조회해야 원값을 얻는다. 그래서 토큰을 쓰는 시스템들을 준수 범위에서 빼는 데 활용되며 카드 데이터 처리에서 널리 쓰인다.

    • A · 암호화와 다른 방식이다.
    • C · 압축이 목적이 아니다.
    • D · 원값은 금고에 보관된다.

    6가명화와 익명화

    쉬운 설명

    처리재식별규제상 취급
    가명화 Pseudonymization식별자를 대체하되 추가 정보를 이용하면 재식별 가능보호 조치로 인정되지만 여전히 개인정보
    익명화 Anonymization재식별 불가능하도록 처리성공하면 GDPR 적용 범위 밖

    원본은 완전한 익명화는 생각보다 어렵고, 집계·추론으로 재식별되는 사례가 많다고 경고합니다.

    원문 사례 — 익명화가 아니었던 익명화. 연구 목적으로 이름과 연락처를 지운 데이터셋을 외부에 제공했는데, 생년월일·성별·우편번호 조합으로 상당수 개인이 재식별되었습니다. 식별자를 지운 것만으로는 익명화가 완성되지 않습니다. 이 데이터는 가명화에 가까우며 여전히 개인정보로 다뤄야 했습니다.

    보충GDPR은 가명화를 제4조 제5호에서 정의하고, 전문(Recital) 26에서 익명 정보에는 이 규정이 적용되지 않는다고 하면서 식별 가능성을 판단할 때 합리적으로 사용될 가능성이 있는 모든 수단(비용, 시간, 이용 가능한 기술)을 고려하라고 합니다. 그래서 판단할 질문은 “이름을 지웠는가”가 아니라 “현실적으로 쓸 수 있는 다른 정보와 방법을 동원하면 다시 사람을 알아볼 수 있는가”입니다. 한국 개인정보 보호법의 가명정보 제도와 같은 개념인지는 이 교재에서 확인하지 않았습니다.

    연결재식별이 일어나는 원리(집계와 추론, 간접 식별자)는 D2.1 자산 식별과 분류의 7절과 원본 문제에서 봤습니다. GDPR의 개인정보 정의와 정보주체의 권리는 D1.4 법률·규제·컴플라이언스에서 다뤘습니다.

    이해 확인 · 자작 상황 문제 (실제 시험 문제 아님)

    회사가 장비 사용 통계를 외부 연구 기관에 제공하려 한다. 환자 이름과 등록번호를 일련번호로 바꾸고, 일련번호와 실제 환자의 대응표는 회사가 따로 보관한다. 이 데이터에 대한 가장 정확한 평가는?

    1. 익명화되었으므로 개인정보 보호 규정의 적용을 받지 않는다.
    2. 대응표로 재식별이 가능하므로 가명화이며, 여전히 개인정보로 보호해야 한다.
    3. 암호화되었으므로 개인정보가 아니다.
    4. 토큰화되었으므로 연구 기관은 아무 의무도 없다.
    정답과 해설 보기

    정답 B. 추가 정보(대응표)로 다시 연결할 수 있으면 가명화입니다. 대응표를 분리해 보호하는 것은 좋은 보호 조치지만 데이터의 성격을 바꾸지 않습니다.

    • A: 재식별 경로가 남아 있습니다. 대응표가 없더라도 다른 속성의 조합으로 재식별될 수 있는지도 따로 봐야 합니다.
    • C: 키로 풀 수 있는 암호화는 개인정보를 지우지 않습니다. 또 지문의 처리는 암호화가 아니라 식별자 대체입니다.
    • D: 대체 방식이 토큰화와 닮았더라도 데이터가 개인정보라는 사실은 바뀌지 않습니다.

    7DLP — 데이터 유출 방지

    쉬운 설명

    DLP(Data Loss Prevention)는 정책에 어긋나는 데이터의 이동·저장·사용을 탐지하고 차단합니다. 공식 개요 2.6이 데이터 보호 방법의 예로 DRM·DLP·CASB를 듭니다.

    배치 위치보는 것
    네트워크 DLP전송 중 데이터(메일, 웹 업로드)
    엔드포인트 DLP단말의 USB 복사, 클립보드, 인쇄
    스토리지 DLP저장된 데이터의 위치와 노출 상태

    어떻게 찾아내는가

    • 패턴 매칭 — 정규식(카드번호, 주민번호)
    • 사전·키워드
    • 데이터 지문(Data Fingerprinting) — 특정 문서의 지문과 대조. 정확도가 높다
    • 분류 라벨 연동 — 분류 결과를 DLP 정책에 연결
    • 통계·머신러닝

    원본이 강조하는 두 가지가 있습니다. 첫째, DLP의 전제는 분류입니다. 무엇이 민감한지 정의되어 있지 않으면 DLP는 패턴 매칭 도구에 그칩니다. 둘째, 운영의 핵심은 오탐 관리입니다. 처음부터 차단 모드로 켜면 업무가 마비되고 신뢰를 잃으므로, 모니터 모드로 시작해 정책을 다듬은 뒤 단계적으로 차단으로 바꿉니다.

    원문 사례 — 차단 모드로 시작한 DLP. DLP를 도입하며 처음부터 전면 차단으로 설정했습니다. 정상 업무 메일이 대량으로 막혀 하루 만에 수백 건의 민원이 생겼고, 결국 정책을 전부 꺼 버렸습니다. 모니터 모드로 2~3개월 운영하며 오탐을 줄이고 신뢰도 높은 규칙부터 단계적으로 차단했어야 했습니다. 원본은 신뢰를 한 번 잃으면 재도입이 어렵다고 덧붙입니다.

    보충모니터 모드로 시작하는 것은 “약하게 하는 것”이 아니라 규칙을 측정하는 기간입니다. 이 기간에 어떤 규칙이 정상 업무를 잡는지(오탐), 어떤 경로로 실제 민감 정보가 나가는지(진짜 위험)를 데이터로 봅니다. 그 결과로 신뢰도가 높은 규칙만 차단으로 올리면, 차단이 걸렸을 때 사용자도 “진짜 문제가 있구나”라고 받아들입니다. D2.2 자산 취급 요구사항에서 본 “사용성을 무시한 규칙은 우회를 낳는다”가 도구 도입에도 그대로 적용됩니다.

    연결분류 라벨은 D2.1 자산 식별과 분류에서 만들고, 라벨이 사람에게 주는 신호와 시스템이 집행하는 규칙의 차이는 D2.2 자산 취급 요구사항의 6절에서 봤습니다. 탐지 도구의 오탐·미탐 조정과 운영은 D7.7 탐지·예방 수단, 경보 관리는 D7.2 로깅·모니터링에서 다룹니다.

    원문 위치: D2.6.md §3 DLP, §4 DLP·Data Fingerprinting, §7 사례 2 · 공식 개요 2.6 “Data protection methods (e.g., DRM, DLP, CASB)” · 기존 문제 주제(DLP 도입 순서, 분류 전제)

    8DRM / IRM — 데이터에 붙는 권한

    쉬운 설명

    DRM(Digital Rights Management)은 데이터 자체에 사용 권한을 붙여 조직 경계를 벗어난 뒤에도 통제를 유지하는 기술입니다. 기업 문서에 적용할 때는 IRM(Information Rights Management)이라고도 부릅니다.

    통제할 수 있는 것은 열람·편집·인쇄·복사·전달 권한, 사용 기한과 원격 권한 취소(revocation), 사용 이력 추적, 워터마크 삽입입니다. 원본은 핵심 가치를 “유출 이후에도 통제가 남는다”로 요약합니다. 파일이 외부로 나가도 권한 서버가 허락하지 않으면 열리지 않습니다.

    한계도 있습니다. 화면 촬영이나 손으로 옮겨 적는 아날로그 갭(Analog Hole)은 막을 수 없고, 전용 뷰어·플러그인이 필요해 외부 협업에서 마찰이 생깁니다.

    원문 사례 — 유출 후에도 살아 있던 통제. 퇴사 예정자가 전략 기획 문서를 개인 메일로 보냈습니다. 문서에 IRM이 적용되어 있어 외부에서 열자 권한 서버가 인증을 요구했고, 권한 취소로 열람이 막혔습니다. 다만 사내에서 이미 화면을 촬영했다면 막을 수 없었을 것입니다.

    연결퇴사 예정자의 위험과 퇴사 절차는 D1.8 인적 보안, 내부자 위협 탐지는 D7.2 로깅·모니터링에서 다룹니다. 워터마크로 유출 출처를 추적하는 것은 D2.2 자산 취급 요구사항의 외부 공유 통제에서 봤습니다.

    원문 위치: D2.6.md §3 DRM, §4 DRM / IRM·Analog Hole, §7 사례 3 · 기존 문제 주제(DRM 원격 취소, 아날로그 갭)

    9CASB — 클라우드로 가는 길목의 통제

    쉬운 설명

    CASB(Cloud Access Security Broker)는 조직과 클라우드 서비스 사이에서 보안 정책을 집행하는 통제 지점입니다.

    기능 축역할
    가시성 Visibility어떤 클라우드 서비스가 쓰이는지 파악. 섀도 IT 발견
    컴플라이언스 Compliance규제 요구 충족 여부 점검
    데이터 보안 Data SecurityDLP, 암호화, 접근 통제 적용
    위협 방어 Threat Protection계정 탈취, 이상 행위 탐지

    배치 방식

    방식작동장점한계
    API 모드 out-of-band클라우드 서비스 API로 사후 점검성능 영향 없음, 이미 저장된 데이터도 검사실시간 차단 불가
    프록시 모드 inline트래픽 경로에 위치실시간 차단 가능. 포워드 프록시는 관리 단말, 리버스 프록시는 비관리 단말에 적용성능 영향, 호환성 문제

    원본은 실무에서는 둘을 함께 쓴다고 정리합니다. API로 전수 점검하고 프록시로 실시간 통제합니다.

    원문 사례 — CASB가 드러낸 섀도 IT. CASB를 가시성 모드로 도입하자 승인된 SaaS는 12개였지만 실제로 쓰이는 서비스는 300개 이상이었고, 일부는 민감 자료를 업로드받고 있었습니다. 원본의 결론은 가시성이 통제의 전제라는 것입니다.

    연결섀도 IT가 인벤토리의 가장 큰 공백이라는 점은 D2.1 자산 식별과 분류·D2.3 안전한 프로비저닝, 도입할 SaaS의 보안 평가는 D8.4 도입 소프트웨어 평가, 계정 탈취와 이상 행위 탐지는 D7.2 로깅·모니터링에서 다룹니다. 프록시가 트래픽 경로에 놓일 때의 네트워크 설계는 D4.1 네트워크 아키텍처에 있습니다.

    원문 위치: D2.6.md §3 CASB, §4 CASB·API Mode / Proxy Mode, §5 넷째 표, §7 사례 4 · 기존 문제 주제(CASB 4축, 배치 모드)

    10세 도구를 고르는 법

    DRM, DLP, CASB는 이름이 비슷한 범주로 묶이지만 답하는 질문이 다릅니다.

    도구답하는 질문통제가 붙는 곳
    DLP민감한 데이터가 허용되지 않은 곳으로 나가려 하는가네트워크, 단말, 저장소(경로)
    DRM / IRM나간 데이터를 받은 사람이 무엇을 할 수 있는가데이터 자체
    CASB어떤 클라우드 서비스를 누가 어떻게 쓰는가조직과 클라우드 사이

    판단 순서데이터 보호 도구를 고르는 상황에서는 먼저 막으려는 행동을 정합니다. ① 승인되지 않은 클라우드 서비스를 쓰는지 모른다 → CASB(가시성) ② 승인된 경로로도 민감 정보가 밖으로 나간다 → DLP(내용 검사) ③ 이미 받은 사람의 재전달·인쇄·열람 기간을 통제해야 한다 → DRM/IRM ④ 화면에 보이는 값 자체를 줄여야 한다 → 마스킹. 그리고 어느 도구든 그 전에 분류가 있어야 무엇이 민감한지 판단할 수 있습니다.

    가상 예시한 팀이 승인되지 않은 클라우드 문서 서비스에 고객 목록을 올리고 있고, 승인된 서비스에서도 대량 내보내기가 됩니다. 어떤 서비스를 쓰는지조차 모르는 상태라면 CASB의 가시성이 먼저입니다. 승인된 서비스 안에서 민감 정보가 외부로 공유되는 조건을 잡으려면 CASB의 데이터 보안 기능이나 DLP가 내용을 보고 탐지·차단해야 합니다. 협력사에 보낸 뒤 재공유까지 막아야 한다면 DRM이 필요합니다. 하나의 사건이라도 단계마다 맞는 도구가 다릅니다.

    이해 확인 · 자작 상황 문제

    회사가 설계 도면을 외부 협력사에 보낸다. 요구사항은 “협력사 담당자만 열람, 인쇄 금지, 프로젝트 종료 시 열람 권한 회수”이다. 가장 적합한 통제는?

    1. 네트워크 DLP로 도면 첨부 메일을 차단한다.
    2. 도면에 IRM을 적용해 열람자·권한·기한을 지정하고 종료 시 원격으로 권한을 취소한다.
    3. CASB API 모드로 협력사의 클라우드 저장소를 점검한다.
    4. 도면 파일을 해시해서 보낸다.
    정답과 해설 보기

    정답 B. 요구사항이 모두 “받은 뒤에 무엇을 할 수 있는가”입니다. 데이터에 권한을 붙여 경계 밖에서도 통제가 유지되는 DRM/IRM의 영역입니다.

    • A: 보내는 것 자체를 막으면 업무가 안 됩니다. DLP는 나가려는 순간을 보는 도구입니다.
    • C: 협력사의 저장소는 우리 조직의 CASB가 관리하는 대상이 아니고, API 모드는 실시간 차단도 못 합니다.
    • D: 해시는 복원할 수 없으므로 도면을 쓸 수 없게 됩니다.

    남는 한계: 협력사 담당자가 화면을 촬영하는 것은 막지 못합니다(아날로그 갭). 그 위험은 계약(NDA)과 워터마크로 억제합니다.

    종합 · 자작 상황 문제

    병원용 장비 제조사가 고객 데이터를 다루는 클라우드 서비스에 통제를 적용하려 한다. ㉠ 무선 네트워크가 없어 무선 통제를 근거 기록 없이 뺐다. ㉡ “로그를 주기적으로 검토”를 “매주 검토”로 바꿨다. ㉢ 지원 화면에 환자 번호 전체가 보여 일부만 보이게 하려 한다. ㉣ DLP를 첫날부터 전면 차단으로 켜려 한다. 각각에 대한 평가로 옳은 것은?

    1. ㉠ 스코핑이지만 제외 근거를 문서화해야 한다 / ㉡ 테일러링(매개변수 지정) / ㉢ 마스킹 / ㉣ 모니터 모드로 시작해 단계적으로 차단
    2. ㉠ 테일러링 / ㉡ 스코핑 / ㉢ 해싱 / ㉣ 문제없음
    3. ㉠ 문제없음 / ㉡ 위험 수용 / ㉢ 익명화 / ㉣ 문제없음
    4. ㉠ 보완 통제 / ㉡ 스코핑 / ㉢ 토큰화 / ㉣ 차단 후 민원이 없으면 유지
    정답과 해설 보기

    정답 A.

    • ㉠ 대상에서 빼는 것은 스코핑이며, 근거 기록이 없으면 감사에서 통제 누락과 구분되지 않습니다(3절).
    • ㉡ 남긴 통제의 값을 구체화하는 것은 테일러링의 매개변수 지정입니다(4절).
    • ㉢ 화면에서 일부만 보이게 하는 표시 수준 통제는 마스킹입니다(5절). 저장된 원본 보호는 별도로 필요합니다.
    • ㉣ 원문 사례 2. 오탐으로 업무가 막히면 정책 전체를 끄게 됩니다(7절).

    원본 연습문제 · D2.6-Q12

    어떤 규제가 특정 개인정보를 자국 내에 저장하도록 요구한다. 팀이 클라우드 공급자의 자국 내 리전을 선택했다. 그 외에 확인해야 하는 것은?

    1. 백업과 복제본, 로그, 지원 인력 접근, 관리형 서비스 처리도 자국 내에 머무는지, 그리고 공급자나 그 모회사가 외국 법에 따라 데이터 공개를 강제받을 수 있는지.
    2. 그 외에 없다. 리전 선택으로 요구가 충족된다.
    3. 해당 리전과 조직 사무실 간의 지연만.
    4. 해당 리전이 다른 리전과 같은 서비스 등급을 제공하는지만.
    정답과 해설 보기

    정답 A. 주 저장 위치만 자국이고 백업이나 로그가 다른 리전으로 가는 설정이 흔하다. 지원 인력이 해외에서 접근하면 그것도 이전으로 볼 수 있고, 관리형 서비스가 내부적으로 다른 리전에서 처리하는 경우도 있다. 법적 관할은 데이터의 물리적 위치만으로 결정되지 않아 공급자의 본국 법에 따른 공개 요구 가능성도 평가 대상이다.

    • B · 부수 데이터와 접근 경로가 남는다.
    • C · 성능은 규제 요구와 다른 축이다.
    • D · 서비스 등급은 준수 요건이 아니다.

    12핵심 개념을 내 말로 설명하기

    복습

    암호화, DLP, DRM이 각각 잘 해결하는 문제는 무엇인가요?

    설명 확인하기

    암호화는 키 없이 내용을 읽기 어렵게 합니다. DLP는 민감 자료의 무단 이동을 식별하거나 제한하고, DRM은 전달한 뒤의 재배포·인쇄 같은 사용 조건을 적용할 수 있습니다. 데이터 상태와 막을 행동부터 정합니다.

    13핵심 요약

    1. 통제 선택 흐름: 분류·규제·위험 → 표준 선정 → 스코핑 → 테일러링 → 구현·검증. 카탈로그를 그대로 복사하지 않는다.
    2. 데이터 상태별 통제: 저장 중(저장 암호화, 백업 암호화) / 전송 중(TLS, IPSec·VPN, 인증서 검증) / 사용 중(기밀 컴퓨팅, 화면 마스킹, 세션 통제). 선택 기준은 등급 + 위협 + 규제 + 비용.
    3. 표준 선정: 규제 의무 → 계약 → 산업 관행 → 조직 위험, 인증이 필요하면 ISO 27001. 겹치면 통합 매핑.
    4. 스코핑 = 적용 대상인가(제외 근거 문서화). 테일러링 = 어떻게 조정하는가(강화 / 완화 / 보완 / 매개변수 / 추가). 모든 조정은 위험 근거와 승인.
    5. PCI DSS 범위 축소 = 네트워크 분할 + 토큰화. 스코핑은 설계 전략.
    6. 암호화(키로 복원) / 토큰화(금고 조회, 수학적 관계 없음) / 마스킹(표시 제한) / 해싱(복원 불가).
    7. 가명화 = 재식별 가능 = 개인정보, 익명화 = 재식별 불가 = 규제 범위 밖. 식별자 제거만으로는 익명화가 아니다.
    8. DLP: 네트워크 / 엔드포인트 / 스토리지. 탐지는 패턴, 키워드, 데이터 지문, 라벨 연동. 분류가 전제, 모니터 모드로 시작.
    9. DRM/IRM: 데이터에 권한 부착, 경계 밖에서도 통제, 원격 취소. 아날로그 갭은 못 막는다.
    10. CASB 4축: 가시성 · 컴플라이언스 · 데이터 보안 · 위협 방어. API 모드(사후, 차단 불가) / 프록시 모드(실시간 차단), 함께 쓴다. 초기 가치는 섀도 IT 발견.
    원문 위치: D2.6.md §8 CISSP 시험 관점, §9 핵심 암기 요약(14항목). 원본의 “자주 나온다”, “오답 방향” 같은 출제 단정 표현은 판단 기준으로 바꿔 적었습니다. 원본 §6의 CIS Controls, ISO/IEC 27001/27002는 2절 표에 반영했습니다.

    14주요 용어 (Glossary)

    영어 원어와 한국어 뜻 · English–Korean

    Scoping · 스코핑

    통제 집합 중 조직에 적용되는 것만 추리는 작업. 제외 근거를 문서화해야 한다.

    Tailoring · 테일러링

    적용 대상 통제를 조직 환경에 맞게 강화·완화·보완·구체화하는 작업.

    Compensating Control · 보완 통제

    요구된 통제를 적용할 수 없을 때 동등한 보호를 제공하는 대체 통제.

    Tokenization · 토큰화

    민감 값을 의미 없는 토큰으로 대체하고 대응 관계를 별도 금고에 보관하는 기법. 토큰과 원본 사이에 수학적 관계가 없다.

    Masking · 마스킹

    표시 시점에 데이터의 일부를 가리는 기법. 저장된 원본은 유지될 수 있다.

    Pseudonymization · 가명화

    개인에게 연결하려면 별도 보호된 추가 정보가 필요하도록 처리합니다. 식별 가능성이 남으면 개인정보 보호 요건을 검토합니다.

    Anonymization · 익명화

    합리적으로 사용될 수 있는 수단으로도 개인을 식별할 수 없게 처리하는 것입니다. 적용 범위는 규정의 식별 가능성 기준으로 판단합니다.

    DRM / IRM — Digital Rights Management / Information Rights Management · 디지털 권리 관리 / 정보 권리 관리

    데이터 자체에 사용 권한을 부착해 조직 경계 밖에서도 통제를 유지하는 기술. 원격 권한 취소가 가능하다.

    Analog Hole · 아날로그 갭

    화면 촬영이나 수기 전사처럼 디지털 통제로 막을 수 없는 유출 경로.

    DLP — Data Loss Prevention · 데이터 유출 방지

    정책 위반 데이터의 이동·저장·사용을 탐지하고 차단하는 기술. 네트워크·엔드포인트·스토리지 유형이 있다.

    Data Fingerprinting · 데이터 지문

    특정 문서의 고유 특징을 추출해 대조하는 DLP 탐지 방식. 패턴 매칭보다 정확도가 높다.

    CASB — Cloud Access Security Broker · 클라우드 접근 보안 중개

    조직과 클라우드 서비스 사이에서 정책을 집행하는 통제 지점. 가시성·컴플라이언스·데이터 보안·위협 방어의 네 축을 갖는다.

    API Mode / Proxy Mode · API 방식 / 프록시 방식

    CASB 배치 방식. API 모드는 사후 점검으로 성능 영향이 없고, 프록시 모드는 실시간 차단이 가능하다.

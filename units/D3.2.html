    연습문제 6개 바로가기

    표시 없는 본문은 원본 정리 파일의 내용 · 보충은 원본에 없어 더한 설명 · 가상 예시는 지어낸 상황 · 연결은 다른 단원과의 관계 · 확인 필요는 그대로 확정하지 않은 부분

    “기밀 정보가 새지 않게 하라”는 정책은 좋은 말이지만, 그대로는 시스템이 지켰는지 검사할 수 없습니다. 보안 모델은 이런 정책을 “이 등급의 사용자는 저 등급의 자료를 읽을 수 없다” 같은 검증 가능한 규칙으로 바꾼 것입니다. 이 단원은 대표적인 모델들이 각각 무엇을 지키려고 만들어졌는지를 다룹니다.

    1보안 모델이란, 그리고 상태 기계

    왜 필요한가

    보안 정책무엇을 지킬 것인가
    →
    보안 모델형식 규칙으로 표현
    →
    실제 시스템규칙을 강제하는 메커니즘

    보안 모델(Security Model)은 보안 정책을 수학적·형식적으로 표현한 것입니다. 원본은 모델이 필요한 이유를 검증 가능성으로 설명합니다. “기밀 정보가 새지 않는다”는 검증할 수 없지만, “낮은 등급 주체는 높은 등급 객체를 읽을 수 없다”는 검증할 수 있습니다.

    원본이 가장 먼저 외우라고 하는 대응입니다.

    모델보호 목표
    Bell-LaPadula기밀성
    Biba무결성
    Clark-Wilson무결성(상용 환경)
    Brewer-Nash이해충돌 방지

    상태 기계 모델

    많은 모델의 바탕에 상태 기계 모델(State Machine Model)이 있습니다. 시스템은 언제나 어떤 상태에 있고, 모든 상태 전이가 안전한 상태에서 안전한 상태로 이루어지면 그 시스템은 안전하다고 봅니다. 안전한 상태에서 출발해 어떤 입력을 받아도 안전한 상태를 유지한다는 것을 기본 보안 정리(Basic Security Theorem)라고 합니다.

    보충상태 기계라는 말이 어렵게 들리지만 생각은 단순합니다. 출입증 시스템을 예로 들면, “지금 누가 어느 방에 들어갈 수 있는가”의 표가 상태입니다. 입사, 퇴사, 권한 변경 같은 사건이 상태를 바꿉니다. 각 사건이 규칙을 어기는 상태(예: 퇴사자가 출입 가능)를 만들지 않는다는 것을 보이면, 처음 상태가 안전했던 한 시스템은 계속 안전합니다. 보안 모델들은 “안전한 상태”가 무엇인지를 각자 다르게 정의합니다.

    원문 위치: D3.2.md §2, §3 상태 기계 모델, §4 Security Model·State Machine Model · 공식 개요 3.2 “Understand the fundamental concepts of security models”

    2격자 기반 접근 통제

    주체와 객체에 등급(label)을 붙이고, 등급 사이의 순서 관계로 접근을 결정합니다.

    Unclassified
    <
    Confidential
    <
    Secret
    <
    Top Secret

    각 주체는 접근할 수 있는 범위의 최소 상한(least upper bound)과 최대 하한(greatest lower bound)을 가집니다. 원본은 이것이 강제적 접근 통제(MAC)의 수학적 기반이며 BLP와 Biba가 모두 이 구조 위에 있다고 설명합니다. 구획(compartment)이 더해지면 단순한 한 줄 순서가 아니라 격자가 됩니다.

    보충왜 “격자”인가. 등급만 있으면 높낮이가 한 줄로 정해지지만, 구획이 더해지면 비교할 수 없는 쌍이 생깁니다. (Secret, {작전 A})와 (Secret, {작전 B})는 어느 쪽이 높다고 할 수 없습니다. 둘 다를 볼 수 있으려면 (Secret, {A, B})가 필요하고, 둘 모두에게 허용되는 것은 (Secret, { })입니다. 이 “둘 다 덮는 가장 작은 것”이 최소 상한, “둘 모두 아래에 있는 가장 큰 것”이 최대 하한입니다. D2.1 자산 식별과 분류에서 본 “등급은 위아래, 구획은 옆”을 수학으로 표현한 것입니다.

    연결등급과 구획, 알 필요성은 D2.1 자산 식별과 분류, MAC를 포함한 접근 통제 모델(DAC, RBAC, ABAC 등)의 구현은 D5.4 인가 메커니즘에서 다룹니다.

    원본 연습문제 · D3.2-Q08

    라벨을 부여하고 라벨 간 순서 관계를 정의함으로써 강제적 접근통제의 수학적 기반을 제공하는 접근 통제 방식은?

    1. 격자 기반 접근통제
    2. 속성 기반 접근통제
    3. 역할 기반 접근통제
    4. 임의적 접근통제
    정답과 해설 보기

    정답 A. 격자 기반 접근통제는 주체와 객체에 등급 라벨을 부여하고 등급 간 순서 관계에 따라 접근을 결정한다. MAC 의 수학적 기반이며 Bell-LaPadula 와 Biba 가 모두 이 구조 위에 있다. 구획이 더해지면 단순 수직 관계가 아니라 격자 구조가 된다.

    • B · ABAC 는 속성 조합으로 정책을 평가한다.
    • C · RBAC 는 역할에 권한을 부여하는 방식이다.
    • D · DAC 는 소유자가 재량으로 권한을 부여하는 방식이다.

    3Bell-LaPadula — 기밀성

    쉬운 설명

    미 국방부 환경을 위해 만들어진 최초의 수학적 보안 모델이며 기밀성만 다룹니다.

    속성규칙뜻
    Simple Security Property 단순 보안 속성No Read Up자기 등급보다 높은 것을 읽을 수 없다
    *-Property 스타 속성No Write Down자기 등급보다 낮은 곳에 쓸 수 없다
    Strong Star Property같은 등급에서만 읽고 쓴다더 엄격한 변형
    Discretionary Security Property접근 매트릭스임의적 통제를 추가로 둔다

    왜 “아래로 쓰기 금지”가 기밀성 보호인가

    Top Secret 사용자가 Unclassified 파일에 쓸 수 있다면, 기밀 내용을 낮은 등급 영역에 옮겨 적을 수 있습니다. 사용자가 실수하든, 사용자 권한으로 실행된 악성 프로그램이 하든 결과는 같습니다. 이것을 막는 것이 스타 속성입니다.

    원문 사례 — BLP가 적용된 군사 시스템. Secret 인가를 가진 분석관이 Top Secret 보고서를 열려 하자 거부되었습니다(No Read Up). 자신이 작성한 Secret 분석 자료를 Unclassified 공유 폴더에 복사하려 하자 그것도 거부되었습니다(No Write Down). 두 번째가 직관에 어긋나 보이지만, 기밀 정보가 낮은 등급으로 흘러나가는 것을 막는 것이 스타 속성의 목적입니다.

    BLP의 한계

    • 무결성을 전혀 다루지 않는다. 낮은 등급 주체가 높은 등급에 쓰는 것(write up)은 허용되므로 데이터 오염이 가능하다
    • 가용성을 다루지 않는다
    • 은닉 채널을 막지 못한다
    • 등급 변경, 객체 생성·삭제를 다루지 않는다

    용어 주의원본은 공식 개요의 “Star Model”이 BLP의 *-property를 가리킨다고 해석합니다. 이 교재는 그 해석을 따르되, ISC2가 이 표현으로 무엇을 의도했는지 공식 설명을 확인하지는 못했습니다.

    연결등급 체계 자체는 D2.1 자산 식별과 분류의 정부·군 분류, BLP를 바탕으로 만든 평가 기준 TCSEC(Orange Book)과 그것을 대체한 Common Criteria는 D3.3 통제 선택 (RMF·CC), BLP 규칙을 시스템이 강제하는 MAC은 D5.4 인가 메커니즘에서 다룹니다.

    원본 연습문제 · D3.2-Q01

    Bell-LaPadula 모델에서 스타 속성(*-property)이 금지하는 것은?

    1. 더 낮은 무결성 수준의 정보를 읽는 것.
    2. 더 높은 무결성 수준으로 정보를 쓰는 것.
    3. 더 높은 분류 등급의 정보를 읽는 것.
    4. 더 낮은 분류 등급으로 정보를 쓰는 것.
    정답과 해설 보기

    정답 D. BLP 의 *-property 는 no write down 으로 자기 등급보다 낮은 곳에 쓰는 것을 금지한다. Top Secret 사용자가 Unclassified 파일에 쓸 수 있다면 기밀 내용을 낮은 등급 영역으로 옮길 수 있기 때문이다. Simple Security Property 가 no read up 에 해당한다.

    • A · 그것은 Biba 의 Simple Integrity Property 다.
    • B · 그것은 Biba 의 *-Integrity Property 다.
    • C · 그것은 Simple Security Property(no read up)다.

    원본 연습문제 · D3.2-Q05

    Bell-LaPadula 모델이 다루지 않는 보안 관심사는?

    1. 낮은 인가 등급 주체가 높은 분류 등급 데이터를 오염시키는 것을 막는 것.
    2. 분류 등급에 근거해 읽기 접근을 제한하는 것.
    3. 하향 정보 흐름을 막기 위해 쓰기 작업을 제한하는 것.
    4. 낮은 인가 등급에게 기밀 정보가 노출되는 것을 막는 것.
    정답과 해설 보기

    정답 A. BLP 는 기밀성만 다루며 무결성을 전혀 다루지 않는다. 낮은 등급 주체가 높은 등급에 쓰는 write up 은 BLP 규칙상 허용되므로 데이터 오염이 가능하다. 이 문제를 다루는 것이 Biba 모델이다.

    • B · Simple Security Property 가 이를 수행한다.
    • C · 스타 속성(*-property)이 이를 수행한다.
    • D · BLP 의 핵심 목적이다.

    4Biba — 무결성

    BLP와 대칭 구조로 설계되었고 무결성만 다룹니다.

    속성규칙뜻
    Simple Integrity Property 단순 무결성 속성No Read Down자기보다 낮은 무결성 수준을 읽을 수 없다
    *-Integrity Property 스타 무결성 속성No Write Up자기보다 높은 무결성 수준에 쓸 수 없다
    Invocation Property—낮은 무결성 주체가 높은 무결성 주체의 서비스를 호출할 수 없다

    왜 아래를 읽지 않는가. 신뢰할 수 없는 저품질 데이터를 읽어 들이면 그것에 기반한 판단과 산출물이 오염됩니다. 원본의 표현으로 무결성 관점에서 오염은 아래에서 위로 전파됩니다.

    원문 사례 — Biba가 필요한 상황. 생산 제어 시스템이 외부 공개 피드에서 설정값을 읽어 들이고 있었습니다. 공격자가 피드를 오염시키자 잘못된 설정이 생산 라인에 반영되었습니다. No Read Down 원칙은 신뢰도가 낮은 출처의 데이터를 높은 무결성 영역이 직접 읽지 못하게 합니다. 원본은 중간에 검증 게이트를 두어 데이터를 승격시키는 구조가 필요했다고 정리합니다.

    가상 예시장비가 사용하는 보정값 테이블을 생각해 봅시다. 공장에서 검증한 보정값(높은 무결성)과 현장 엔지니어가 노트북에서 입력한 임시값(낮은 무결성)이 있습니다. 장비가 임시값을 바로 읽어 측정에 쓰면 Biba의 No Read Down을 어긴 것이고, 엔지니어 노트북이 공장 보정값 파일을 덮어쓸 수 있으면 No Write Up을 어긴 것입니다. 원문 사례의 “검증 게이트”는 여기서 서명 확인과 범위 검사를 거친 값만 정식 보정값으로 올리는 절차입니다.

    원본 연습문제 · D3.2-Q12

    Biba 모델이 금지하는 것은?

    1. 더 높은 무결성 등급의 데이터를 읽는 것과 더 낮은 등급에 쓰는 것.
    2. 더 낮은 무결성 등급의 데이터를 읽는 것과 더 높은 무결성 등급에 쓰는 것. 낮은 무결성 데이터가 높은 무결성 데이터를 오염시키지 못하게 한다.
    3. 서로 다른 등급 간의 모든 접근을 양방향으로 금지한다.
    4. 감사 기록 없이 객체에 쓰는 모든 행위.
    정답과 해설 보기

    정답 B. Biba 는 무결성 모델이므로 오염을 막는 방향이다. 신뢰도가 낮은 출처의 데이터를 읽어 들이면 판단이 오염되고, 낮은 등급 주체가 높은 등급 객체에 쓰면 신뢰도가 떨어진다. 그래서 올려 읽기 금지가 아니라 내려 읽기 금지, 내려 쓰기 금지가 아니라 올려 쓰기 금지다. Bell-LaPadula 와 방향이 반대라는 점이 핵심이다.

    • A · Bell-LaPadula 의 방향이다.
    • C · 모든 접근을 금지하지 않는다.
    • D · 감사 요구는 모델의 규칙이 아니다.

    5BLP와 Biba, 방향 정리

    원본은 이 부분을 가장 혼동하기 쉽다고 하며 다음 구조로 정리합니다.

    모델Simple = 읽기Star(*) = 쓰기
    BLP(기밀성)No Read UpNo Write Down
    Biba(무결성)No Read DownNo Write Up

    원본의 요령은 보호 목표를 먼저 떠올리면 방향이 따라온다입니다.

    • 기밀성을 지키려면 → 높은 비밀을 못 읽고, 낮은 곳으로 못 흘린다
    • 무결성을 지키려면 → 오염된 것을 안 읽고, 신뢰 영역을 못 더럽힌다

    보충“Simple은 읽기, Star는 쓰기”가 두 모델에서 똑같다는 점이 첫 번째 고정점입니다. 그다음은 정보가 흐르는 방향으로 생각하면 됩니다. 읽기는 자료에서 사용자에게, 쓰기는 사용자에서 자료로 정보가 흐릅니다. 기밀성은 정보가 높은 곳에서 낮은 곳으로 흐르는 것이 문제이므로 위에서 읽어 오는 것과 아래로 써 내리는 것을 막습니다. 무결성은 정보가 낮은 신뢰에서 높은 신뢰로 흐르는 것이 문제이므로 아래에서 읽어 오는 것과 위로 써 올리는 것을 막습니다. 두 모델은 막는 흐름의 방향이 정반대일 뿐 같은 생각입니다.

    CISSP 관점모델 규칙을 묻는 상황에서는 ① 지문이 기밀성(유출)을 걱정하는지 무결성(오염)을 걱정하는지 먼저 가리고 ② 기밀성이면 BLP, 무결성이면 Biba(상용 거래면 Clark-Wilson) ③ 읽기를 묻는지 쓰기를 묻는지 확인한 뒤 ④ 위 표의 방향을 적용합니다. “BLP가 다루지 않는 것”을 물으면 무결성, 가용성, 은닉 채널입니다.

    이해 확인 · 자작 상황 문제 (실제 시험 문제 아님)

    한 시스템에서 Secret 등급 사용자가 Top Secret 문서에 의견을 덧붙여 저장하는 것은 허용되고, Confidential 문서에 메모를 남기는 것은 거부되었다. 이 시스템이 따르는 모델과 그 결과의 위험으로 옳은 것은?

    1. Biba — 위로 쓰기를 막으므로 무결성이 보장된다.
    2. BLP — 아래로 쓰기를 막아 기밀성은 지키지만, 낮은 등급 사용자가 높은 등급 문서를 오염시킬 수 있다.
    3. Clark-Wilson — 프로그램을 거쳐야 하므로 모든 위험이 사라진다.
    4. Brewer-Nash — 접근 이력에 따라 쓰기가 결정되었다.
    정답과 해설 보기

    정답 B. 위로 쓰기 허용 + 아래로 쓰기 거부는 BLP의 스타 속성입니다. BLP는 무결성을 다루지 않으므로 write up으로 높은 등급 자료가 오염될 수 있습니다.

    • A: Biba라면 위로 쓰기를 막아야 합니다. 지문은 반대입니다.
    • C: 등급에 따른 읽기·쓰기 방향 규칙은 Clark-Wilson의 특징이 아닙니다.
    • D: 접근 이력에 대한 언급이 없습니다.

    6Clark-Wilson — 상용 환경의 무결성

    왜 필요한가

    BLP와 Biba는 군사 등급 체계를 전제로 합니다. 하지만 기업의 회계 시스템에는 Top Secret 같은 등급이 없고, 걱정하는 것은 “장부가 엉터리로 바뀌지 않는가”입니다. Clark-Wilson은 상용 환경을 겨냥한 무결성 모델이며, 원본은 실제 기업 시스템 설계에 가장 가깝다고 설명합니다.

    구성 요소

    요소의미
    CDI Constrained Data Item무결성을 보호해야 할 데이터
    UDI Unconstrained Data Item보호 대상이 아닌 데이터(예: 아직 검증되지 않은 입력)
    TP Transformation ProcedureCDI를 바꿀 수 있는 인가된 프로그램
    IVP Integrity Verification ProcedureCDI의 무결성 상태를 검증하는 절차

    접근 3요소

    주체 Subject
    →
    프로그램 TP

    객체 CDI

    주체가 객체에 직접 접근하지 못하고 반드시 인가된 프로그램을 거칩니다. 원본은 이것을 BLP·Biba와의 결정적 차이로 꼽습니다. 두 가지 핵심 개념이 있습니다.

    • 잘 구성된 거래(Well-Formed Transaction) — 데이터를 임의로 바꿀 수 없고 정해진 방식으로만 바꾼다
    • 직무 분리 — 모델 자체에 들어 있다

    원본은 Clark-Wilson이 무결성의 세 목표를 모두 다룬다고 설명합니다. ① 인가되지 않은 사용자의 변경 방지 ② 인가된 사용자의 부적절한 변경 방지 ③ 내부·외부 일관성 유지. BLP와 Biba는 첫째만 다루므로, 이 점이 상용 환경에서 더 실용적인 이유라는 것입니다.

    원문 사례 — Clark-Wilson이 설명하는 기업 시스템. 경리 담당자가 데이터베이스에 직접 접속해 잔액을 고칠 수 있다면 무결성은 무너집니다. 실제 설계에서는 회계 애플리케이션(TP)으로만 거래를 입력하고, 애플리케이션이 차변·대변 일치를 강제하며, 승인자는 다른 계정이어야 합니다. 야간 배치로 도는 잔액 검증이 IVP에 해당합니다.

    보충둘째 목표, “인가된 사용자의 부적절한 변경”이 Clark-Wilson의 진짜 기여입니다. 경리 담당자는 장부를 고칠 권한이 있는 사람이므로 BLP·Biba식 “권한 없는 사람 차단”으로는 막을 수 없습니다. 권한 있는 사람이라도 정해진 거래 형식(TP)으로만, 다른 사람의 승인을 받아서만 바꿀 수 있게 만드는 것이 해법입니다. D1.2 보안 개념 (CIA 등)에서 “무결성 통제 목록에 직무 분리가 들어 있는 이유”를 다룬 것이 바로 이 지점입니다.

    연결설계 원칙으로서의 직무 분리는 D3.1 안전한 설계 원칙, 운영 절차로서의 직무 분리는 D7.4 기본 보안 운영 개념, 입력 검증과 업무 규칙 검증은 D8.5 안전한 코딩에서 다룹니다.

    원문 위치: D3.2.md §3 Clark-Wilson, §4 CDI / UDI·TP / IVP·Access Triple·Well-Formed Transaction, §5 둘째 표, §7 사례 3 · 기존 문제 주제(접근 3요소)

    7Brewer-Nash (Chinese Wall) — 이해충돌 방지

    다른 모델의 규칙이 고정되어 있는 것과 달리, 이 모델은 접근 이력에 따라 권한이 동적으로 바뀝니다.

    배경은 컨설팅 회사입니다. 경쟁 관계인 A사와 B사가 모두 고객이라면, 컨설턴트가 A사 자료를 본 순간 B사 자료는 볼 수 없어야 합니다.

    이해충돌 범주 Conflict of Interest Class
    ⊃
    회사 데이터셋 Company Dataset
    ⊃
    개별 객체

    처음에는 어느 데이터셋이든 접근할 수 있지만, 하나를 고르는 순간 같은 이해충돌 범주 안의 다른 데이터셋은 막힙니다. 원본의 표현으로 벽은 사용자가 움직이는 대로 세워집니다.

    원문 사례 — 컨설팅 회사. 같은 회사가 경쟁 관계인 두 통신사를 모두 고객으로 두었고, 컨설턴트가 A사 프로젝트 자료를 연 순간 시스템이 B사 자료 접근을 자동으로 차단했습니다.

    보충이 모델을 구현하려면 시스템이 “누가 무엇을 이미 봤는가”를 기억해야 합니다. 그래서 접근 기록이 단순한 감사 자료가 아니라 다음 접근을 결정하는 입력이 됩니다. 다른 범주(예: 통신사와 은행)의 자료는 서로 막지 않는다는 점도 기억해 둘 만합니다. 벽은 경쟁 관계 안에서만 세워집니다.

    원문 위치: D3.2.md §3 Brewer-Nash, §4 Chinese Wall / Brewer-Nash, §5 셋째 표, §7 사례 4 · 기존 문제 주제(동적 접근 통제)

    8권한이 생기고 옮겨지는 것을 다루는 모델

    BLP와 Biba는 “지금 이 접근이 허용되는가”를 다룹니다. 원본은 “권한이 어떻게 생기고 옮겨지는가”를 다루는 세 모델을 함께 소개합니다.

    모델다루는 것핵심
    Graham-Denning보호 권한의 기본 연산8가지: 객체 생성·삭제, 주체 생성·삭제, 읽기 권한 조회, 권한 부여(grant)·삭제(delete)·전달(transfer)
    Harrison-Ruzzo-Ullman (HRU)접근 매트릭스와 그 변경 규칙안전성 문제(Safety Problem)는 결정 불가능(undecidable)
    Take-Grant그래프로 표현한 권한 전파Take · Grant · Create · Remove 4규칙. 특정 조건에서 전파 가능성을 효율적으로 판정

    HRU의 결과를 풀면 이렇습니다. 임의의 시스템에서 “어떤 주체가 특정 권한을 얻게 될 수 있는가”를 모든 경우에 판정하는 일반적인 절차는 존재하지 않습니다. 원본은 이것이 완벽한 권한 분석이 이론적으로 불가능하다는 뜻이며, 실무에서 보수적으로 설계하고 계속 검토해야 하는 이론적 근거라고 설명합니다.

    보충“결정 불가능”은 “아무것도 검사할 수 없다”는 뜻이 아닙니다. 일반 모형에서 모든 경우에 답하는 방법이 없다는 뜻이고, 연산과 범위를 제한한 실제 정책에서는 검사할 수 있는 것이 많습니다(Take-Grant가 그런 제한된 경우의 예). 또 권한 전파 모델이 보는 것은 “지금 누가 접근하는가”가 아니라 “권한을 주고받을 수 있는 연결 때문에 다음에 누가 접근하게 될 수 있는가”입니다. 두 계정이 같은 파일을 읽을 수 있어도 한쪽만 다른 사람에게 권한을 넘길 수 있다면 위험이 다릅니다.

    연결권한 부여와 회수의 실제 관리는 D5.5 프로비저닝 생애주기, 권한 누적은 D1.8 인적 보안에서 다룹니다.

    원문 위치: D3.2.md §3 Graham-Denning, Harrison-Ruzzo-Ullman, Take-Grant, §4 Safety Problem

    9정보 흐름, 비간섭, 은닉 채널

    정보 흐름 모델(Information Flow Model)은 정보가 한 객체에서 다른 객체로 흐르는 것을 통제합니다. 원본은 BLP와 Biba를 정보 흐름 모델의 특수한 형태로 볼 수 있다고 하고, 은닉 채널도 정보 흐름의 관점에서 분석된다고 설명합니다.

    비간섭 모델(Non-interference Model)의 요구는 높은 등급 주체의 행위가 낮은 등급 주체에게 관찰되지 않아야 한다입니다. 왜 필요할까요. BLP를 완벽히 지켜도, 고등급 사용자의 행위가 시스템 성능, 응답 시간, 자원 상태에 영향을 주면 저등급 사용자가 그것을 보고 무언가를 추론할 수 있습니다. 이렇게 정상 통신 경로가 아닌 수단으로 정보가 흐르는 경로가 은닉 채널(Covert Channel)이며, 저장 채널과 타이밍 채널이 있습니다.

    원문 사례 — 은닉 채널. 고등급 프로세스가 특정 파일을 잠갔다 풀었다를 반복해, 저등급 프로세스가 잠금 상태를 관찰하며 1비트씩 정보를 받았습니다. BLP 규칙은 모두 지켜졌지만 정보는 흘렀습니다. 원본은 실무 대응으로 자원 분리와 타이밍 잡음 추가를 듭니다.

    보충은닉 채널과 부채널(Side Channel)은 구분해 두면 좋습니다. 은닉 채널은 안쪽의 주체가 일부러 신호를 보내는 것(위 사례의 파일 잠금)이고, 부채널은 처리 과정에서 의도치 않게 새는 물리적·시간적 정보(전력 소비, 처리 시간)를 바깥에서 관찰해 비밀을 추론하는 것입니다(NIST 용어집의 Side Channel·Covert Timing Channel 정의에 따른 구분). 비간섭은 두 경우 모두에 대해 “높은 쪽의 행동이 낮은 쪽의 관찰을 바꾸는가”를 묻습니다.

    연결은닉 채널이 시스템 취약점으로 다뤄지는 곳은 D3.5 아키텍처별 취약점, 부채널 공격은 D3.7 암호 분석 공격의 암호 분석 공격에서 다룹니다. D2.1 자산 식별과 분류의 추론 문제(공개 정보로 비공개 정보를 알아냄)와도 같은 계열입니다.

    원문 위치: D3.2.md §3 정보 흐름 모델과 비간섭, §4 Non-interference·Covert Channel, §7 사례 5 · 외부 확인: NIST 용어집 Side Channel, Covert Timing Channel

    복습

    보안 모델 문제에서 읽기·쓰기 금지 방향이 헷갈리면 어디서 시작하나요?

    설명 확인하기

    보호 속성과 데이터가 흐르는 방향을 그립니다. 기밀성은 높은 등급의 정보가 낮은 곳으로 유출되는 것을, 무결성은 낮은 신뢰의 정보가 높은 신뢰의 기록을 오염시키는 것을 막으려 합니다.

    13핵심 요약

    1. 보안 모델 = 정책을 검증 가능한 형식 규칙으로 표현한 것. 상태 기계 모델: 안전한 상태 → 안전한 상태(기본 보안 정리).
    2. BLP = 기밀성 / Biba = 무결성 / Clark-Wilson = 상용 무결성 / Brewer-Nash = 이해충돌.
    3. Simple = 읽기, Star(*) = 쓰기.
    4. BLP: No Read Up, No Write Down. Strong Star = 같은 등급에서만. 무결성·가용성·은닉 채널은 다루지 않는다.
    5. Biba: No Read Down, No Write Up. Invocation: 낮은 무결성 주체가 높은 쪽 서비스를 호출하지 못한다.
    6. 기밀성은 위를 못 읽고 아래로 못 흘린다. 무결성은 아래를 안 읽고 위를 못 더럽힌다.
    7. 격자 기반 접근 통제 = MAC의 수학적 기반. 등급 + 구획 → 격자.
    8. Clark-Wilson: 주체 → TP → CDI. 직접 접근 불가. CDI/UDI/TP/IVP, 잘 구성된 거래, 직무 분리 내장, 무결성 3목표 모두.
    9. Brewer-Nash = 접근 이력 기반 동적 통제.
    10. Graham-Denning = 8가지 기본 보호 연산. HRU = 안전성 문제 결정 불가능. Take-Grant = Take·Grant·Create·Remove.
    11. 비간섭 = 고등급 행위가 저등급에게 관찰되지 않아야. 은닉 채널(저장·타이밍) 대응.
    원문 위치: D3.2.md §8 CISSP 시험 관점, §9 핵심 암기 요약(16항목). 원본 §6의 연도(BLP 1973, Biba 1977, Clark-Wilson 1987, Brewer-Nash 1989)와 TCSEC → Common Criteria(ISO/IEC 15408) 대체 관계는 여기에 적어 둡니다. 원본은 Common Criteria를 D3.4에서 상세히 다룬다고 하지만, 원본 노트에서 Common Criteria가 실제로 자세히 나오는 곳은 D3.3입니다.

    14주요 용어 (Glossary)

    영어 원어와 한국어 뜻 · English–Korean

    Security Model · 보안 모델

    보안 정책을 수학적·형식적 규칙으로 표현한 것. 검증 가능성을 제공한다.

    State Machine Model · 상태 기계 모델

    모든 상태 전이가 안전한 상태 사이에서 이루어지면 시스템이 안전하다고 보는 모델.

    Lattice-Based Access Control · 격자 기반 접근통제

    주체와 객체에 등급을 부여하고 등급 간 순서 관계로 접근을 결정하는 구조. MAC 의 수학적 기반이다.

    Simple Security Property · 단순 보안 속성

    BLP 의 읽기 규칙. No Read Up — 자기보다 높은 등급을 읽을 수 없다.

    *-Property / Star Property · 스타 속성

    BLP 의 쓰기 규칙. No Write Down — 자기보다 낮은 등급에 쓸 수 없다.

    Simple Integrity Property · 단순 무결성 속성

    Biba 의 읽기 규칙. No Read Down — 자기보다 낮은 무결성 수준을 읽을 수 없다.

    *-Integrity Property · 스타 무결성 속성

    Biba 의 쓰기 규칙. No Write Up — 자기보다 높은 무결성 수준에 쓸 수 없다.

    CDI / UDI — Constrained Data Item / Unconstrained Data Item · 제약 데이터 항목 / 비제약 데이터 항목

    Clark-Wilson 의 제약 데이터 항목(무결성 보호 대상)과 비제약 데이터 항목.

    TP / IVP — Transformation Procedure / Integrity Verification Procedure · 변환 절차 / 무결성 검증 절차

    변환 절차(CDI 를 변경할 수 있는 인가된 프로그램)와 무결성 검증 절차.

    Access Triple · 접근 3요소

    Clark-Wilson 의 주체-프로그램-객체 구조. 주체가 객체에 직접 접근하지 못하게 한다.

    Well-Formed Transaction · 잘 구성된 거래

    데이터를 임의로 변경할 수 없고 정해진 방식으로만 변경하도록 하는 거래 구조.

    Chinese Wall / Brewer-Nash · 이해충돌 방지 접근 통제 모델

    접근 이력에 따라 접근 권한이 동적으로 변하는 이해충돌 방지 모델.

    Safety Problem · 안전성 문제

    임의 시스템에서 권한 획득 가능성을 일반적으로 판정하는 문제. HRU 가 결정 불가능함을 증명했다.

    Non-interference · 비간섭

    높은 등급 주체의 행위가 낮은 등급 주체에게 관찰되지 않아야 한다는 원칙. 은닉 채널 대응의 이론적 기반이다.

    Covert Channel · 은닉 채널

    정상적인 통신 경로가 아닌 수단으로 정보가 흐르는 경로. 저장 채널과 타이밍 채널이 있다.

    • Bell-LaPadula (1973) — 기밀성 중심 최초의 형식 모델

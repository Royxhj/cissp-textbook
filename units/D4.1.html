    연습문제 6개 바로가기

    표시 없는 본문은 원본 정리 파일의 내용 · 보충은 원본에 없어 더한 설명 · 가상 예시는 지어낸 상황 · 연결은 다른 단원과의 관계 · 확인 필요는 그대로 확정하지 않은 부분

    네트워크 보안의 많은 판단은 “이 통제가 어느 계층에서 무엇을 볼 수 있는가”와 “신뢰 경계가 어디에 있는가”로 귀결됩니다. 이 단원은 공식 개요 4.1의 세부 항목(OSI·TCP/IP, IPv4/6, 안전한 프로토콜, 다계층·융합 프로토콜, 전송 아키텍처, 성능 지표, 트래픽 흐름, 세그멘테이션, 엣지, 무선, 셀룰러, CDN, SDN·VPC, 모니터링과 관리. 원본은 이를 18개로 셉니다)를 다룹니다. 원본이 제시하는 네 가지 질문(어느 계층인가, 신뢰 경계가 어디인가, 가시성이 있는가, 가용성은 어떻게 지키는가)을 각 기술에 적용해 보는 것이 이 단원을 읽는 방법입니다.

    1핵심 개념

    네트워크 보안 설계의 출발점은 계층 구조의 이해다. 각 계층마다 위협과 통제가 다르므로, 문제가 어느 계층에 있는지 식별하는 것이 첫 단계다.

    핵심 원칙은 D3.1 과 같다. 심층 방어, 최소권한, 기본 거부, 제로 트러스트를 네트워크에 적용한다.

    가장 중요한 변화: 경계(perimeter)만으로는 부족하다. 클라우드와 원격 근무로 경계가 흐려졌고, 침해 후 동서 트래픽을 통한 횡적 이동이 주요 위협이 되었다.

    이 주제를 관통하는 네 가지 질문이 있다. 세부 항목이 18개로 많지만, 결국 아래 네 가지를 각 기술에 적용하는 것이다.

    질문 무엇을 따지는가
    어느 계층인가 통제가 무엇을 볼 수 있고 무엇을 못 보는가
    신뢰 경계가 어디인가 세그멘테이션, 융합 프로토콜, 제3자 위탁
    가시성이 있는가 흐름 데이터, 로그, 암호화된 구간의 검사
    가용성은 어떻게 지키는가 이중화, 용량, QoS, DDoS 대응

    예를 들어 CDN 은 가용성을 얻고 신뢰 경계를 외부로 넓히는 선택이며, 마이크로세그멘테이션은 신뢰 경계를 워크로드 단위로 좁히는 선택이다. 기술을 하나씩 외우기보다 이 틀에 넣어 보는 편이 판단에 더 잘 작동한다.

    2계층 공격이 특히 중요하다. 암호화된 통신도 ARP 스푸핑으로 경로가 바뀌면 중간자 공격의 발판이 된다.

    캡슐화 — 계층이 실제로 어떻게 쌓이는가

    계층 모델을 외우는 이유는 통제가 어느 계층에서 동작하는지 알아야 하기 때문이다. 데이터가 내려갈 때 각 계층은 자기 헤더를 덧붙인다.

    응용 데이터
→ [TCP 헤더 | 데이터]            세그먼트 (4계층)
→ [IP 헤더 | TCP 헤더 | 데이터]   패킷   (3계층)
→ [프레임 헤더 | IP 패킷 | FCS]   프레임  (2계층)
→ 비트 스트림                     (1계층)

    받는 쪽은 역순으로 헤더를 벗긴다(역캡슐화). 여기서 보안 설계의 핵심 결론이 나온다.

    • 통제는 자기가 볼 수 있는 계층까지만 판단한다. 3계층 라우터 ACL 은 IP 와 포트를 보지만 HTTP 본문은 못 본다. 그래서 7계층 공격을 막으려면 WAF 가 필요하다
    • 암호화 지점이 검사 지점을 결정한다. TLS 로 암호화하면 중간의 IDS 는 페이로드를 못 본다. 그래서 복호화 프록시를 두거나, 엔드포인트에서 검사(EDR)해야 한다
    • 낮은 계층이 뚫리면 상위 계층의 가정이 무너진다. ARP(2계층)가 스푸핑되면 3계층 라우팅이 공격자를 거치고, 7계층 애플리케이션은 아무 이상도 감지하지 못한다

    판단 기준 "어느 계층에서 동작하는 통제인가" 방화벽은 3·4계층(차세대는 7계층까지), 스위치는 2계층, 라우터는 3계층, 프록시와 WAF 는 7계층이다.

    3TCP/IP 모델과의 대응

    TCP/IP (4계층) OSI 대응
    응용 Application 5·6·7
    전송 Transport 4
    인터넷 Internet 3
    네트워크 접근 Link 1·2

    실제 구현은 TCP/IP 이고 OSI 는 참조 모델이다. 판단의 언어로는 OSI 계층이 자주 쓰인다.

    두 모델이 왜 둘 다 필요한가. OSI 는 역할을 분석하는 언어다. "이 통제는 어느 역할을 하는가" 를 7단계로 나눠 따질 수 있다. TCP/IP 는 실제로 돌아가는 구현이고, 세션·표현 계층을 따로 두지 않는다. 그래서 TLS 처럼 OSI 로는 한 계층에 깔끔히 들어가지 않는 것이 존재한다. TLS 는 전송 계층(4) 위, 응용 계층(7) 아래에서 동작해 흔히 "5~6계층" 또는 "전송 계층 보안" 으로 설명된다.

    실무 요소 TCP/IP OSI 로 말하면
    HTTP, DNS, SMTP 응용 7
    TLS 응용 하부 5~6 (경계 사례)
    TCP, UDP 전송 4
    IPSec 인터넷 3
    IP, ICMP, 라우팅 인터넷 3
    이더넷, ARP, Wi-Fi 링크 1~2

    판단 기준 IPSec 은 3계층, TLS 는 4계층 위 이 차이가 실제 결과를 만든다. IPSec 은 애플리케이션을 수정하지 않고 모든 상위 트래픽을 보호하고, TLS 는 애플리케이션이 직접 호출해야 하지만 세션 단위로 세밀하게 제어된다.

    주소 전달 방식 네 가지 — 공식 세부 항목에 명시되어 있다.

    방식 받는 대상 (쓰임) 보안 관점
    유니캐스트 Unicast 1 대 1, 특정 호스트 하나 (일반 통신 대부분) 기본 형태
    브로드캐스트 Broadcast 세그먼트 내 전체 (ARP, DHCP 탐색) 증폭 공격의 재료. IPv6 에는 없다
    멀티캐스트 Multicast 가입한 그룹 (스트리밍, 라우팅 프로토콜) 그룹 가입 통제 필요
    애니캐스트 Anycast 같은 주소를 가진 노드 중 가장 가까운 하나 (DNS 루트, CDN) DDoS 분산에 유리

    꼭 짚어 둘 세 가지

    • 브로드캐스트는 증폭 공격의 재료다. 스머프(Smurf) 공격은 출발지를 피해자로 위조한 ICMP 를 브로드캐스트 주소로 보내, 세그먼트의 모든 호스트가 피해자에게 응답하게 만든다. 그래서 라우터에서 방향성 브로드캐스트를 차단한다
    • 애니캐스트는 가용성 설계 수단이다. 같은 IP 를 여러 지역에 두면 공격 트래픽이 가장 가까운 노드로 흩어진다. DNS 루트 서버와 CDN 이 이 방식으로 DDoS 를 견딘다
    • IPv6 가 브로드캐스트를 없앤 이유가 바로 이 비효율과 증폭 위험이다. 대신 멀티캐스트와 애니캐스트로 같은 기능을 수행한다

    보안 함의

    • IPv6 는 주소 공간이 방대해 스캔이 어렵다 — 공격자에게 불리하지만 자산 발견도 어려워진다
    • NAT 가 제공하던 우발적 은폐가 사라진다. NAT 는 보안 통제가 아니었지만 실질적으로 내부 노출을 줄였다. IPv6 에서는 방화벽으로 명시적 통제가 필요하다
    • 듀얼 스택 환경의 위험 — IPv4 만 방화벽으로 통제하고 IPv6 는 무방비로 열려 있는 경우가 흔하다. 터널링(6to4, Teredo)으로 통제를 우회할 수도 있다
    • 라우터 광고(RA) 스푸핑 같은 IPv6 고유 공격

    판단 기준 사용하지 않는 IPv6 는 비활성화하거나, 사용한다면 IPv4 와 동등한 통제를 적용한다.

    IPSec — 네트워크 계층에서 동작해 상위 애플리케이션 변경 없이 보호한다.

    구성요소 역할
    AH (Authentication Header) 무결성·인증. 암호화 없음
    ESP (Encapsulating Security Payload) 암호화 + 무결성·인증
    IKE 키 교환과 SA 협상
    모드 보호 범위
    전송 모드 (Transport) 페이로드만 암호화. 종단 간
    터널 모드 (Tunnel) IP 헤더 포함 전체 암호화. VPN 에 사용

    AH 는 암호화하지 않는다. 기밀성이 필요하면 ESP 를 쓴다. AH와 ESP는 “암호화가 필요한가”로 구분한다.

    SSH — 원격 셸의 표준이다. 단순한 "암호화된 Telnet" 이 아니라 인증·터널링·파일 전송을 함께 제공한다.

    • 호스트 키로 서버를 인증한다. 첫 접속 때 지문을 확인하지 않고 그냥 승인하면 중간자 공격을 받아들이는 것이다
    • 공개키 인증이 비밀번호보다 안전하다. 비밀번호 인증은 무차별 대입에 노출된다
    • 포트 포워딩이 양날의 칼이다. SSH 터널로 방화벽을 우회해 내부 서비스를 외부로 노출할 수 있다. 필요 없으면 AllowTcpForwarding no 로 끈다
    • SSHv1 은 설계 결함으로 사용하지 않는다. v2 만 쓴다

    TLS — 전송 계층 위에서 동작하며 기밀성·무결성·서버 인증을 제공한다. 상세는 D3.6 참조.

    • TLS 1.2 이상을 쓰고 SSL 2.0/3.0 과 TLS 1.0/1.1 은 비활성화한다
    • TLS 1.3 은 핸드셰이크를 1-RTT 로 줄이고 취약한 암호군(RC4, CBC 모드 일부, 정적 RSA 키 교환)을 규격에서 제거했다
    • 인증서 검증을 생략하면 암호화의 의미가 없다. 암호화는 되지만 누구와 통신하는지 보장되지 않는다

    판단 기준 프로토콜 다운그레이드 공격. 서버가 구버전을 계속 지원하면 공격자가 협상을 끌어내려 약한 암호군을 쓰게 만든다(POODLE, FREAK 류). 대응은 구버전 지원 자체를 제거하는 것이고, 이것이 "안전한 기본값" 원칙의 전형적 예다.

    SNMPv3 — 네트워크 관리 프로토콜. v1/v2c 는 커뮤니티 스트링을 평문으로 보내며 기본값이 public/private 인 경우가 많다. v3 가 인증과 암호화를 추가했다. 관리 프로토콜은 장비 전체를 장악할 수 있는 통로이므로 여기서 타협하면 안 된다.

    6다계층 프로토콜의 함의

    TCP/IP 는 캡슐화를 통해 계층을 쌓는다. 이 유연성이 보안 문제를 만든다.

    위험

    • 터널링과 은닉 채널 — 허용된 프로토콜 안에 다른 프로토콜을 숨긴다. DNS 터널링, ICMP 터널링, HTTP 를 통한 임의 통신이 대표적이다
    • 필터 우회 — 방화벽이 상위 계층 내용을 보지 못하면 통과한다
    • 중첩 캡슐화로 검사 회피
    • 프로토콜 변환 지점의 취약점

    터널링이 왜 막기 어려운가

    방화벽은 보통 포트와 프로토콜로 판단한다. 그런데 터널링은 허용된 포트를 그대로 쓴다.

    터널 겉보기 실제
    DNS 터널링 정상 DNS 질의(UDP/53) 질의 이름에 데이터를 인코딩해 주고받는다
    ICMP 터널링 핑(ping) ICMP 페이로드에 데이터를 넣는다
    HTTP(S) 터널링 웹 트래픽(443) 임의 프로토콜을 HTTP 로 감싼다
    SSH 포트 포워딩 정상 SSH 내부 서비스를 외부로 중계

    DNS 가 특히 악용되는 이유는 세 가지다. 거의 모든 네트워크가 DNS 를 허용하고, 재귀 질의 구조상 내부에서 외부로 자동 전달되며, 많은 조직이 DNS 로그를 보지 않는다.

    대응

    • 심층 패킷 검사(DPI) — 포트가 아니라 실제 내용으로 프로토콜을 판정한다
    • 허용 목록 기반 아웃바운드 통제 — "막을 것을 고르는" 대신 "허용할 것만 고른다"
    • DNS 질의 모니터링 — 비정상적으로 긴 이름, 높은 질의 빈도, 희귀 도메인. 내부 리졸버 경유를 강제해 단말이 외부 DNS 를 직접 쓰지 못하게 한다
    • 프록시 경유 강제 — 검사 지점을 하나로 모은다
    • 기준선 대비 이상 탐지 — 평소 패턴을 알아야 벗어남이 보인다

    판단 기준 캡슐화는 설계상의 기능이지 결함이 아니다. 그래서 "프로토콜을 고쳐 막는다" 는 답이 아니고, 통제 지점을 상위 계층으로 올리고(DPI·프록시) 아웃바운드를 기본 거부하는 것이 답이다.

    암호화 트래픽을 검사하거나 그대로 전달하는 경계

    가상 예시외부 게이트웨이가 TLS를 종료하고 뒤쪽 애플리케이션으로 요청을 전달합니다. 설계서는 ‘사용자는 TLS로 접속한다’만 기록했습니다.

    판단 순서

    1. 사용자부터 게이트웨이와 게이트웨이부터 업무 서비스의 구간을 따로 표시합니다.
    2. 어느 지점에서 평문이 생기는지, 누가 그 시스템과 로그에 접근하는지, 다음 구간의 상대는 어떻게 인증하는지 확인합니다.
    3. 파일 전달·점검을 위해 검사하는 위치가 추가되면 그 위치도 신뢰 경계가 됩니다.

    조건을 바꿔 보기. TLS를 중간에서 종료하지 않고 전달한다면 중간 장비의 내용 기반 검사는 제한될 수 있습니다. 어떤 속성을 어디서 확인할지 전체 연결을 기준으로 고릅니다.

    7융합 프로토콜 (Converged Protocols)

    전용망에서 쓰이던 프로토콜을 IP 네트워크 위에서 운반하는 것이다.

    프로토콜 설명 보안 고려
    iSCSI SCSI 스토리지를 IP 로 평문 전송 가능. 인증·암호화·전용망 분리
    VoIP 음성을 IP 로 도청, 스푸핑. SRTP·TLS, VLAN 분리
    FCoE 파이버채널을 이더넷으로 손실 없는 네트워크 요구
    InfiniBand over Ethernet 고성능 상호연결 HPC 환경 격리
    Compute Express Link (CXL) CPU-장치 간 고속 연결 물리 신뢰 경계 확장

    핵심 위험: 전용망을 전제로 설계된 프로토콜이 공용망에 올라온다. 원래 신뢰된 환경을 가정했기 때문에 인증과 암호화가 약하거나 없다. iSCSI 와 산업 프로토콜이 대표적이다(D3.5 아키텍처별 취약점 참조).

    왜 이것이 설계 문제인가

    융합의 동기는 비용과 단순화다. 회선 하나로 음성·스토리지·데이터를 모두 운반하면 투자와 운영이 줄어든다. 그러나 신뢰 경계도 함께 합쳐진다.

    • 파이버채널 전용망에서 스토리지 트래픽은 물리적으로 분리된 신뢰 영역에 있었다. iSCSI 로 바꾸면 업무망의 침해자가 스토리지 트래픽에 닿을 수 있다
    • 스토리지 프로토콜은 블록 단위 접근이다. 파일 권한을 우회해 디스크 내용을 그대로 읽는다는 뜻이고, 그래서 노출의 결과가 더 심각하다
    • CXL 같은 메모리·장치 연결 프로토콜은 신뢰 경계를 CPU 바로 옆까지 확장한다. 물리적으로 신뢰된 범위 안에서만 써야 한다

    대응

    수단 적용
    분리 전용 VLAN, 가능하면 물리 분리. 가장 효과적
    인증 iSCSI 의 CHAP, 상호 인증 활성화
    암호화 IPSec 또는 프로토콜 자체 암호화
    접근 통제 스토리지의 LUN 마스킹·조닝

    판단 기준 융합 프로토콜 문제에서 가장 먼저 떠올릴 답은 "분리(세그멘테이션)" 다. 프로토콜 자체를 고칠 수 없으니 환경을 원래의 가정에 맞춰주는 것이 올바른 접근이다.

    8전송 아키텍처

    세 가지 평면(Plane).

    평면 역할
    데이터 평면 (Data / Forwarding) 실제 트래픽 전달
    제어 평면 (Control) 경로 결정, 라우팅 프로토콜
    관리 평면 (Management) 장비 설정·모니터링

    관리 평면은 반드시 분리해야 한다. 데이터 평면과 섞이면 업무 트래픽에서 장비 관리 접근이 가능해진다. 대역 외(out-of-band) 관리가 원칙이다.

    스위칭 방식

    방식 동작
    저장 후 전달 (Store-and-forward) 프레임 전체 수신 후 오류 검사 하고 전달
    컷스루 (Cut-through) 목적지 주소만 읽고 즉시 전달. 빠르지만 오류 프레임도 전달
    조각 없음 (Fragment-free) 앞부분만 검사하는 절충

    토폴로지 — 공식 세부 항목에 명시되어 있다. 보안·가용성 관점에서 보는 것이 핵심이다.

    토폴로지 가용성 보안 관점
    버스 Bus (공유 매체) 매체 하나가 끊기면 전체 중단 모든 트래픽이 모두에게 보인다(도청 쉬움)
    링 Ring (고리) 한 지점 단절에 취약(이중 링으로 보완) 통과 노드가 트래픽을 본다
    스타 Star (중앙 집중) 중앙 장비가 단일 장애점 중앙에서 통제·모니터링이 쉽다
    메시 Mesh (다중 경로) 가장 높음 — 경로 하나 실패에도 생존 경로가 많아 통제점 관리가 복잡

    현대는 대부분 스타(스위치 중심) 이며 데이터센터는 리프-스파인(부분 메시) 구조다. 허브 시대의 버스형이 스위치 기반 스타로 바뀐 것은 성능 때문이지만, 보안상으로도 큰 개선이었다. 허브는 모든 포트로 프레임을 복제해 도청이 쉬웠고, 스위치는 목적지 포트로만 보낸다.

    판단 기준 스위치가 도청을 "어렵게" 만들지만 막지는 못한다. MAC 플러딩으로 스위치의 MAC 테이블을 넘치게 하면 스위치가 허브처럼 모든 포트로 브로드캐스트하는 상태(fail-open)가 된다. 대응은 포트 보안(포트별 MAC 수 제한) 이다.

    가용성과 통제의 교환 관계가 토폴로지 선택에 들어 있다. 메시는 가용성이 높지만 트래픽이 지나는 경로가 많아 모든 트래픽을 한 곳에서 검사하기 어렵다. 스타는 통제가 쉽지만 중앙이 단일 장애점이다. 그래서 실무는 중앙 통제 + 중앙 이중화로 둘을 모두 얻으려 한다.

    9성능 지표

    지표 의미
    대역폭 Bandwidth 이론적 최대 전송 용량
    처리량 Throughput 실제 전송량
    지연 Latency 전달에 걸리는 시간
    지터 Jitter 지연의 변동 폭
    SNR 신호 대 잡음비

    1Gbps 회선(대역폭)에서 실제로 400Mbps 밖에 못 쓴다면(처리량), 차이는 프로토콜 오버헤드, 재전송, 혼잡, 장비 처리 한계에서 온다. 대역폭을 늘려도 처리량이 안 늘어나는 경우가 흔하고, 그때 병목은 회선이 아니다.

    VoIP 와 실시간 통신에서는 지터가 대역폭보다 중요하다. 대역폭이 충분해도 지터가 크면 통화 품질이 무너진다. 음성은 일정한 간격으로 도착해야 재생되기 때문이다. 수신 측은 지터 버퍼로 흔들림을 흡수하지만, 버퍼를 키우면 지연이 늘어 대화가 어색해진다. 지터와 지연은 맞바꿔야 하는 관계다.

    SNR(신호 대 잡음비) 은 주로 무선과 물리 매체의 품질 지표다. 낮으면 오류율이 올라가 재전송이 늘고, 결과적으로 처리량이 떨어진다. 전파 방해(재밍)는 SNR 을 떨어뜨려 가용성을 공격하는 것이다.

    가용성 공격은 이 지표를 겨냥한다.

    공격 겨냥하는 지표
    볼류메트릭 DDoS 대역폭 포화
    자원 소진(SYN 플러드 등) 처리량 — 회선은 한가한데 장비가 죽는다
    재밍 SNR

    이 구분이 대응을 결정한다. 대역폭 포화는 회선 앞단(ISP·CDN·스크러빙 센터)에서만 막을 수 있고, 내 방화벽을 키워도 소용없다. 반면 자원 소진은 장비 설정(SYN 쿠키, 연결 제한)으로 완화된다.

    보충회선의 대역폭은 옮길 수 있는 용량을, 처리량은 관측 구간에 실제로 전달된 양을 나타냅니다. 사용자가 느린 원인을 찾을 때는 재전송·지연·장비 한계와 함께 측정해 어느 지점이 병목인지 확인합니다.

    음성 지연을 회선 용량 문제로 단정하면 놓치는 것

    보충평균 처리량이 충분해도 패킷이 고르지 않게 도착하면 음성이 끊길 수 있습니다. 대역폭과 실제 처리량, 지연과 지연 변동을 함께 측정하면 병목의 종류가 달라집니다. 장비를 바꾸기 전에 혼잡 시간과 재전송, 경로별 영향을 확인합니다.

    10트래픽 흐름 — 남북과 동서

    구분 방향 특징
    남북(North-South) 외부 ↔ 데이터센터 전통적 경계 방화벽이 통제
    동서(East-West) 내부 서버 ↔ 서버 전통적으로 통제가 약함

    현대 데이터센터 트래픽의 대부분이 동서 트래픽이다. 가상화와 마이크로서비스 때문이다.

    침해 후 횡적 이동이 동서 트래픽을 타고 일어난다. 경계만 지키면 한 번 들어온 공격자가 자유롭게 움직인다. 이것이 마이크로세그멘테이션과 제로 트러스트가 필요한 이유다(D3.1 안전한 설계 원칙 참조).

    왜 동서 트래픽이 통제의 사각지대가 되었는가

    세 가지가 겹쳤다.

    • 설계상 안 지나간다. 같은 서브넷 안의 서버끼리는 라우터를 거치지 않으므로 경계 방화벽을 통과하지 않는다. 방화벽이 아무리 강해도 볼 수 없는 트래픽이다
    • 양이 압도적이다. 가상화·마이크로서비스로 하나의 사용자 요청이 내부에서 수십 번의 서버 간 호출로 쪼개진다. 전부 검사하려면 비용이 급증한다
    • "내부는 신뢰" 라는 암묵적 가정 — 경계 모델의 전제가 그대로 남아 있었다

    단계 사용하는 흐름
    초기 침투 남북 (피싱, 취약 웹 서비스)
    정찰·횡적 이동·권한 상승 동서
    데이터 수집 동서

    11세그멘테이션 — 세 가지 수준

    물리적 세그멘테이션 (Physical)

    방식 설명
    대역 내 (in-band) 업무망과 같은 경로로 관리
    대역 외 (out-of-band) 별도 물리 경로로 관리. 권장
    에어갭 (air-gapped) 물리적으로 완전 분리

    대역 외 관리가 왜 원칙인가

    관리 경로가 업무망과 같으면 두 가지 문제가 동시에 생긴다.

    • 침해 확산 — 업무망의 침해자가 네트워크 장비 관리 화면에 닿는다. 장비를 잡으면 네트워크 전체의 트래픽을 보고 바꿀 수 있다
    • 장애 시 접근 불가 — 네트워크가 죽으면 그 네트워크를 통해 장비에 접속할 수 없다. 복구해야 할 때 손이 닿지 않는다

    두 번째 이유는 보안보다 가용성 문제지만, 실무에서 대역 외 관리를 도입하는 직접적 동기가 되는 쪽이다.

    에어갭도 절대적이지 않다. USB 매체, 공급망, 전자파 부채널로 데이터가 넘어갈 수 있다. 다만 공격 난이도를 극적으로 높인다.

    에어갭을 넘는 경로 설명
    이동식 매체 USB 가 가장 흔하다. 스턱스넷의 전파 경로였다
    공급망 장비·소프트웨어가 이미 감염된 상태로 들어온다
    내부자 사람이 직접 들고 나간다
    부채널 전자파·소리·열·광학. 속도가 매우 느려 대량 유출에는 비현실적

    판단 기준 에어갭 환경에서 가장 현실적인 위협은 부채널이 아니라 이동식 매체와 내부자다. 그래서 에어갭 구간의 통제는 매체 통제와 인적 통제가 핵심이고, 기술적 격리만으로는 완성되지 않는다.

    논리적 세그멘테이션 (Logical)

    기술 설명
    VLAN 2계층 논리 분리. VLAN 간 통신은 라우팅 필요
    VPN 공용망 위 암호화 터널
    VRF 라우팅 테이블 분리
    가상 도메인 장비 내 논리 분할

    VLAN 은 보안 경계가 아니라 브로드캐스트 도메인 분리가 1차 목적이다. 왜 경계로 믿을 수 없는지는 VLAN 호핑의 두 가지 방식을 보면 분명해진다.

    방식 원리 대응
    스위치 스푸핑 Switch spoofing 공격자 PC 가 스위치인 척 트렁크 협상(DTP) 을 해 모든 VLAN 트래픽을 받는다 트렁크 자동 협상 비활성화, 접근 포트는 access 로 고정
    이중 태깅 Double tagging 프레임에 VLAN 태그를 두 개 붙인다. 첫 스위치가 바깥 태그(네이티브 VLAN)를 떼면 안쪽 태그가 살아 다른 VLAN 으로 넘어간다 네이티브 VLAN 을 사용하지 않는 번호로 변경, 네이티브 VLAN 태깅 강제

    이중 태깅이 네이티브 VLAN 변경을 요구하는 이유가 여기 있다. 네이티브 VLAN 은 태그 없이 전달되는 VLAN 이라, 기본값(VLAN 1)을 그대로 두면 공격자가 바깥 태그를 VLAN 1 로 맞추기만 하면 된다.

    VLAN 보안 기본 조치

    • 네이티브 VLAN 을 쓰지 않는 번호로 바꾸고, 사용자 포트에 할당하지 않는다
    • 트렁크 협상(DTP) 비활성화, 트렁크 포트에는 필요한 VLAN 만 허용
    • 미사용 포트는 비활성화하고 쓰지 않는 VLAN 에 격리
    • VLAN 1 을 업무에 쓰지 않는다

    판단 기준 "VLAN 으로 분리했는데 안전한가" 라는 물음의 답은 "브로드캐스트 도메인은 분리되지만 보안 경계로는 부족하다" 다. 민감 구간은 라우팅 경계에 방화벽을 두거나 물리 분리로 올린다.

    마이크로세그멘테이션 (Micro-segmentation)

    워크로드 단위로 통신을 제한한다. 전통적 세그멘테이션이 서브넷 단위라면, 마이크로세그멘테이션은 개별 서버·컨테이너 단위다.

    • 분산 방화벽 — 각 워크로드에 정책 적용
    • 네트워크 오버레이와 캡슐화(VXLAN 등)
    • 신원·태그 기반 정책 — IP 가 아니라 워크로드 속성으로 판단
    • 제로 트러스트 구현의 핵심 수단

    동서 트래픽 통제의 답이며, 침해 시 영향 범위를 극적으로 줄인다.

    전통적 세그멘테이션과의 결정적 차이는 정책의 기준이다.

    구분 전통적 마이크로세그멘테이션
    정책 기준 IP 주소와 서브넷 워크로드의 신원·태그·레이블
    적용 지점 경계 방화벽, VLAN 간 라우터 각 워크로드에 붙은 분산 방화벽
    동적 환경 IP 가 바뀌면 정책이 깨진다 IP 가 바뀌어도 태그가 따라간다
    기본 자세 같은 세그먼트 안은 허용 기본 거부, 필요한 쌍만 허용

    왜 IP 기반 정책이 현대 환경에서 무너지는가. 컨테이너와 오토스케일링 환경에서 워크로드의 IP 는 몇 분 단위로 바뀐다. "10.1.2.0/24 를 허용" 이라는 규칙은 그 대역에 어떤 워크로드가 들어올지 보장하지 못한다. 그래서 "결제 서비스는 데이터베이스의 3306 만 호출할 수 있다" 처럼 역할로 정책을 쓴다.

    구현 수단

    • 분산 방화벽 — 하이퍼바이저나 호스트 커널에서 각 워크로드의 입출력을 직접 통제한다. 트래픽이 중앙 방화벽을 거치지 않아도 정책이 적용된다
    • 네트워크 오버레이와 캡슐화(VXLAN 등) — 물리 토폴로지와 무관한 논리망을 만든다
    • 신원·태그 기반 정책 — IP 가 아니라 워크로드 속성으로 판단
    • 제로 트러스트 구현의 핵심 수단

    도입의 현실적 난점은 정책을 만드는 일 자체다. 어떤 워크로드가 어디와 통신해야 하는지 아무도 정확히 모르는 경우가 많다. 그래서 먼저 흐름을 관찰해(흐름 데이터) 실제 통신 지도를 그리고, 관찰 모드로 검증한 뒤 차단으로 전환하는 순서를 밟는다. 곧바로 차단하면 업무가 멈춘다.

    연결D3.1 8) 제로 트러스트 (Zero Trust) · 업무·관리·방문자 환경을 구획하면 허용 흐름의 경계를 그릴 수 있습니다. 그 경계에서 요청 단위 권한과 상태를 판정해야 망에 들어왔다는 사실만으로 내부 접근이 이어지지 않습니다.

    12엣지 네트워크

    엣지는 내 네트워크가 남의 네트워크와 만나는 지점이다. 통제의 밀도가 가장 높아야 할 곳이고, 동시에 내 통제가 끝나는 곳이다.

    인그레스와 이그레스

    방향 통제 막는 것
    인그레스 Ingress (들어옴) 출발지 주소 검증, 허용 서비스만 공개 스푸핑, 불필요한 노출
    이그레스 Egress (나감) 아웃바운드 허용 목록, 프록시 경유 강제 C2 통신, 데이터 유출, 내부에서 출발하는 스푸핑

    이그레스 필터링이 자주 간과된다. 대부분의 조직이 들어오는 것은 엄격히 막고 나가는 것은 전부 허용한다. 그러나 침해는 이미 안에서 시작되며, 공격자는 나가는 통로로 명령을 받고 데이터를 빼낸다.

    • 인그레스 필터링(BCP 38) — 내 주소 대역이 아닌 출발지를 가진 들어오는 패킷을 버린다. 반대로 내 대역이 아닌 출발지로 나가는 패킷도 버린다. 이것이 전 세계적으로 적용되면 IP 스푸핑 기반 증폭 DDoS 가 크게 줄어든다. 즉 내 네트워크가 남을 공격하는 데 쓰이지 않게 하는 의무이기도 하다
    • 아웃바운드는 필요한 목적지·포트만 허용하는 것이 원칙이다. 최소한 DNS 와 HTTP(S) 는 내부 리졸버와 프록시를 경유하게 강제한다

    피어링과 BGP

    피어링은 두 자율 시스템(AS)이 트래픽을 직접 교환하는 합의다. BGP 가 이 경로 정보를 주고받는다.

    BGP 의 근본 문제는 신뢰 기반 설계다. 어떤 AS 가 "이 주소 대역은 내 것" 이라고 알리면 이웃은 기본적으로 믿는다.

    위협 설명 영향
    경로 하이재킹 Prefix hijacking 남의 주소 대역을 자기 것이라 광고 트래픽이 공격자로 흘러 도청·차단
    경로 누출 Route leak 받은 경로를 광고하면 안 될 쪽으로 전파 대규모 우회·장애
    AS 경로 위조 경로를 짧게 위조해 선택되게 만든다 트래픽 유인

    대응

    • RPKI 와 ROA — 어떤 AS 가 어떤 대역을 광고할 권리가 있는지 암호학적으로 검증한다
    • 경로 필터링과 최대 접두사 수 제한 — 이웃이 비정상적으로 많은 경로를 광고하면 차단
    • 피어 인증(TCP-AO/MD5), 경로 모니터링

    판단 기준 BGP 하이재킹은 암호화로 막을 수 없다. 트래픽이 암호화되어 있어도 경로가 공격자를 거치면 메타데이터 노출과 가용성 침해가 일어난다. 경로 자체의 진위를 검증하는 RPKI 가 답이다.

    공유 비밀번호의 근본 문제는 폐기 불가능성이다. 한 명이 떠나도 전체를 바꿔야 하므로 실제로는 바꾸지 않고, 결국 비밀번호가 영구히 유통된다.

    EAP 방식 — 802.1X 안에서 무엇으로 인증하는가

    방식 특징
    EAP-TLS 양쪽 모두 인증서. 가장 강하고 비밀번호가 없다
    PEAP / EAP-TTLS TLS 터널 안에서 비밀번호 인증. 서버 인증서만 필요
    EAP-MD5 사용 금지 — 상호 인증 없고 약하다

    터널형(PEAP 등)에서 반드시 서버 인증서를 검증해야 한다. 검증하지 않으면 가짜 AP 가 터널을 끝내고 자격증명을 그대로 받는다. 이것이 기업 무선에서 가장 흔한 설정 실수다.

    판단 기준 "무선에서 가장 강한 인증" 을 묻는다면 EAP-TLS(상호 인증서) 다. "WPA2-PSK 의 한계" 를 묻는다면 공유 비밀번호와 오프라인 사전 공격이고, 그 답이 WPA3 의 SAE 다.

    대표 무선 공격

    공격 설명
    악성 쌍둥이(Evil Twin) 정상 AP 를 사칭한 가짜 AP
    불량 AP(Rogue AP) 내부에 몰래 설치된 AP
    디어소시에이션 연결 강제 해제 후 재접속 유도
    워드라이빙 이동하며 AP 탐색
    재밍 전파 방해(가용성)

    다른 무선 기술

    • Bluetooth — 블루재킹(메시지 전송), 블루스나핑(데이터 탈취). 페어링 보안, 비발견 모드
    • Zigbee — IoT 저전력. 기본 키 사용 문제(D3.5 아키텍처별 취약점 참조)
    • 위성 — 긴 지연, 광범위 커버리지. 암호화 필수

    14셀룰러 네트워크

    세대 보안 특징
    4G/LTE 상호 인증 도입
    5G 더 강한 암호화, 네트워크 슬라이싱, 엣지 컴퓨팅

    세대별로 무엇이 달라졌는가

    • 2G/3G 는 단방향 인증이었다. 네트워크가 단말을 인증했지만 단말은 네트워크를 인증하지 않았다. 그래서 가짜 기지국(IMSI 캐처, 스팅레이)이 단말을 끌어올 수 있었다
    • 4G/LTE 가 상호 인증을 도입해 이 문제를 줄였다. 다만 하위 세대로 강제 다운그레이드시키는 공격은 남는다
    • 5G 는 암호화를 강화하고 가입자 식별자(SUPI)를 암호화해 IMSI 노출을 줄였다

    확인 필요원본은 2G/3G를 단방향 인증, 4G를 상호 인증의 시작으로 적었지만, 3GPP TS 33.102(3G 보안 구조)는 UMTS AKA가 사용자와 네트워크의 상호 인증을 달성한다고 명시합니다. 단방향 인증은 2G(GSM)의 특징이며, 가짜 기지국이 3G·4G 단말을 2G로 끌어내리는 다운그레이드 공격이 그래서 의미를 가집니다. 시험 관점의 핵심(구세대의 단방향 인증 → 가짜 기지국, 다운그레이드 위험, 종단 간 암호화)은 같습니다.

    5G 네트워크 슬라이싱 — 하나의 물리 인프라를 논리적으로 분할해 용도별로 격리한다. 긴급 통신, 산업 제어, 일반 소비자 트래픽이 같은 물리망 위에서 서로 다른 품질과 격리 수준을 갖는다.

    슬라이스 간 격리가 보안 요구사항이 된다. 이는 가상화의 격리 문제와 같은 구조다 — 공유 인프라에서 한 테넌트가 다른 테넌트에 영향을 주면 안 된다(D3.5 의 멀티테넌시와 같은 논리다).

    엣지 컴퓨팅(MEC) 도 5G 와 함께 온다. 처리를 기지국 가까이 옮겨 지연을 줄이는데, 데이터와 연산이 중앙 데이터센터 밖으로 나가므로 물리 보안과 자산 관리 범위가 넓어진다.

    주의: 모바일 네트워크를 신뢰하지 않고 종단 간 암호화를 적용하는 것이 원칙이다. 통신사 구간을 내가 통제할 수 없고, 다운그레이드 공격과 가짜 기지국의 가능성이 남아 있기 때문이다. 이것은 "전송 구간을 신뢰하지 않는다" 는 제로 트러스트 원칙의 적용이다.

    15CDN — 콘텐츠 전송 네트워크

    콘텐츠를 사용자 가까운 엣지에 캐시한다.

    보안 효과

    • DDoS 흡수 — 분산된 용량으로 공격 트래픽 분산
    • 오리진 서버 은폐
    • WAF 통합 제공

    CDN 이 DDoS 를 흡수하는 원리는 애니캐스트와 분산 용량이다. 같은 주소를 전 세계 엣지에 두면 공격 트래픽이 발신지에 가까운 노드로 흩어진다. 한 곳에 모이지 않으므로 포화시키려면 전 세계 엣지 용량의 총합을 넘겨야 한다.

    보안 고려

    • 캐시에 민감 데이터가 남지 않도록 캐시 정책 관리. 인증이 필요한 응답이 캐시되어 다른 사용자에게 제공되는 사고가 실제로 발생한다. Cache-Control: private/no-store 와 사용자별 응답의 캐시 키 설계가 중요하다
    • 오리진 접근을 CDN 으로만 제한 — 오리진 IP 가 알려지면 공격자가 CDN 을 건너뛰고 직접 때린다. CDN 도입의 효과가 사라지므로 오리진 방화벽에서 CDN 대역만 허용한다
    • TLS 종단 지점 — CDN 에서 복호화되는 구간의 신뢰. CDN 사업자가 평문을 보게 되므로 제3자 위탁의 문제가 된다(D1.11·D2 참조). 민감 데이터는 CDN 에서 오리진까지 재암호화하거나, CDN 을 경유하지 않도록 설계한다
    • 캐시 포이즈닝 — 조작된 요청으로 잘못된 응답을 캐시에 심어 다수 사용자에게 배포시키는 공격

    판단 기준 CDN 은 가용성(DDoS 흡수)과 성능에 기여하는 통제이면서, 동시에 TLS 복호화 지점을 외부 사업자에게 넘기는 위험을 들여온다. 두 면을 함께 따져야 한다.

    16SDN / NFV / SD-WAN

    SDN (Software-Defined Networking) — 제어 평면과 데이터 평면을 분리하고 중앙 컨트롤러가 제어한다.

    • 장점: 중앙 집중 정책, 자동화, 신속한 변경
    • 위험: 컨트롤러가 단일 장애점이자 최우선 공격 목표다. 컨트롤러 침해 = 네트워크 전체 장악
    • 노스바운드/사우스바운드 API 보안이 핵심

    SDN 의 보안이 양면적인 이유. 중앙 컨트롤러는 통제를 강화하는 수단이면서 집중된 위험이다.

    측면 내용
    얻는 것 전체 네트워크에 일관된 정책을 즉시 적용. 수동 설정 오류가 줄고, 마이크로세그멘테이션 같은 세밀한 정책이 실현 가능해진다
    잃는 것 컨트롤러 한 곳이 네트워크 전체의 장악 지점이 된다. 침해되면 모든 경로를 공격자가 정한다

    따라서 SDN 환경의 보안은 컨트롤러 보호에 집중된다.

    • 컨트롤러 접근을 대역 외 관리망으로 제한하고 강한 인증(MFA)과 권한 분리 적용
    • 노스바운드 API(애플리케이션 ↔ 컨트롤러)와 사우스바운드 API(컨트롤러 ↔ 장비) 모두 인증·암호화. 사우스바운드가 위조되면 가짜 정책이 장비에 내려간다
    • 컨트롤러 이중화 — 단일 장애점 해소
    • 정책 변경 감사 로그와 승인 절차 (변경 관리, D7 참조)

    NFV (Network Function Virtualization) — 방화벽·로드밸런서 같은 네트워크 기능을 전용 하드웨어 대신 소프트웨어로 구현한다. 필요할 때 생성하고 폐기할 수 있어 유연하지만, 네트워크 기능이 가상화 플랫폼의 취약점을 그대로 물려받는다. 하이퍼바이저가 뚫리면 그 위의 방화벽도 무력화된다(D3.4 의 Ring -1 논리와 같다).

    SD-WAN — 지점 간 WAN 을 소프트웨어로 제어한다. 전용선(MPLS) 대신 인터넷 회선을 쓰면서 암호화 터널과 경로 선택을 자동화해 비용을 낮춘다. SASE 의 네트워크 구성요소다(D3.1 안전한 설계 원칙 참조).

    • 공용 인터넷을 쓰므로 구간 암호화가 필수다
    • 중앙 오케스트레이터가 SDN 컨트롤러와 같은 집중 위험을 갖는다

    보충정책을 정하는 제어 영역, 트래픽을 전달하는 영역, 설정과 운영을 담당하는 관리 영역은 서로 다른 종류의 접근이 필요합니다. 예를 들어 사용자의 업무 통신이 전달되더라도 장비 설정을 바꿀 권한까지 얻어서는 안 됩니다.

    17VPC — 가상 사설 클라우드

    클라우드 내 논리적으로 격리된 네트워크 공간이다.

    온프레미스의 네트워크 설계를 클라우드에서 다시 하는 자리이며, 구성요소의 이름과 성격이 다릅니다.

    구성요소 적용 단위 / 상태 추적 규칙
    보안 그룹 Security Group 인스턴스(ENI) · 상태 기반 Stateful 허용 규칙만. 응답 트래픽은 자동 허용
    네트워크 ACL 서브넷 · 무상태 Stateless 허용·거부 모두. 양방향 규칙을 각각 써야 한다

    AWS VPC에서 무상태라는 뜻. 서브넷 네트워크 ACL에서 들어오는 웹 요청을 허용해도 응답 방향은 별도로 평가된다. 요청을 받은 서비스의 포트와 응답을 받는 클라이언트의 임시 포트는 다르다. 보안 그룹은 허용된 연결의 응답을 상태에 따라 허용한다. AWS VPC 네트워크 ACL

    서브넷 설계

    • 공개 서브넷 — 인터넷 게이트웨이로 가는 경로가 있다. 로드밸런서·베스천만 둔다
    • 사설 서브넷 — 인터넷에서 직접 닿을 수 없다. 애플리케이션·데이터베이스를 둔다
    • 사설 서브넷의 아웃바운드는 NAT 게이트웨이를 거친다. 나가는 것은 되지만 들어오는 것은 안 되는 구조다
    • "공개/사설" 을 가르는 것은 서브넷 이름이 아니라 라우팅 테이블이다

    연결 수단

    • VPC 피어링 — 두 VPC 를 직접 연결. 전이적(transitive)이지 않다. A-B, B-C 가 있어도 A-C 는 통신할 수 없다
    • VPC 엔드포인트 / 프라이빗 링크 — 클라우드 관리형 서비스(스토리지 등)를 공용 인터넷을 거치지 않고 호출한다. 트래픽이 외부로 나가지 않으므로 노출 면적이 줄어든다
    • 전용 연결(Direct Connect 류) — 온프레미스와 전용 회선으로 연결

    흔한 실수: 보안 그룹을 0.0.0.0/0 으로 열어 두는 것. 클라우드 침해의 대표 원인이다(D3.5 아키텍처별 취약점 참조). 특히 데이터베이스 포트(3306, 5432, 27017)와 관리 포트(22, 3389) 의 전체 개방이 전형적이다.

    흐름 로그(VPC Flow Logs) 를 켜 두는 것이 중요하다. 클라우드에서는 물리 탭을 설치할 수 없으므로 흐름 로그가 네트워크 가시성의 사실상 유일한 수단이고, 사고 조사 때 켜져 있지 않으면 되돌릴 방법이 없다.

    판단 기준 보안 그룹(인스턴스·상태 기반·허용만) vs 네트워크 ACL(서브넷·무상태·허용과 거부). 두 통제의 범위와 응답 트래픽을 평가하는 방식을 구분한다. 둘은 대체재가 아니라 계층적으로 함께 쓰는 것이고, 심층 방어의 클라우드 구현이다.

    18모니터링과 관리

    공식 세부 항목이 관측 가능성, 트래픽 흐름·셰이핑, 용량 관리, 장애 탐지와 처리 네 가지를 명시한다. 이 항목은 가용성(CIA 의 A)이 네트워크에서 어떻게 구현되는가를 묻는 자리다.

    관측 가능성 (Observability)

    모니터링이 "미리 정한 지표를 보는 것" 이라면, 관측 가능성은 예상하지 못한 질문에도 답할 수 있는 상태다. 세 가지 축으로 구성된다.

    축 무엇 보안 용도
    로그 Logs 개별 사건 기록 사고 조사의 1차 증거
    메트릭 Metrics 수치의 시계열 이상 징후 조기 탐지
    추적 Traces 요청이 지나간 경로 영향 범위 파악

    네트워크 흐름 데이터(NetFlow, IPFIX, sFlow) 가 특히 중요하다. 패킷 전체를 저장하지 않고 "누가 누구와 언제 얼마나 통신했는가" 만 기록하므로 비용이 낮고 장기 보관이 가능하다.

    • 암호화된 트래픽도 흐름 분석은 가능하다. 내용을 못 봐도 통신 상대와 패턴은 보인다. 평소에 없던 외부 IP 와 주기적으로 소량 통신하는 호스트는 C2 의 전형적 신호다
    • 사고 조사에서 "언제부터 침해됐나" 를 답하는 것이 흐름 데이터다

    시간 동기화(NTP)가 전제 조건이다. 장비 간 시계가 틀리면 로그 상관분석이 불가능하고, 법적 증거로서의 가치도 떨어진다(D3.5·D7 참조).

    트래픽 흐름과 셰이핑 (QoS)

    수단 동작
    분류와 표시 트래픽을 등급으로 나눈다
    셰이핑 Shaping 초과분을 버퍼에 담아 지연시켜 평탄화
    폴리싱 Policing 초과분을 즉시 폐기
    우선순위 큐 지연에 민감한 트래픽(VoIP)을 먼저 보낸다

    QoS 는 가용성 통제다. 회선이 포화됐을 때 무엇을 먼저 버릴지 미리 정해두는 것이고, 정하지 않으면 장애 시 가장 중요한 트래픽이 먼저 죽는다.

    판단 기준 QoS 자체가 DDoS 대응은 아니지만, 중요 서비스의 최소 품질을 보장해 공격 중에도 핵심 기능이 살아남게 한다. 셰이핑(지연)과 폴리싱(폐기)의 차이를 구분한다.

    용량 관리 (Capacity Management)

    가용성은 설계 단계에서 결정된다. 용량이 부족하면 평시에는 느리고 공격 시에는 즉시 무너진다.

    • 기준선(baseline)을 측정해 정상 범위를 알아야 이상을 탐지할 수 있다
    • 성장 추세를 반영한 증설 계획 — 사후 대응은 이미 장애다
    • 임계치 경보를 포화 전에 설정한다

    장애 탐지와 처리 (Fault Detection and Handling)

    수단 역할
    이중화 Redundancy 장비·회선·경로를 둘 이상 (D7 가용성 참조)
    헬스 체크와 자동 전환 Failover 장애를 감지해 예비 경로로 전환
    단일 장애점 제거 한 지점 고장이 전체를 멈추지 않게

    이중화는 "있다" 가 아니라 "검증했다" 여야 한다. 전환이 실제로 동작하는지 시험하지 않은 이중화는 장애 때 작동하지 않는 경우가 흔하다(D7 의 DR 시험과 같은 원리다).

    판단 기준 모니터링은 탐지 통제(detective control) 다. 공격을 막지는 않지만, 탐지 없이는 대응도 복구도 불가능하다. "사고를 먼저 알 수 있게 하는 것" 이 이 항목의 보안적 가치다.

    20실무 적용 사례

    사례 1 — 듀얼 스택의 열린 뒷문

    방화벽 정책이 IPv4 기준으로만 작성되어 있었다. 서버가 IPv6 를 기본 활성화한 상태로 배포되었고, IPv6 주소로는 관리 포트가 그대로 열려 있었다.

    IPv4 와 IPv6 는 동등한 통제를 받아야 한다. 사용하지 않으면 비활성화하는 것이 안전하다.

    사례 2 — DNS 터널링으로 빠져나간 데이터

    방화벽이 아웃바운드를 엄격히 제한했지만 DNS 는 허용되어 있었다. 공격자가 데이터를 DNS 질의에 인코딩해 조금씩 유출했다.

    다계층 프로토콜의 캡슐화를 이용한 은닉 채널이다. DNS 질의 패턴 모니터링과 내부 DNS 리졸버 강제 경유로 대응했다.

    사례 3 — 평문 iSCSI

    스토리지 트래픽이 업무 VLAN 과 같은 네트워크에서 인증과 암호화 없이 흐르고 있었다. 내부 침해자가 스토리지 트래픽을 캡처해 데이터베이스 파일 내용을 복원했다.

    전용망을 전제로 설계된 프로토콜이 공용 경로에 올라온 전형적 사례다. 전용 VLAN 분리와 CHAP 인증, 암호화를 적용했다.

    사례 4 — 경계는 지켰지만 내부는 무방비

    경계 방화벽은 견고했으나 데이터센터 내부 서버 간 통신에는 제한이 없었다. 웹 서버 한 대가 침해되자 공격자가 데이터베이스, 백업 서버, 도메인 컨트롤러로 자유롭게 이동했다.

    동서 트래픽 통제 부재가 원인이다. 마이크로세그멘테이션을 도입해 워크로드 간 필요한 통신만 허용하도록 바꿨다.

    사례 5 — 관리 평면이 노출된 스위치

    네트워크 스위치의 관리 인터페이스가 업무 VLAN 에서 접근 가능했다. 침해된 사용자 PC 에서 스위치 관리자 로그인 시도가 가능했다.

    관리 평면은 대역 외로 분리해야 한다. 전용 관리 VLAN 과 별도 접근 경로로 변경했다.

    사례 6 — 열린 보안 그룹

    클라우드 데이터베이스 인스턴스의 보안 그룹이 0.0.0.0/0 으로 3306 포트를 허용하고 있었다. 외부에서 직접 접근이 가능했다.

    클라우드 침해의 대표 원인이다. 보안 그룹을 애플리케이션 서버 그룹으로만 제한하고, 정책 코드화로 사전 차단했다(D2.3 안전한 프로비저닝 참조).

    사례 7 — 이중 태깅으로 넘어간 VLAN

    사용자 VLAN 과 서버 VLAN 을 분리해 두었으나 트렁크의 네이티브 VLAN 이 기본값(VLAN 1) 이었고 사용자 포트도 VLAN 1 에 있었다. 공격자가 바깥 태그를 VLAN 1, 안쪽 태그를 서버 VLAN 으로 지정한 프레임을 보내자 첫 스위치가 바깥 태그를 떼면서 서버 VLAN 으로 프레임이 전달되었다.

    VLAN 은 보안 경계가 아니다를 보여주는 전형적 사례다. 네이티브 VLAN 을 사용하지 않는 번호로 바꾸고, 민감 구간은 방화벽이 있는 라우팅 경계로 올렸다.

    사례 8 — 검증하지 않은 서버 인증서

    기업 무선을 WPA2-Enterprise(PEAP)로 운영했지만 단말 프로파일에서 서버 인증서 검증이 꺼져 있었다. 공격자가 같은 SSID 의 가짜 AP 와 가짜 RADIUS 를 세우자 단말이 그대로 접속해 사용자 자격증명이 공격자에게 전달되었다.

    802.1X 를 쓴다는 사실만으로 안전해지지 않는다. 터널형 EAP 에서는 서버 인증서 검증이 보안의 전부다. 검증을 강제하고 신뢰 CA 를 고정했으며, 장기적으로 EAP-TLS 로 전환했다.

    사례 9 — 무상태 ACL 때문에 끊긴 응답

    클라우드에서 네트워크 ACL 로 인바운드 443 만 허용했는데 서비스가 동작하지 않았다. 네트워크 ACL 은 무상태이므로 응답이 나가는 아웃바운드 임시 포트 범위가 막혀 있었던 것이다.

    보안 그룹(상태 기반)에만 익숙하면 겪는 전형적 혼동이다. 상태 추적 여부가 설정 방식을 바꾼다는 점을 이해해야 한다.

    사례 10 — 꺼져 있던 흐름 로그

    침해 사고 조사에서 어떤 내부 서버가 외부와 통신했는지 확인할 수 없었다. VPC 흐름 로그가 비활성화 상태였고, 클라우드에는 물리 탭을 설치할 수 없어 과거 트래픽을 되살릴 방법이 없었다.

    가시성은 사고 전에 켜 두어야만 존재한다. 흐름 로그를 전 VPC 에 활성화하고 중앙 로그 저장소로 보내 보존 기간을 정했다(D7 참조).

    서비스가 동작하려면 가용률 99.9%, 99.9%, 99.5%인 장비 세 대가 모두 정상이어야 한다. 장비 고장이 서로 독립이라고 가정한다. 종단 간 가용률은 대략 얼마이며 이것이 시사하는 바는?

    1. 약 99.9%. 경로는 가장 좋은 구성요소만큼 좋다.
    2. 약 99.5%. 가장 약한 구성요소가 결과를 정확히 결정한다.
    3. 약 100%. 세 장비가 서로 이중화를 제공한다.
    4. 약 99.3%. 독립인 필수 구성요소의 가용률을 곱한다.
    정답과 해설 보기

    정답 D. 각 구성요소가 모두 작동해야 하고 장애가 서로 독립이면 경로의 가용률은 각 구성요소 가용률의 곱이다. 0.999 와 0.999, 0.995 를 곱하면 약 0.9930 으로 99.3% 다. 어떤 구성요소보다도 낮아지며 직렬 구성요소를 늘릴수록 가용률이 떨어진다는 점이 핵심이다. 이중화를 검토할 때는 공통 전원이나 회선 장애가 두 경로에 함께 영향을 주는지 확인한다. 공통 장애가 있으면 독립 가정을 그대로 사용하기 어렵다. AWS 의존성 가용률 예시

    • A · 최고 구성요소가 아니라 곱이 결과를 정한다.
    • B · 가장 약한 구성요소보다도 낮아진다.
    • C · 직렬 배치는 이중화가 아니다.

    4. BGP 가 신뢰를 전제로 경로 광고를 수락하기 때문에 발생하는 BGP 경로 하이재킹이다. RPKI 경로 출처 검증, 피어와의 접두사 필터링, 예상치 못한 광고 모니터링으로 완화한다.
    정답과 해설 보기

    정답 D. BGP 는 설계상 상대가 광고하는 경로를 신뢰한다. 다른 자율 시스템이 더 구체적인 접두사를 광고하면 트래픽이 그쪽으로 끌려간다. 실수로도 발생하고 의도적 가로채기에도 쓰인다. RPKI 로 경로 출처를 검증하고, 피어와 접두사 필터를 합의하고, 자사 접두사에 대한 예상 외 광고를 모니터링해야 한다.

    • A · ARP 는 같은 2계층 세그먼트에서만 동작한다.
    • B · 내부 프로토콜 문제가 아니라 외부 경로 광고 문제다.
    • C · 이름 해석이 아니라 경로 선택 문제다.

    실시간 음성과 영상에 UDP 가 흔히 선택되는 이유는?

    1. UDP 가 기본적으로 페이로드를 암호화하므로.
    2. UDP 가 전달 순서를 보장하므로.
    3. 연결 수립과 재전송의 지연을 피하므로. 실시간 미디어에서 늦게 도착한 패킷은 쓸모가 없으므로 전달 보장보다 낮은 지연이 선호된다.
    4. UDP 가 TCP 보다 적은 포트 번호를 쓰므로.
    정답과 해설 보기

    정답 C. TCP 는 손실된 패킷을 재전송해 신뢰성을 주지만 그 재전송이 도착할 때쯤 그 음성 구간은 이미 지났다. 그래서 실시간 미디어는 약간의 손실을 감수하고 지연을 줄인다. UDP 는 암호화나 순서 보장을 제공하지 않으므로 보안이 필요하면 SRTP 처럼 상위에서 보호를 더한다.

    • A · UDP 는 암호화를 제공하지 않는다.
    • B · 순서 보장은 TCP 의 특성이다.
    • D · 포트 번호 공간은 동일하다.

    24주요 용어 (Glossary)

    영어 원어와 한국어 뜻 · English–Korean

    OSI Model · OSI 참조 모델

    7계층 네트워크 참조 모델. 응용-표현-세션-전송-네트워크-데이터링크-물리.

    PDU — Protocol Data Unit · 프로토콜 데이터 단위

    전송 계층은 세그먼트, 네트워크 계층은 패킷, 데이터링크 계층은 프레임, 물리 계층은 비트.

    AH / ESP — Authentication Header / Encapsulating Security Payload · 인증 헤더 / 캡슐화 보안 페이로드

    IPSec 의 구성요소. AH 는 무결성·인증만 제공하고 암호화하지 않으며, ESP 는 암호화를 포함한다.

    Transport Mode / Tunnel Mode · 전송 모드 / 터널 모드

    IPSec 모드. 전송 모드는 페이로드만, 터널 모드는 IP 헤더를 포함한 전체를 보호한다.

    Multilayer Protocol · 다계층 프로토콜

    캡슐화로 계층을 쌓는 구조. 터널링과 은닉 채널의 기반이 된다.

    Converged Protocol · 융합 프로토콜

    전용망 프로토콜을 IP 위에서 운반하는 것. iSCSI, VoIP, FCoE 가 해당한다.

    Data / Control / Management Plane · 데이터 평면 / 제어 평면 / 관리 평면

    실제 트래픽 전달, 경로 결정, 장비 설정의 세 평면. 관리 평면은 분리해야 한다.

    Store-and-Forward / Cut-Through · 저장 후 전달 / 즉시 전달

    프레임 전체를 받고 검사한 뒤 전달하는 방식과 목적지 주소만 읽고 즉시 전달하는 방식.

    Jitter · 지터

    지연의 변동 폭. 실시간 통신 품질을 좌우한다.

    North-South / East-West Traffic · 남북 트래픽 / 동서 트래픽

    외부와 데이터센터 간 트래픽과 내부 서버 간 트래픽. 동서 트래픽이 횡적 이동의 경로다.

    Air Gap · 에어갭

    물리적으로 완전히 분리된 네트워크. 절대적이지는 않지만 공격 난이도를 크게 높인다.

    Out-of-Band Management · 대역 외 관리

    업무 트래픽과 분리된 별도 경로로 장비를 관리하는 방식.

    VLAN / VRF — Virtual Local Area Network / Virtual Routing and Forwarding · 가상 LAN / 가상 라우팅 및 전달

    2계층 논리 분리와 라우팅 테이블 분리.

    Micro-segmentation · 마이크로세그멘테이션

    워크로드 단위로 통신을 제한하는 방식. 동서 트래픽 통제와 제로 트러스트의 핵심 수단이다.

    Egress Filtering · 이그레스 필터링

    나가는 트래픽을 통제하는 것. C2 통신과 데이터 유출을 막는다.

    SAE — Simultaneous Authentication of Equals · 동등한 참여자의 동시 인증

    WPA3 의 핸드셰이크 방식. 오프라인 사전 공격을 방어하고 전방향 비밀성을 제공한다.

    Evil Twin / Rogue AP · 정상 AP 사칭 / 비인가 AP

    정상 AP 를 사칭한 가짜 AP 와 내부에 몰래 설치된 AP.

    Network Slicing · 네트워크 슬라이싱

    5G 에서 물리 인프라를 논리적으로 분할해 용도별로 격리하는 기술.

    SDN / NFV / SD-WAN — Software-Defined Networking / Network Functions Virtualization / Software-Defined Wide Area Network · 소프트웨어 정의 네트워크 / 네트워크 기능 가상화 / 소프트웨어 정의 광역망

    제어·데이터 평면 분리, 네트워크 기능의 소프트웨어화, 소프트웨어 기반 WAN 제어.

    VPC — Virtual Private Cloud · 가상 사설 클라우드

    클라우드 내 논리적으로 격리된 네트워크 공간.

    Security Group / Network ACL · 보안 그룹 / 네트워크 접근 제어 목록

    인스턴스 단위 상태 기반 필터와 서브넷 단위 무상태 필터. 무상태인 네트워크 ACL 은 응답 트래픽을 위한 임시 포트 범위를 따로 허용해야 한다.

    Unicast / Broadcast / Multicast / Anycast · 단일 대상 전송 / 전체 전송 / 그룹 전송 / 경로상 한 대상 전송

    1 대 1, 세그먼트 전체, 가입한 그룹, 같은 주소를 가진 노드 중 가장 가까운 하나로 보내는 네 가지 전달 방식.

    Anycast · 애니캐스트

    동일 IP 를 여러 지역에 두어 가장 가까운 노드가 응답하게 하는 방식. DNS 루트 서버와 CDN 의 DDoS 분산 기반이다.

    Smurf Attack · 스머프 공격

    출발지를 피해자로 위조한 ICMP 를 브로드캐스트 주소로 보내 세그먼트 전체가 피해자에게 응답하게 만드는 증폭 공격. 방향성 브로드캐스트 차단으로 대응한다.

    Encapsulation / Decapsulation · 캡슐화 / 역캡슐화

    계층을 내려가며 헤더를 덧붙이고 올라가며 벗기는 과정. 통제가 어느 계층에서 무엇을 볼 수 있는지를 결정한다.

    Protocol Downgrade Attack · 프로토콜 다운그레이드

    협상을 구버전이나 약한 암호군으로 끌어내리는 공격. 대응은 구버전 지원 자체를 제거하는 것이다.

    SNMPv3 — Simple Network Management Protocol version 3 · 단순 네트워크 관리 프로토콜 3판

    네트워크 관리 프로토콜의 보안 버전. v1/v2c 는 커뮤니티 스트링을 평문으로 전송한다.

    SSH Port Forwarding · SSH 포트 포워딩

    SSH 터널로 임의 포트를 중계하는 기능. 내부 서비스를 외부로 노출해 방화벽을 우회할 수 있다.

    Switch Spoofing / Double Tagging · 스위치 사칭 / 이중 태그

    VLAN 호핑의 두 방식. 트렁크 협상을 흉내 내는 것과 VLAN 태그를 두 개 붙여 네이티브 VLAN 을 통과하는 것.

    Native VLAN · 네이티브 VLAN

    트렁크에서 태그 없이 전달되는 VLAN. 기본값(VLAN 1)을 그대로 두면 이중 태깅의 발판이 된다.

    MAC Flooding · MAC 플러딩

    스위치의 MAC 테이블을 넘치게 해 모든 포트로 프레임을 브로드캐스트하게 만드는 공격. 포트 보안으로 대응한다.

    Ingress / Egress Filtering · 유입 트래픽 필터링 / 유출 트래픽 필터링

    들어오는 트래픽과 나가는 트래픽의 통제. 이그레스 필터링은 C2 통신과 데이터 유출을 막는다.

    BCP 38 · 출발지 IP 위조를 줄이기 위한 네트워크 유입 필터링 지침

    자기 주소 대역이 아닌 출발지를 가진 패킷을 버리는 출발지 주소 검증 권고. IP 스푸핑 기반 증폭 DDoS 를 줄인다.

    BGP Prefix Hijacking · 경로 하이재킹

    남의 주소 대역을 자기 것이라 광고해 트래픽을 끌어오는 공격. 암호화로는 막을 수 없다.

    RPKI / ROA — Resource Public Key Infrastructure / Route Origin Authorization · 인터넷 번호 자원 공개키 기반구조 / 경로 원점 인가

    어떤 AS 가 어떤 대역을 광고할 권리가 있는지 암호학적으로 검증하는 체계.

    EAP-TLS / PEAP — Extensible Authentication Protocol–Transport Layer Security / Protected Extensible Authentication Protocol · TLS 기반 확장 인증 / 보호형 확장 인증

    802.1X 안에서 쓰이는 인증 방식. EAP-TLS 는 양쪽 모두 인증서를 쓰고, PEAP 는 TLS 터널 안에서 비밀번호로 인증한다.

    WPA2/3-Personal vs Enterprise · 개인용 / 기업용 무선 보안 방식

    공유 비밀번호 방식과 사용자별 자격증명을 외부 인증 서버로 검증하는 방식.

    IMSI Catcher · 가짜 기지국

    단말을 끌어오는 위조 기지국. 2G/3G 의 단방향 인증이 원인이었고 4G 의 상호 인증으로 완화되었다.

    MEC — Multi-access Edge Computing · 다중 접속 엣지 컴퓨팅

    연산을 기지국 가까이 배치해 지연을 줄이는 구조. 데이터가 중앙 밖으로 나가므로 물리 보안 범위가 넓어진다.

    Observability · 관측 가능성

    로그·메트릭·추적으로 예상하지 못한 질문에도 답할 수 있는 상태. 사전에 정한 지표만 보는 모니터링보다 넓은 개념이다.

    NetFlow / IPFIX / sFlow · 네트워크 흐름 기록·내보내기·샘플링 방식

    패킷 전체가 아니라 통신 상대·시각·양을 기록하는 흐름 데이터. 암호화된 트래픽에서도 패턴 분석이 가능하다.

    Traffic Shaping / Policing · 셰이핑 / 폴리싱

    초과 트래픽을 버퍼에 담아 지연시키는 방식과 즉시 폐기하는 방식.

    Topology · 토폴로지

    버스·링·스타·메시의 연결 구조. 가용성과 통제 용이성이 서로 교환 관계에 있다.

    Leaf-Spine · 리프-스파인

    데이터센터의 부분 메시 구조. 서버 간 경로 길이를 일정하게 유지해 동서 트래픽에 적합하다.

    Cache Poisoning · 캐시 포이즈닝

    조작된 요청으로 잘못된 응답을 캐시에 심어 다수 사용자에게 배포시키는 공격.

    Northbound / Southbound API · 상위 앱 방향 API / 하위 장비 방향 API

    SDN 에서 애플리케이션과 컨트롤러 사이, 컨트롤러와 장비 사이의 인터페이스. 사우스바운드가 위조되면 가짜 정책이 장비에 내려간다.

    VPC Endpoint / Private Link · VPC 엔드포인트 / 사설 연결

    클라우드 관리형 서비스를 공용 인터넷을 거치지 않고 호출하는 연결. 노출 면적을 줄인다.

    VPC Flow Logs · 흐름 로그

    클라우드 네트워크의 흐름 기록. 물리 탭을 설치할 수 없는 환경에서 사실상 유일한 가시성 수단이다.

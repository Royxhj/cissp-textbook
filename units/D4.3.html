    연습문제 5개 바로가기

    표시 없는 본문은 원본 정리 파일의 내용 · 보충은 원본에 없어 더한 설명 · 가상 예시는 지어낸 상황 · 연결은 다른 단원과의 관계 · 확인 필요는 그대로 확정하지 않은 부분

    통신 채널을 보호한다는 것은 두 질문에 답하는 일입니다. 상대가 진짜인가(인증), 그리고 내용이 보호되는가(암호화·무결성). 원본은 출발점으로 경로를 믿을 수 없다고 가정한다를 듭니다. 전용 회선이든 인터넷이든 통신사 네트워크든 종단 간 보호를 적용합니다. 이 단원은 공식 개요 4.3이 드는 음성·영상·협업, 원격 접근, 데이터 통신 경로, 제3자 연결을 다룹니다.

    1음성 통신 (VoIP)

    원본은 음성이 IP 네트워크를 타면서 데이터 네트워크의 위협을 그대로 받는다고 설명합니다.

    위협설명
    도청평문 RTP 패킷을 캡처해 통화 재구성
    통화 가로채기SIP 조작으로 호 경로 변경
    톨 사기 Toll Fraud시스템을 탈취해 국제전화 무단 발신
    비싱 Vishing발신번호 위조로 신뢰 획득
    SPIT음성 스팸
    DoS호 처리 마비

    보호 수단: SRTP(음성 미디어 암호화), SIP over TLS(호 제어 신호 보호), 전용 VLAN 분리, 강한 관리자 인증과 기본 자격증명 변경, 국제전화 발신 제한과 이상 발신 모니터링, 발신번호를 신뢰하지 않기.

    원본의 경고입니다. 발신번호는 위조할 수 있다. 전화로 받은 지시를 신원 증거로 삼으면 안 되며, 딥페이크 음성까지 더해지면 더욱 그렇습니다.

    보충VoIP 보호는 두 갈래입니다. 통화 내용(미디어, RTP)과 통화를 거는 신호(SIP)가 따로 흐르므로 둘 다 보호해야 합니다. 하나만 암호화하면 다른 쪽으로 새거나 조작됩니다. 톨 사기는 기밀성이 아니라 돈의 문제라서 발신 통계의 이상 감시가 핵심 통제입니다. 주말 새벽에 해외 유료 번호로 수백 건이 걸리는 것은 탐지하기 쉽지만, 아무도 보지 않으면 청구서로 처음 알게 됩니다.

    연결음성을 IP로 운반하는 융합 프로토콜과 VLAN 분리는 D4.1 네트워크 아키텍처, 비싱과 딥페이크는 D1.12 인식·교육·훈련에서 다룹니다.

    원문 위치: D4.3.md §2, §3 음성 통신 · 공식 개요 4.3 “Voice, video, and collaboration”

    2영상과 협업 도구

    위협통제
    무단 참가(회의 난입) — 링크만 알면 들어오는 설정대기실과 참가 승인, 회의 암호, 고유 회의 ID(개인 회의실 상시 사용 금지), 참가자 잠금
    녹화와 전사본 유출녹화 고지와 보존 정책
    화면 공유로 인한 노출호스트 권한 관리
    배경·화이트보드의 민감 정보외부 참가자 식별 표시

    협업 플랫폼에서는 외부 공유 기본값 제한, 게스트 접근의 범위와 기한, 데이터 보존과 eDiscovery 대응, 채널 공개 범위 기본값, 연동 앱(서드파티 통합)의 권한 검토를 봅니다.

    원문 사례 — 화상회의 난입. 개인 회의실 ID를 고정으로 쓰며 비밀번호 없이 링크를 공유해 왔는데, 외부인이 링크를 입수해 경영 회의에 들어와 내용이 유출되었습니다. 고유 회의 ID, 비밀번호, 대기실과 참가 승인을 기본값으로 바꿨습니다. 원본은 여기서도 기본값이 곧 정책이라고 정리합니다.

    보충회의의 전송이 암호화되어 있다는 것과 누가 회의에 들어올 수 있느냐는 별개입니다. 링크를 받은 사람은 그 링크를 다른 사람에게 넘길 수 있습니다. 그래서 전송 보호와 별도로 참가 승인, 화면 공유 권한, 녹화의 보존·열람 범위를 정해야 하고, 안건이 민감할수록 회의가 끝난 뒤의 기록(녹화, 전사본, 채팅) 접근까지 검토합니다.

    연결외부 공유 기본값과 “기본값이 곧 정책”은 D2.2 자산 취급 요구사항, 보존 기간은 D2.4 데이터 생애주기, 전자증거 개시와 보존 의무는 D1.5 조사 유형에서 다룹니다.

    원문 위치: D4.3.md §3 영상과 협업 도구, §7 사례 4 · 공식 개요 4.3 “Voice, video, and collaboration (e.g., conferencing, Zoom rooms)”

    3원격 접근: VPN과 ZTNA

    방식계층특징
    IPSec VPN3전체 네트워크 접근, 클라이언트 필요, 사이트 간 연결에 적합
    SSL/TLS VPN6·7브라우저 기반 가능, 애플리케이션 단위 접근, 방화벽 통과 쉬움
    ZTNA7애플리케이션 단위, 신원·상황 기반, 네트워크 노출 없음

    원본은 전통적 VPN의 근본 문제를 네트워크 수준 접근을 준다는 데서 찾습니다. 한 번 연결되면 사용자는 내부망의 일원이 되어, 침해된 단말이 곧 내부 침입 경로가 됩니다. ZTNA는 네트워크가 아니라 애플리케이션에 연결하므로 인가되지 않은 자원은 존재 자체가 보이지 않습니다.

    분할 터널링

    방식동작결과
    전체 터널링모든 트래픽이 회사 네트워크 경유검사 가능, 대역폭 부담
    분할 터널링회사 트래픽만 터널, 나머지는 직접 인터넷성능 좋음, 검사 불가

    분할 터널링의 위험은 단말이 회사망과 인터넷에 동시에 연결되어, 감염된 단말이 외부 C2와 통신하면서 동시에 내부 자원에 접근할 수 있다는 것입니다. 아웃바운드 트래픽도 검사할 수 없습니다. 원본의 절충안은 고위험 트래픽만 터널링하거나, 엔드포인트의 로컬 통제와 클라우드 기반 검사(SASE)를 적용하는 것입니다.

    원문 사례 — 분할 터널링으로 번진 침해. 재택 직원 단말이 분할 터널링 상태에서 피싱으로 감염되었고, 외부 C2와 통신하면서 VPN으로 내부 파일 서버에 접근했습니다. 아웃바운드 트래픽이 회사 검사 지점을 거치지 않아 C2 통신이 탐지되지 않았습니다.

    판단 순서원격 접근 방식을 고를 때 ① 사용자가 필요한 것이 네트워크 전체인가, 특정 애플리케이션 몇 개인가(후자면 ZTNA) ② 사이트 간 연결인가(IPSec) ③ 단말의 인터넷 트래픽을 회사가 검사해야 하는가(그렇다면 전체 터널링 또는 SASE) ④ 단말 상태를 확인하는가(NAC·ZTNA의 상태 검사)를 봅니다.

    연결ZTNA·SASE와 제로 트러스트는 D3.1 안전한 설계 원칙, 이그레스 필터링은 D4.1 네트워크 아키텍처, IPSec과 TLS의 차이는 D4.1 네트워크 아키텍처·D3.6 암호 솔루션에서 다룹니다.

    원본 연습문제 · D4.3-Q01

    재택 직원의 노트북이 회사 VPN 과 인터넷에 동시 연결되어 있다. 노트북의 악성코드가 외부 명령 서버와 통신하는 동안 사용자는 내부 파일 공유에 접근한다. 이를 가능하게 한 구성은?

    1. 모든 트래픽을 회사 네트워크로 보내는 전체 터널링.
    2. 회사 트래픽만 VPN 으로 보내는 분할 터널링.
    3. 인증서 기반 VPN 인증.
    4. IPSec 터널 모드 캡슐화.
    정답과 해설 보기

    정답 B. 분할 터널링은 회사 트래픽만 VPN 으로 보내고 나머지는 직접 인터넷으로 보낸다. 단말이 회사망과 인터넷에 동시 연결되어 감염 단말이 외부 C2 와 통신하면서 내부 자원에도 접근할 수 있고, 아웃바운드 트래픽이 회사 검사 지점을 거치지 않아 C2 통신이 탐지되지 않는다.

    • A · 전체 터널링은 모든 트래픽이 검사 지점을 거치므로 이 상황을 만들지 않는다.
    • C · 인증 방식은 터널링 범위와 무관하다.
    • D · 캡슐화 모드는 보호 범위의 문제이며 동시 연결과 다르다.

    4관리 기능의 원격 접근

    공식 개요는 원격 접근의 예로 “network administrative functions”를 명시합니다. 원본은 관리자 원격 접근이 일반 사용자보다 훨씬 엄격해야 한다고 강조합니다.

    통제내용
    점프 서버 / 베스천 호스트관리 접근을 하나의 통제 지점으로 집중
    대역 외 관리업무망과 분리된 경로
    MFA관리 접근에는 필수
    PAM(특권 접근 관리)자격증명 금고, 적시 권한 상승
    세션 녹화관리 작업 전체 기록
    특권 접근 워크스테이션전용 단말, 일반 업무·인터넷 사용 금지

    원본은 점프 서버 자체가 고가치 표적이므로 강화하고 감시하며, 그것만으로 접근 통제를 끝내지 말라고 합니다. 또 Pass the Hash 대응과 연결된다고 짚습니다. 관리자 자격증명이 일반 단말 메모리에 남지 않게 하는 것이 핵심입니다.

    원문 사례 — 점프 서버 없는 관리 접근. 관리자들이 각자의 업무 단말에서 서버에 바로 SSH로 접속했습니다. 한 관리자 단말이 침해되자 자격증명이 메모리에서 탈취되어 다수 서버로 이동할 수 있었습니다. 점프 서버와 특권 접근 워크스테이션을 도입하고, PAM으로 자격증명을 금고에 넣어 필요할 때만 발급하게 바꿨습니다.

    가상 예시병원에 설치된 장비 한 대를 외주 기사가 원격으로 점검해야 합니다. 조직의 모든 원격 사용자는 업무 VPN으로 들어오는 상태입니다. 관리 작업을 업무 VPN에 태우면 기사는 병원 네트워크 전체에 닿을 수 있습니다. 대신 관리 작업용 경로를 따로 두어 ① 점검 요청이 승인된 장비와 기간에만 ② 점프 서버를 통해 ③ MFA와 세션 녹화를 거쳐 접속하게 합니다. 작업이 끝나면 경로를 닫습니다(7절의 “상시 연결 금지”).

    연결Pass the Hash와 특권 계정 계층화는 D3.7 암호 분석 공격, 특권 계정 관리는 D7.4 기본 보안 운영 개념, 적시 권한은 D3.1 안전한 설계 원칙, 대역 외 관리는 D4.1 네트워크 아키텍처에서 다룹니다.

    원문 위치: D4.3.md §3 관리 기능 원격 접근, §7 사례 5 · 공식 개요 4.3 “Remote access (e.g., network administrative functions)”

    5데이터 통신 경로

    경로특성보안 고려
    전용 회선안정적, 고비용통신사 내부는 신뢰 범위 밖
    MPLS논리 분리암호화는 기본 제공 아님
    인터넷 VPN저비용암호화 필수
    백홀기지국·엣지에서 코어로 집선물리 경로 보호
    위성넓은 커버리지긴 지연, 넓은 지역에서 수신 가능 → 암호화 필수

    원본은 MPLS가 암호화를 제공한다는 오해가 흔하다고 지적합니다. MPLS는 논리적 분리일 뿐이며, 기밀성이 필요하면 그 위에 암호화를 얹어야 합니다. 위성 신호는 넓은 지역에 닿아 누구나 수신할 수 있으므로 암호화 없이는 사실상 공개 방송이고, 지연이 커서 실시간 애플리케이션과 일부 프로토콜에 영향을 줍니다. 경로 다양성은 집중 위험과 연결됩니다. 사업자가 달라도 물리 경로가 같으면 이중화가 아닙니다.

    원문 사례 — MPLS를 암호화로 오해. 지사 간 MPLS 전용 회선을 쓰면서 “전용 회선이니 안전하다”며 암호화하지 않았는데, 통신사 내부 구간은 조직의 통제 범위 밖이었습니다. IPSec을 얹어 종단 간 보호를 적용했습니다.

    연결물리 경로 분리와 관로 사례는 D3.8 사이트·설비 설계 원칙, 집중 위험은 D1.7 업무연속성 요구사항에서 다뤘습니다.

    원문 위치: D4.3.md §3 데이터 통신 경로, §7 사례 3 · 공식 개요 4.3 “Data communications (e.g., backhaul networks, satellite)”

    6이메일 인증: SPF, DKIM, DMARC

    왜 필요한가

    이메일에는 발신자를 검증하는 수단이 원래 없었습니다. 누구나 임의의 주소로 보낸 것처럼 꾸밀 수 있어 도메인 사칭이 피싱의 기반이 됩니다. 세 표준이 이를 보완합니다.

    표준검증 대상방식한계
    SPF발송 서버의 IPDNS에 허용 발송 IP 목록 게시전달(forwarding)되면 실패. SMTP 봉투의 발신자를 보므로 사용자가 보는 From과 다를 수 있다
    DKIM메시지 무결성과 서명 도메인발송 시 서명, 수신 측이 DNS 공개키로 검증그 도메인이 서명했다는 뜻일 뿐, From과 일치하는지는 보장하지 않는다
    DMARC두 결과와 From 도메인의 정렬, 처리 정책none(관찰) / quarantine(격리) / reject(거부), 집계 보고—

    원본의 핵심 문장입니다. SPF와 DKIM만으로는 사용자가 보는 발신자 사칭을 막지 못한다. 공격자가 자기 도메인에 정상 SPF·DKIM을 설정하고 From 헤더만 피해 도메인으로 쓰면 둘 다 통과합니다. DMARC의 정렬 검증이 이것을 막습니다.

    도입 순서와 흔한 실패

    1. SPF·DKIM 구성
    2. DMARC p=none으로 시작 → 보고 수집
    3. 보고 분석 → 빠진 정당한 발송 시스템 식별
    4. p=quarantine → p=reject로 단계적 강화
    • 처음부터 p=reject를 걸면 정당한 메일이 차단된다. 마케팅 도구, 외부 발송 서비스, 고객 지원 시스템처럼 조직 도메인으로 메일을 보내는 시스템이 생각보다 많다
    • 메일을 보내지 않는 도메인에도 설정한다. 쓰지 않는 도메인을 사칭에 쓰는 것이 흔하다. v=spf1 -all과 p=reject로 막는다
    • 하위 도메인 정책이 상위 정책을 상속하는지 확인한다

    보충받는 서버 입장에서 순서대로 읽으면 정리됩니다. ① 연결해 온 서버의 IP가 봉투 발신 도메인의 SPF 목록에 있는가 ② 메시지의 DKIM 서명이 유효하고 어느 도메인의 서명인가 ③ 그 두 도메인 중 하나라도 사용자에게 보이는 From 도메인과 맞는가(정렬) ④ 맞지 않으면 From 도메인이 DMARC로 지정한 정책대로 처리. 자동 전달이나 발송 대행이 있으면 ①②의 도메인이 From과 달라질 수 있으므로, 메일이 실패한 이유를 볼 때 정렬까지 확인해야 합니다. DMARC 도입이 none부터 시작하는 것은 D2.6 데이터 보안 통제의 DLP나 D4.2 네트워크 구성요소의 IPS를 모니터 모드로 시작하는 것과 같은 이유입니다.

    CISSP 관점이메일 인증 상황에서는 ① “허용 발송 서버 목록”을 묻는다면 SPF, “서명으로 무결성 확인”이면 DKIM, “From과의 정렬과 처리 정책·보고”면 DMARC를 고르고 ② 사칭이 SPF·DKIM을 통과했다면 DMARC 정렬이 빠진 것이며 ③ 도입 순서를 묻는다면 none → quarantine → reject 단계 적용입니다. 피싱 전체에 대한 대책을 묻는다면 이메일 인증만이 아니라 첨부·링크 검사, 사용자 교육과 신고 경로, MFA 같은 여러 겹의 조합이 원본 문제의 방향입니다.

    연결피싱과 사회공학, 신고 문화는 D1.12 인식·교육·훈련, 디지털 서명 원리는 D3.6 암호 솔루션에서 다룹니다.

    원본 연습문제 · D4.3-Q37

    어떤 도메인을 위해 메일을 보낼 수 있도록 허용된 서버 목록을 게시하는 이메일 인증 수단은?

    1. 실패 처리 정책을 정의하는 DMARC.
    2. 발신 메시지에 서명하는 DKIM.
    3. 인가된 발송 주소를 DNS 에 게시하는 SPF.
    4. 메일 서버 간 연결을 암호화하는 TLS.
    정답과 해설 보기

    정답 C. 세 수단의 역할을 구분하는 것이 핵심이다. SPF 는 "이 주소에서만 우리 메일이 나간다" 를 DNS 에 공표하고, DKIM 은 서명으로 발신 도메인과 무결성을 증명하며, DMARC 는 그 두 결과가 사용자가 보는 From 도메인과 정렬되는지 확인해 실패 시 처리 정책을 지시한다. TLS 는 전송 구간 암호화로 인증과 다른 목적이다.

    • A · DMARC 는 정책과 정렬을 다룬다.
    • B · DKIM 은 서명 방식이다.
    • D · TLS 는 전송 암호화다.

    원본 연습문제 · D4.3-Q13

    조직이 소유하고 있으나 메일을 전혀 보내지 않는 도메인에 제한적인 SPF 와 DMARC 레코드를 게시해야 하는 이유는?

    1. 공격자가 정책이 없는 방치 도메인을 흔히 사칭하므로 인가된 발송자가 없음을 명시한 레코드가 수신 측이 그런 메일을 거부할 수 있게 한다.
    2. 권한 있는 네임 서버의 DNS 질의 부하를 줄이기 위해.
    3. 조직 주 도메인 메일의 전달률을 개선하기 위해.
    4. 도메인 등록 기관이 모든 등록 도메인에 메일 레코드를 요구하므로.
    정답과 해설 보기

    정답 A. 정책이 없는 도메인은 수신 측이 판단 근거를 갖지 못해 사칭 메일을 통과시킬 수 있다. 메일을 보내지 않는 도메인에는 인가 발송자가 없음을 명시하는 SPF 와 거부 정책의 DMARC 를 게시해 사칭을 차단한다. 과거 캠페인용 도메인과 인수 과정에서 들어온 도메인이 흔한 사각지대다.

    • B · DNS 부하와 무관하다.
    • C · 미사용 도메인 설정이 다른 도메인 전달률을 바꾸지 않는다.
    • D · 등록 기관은 메일 레코드를 요구하지 않는다.

    피싱이 여전히 가장 흔한 초기 침입 경로다. 이를 가장 잘 해소하는 조합은?

    1. 모든 외부 이메일을 차단하고 내부 왕래만 허용한다.
    2. 사용자가 마지막 방어선이므로 연간 인식 교육만으로 충분하다.
    3. 사용자가 모든 메시지를 조치 전에 전화로 확인하도록 요구한다.
    4. 이메일 인증(SPF·DKIM·DMARC), 첨부와 링크 분석, 외부 발신자 표시, 피싱에 강한 다중 인증, 신고와 신속 대응으로 이루어진 계층 통제. 어떤 단일 통제도 피싱을 막지 못하기 때문이다.
    정답과 해설 보기

    정답 D. 피싱은 기술과 사람 양쪽을 노리므로 단일 통제로 막히지 않는다. 이메일 인증으로 도메인 사칭을 줄이고, 첨부·링크를 분석하고, 외부 발신자를 눈에 띄게 표시하고, 자격증명이 유출되어도 쓰이지 못하게 피싱에 강한 다중 인증을 적용하고, 사용자가 신고할 수 있게 하고 신고에 빠르게 대응한다. 교육만으로는 실패율을 0으로 만들 수 없다.

    • A · 업무가 불가능해지며 우회를 유발한다.
    • B · 교육만으로는 불충분하다.
    • C · 현실적으로 유지 불가능하다.

    7제3자 연결

    원본은 벤더·협력사 연결이 가장 흔한 침해 경로 중 하나라고 말합니다. 연결 유형은 상시 전용 연결(사이트 간 VPN, 전용 회선), 벤더 원격 지원, API·데이터 연동, 하드웨어 유지보수 업체의 현장·원격 접근입니다.

    원칙내용
    최소 권한과 범위 제한필요한 시스템에만, 필요한 포트만
    상시 연결 금지요청 시 활성화, 작업 후 비활성화
    시간 제한계정과 접근에 만료일
    감독과 기록세션 녹화, 작업 로그
    전용 식별자공유 계정 금지, 개인별 식별
    네트워크 격리전용 세그먼트에서만 접근
    계약 명시보안 요구사항, 감사 권한, 통지 의무

    상호접속 보안 협정(ISA, Interconnection Security Agreement)과 MOU로 연결 조건·책임·종료 절차를 문서화합니다. 원본은 연결 종료 시 계정 비활성화, 방화벽 규칙 제거, 공유 자격증명 변경, 전용 회선 해지가 빠져 수개월간 열려 있는 경로가 남는 사례가 흔하다고 경고합니다.

    원문 사례 — 상시 열려 있던 벤더 VPN. 설비 벤더의 원격 지원용 VPN 계정이 2년간 상시 활성 상태였고, 벤더 쪽 단말이 침해되자 그 경로로 내부망 접근이 일어났습니다. 요청 시에만 활성화하고 작업 후 비활성화하는 방식으로 바꾸고, 전용 세그먼트 제한과 세션 녹화를 적용했습니다.

    가상 예시의료기기 제조사가 병원 장비를 원격 지원하는 입장이라면 이 표는 반대쪽에서 읽힙니다. 병원은 제조사에 대해 상시 연결 금지, 장비 단위 접근, 기사별 개인 계정, 세션 기록을 요구할 것이고, 제조사는 그것을 지원할 수 있는 원격 지원 구조를 미리 갖춰야 합니다. 모든 병원에 같은 공유 계정과 상시 VPN을 쓰는 구조라면, 제조사 쪽 단말 하나가 털렸을 때 모든 고객 병원이 함께 위험해집니다.

    연결공급자 계약과 감사 권한, 종료 시 회수는 D1.11 공급망 위험 관리, 외부 인력 계정의 만료와 회수는 D1.8 인적 보안·D5.5 프로비저닝 생애주기에서 다룹니다.

    원문 위치: D4.3.md §3 제3자 연결, §7 사례 2 · 공식 개요 4.3 “Third-party connectivity (e.g., telecom providers, hardware support)”

    8종합 이해 확인

    종합 · 자작 상황 문제 (실제 시험 문제 아님)

    점검 결과다. ㉠ 지사 간 MPLS 회선에 암호화가 없다. ㉡ 벤더 원격 지원 VPN이 상시 켜져 있다. ㉢ 회사 도메인을 사칭한 메일이 SPF·DKIM을 통과해 직원에게 도착했다. ㉣ 관리자들이 업무 노트북에서 서버에 바로 접속한다. 가장 적절한 대책 묶음은?

    1. ㉠ MPLS 위에 IPSec / ㉡ 요청 시 활성화·작업 후 비활성화, 전용 세그먼트, 세션 녹화 / ㉢ DMARC 정렬과 단계적 reject / ㉣ 점프 서버·특권 접근 워크스테이션·PAM
    2. ㉠ 그대로 / ㉡ 비밀번호만 변경 / ㉢ SPF 레코드 추가 / ㉣ 노트북 백신 업데이트
    3. ㉠ 회선 사업자 변경 / ㉡ VPN 대역폭 축소 / ㉢ 메일 서버 교체 / ㉣ 관리자 교육
    4. ㉠ 분할 터널링 / ㉡ 계정 공유 / ㉢ 첫날부터 p=reject만 / ㉣ VPN 경유
    정답과 해설 보기

    정답 A. ㉠ 5절(MPLS는 분리일 뿐 암호화가 아니다), ㉡ 7절(원문 사례 2), ㉢ 6절(SPF·DKIM 통과 사칭은 DMARC 정렬로 막는다), ㉣ 4절(원문 사례 5). D의 “첫날부터 reject”는 정당한 메일을 막을 수 있습니다.

    복습

    암호화된 원격 터널을 쓰는데도 연결한 장치만 제한해야 하는 이유는 무엇인가요?

    설명 확인하기

    암호화는 경로에서 내용을 보호합니다. 원격 장치와 사용자의 신원·상태를 확인하고, 접근을 허용하는 목적지만 열어야 보호된 경로를 통한 과도한 접근을 줄일 수 있습니다.

    10핵심 요약

    1. 통신 채널 보안 = 상대가 진짜인가(인증) + 내용이 보호되는가(암호화·무결성). 경로를 믿지 않는다.
    2. VoIP: 도청, 가로채기, 톨 사기, 비싱. SRTP(미디어) + SIP over TLS(신호), VLAN 분리, 이상 발신 감시. 발신번호는 위조 가능.
    3. 회의·협업: 대기실·참가 승인, 고유 회의 ID, 녹화 고지·보존, 외부 공유 기본값 제한. 기본값이 곧 정책.
    4. IPSec VPN(3, 네트워크 전체) / SSL VPN(앱) / ZTNA(앱 단위, 비인가 자원은 안 보임). 전통 VPN의 문제 = 네트워크 수준 접근.
    5. 분할 터널링 = 동시 연결 + 아웃바운드 검사 불가. 전체 터널링 또는 SASE.
    6. 관리 접근: 점프 서버, 대역 외 관리, MFA, PAM(금고·적시 권한), 세션 녹화, 특권 접근 워크스테이션.
    7. MPLS는 논리 분리일 뿐 암호화가 아니다. 위성은 넓게 수신되고 지연이 크다 → 암호화 필수. 물리 경로가 같으면 이중화가 아니다.
    8. SPF = 허용 발송 IP, DKIM = 서명(무결성), DMARC = From 정렬 + 정책 + 보고. SPF·DKIM만으로는 사칭을 못 막는다. none → quarantine → reject. 메일 안 보내는 도메인도 설정.
    9. 제3자 연결: 최소 범위, 상시 연결 금지, 만료, 세션 녹화, 개인 식별자, 격리, 계약. ISA·MOU. 종료 시 회수 누락이 흔하다.
    원문 위치: D4.3.md §8 CISSP 시험 관점, §9 핵심 암기 요약. 원본의 출제 단정 표현은 판단 기준으로 바꿔 적었습니다.

    11주요 용어 (Glossary)

    영어 원어와 한국어 뜻 · English–Korean

    SRTP — Secure Real-time Transport Protocol · 보안 실시간 전송 프로토콜

    VoIP 음성 미디어 스트림을 암호화하는 프로토콜.

    SIP (Session Initiation Protocol) over TLS (Transport Layer Security) · TLS로 보호하는 SIP 신호 통신

    VoIP 호 제어 신호를 TLS 로 보호하는 방식.

    Toll Fraud · 톨 사기

    전화 시스템을 탈취해 국제전화 등을 무단 발신하는 공격.

    IPSec VPN / SSL VPN · IPsec 기반 가상 사설망 / TLS 기반 가상 사설망

    네트워크 계층에서 전체 네트워크 접근을 제공하는 방식과, 애플리케이션 계층에서 브라우저 기반 접근을 제공하는 방식.

    ZTNA — Zero Trust Network Access · 제로 트러스트 네트워크 접근

    신원과 상황에 기반해 애플리케이션 단위로 접근을 허용하는 방식. 네트워크 자체를 노출하지 않는다.

    Split Tunneling · 분할 터널링

    회사 트래픽만 VPN 으로 보내고 나머지는 직접 인터넷으로 보내는 구성. 검사 불가와 동시 연결 위험이 있다.

    Jump Server / Bastion Host · 점프 서버

    관리 접근을 단일 통제 지점으로 집중시키는 중계 서버.

    PAM — Privileged Access Management · 특권 접근 관리

    특권 자격증명을 금고에 보관하고 적시 권한 상승과 세션 기록을 제공하는 체계.

    PAW — Privileged Access Workstation · 특권 접근 전용 워크스테이션

    관리 업무 전용 단말. 일반 업무와 인터넷 사용을 금지한다.

    Backhaul · 백홀

    엣지나 기지국에서 코어 네트워크로 트래픽을 집선해 전달하는 구간.

    MPLS — Multiprotocol Label Switching · 다중 프로토콜 라벨 스위칭

    라벨 기반 전달 기술. 논리 분리를 제공하지만 암호화는 제공하지 않는다.

    ISA — Interconnection Security Agreement · 상호접속 보안 협정

    조직 간 연결의 보안 조건과 책임을 명시한 협정.

    연습문제 6개 바로가기

    표시 없는 본문은 원본 정리 파일의 내용 · 보충은 원본에 없어 더한 설명 · 가상 예시는 지어낸 상황 · 연결은 다른 단원과의 관계 · 확인 필요는 그대로 확정하지 않은 부분

    애플리케이션을 아무리 잘 만들어도, 그 아래의 운영체제나 하드웨어가 뚫리면 모든 것이 무너집니다. 이 단원은 그 바닥, 즉 하드웨어와 운영체제가 제공하는 보안 기능을 다룹니다. 누가 모든 접근을 검사하는가(참조 모니터), 프로그램끼리 서로를 어떻게 침범하지 못하는가(격리와 메모리 보호), 기기가 변조되지 않았음을 어떻게 아는가(TPM, 보안 부팅)가 중심입니다.

    원본은 관계를 TCB ⊃ 보안 커널 ⊃ 참조 모니터로 정리합니다. 그리고 TCB는 작을수록 좋다고 강조합니다. 신뢰해야 하는 범위가 작아야 검증할 수 있기 때문입니다.

    참조 모니터의 세 가지 요건

    요건의미
    완전한 중재 Complete mediation모든 접근을 예외 없이 검사한다
    변조 불가 Tamper-proof격리되어 수정할 수 없다
    검증 가능 Verifiable충분히 작고 단순해 정확성을 분석할 수 있다

    원본의 핵심 문장은 우회 경로가 하나라도 있으면 참조 모니터는 무의미하다입니다. 완전한 중재가 첫 번째 요건인 이유입니다.

    보충세 요건을 건물 출입 관리에 대어 보면 이렇습니다. 완전한 중재는 “모든 출입구에 경비가 있다”, 변조 불가는 “경비를 매수하거나 출입 명부를 고칠 수 없다”, 검증 가능은 “경비 규칙이 단순해서 제대로 지켜지는지 감사할 수 있다”입니다. 뒷문 하나가 열려 있으면 정문 경비가 아무리 엄격해도 소용이 없습니다. 소프트웨어에서는 정상 화면만 검사하고 백그라운드 작업이나 내보내기 기능이 같은 자료를 검사 없이 읽는 경우가 그 뒷문입니다.

    연결TCB를 작게 하는 원칙은 D3.1 안전한 설계 원칙의 7절, 참조 모니터가 강제하는 규칙(BLP, Biba 등)은 D3.2 보안 모델에서 다뤘습니다. “모든 접근을 매번 검사”는 제로 트러스트의 생각과도 같습니다. 원본은 참조 모니터 개념의 기원으로 Anderson Report(1972)를 듭니다.

    원본 연습문제 · D3.4-Q01

    참조 모니터가 충족해야 하는 속성의 조합은?

    1. 완전한 중재, 변조 불가 동작, 검증 가능성.
    2. 저장·전송·사용 중 암호화.
    3. 높은 성능, 벤더 독립성, 오픈소스 라이선스.
    4. 이중화, 지리적 분산, 자동 장애 조치.
    정답과 해설 보기

    정답 A. 참조 모니터는 모든 접근 요청을 예외 없이 검사하고(완전한 중재), 격리되어 수정할 수 없으며(변조 불가), 충분히 작고 단순해 정확성을 분석할 수 있어야 한다(검증 가능). 우회 경로가 하나라도 있으면 참조 모니터는 무의미해진다.

    • B · 데이터 상태별 암호화는 별개의 보호 수단이다.
    • C · 성능과 라이선스는 참조 모니터의 정의 요건이 아니다.
    • D · 이중화는 가용성 설계 요소다.

    2보호 링

    보호 링(Protection Rings)은 CPU가 제공하는 권한 계층입니다. 안쪽일수록 권한이 높습니다.

    링영역
    Ring -3관리 엔진 등 하위 펌웨어
    Ring -2시스템 관리 모드(SMM)
    Ring -1하이퍼바이저
    Ring 0운영체제 커널 (최고 권한, 전통적 의미)
    Ring 1·2장치·입출력 드라이버(일부 설계)
    Ring 3사용자 애플리케이션 (최저 권한)

    현대 운영체제는 대부분 Ring 0과 Ring 3만 씁니다. 가상화와 펌웨어가 더해지면서 음수 링이라는 표현이 쓰입니다. 사용자 모드와 커널 모드 사이의 전환은 시스템 호출(system call)로 이루어지며, 이 경계가 중요한 신뢰 경계입니다.

    원본이 강조하는 결과는 이것입니다. 더 낮은 링이 침해되면 그 위 전체가 무력화된다. 하이퍼바이저가 뚫리면 그 위의 모든 가상 머신이 노출됩니다. 펌웨어와 하이퍼바이저 보안이 중요한 이유입니다.

    보충낮은 링은 위층을 감시하는 자리이기도 합니다. 그래서 낮은 층에 숨은 악성코드(부트킷, 펌웨어 악성코드)는 위층의 백신이 볼 수 없습니다. 감시하는 쪽보다 아래에 있기 때문입니다. 6절의 보안 부팅과 측정 부팅이 아래층부터 차례로 검증하는 이유가 여기 있습니다.

    연결사용자-커널 경계를 신뢰 경계로 보는 관점은 D1.10 위협 모델링의 위협 모델링, 하이퍼바이저와 VM 탈출은 9절과 D3.5 아키텍처별 취약점에서 다룹니다.

    원본 연습문제 · D3.4-Q05

    가상화 환경에서 하이퍼바이저 침해가 특히 심각하게 평가되는 이유는?

    1. 게스트 운영체제는 자체 보안 통제를 전혀 갖지 않는다.
    2. 하이퍼바이저는 운영에 배포되면 패치할 수 없다.
    3. 게스트 커널보다 낮은 링에서 동작하므로 그 위의 모든 게스트가 노출된다.
    4. 하이퍼바이저는 설계상 모든 게스트 데이터를 평문으로 저장한다.
    정답과 해설 보기

    정답 C. 하이퍼바이저는 Ring -1 에서 동작해 게스트 커널(Ring 0)보다 낮은 계층에 있다. 더 낮은 링이 침해되면 그 위의 모든 계층이 무력화되므로 하이퍼바이저가 뚫리면 그 위의 모든 가상머신이 노출된다.

    • A · 게스트 OS 도 자체 통제를 갖지만 하위 계층 침해에는 무력하다.
    • B · 하이퍼바이저도 패치 가능하다.
    • D · 평문 저장이 설계 전제가 아니다.

    3프로세스 격리와 메모리 보호

    프로세스 격리

    각 프로세스는 자기 주소 공간만 접근할 수 있고, 다른 프로세스의 메모리를 읽거나 쓸 수 없습니다. 구현 수단은 가상 메모리(프로세스마다 독립된 가상 주소 공간), 세그멘테이션(논리 단위로 나눠 권한 부여), 페이징(고정 크기 페이지 단위 관리), MMU(주소 변환과 권한 검사를 하드웨어로 수행)입니다.

    공격 완화 기법

    기법막는 것
    ASLR 주소 공간 배치 무작위화공격자가 메모리 주소를 예측하는 것
    DEP / NX 데이터 실행 방지데이터 영역의 코드 실행
    스택 카나리스택 버퍼 오버플로로 복귀 주소를 바꾸는 것
    CFI 제어 흐름 무결성비정상적인 실행 흐름 전환
    스택/힙 분리영역 간 침범

    원본의 핵심은 이 기법들은 취약점을 없애는 것이 아니라 악용을 어렵게 만든다는 것입니다. 근본 해결은 안전한 코딩입니다.

    메모리 잔류

    메모리에 남은 키나 자격증명은 덤프로 유출될 수 있어서, 사용 후 명시적으로 지워야(zeroization) 합니다.

    원문 사례 — 메모리에 남은 키. 프로세스 메모리 덤프에서 복호화 키가 평문으로 발견되었습니다. 사용 후 버퍼를 지우지 않았기 때문입니다. 원본은 암호 라이브러리가 보통 키 버퍼를 지우지만, 애플리케이션이 복사본을 만들어 두면 그 복사본은 남는다고 지적합니다.

    보충스택 버퍼 오버플로를 예로 세 기법의 역할을 나누면 이렇습니다. 공격자는 버퍼를 넘치게 해 복귀 주소를 자기 코드 주소로 바꾸려 합니다. 카나리는 덮어쓰기를 탐지하고, DEP는 넣은 코드가 실행되지 못하게 하고, ASLR은 어디로 뛰어야 할지 모르게 합니다. 셋 다 공격을 어렵게 할 뿐 버퍼가 넘치는 버그 자체는 남아 있으므로, 우회 기법이 나오면 다시 위험해집니다.

    연결버퍼 오버플로 같은 취약점을 코드에서 없애는 방법은 D8.5 안전한 코딩, 사용 중 데이터 보호는 D2.2 자산 취급 요구사항·D2.6 데이터 보안 통제에서 다룹니다. D2.4 데이터 생애주기의 데이터 잔류가 저장 매체의 문제라면 메모리 잔류는 같은 문제의 메모리 버전입니다.

    원문 위치: D3.4.md §3 프로세스 격리와 메모리 보호, §7 사례 4 · 기존 문제 주제(완화 기법)

    4TPM — 기기의 무결성을 보증하는 칩

    쉬운 설명

    TPM(Trusted Platform Module)은 메인보드에 들어 있는 하드웨어 보안 칩이며, TCG(Trusted Computing Group) 표준입니다.

    기능설명
    키 생성·보관하드웨어 난수로 키를 만들고, 키가 칩 밖으로 나오지 않는다
    플랫폼 무결성 측정부팅 과정의 해시를 PCR에 누적 기록
    봉인(Sealing)특정 플랫폼 상태에서만 복호화되도록 데이터를 묶는다
    증명(Attestation)플랫폼 상태를 외부에 증명한다
    바인딩(Binding)특정 TPM에서만 복호화할 수 있게 암호화

    PCR(Platform Configuration Register)은 부팅의 각 단계를 측정한 해시를 누적합니다. 한 단계라도 바뀌면 PCR 값이 달라집니다.

    봉인이 핵심이다

    디스크 암호화 키를 PCR 값에 봉인해 두면, 부팅 구성이 변조된 상태에서는 키가 풀리지 않습니다. 디스크를 떼어 다른 기기에 붙여도 복호화할 수 없습니다.

    원문 사례 — TPM 봉인이 막은 디스크 탈취. 도난당한 노트북의 SSD를 떼어 다른 기기에 연결했지만 데이터를 읽을 수 없었습니다. 전체 디스크 암호화 키가 원래 기기의 TPM에 PCR 값과 함께 봉인되어 있었기 때문입니다.

    보충봉인과 바인딩의 차이는 조건의 개수입니다. 바인딩은 “이 TPM에서만”이고, 봉인은 “이 TPM에서, 그리고 이 부팅 상태일 때만”입니다. 그래서 봉인은 디스크를 옮기는 공격과 부팅 과정을 바꾸는 공격(부트로더 교체)을 함께 막습니다. 반대로 정상적인 펌웨어 업데이트도 PCR 값을 바꾸므로, 업데이트 절차에 키 재봉인이나 복구 키 준비가 들어가야 정상 사용자가 잠기는 일이 없습니다.

    원문 위치: D3.4.md §3 TPM, §6 TCG TPM Specification, §7 사례 1 · 공식 개요 3.4 “Trusted Platform Module (TPM)”

    성능낮음높음(하드웨어 가속)
    인증—FIPS 140 수준 인증이 일반적

    원본의 요약입니다. TPM은 “이 기기가 변조되지 않았음”을 보증하고, HSM은 “키를 안전하게 보관하고 대량 연산을 처리”합니다.

    가상 예시한 회사가 두 가지 키를 강화하려 합니다. 하나는 각 노트북의 디스크 잠금을 푸는 키, 다른 하나는 배포하는 장비 소프트웨어에 서명하는 회사 전체의 키입니다. 둘을 같은 장치에 넣자는 제안이 나왔습니다. 첫째 키의 목표는 “승인된 부팅 상태의 그 노트북에서만 풀린다”이므로 노트북마다 있는 TPM이 맞습니다. 둘째 키는 여러 빌드 작업이 사용하고, 키를 꺼내지 않고 서명만 하며, 누가 언제 서명했는지 기록하고 이중 승인을 걸어야 하므로 HSM이 맞습니다. 서명 키가 유출되면 모든 고객 장비가 위조 소프트웨어를 믿게 되기 때문입니다.

    연결FIPS 140(암호 모듈 보안 요구사항, 현행은 140-3)과 키 관리 수명주기는 D3.6 암호 솔루션, 소프트웨어 서명과 공급망 무결성은 D8.2 개발 생태계 보안 통제에서 다룹니다.

    원문 위치: D3.4.md §3 TPM vs HSM, §5 둘째 표, §6 FIPS 140-2 / 140-3 · 기존 문제 주제(TPM과 HSM 구분)

    6보안 부팅, 측정 부팅, 신뢰 사슬

    쉬운 설명

    구분동작목적
    Secure Boot 보안 부팅서명을 검증해 맞지 않으면 부팅을 중단차단
    Measured Boot 측정 부팅각 단계를 측정해 PCR에 기록하고 부팅은 계속기록과 증명

    측정 부팅은 나중에 원격 증명(remote attestation)으로 “이 기기가 어떤 상태로 부팅했는지”를 입증하는 데 쓰입니다.

    운영체제

    변경할 수 없는 신뢰 루트(Root of Trust)에서 시작해 각 단계가 다음 단계를 검증하며 올라갑니다. UEFI Secure Boot가 대표적인 구현이며 서명되지 않은 부트로더나 드라이버의 로딩을 막습니다.

    원문 사례 — 측정 부팅으로 발견한 펌웨어 변조. 원격 증명 결과 일부 단말의 PCR 값이 기준과 달랐고, 조사해 보니 부트로더가 교체되어 있었습니다. 원본은 보안 부팅만 있었다면 부팅이 막혀 사용자는 “고장”으로 여겼을 수 있지만, 측정 부팅은 상태를 기록하고 증명하므로 중앙에서 어떤 단말이 어떻게 변조되었는지 식별할 수 있었다고 설명합니다.

    보충둘은 경쟁 관계가 아니라 짝입니다. 보안 부팅은 알려진 나쁜 것(서명 없는 코드)을 그 자리에서 막고, 측정 부팅은 서명은 맞지만 기대와 다른 상태(예: 승인된 구버전으로 되돌린 부트로더)까지 기록해서 나중에 판단할 수 있게 합니다. 증명(attestation)은 그 기록을 원격 검증자에게 보여 주는 단계입니다. 서버가 “PCR 값이 기준과 같은 단말만 사내 자원에 접속 허용”으로 정책을 걸면, D3.1 안전한 설계 원칙의 제로 트러스트에서 말한 “기기 상태를 신호로 쓰는 판단”이 됩니다.

    용어 주의Root of Trust는 이 교재에서 신뢰 루트로 통일합니다(원본 D1.11은 ‘신뢰 기반’). 1절의 TCB(신뢰 컴퓨팅 기반)와는 다른 개념입니다. 신뢰 루트는 사슬의 출발점 하나이고, TCB는 보안을 강제하는 메커니즘 전체입니다.

    연결하드웨어 신뢰 루트(Silicon Root of Trust)와 PUF는 D1.11 공급망 위험 관리, 사슬의 각 고리인 디지털 서명 검증은 D1.2 보안 개념 (CIA 등)·D3.6 암호 솔루션에서 다룹니다. 원본은 NIST SP 800-147(BIOS 보호), 800-155(BIOS 무결성 측정), 800-193(플랫폼 펌웨어 복원력)을 관련 표준으로 듭니다.

    이해 확인 · 자작 상황 문제 (실제 시험 문제 아님)

    회사가 현장에 출하한 장비 500대 중 일부의 부트로더가 바뀌었다는 첩보를 받았다. 장비를 멈추지 않고 어떤 장비가 영향을 받았는지 중앙에서 식별하려면 무엇이 가장 직접적인가?

    1. 보안 부팅만 켜서 변조된 장비가 부팅되지 않게 한다.
    2. 측정 부팅으로 기록된 PCR 값을 원격 증명으로 받아 기준값과 비교한다.
    3. 모든 장비의 디스크를 HSM으로 암호화한다.
    4. ASLR을 켠다.
    정답과 해설 보기

    정답 B. 측정 부팅은 부팅을 막지 않고 상태를 기록하며, 원격 증명으로 그 기록을 중앙에서 확인할 수 있습니다(원문 사례 2).

    • A: 변조된 장비는 멈추지만 “장비를 멈추지 않고 식별”이라는 요구와 맞지 않고, 현장에서는 고장으로 보입니다.
    • C: HSM은 장비마다 들어가는 무결성 측정 장치가 아닙니다.
    • D: ASLR은 실행 중 메모리 공격을 어렵게 할 뿐 부트로더 변조를 알려 주지 않습니다.

    7TEE — 신뢰 실행 환경

    TEE(Trusted Execution Environment)는 CPU 안에 격리된 실행 영역을 만들어 그 안의 코드와 데이터를 운영체제조차 접근할 수 없게 합니다.

    • 운영체제나 하이퍼바이저가 침해되어도 enclave 내부는 보호된다
    • 기밀 컴퓨팅(Confidential Computing)의 기반이다
    • 사용 중(in use) 데이터 보호의 핵심 수단이다

    보충TEE가 줄이는 위험과 남기는 위험을 나눠 봐야 합니다. 줄이는 것은 “같은 기계의 운영체제나 관리자가 처리 중인 데이터를 들여다보는 위험”입니다. 남는 것은 TEE에 넣은 코드 자체의 버그, 밖에서 들어오는 입력을 누가 검사하는가, 결과가 어디로 나가는가입니다. 안전한 영역에서 계산해도 결과를 평문 로그로 내보내면 그 로그는 여전히 보호가 필요합니다. 또 TEE도 부채널 공격의 대상이 될 수 있습니다(10절).

    연결데이터의 세 상태와 사용 중 데이터의 어려움은 D2.2 자산 취급 요구사항, 통제 선택은 D2.6 데이터 보안 통제에서 다뤘습니다.

    원본 연습문제 · D3.4-Q09

    신뢰 실행 환경(TEE)이 전통적 프로세스 격리가 제공하지 못하는 보안 속성은?

    1. 두 사용자 프로세스가 서로의 메모리를 읽지 못하게 한다.
    2. 운영체제나 하이퍼바이저가 침해되어도 enclave 내부를 보호한다.
    3. 애플리케이션에 소프트웨어 취약점이 결코 없음을 보장한다.
    4. 저장 데이터 암호화의 필요성을 제거한다.
    정답과 해설 보기

    정답 B. 전통적 프로세스 격리는 OS 가 신뢰된다는 전제 위에 있어 OS 가 침해되면 무력해진다. TEE 는 CPU 내부에 격리된 실행 영역을 만들어 OS 나 하이퍼바이저가 침해되어도 enclave 내부의 코드와 데이터를 보호한다. 기밀 컴퓨팅의 기반이다.

    • A · 그것은 일반적인 프로세스 격리도 제공한다.
    • C · 취약점 부재를 보장하지 않는다.
    • D · 저장 데이터 보호는 별개의 요구다.

    8암호화를 돕는 하드웨어 기능

    • 하드웨어 가속 — CPU의 암호 명령어 집합으로 성능 향상
    • 하드웨어 난수 생성기(TRNG) — 예측 불가능한 난수. 소프트웨어 의사난수보다 안전하다
    • 전체 디스크 암호화(FDE) — TPM에 키를 봉인해 사용
    • 자체 암호화 드라이브(SED) — 드라이브가 스스로 암복호화한다. 암호 소거에 유용하다
    • 메모리 암호화 — 메모리 덤프로부터 보호

    보충난수가 왜 하드웨어 기능 목록에 있을까요. 암호 키는 예측할 수 없어야 하는데, 소프트웨어가 만드는 의사난수는 출발값(시드)을 알면 다시 만들 수 있습니다. 부팅 직후의 임베디드 장비처럼 무작위성의 원천이 부족한 환경에서 같은 키가 여러 장비에 만들어지는 문제가 실제로 보고되어 왔습니다(일반 지식에 근거한 보충). 하드웨어 난수 생성기는 물리 현상에서 무작위성을 얻어 이 문제를 줄입니다.

    연결SED와 암호 소거는 D2.4 데이터 생애주기, 디지털 서명이 제공하는 속성(무결성, 출처 인증, 부인방지)과 암호 알고리즘은 D3.6 암호 솔루션에서 다룹니다.

    원본 연습문제 · D3.4-Q13

    디지털 서명이 제공하는 속성은?

    1. 기밀성만.
    2. 기밀성과 가용성.
    3. 가용성과 부인방지.
    4. 무결성, 서명자 인증, 부인방지. 다만 기밀성은 제공하지 않는다. 서명이 내용을 가리지 않기 때문이다.
    정답과 해설 보기

    정답 D. 서명은 사설키로 만들고 공개키로 검증한다. 그래서 서명자만 만들 수 있고(인증), 내용이 바뀌면 검증이 실패하며(무결성), 서명자가 나중에 부인할 수 없다(부인방지). 내용을 숨기려면 암호화를 함께 적용해야 하며 서명과 암호화는 별개 연산이다.

    • A · 기밀성이 아니라 무결성·인증·부인방지다.
    • B · 서명은 기밀성을 제공하지 않는다.
    • C · 가용성과 무관하다.

    9가상화와 격리 강도

    기술격리 수준
    전가상화 하이퍼바이저강함 — 커널 분리
    컨테이너약함 — 커널 공유
    샌드박스애플리케이션 수준

    컨테이너는 호스트 커널을 공유하므로 가상 머신보다 격리가 약합니다. 커널 취약점이 컨테이너 탈출(container escape)로 이어질 수 있습니다. 여러 고객(테넌트)을 한 환경에 올리면서 강한 격리가 필요하면 가상 머신이나 전용 경량 VM을 씁니다. VM 탈출(VM escape)은 게스트에서 하이퍼바이저로 침투하는 공격이며, Ring -1이 뚫리는 것이므로 영향이 치명적입니다.

    원문 사례 — 컨테이너 격리를 과신한 경우. 여러 고객의 서비스를 컨테이너로만 나눠 운영했는데, 커널 취약점이 공개되자 컨테이너 탈출로 같은 호스트의 다른 고객 컨테이너까지 접근할 수 있게 되었습니다.

    판단 순서격리 방식을 고를 때 ① 같은 호스트 위에 함께 놓이는 것들이 서로 믿을 수 있는 사이인가(같은 팀의 서비스인가, 서로 다른 고객인가) ② 서로 믿을 수 없다면 커널을 공유해도 되는가 ③ 안 된다면 VM 또는 경량 VM ④ 같은 팀 안이라면 컨테이너 + 커널 패치와 런타임 제한으로 충분한가를 봅니다.

    연결가상화·컨테이너·클라우드 아키텍처의 취약점과 완화는 D3.5 아키텍처별 취약점, 공동 책임 모델(누가 하이퍼바이저를 책임지나)은 D3.1 안전한 설계 원칙에서 다룹니다.

    10은닉 채널과 부채널

    은닉 채널은 정상 통신 경로가 아닌 수단으로 정보가 흐르는 경로입니다(D3.2 보안 모델의 비간섭 모델).

    유형방식
    저장 채널 Storage공유 자원의 상태로 전달(파일 잠금, 디스크 사용량)
    타이밍 채널 Timing응답 시간의 차이로 전달

    대응은 자원 분리, 잡음 추가, 대역폭 제한, 감사입니다. 원본은 완전한 제거는 어렵고 대역폭을 받아들일 수 있는 수준으로 낮추는 것이 현실적인 목표라고 설명합니다.

    원문 사례 — 은닉 채널을 통한 유출. 격리된 고등급 시스템에서 저등급 시스템으로 디스크 사용량 변화를 이용해 데이터가 새어 나갔습니다. 고등급 프로세스가 파일 크기를 조절하고 저등급 프로세스가 남은 용량을 관찰하는 방식이었습니다.

    원본은 부채널 공격(Side-channel attack)과 구분하라고 합니다. 은닉 채널은 내부 공모자가 일부러 정보를 내보내는 경로이고, 부채널은 관찰을 통해 비밀을 추출하는 공격(전력 소비, 전자파, 처리 시간 분석)입니다.

    연결비간섭 모델은 D3.2 보안 모델, 전력·타이밍 분석 같은 부채널 공격은 D3.7 암호 분석 공격에서 다룹니다.

    원문 위치: D3.4.md §3 은닉 채널, §7 사례 5

    11종합 이해 확인

    종합 · 자작 상황 문제

    보안 설계 검토에서 나온 주장이다. ㉠ “ASLR과 DEP를 켰으니 이 버퍼 오버플로 취약점은 해결되었다.” ㉡ “고객별 서비스를 컨테이너로 나눴으니 VM만큼 격리된다.” ㉢ “TPM이 있으니 회사 전체의 코드 서명 키도 각 서버의 TPM에 보관하면 된다.” ㉣ “접근 검사 모듈이 화면 요청은 모두 검사하니, 일괄 내보내기 배치 작업은 검사를 생략해도 된다.” 바르게 반박한 것은?

    1. ㉠ 완화 기법은 악용을 어렵게 할 뿐 취약점을 없애지 않는다 / ㉡ 컨테이너는 커널을 공유한다 / ㉢ 중앙 서명 키는 HSM이 맞다 / ㉣ 완전한 중재 위반이다
    2. ㉠ 맞다 / ㉡ 맞다 / ㉢ 맞다 / ㉣ 맞다
    3. ㉠ CFI도 켜야 해결된다 / ㉡ 샌드박스가 VM보다 강하다 / ㉢ TPM은 서명을 못 한다 / ㉣ 검증 가능성 위반이다
    4. ㉠ 측정 부팅이 필요하다 / ㉡ Ring 3에서 실행하면 된다 / ㉢ PCR에 키를 저장한다 / ㉣ 변조 불가 위반이다
    정답과 해설 보기

    정답 A. ㉠ 3절, ㉡ 9절, ㉢ 5절(가상 예시), ㉣ 1절. 우회 경로가 하나라도 있으면 참조 모니터는 의미가 없고, 이것은 “모든 접근을 검사한다”는 완전한 중재의 위반입니다.

    12핵심 개념을 내 말로 설명하기

    복습

    TPM, HSM, 보호 링을 모두 키를 넣는 상자로 생각하면 무엇을 놓치나요?

    설명 확인하기

    TPM은 플랫폼의 상태 및 장치에 결부된 신뢰에, HSM은 조직이 관리하는 암호 키와 암호 연산에 쓰입니다. 보호 링은 실행 코드가 자원에 행사할 특권을 분리하는 메커니즘입니다.

    13핵심 요약

    1. TCB(전체) ⊃ 보안 커널(구현) ⊃ 참조 모니터(개념). TCB는 작을수록 좋다.
    2. 참조 모니터 3요건: 완전한 중재 · 변조 불가 · 검증 가능. 우회 경로가 하나라도 있으면 무의미.
    3. Ring 0 커널 / Ring 3 사용자 / Ring -1 하이퍼바이저 / Ring -2 SMM. 현대 OS는 주로 0과 3. 낮은 링이 뚫리면 위 전체가 무력화.
    4. 메모리 보호: 가상 메모리, 세그멘테이션, 페이징, MMU. 완화 기법: ASLR / DEP·NX / 스택 카나리 / CFI — 취약점 제거가 아니라 악용을 어렵게. 키는 사용 후 소거.
    5. TPM = 메인보드 칩, 플랫폼 무결성. 기능: 키 생성·보관, PCR 측정, 봉인, 증명, 바인딩. 봉인 = 특정 PCR 상태에서만 복호화.
    6. HSM = 전용 장비, 키 관리·대량 연산, FIPS 140 인증.
    7. Secure Boot = 서명 검증 실패 시 차단, Measured Boot = 측정해 PCR에 기록하고 계속(원격 증명에 사용).
    8. 신뢰 사슬: 신뢰 루트 → 펌웨어 → 부트로더 → 커널 → OS. UEFI Secure Boot.
    9. TEE/enclave = CPU 안의 격리 실행 영역. OS가 침해되어도 내부 보호. 기밀 컴퓨팅의 기반.
    10. 하드웨어 암호 지원: 가속, TRNG, FDE, SED(암호 소거), 메모리 암호화.
    11. 컨테이너는 커널 공유 → 격리 약함. VM 탈출은 Ring -1 침해.
    12. 은닉 채널 = 저장(상태) + 타이밍(시간). 대역폭 축소가 현실적 목표. 은닉 채널(의도적 유출) ≠ 부채널(관찰로 추출).
    원문 위치: D3.4.md §8 CISSP 시험 관점, §9 핵심 암기 요약(16항목). 원본의 “가장 자주 묻는 구분” 같은 출제 단정 표현은 판단 기준으로 바꿔 적었습니다. 공식 개요 3.4의 예시는 memory protection, Trusted Platform Module (TPM), encryption/decryption입니다.

    14주요 용어 (Glossary)

    영어 원어와 한국어 뜻 · English–Korean

    TCB — Trusted Computing Base · 신뢰 컴퓨팅 기반

    보안 정책을 강제하는 하드웨어·펌웨어·소프트웨어의 총합. 작을수록 검증이 쉽다.

    Reference Monitor · 참조 모니터

    주체의 객체 접근을 중재하는 추상 개념. 완전한 중재, 변조 불가, 검증 가능을 충족해야 한다.

    Security Kernel · 보안 커널

    참조 모니터를 실제로 구현한 TCB 의 핵심 부분.

    Complete Mediation · 완전한 중재

    모든 접근 요청을 예외 없이 검사해야 한다는 요건. 우회 경로가 하나라도 있으면 무의미하다.

    Protection Rings · 보호 링

    CPU 가 제공하는 권한 계층. Ring 0 커널, Ring 3 사용자, Ring -1 하이퍼바이저, Ring -2 SMM.

    Process Isolation · 프로세스 격리

    각 프로세스가 자신의 주소 공간만 접근하도록 제한하는 것.

    ASLR — Address Space Layout Randomization · 주소 공간 배치 무작위화

    메모리 배치를 무작위화해 공격자가 주소를 예측하지 못하게 하는 기법.

    DEP / NX — Data Execution Prevention / No-eXecute · 데이터 실행 방지 / 실행 금지

    데이터 영역에서 코드가 실행되지 못하게 하는 기법.

    Stack Canary · 스택 카나리

    스택에 삽입한 값의 변조 여부로 버퍼 오버플로를 탐지하는 기법.

    TPM — Trusted Platform Module · 신뢰 플랫폼 모듈

    플랫폼 무결성 측정과 키 보호를 담당하는 메인보드 내장 보안 칩.

    PCR — Platform Configuration Register · 플랫폼 구성 레지스터

    TPM 내부에서 부팅 단계별 측정 해시를 누적 기록하는 레지스터.

    Sealing · 봉인

    데이터를 특정 플랫폼 상태(PCR 값)에 묶어 그 상태에서만 복호화되게 하는 TPM 기능.

    Attestation · 증명

    플랫폼의 무결성 상태를 외부에 입증하는 기능.

    HSM — Hardware Security Module · 하드웨어 보안 모듈

    키 관리와 대량 암호 연산을 수행하는 전용 하드웨어. FIPS 140 인증이 일반적이다.

    Secure Boot / Measured Boot · 보안 부팅 / 측정 부팅

    서명 검증 실패 시 부팅을 중단하는 방식과, 각 단계를 측정해 기록하되 부팅은 계속하는 방식.

    Root of Trust · 신뢰 기반

    변경 불가능한 신뢰의 출발점. 신뢰 사슬이 여기서 시작된다.

    TEE — Trusted Execution Environment · 신뢰 실행 환경

    CPU 내부의 격리된 실행 영역. OS 가 침해되어도 내부는 보호된다.

    Covert Channel · 은닉 채널

    정상 통신 경로가 아닌 수단으로 정보가 흐르는 경로. 저장 채널과 타이밍 채널이 있다.

    VM Escape / Container Escape · 가상 머신 격리 이탈 / 컨테이너 격리 이탈

    게스트에서 하이퍼바이저로, 또는 컨테이너에서 호스트로 탈출하는 공격.

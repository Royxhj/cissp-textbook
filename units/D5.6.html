    2Kerberos

    MIT에서 개발한 티켓 기반 대칭키 인증 프로토콜이며 Windows 도메인 인증의 기본입니다. 이름은 머리 셋 달린 지옥문 개에서 왔고, 세 요소(클라이언트, 서버, KDC)를 가리킵니다.

    구성요소역할
    KDC Key Distribution Center인증 서비스 전체를 호스팅
    AS Authentication Service신원 확인 후 TGT 발급
    TGS Ticket Granting ServiceTGT를 받아 서비스 티켓 발급
    Principal인증 대상(사용자, 서비스, 호스트)
    Realm공통 KDC를 공유하는 관리 영역

    인증 흐름

    1. 클라이언트 → AS: 인증 요청(사용자 식별자)
    2. AS → 클라이언트: TGT + 세션키(사용자 비밀키로 암호화)
    3. 클라이언트 → TGS: TGT + 서비스 요청 + 인증자(authenticator)
    4. TGS → 클라이언트: 서비스 티켓 + 서비스 세션키
    5. 클라이언트 → 서비스: 서비스 티켓 + 인증자
    6. 서비스 → 클라이언트: (상호 인증 시) 타임스탬프 응답
    설계 특징의미
    비밀번호가 네트워크로 전송되지 않음비밀번호에서 파생된 키로 암호화된 데이터를 복호화할 수 있는지로 증명
    상호 인증서버도 자신을 증명 → 가짜 서버 탐지
    SSOTGT를 가진 동안 서비스마다 비밀번호 재입력 없음
    티켓 수명 제한TGT는 보통 10시간, 서비스 티켓은 더 짧음
    타임스탬프로 재생 방지인증자에 타임스탬프 포함

    보충TGT는 놀이공원 입장 팔찌, 서비스 티켓은 놀이기구별 탑승권에 비유할 수 있습니다. 입구(AS)에서 신분을 한 번 확인받고 팔찌를 차면, 놀이기구마다 매표소(TGS)에 팔찌를 보여 주고 탑승권을 받습니다. 팔찌만으로 놀이기구에 바로 탈 수는 없고, 탑승권이 있어도 키 제한(앱의 인가 정책)은 따로 적용됩니다. 티켓이 있다는 것과 특정 자료에 접근할 수 있다는 것은 다른 문제입니다.

    전제 조건과 취약점

    시각 동기화가 필수입니다. 타임스탬프 기반 재생 방지 때문에 허용 오차(보통 5분)를 넘으면 인증이 실패합니다. 특정 도메인 컨트롤러로만 인증이 갑자기 전면 실패한다면 시각 차이를 가장 먼저 의심합니다.

    원문 사례 — 시각 동기화로 멈춘 Kerberos. 도메인 컨트롤러 한 대의 시각 동기화가 끊겨 약 12분 차이가 났고, 그 컨트롤러로 인증한 사용자들이 원인 불명으로 로그인에 실패했습니다. 시각 원천을 통일하고 동기화 상태를 모니터링했습니다.

    KDC는 단일 실패점이자 최고가치 표적입니다.

    위협내용대응
    가용성KDC가 멈추면 도메인 인증 전면 중단다중화
    골든 티켓krbtgt 키(KDC가 TGT를 서명하는 키)를 가진 자는 임의 사용자·임의 권한의 TGT를 스스로 만든다krbtgt 비밀번호를 두 번 연속 교체
    실버 티켓특정 서비스 계정 키로 그 서비스의 티켓 위조. KDC를 거치지 않아 탐지가 더 어려움서비스 계정 키 보호
    Kerberoasting서비스 티켓을 요청해 받아 오프라인에서 서비스 계정 비밀번호 크래킹길고 무작위한 비밀번호, 관리형 서비스 계정
    Pass-the-Ticket메모리에서 티켓을 훔쳐 재사용특권 계정 로그온 위치 제한, 자격증명 보호 기능
    AS-REP Roasting사전 인증이 꺼진 계정은 응답을 받아 오프라인 크래킹 가능사전 인증 강제
    무제한 위임위임을 허용한 서버가 침해되면 접속한 사용자의 TGT로 다른 서비스에 가장제약 위임·자원 기반 제약 위임, 특권 계정은 위임 불가 표시

    원문 사례 — Kerberoasting으로 뚫린 서비스 계정. 일반 사용자 권한을 얻은 공격자가 SPN이 등록된 서비스 계정들의 티켓을 요청해 오프라인에서 크래킹했고, 사전 단어 기반 비밀번호를 쓰던 계정 두 개를 복원했습니다. 관리형 서비스 계정으로 전환하고, 불필요한 SPN을 제거하고, 비정상적인 서비스 티켓 요청 패턴을 탐지 규칙으로 추가했습니다.

    연결골든 티켓, Pass the Ticket, Kerberoasting의 공격 관점은 D3.7 암호 분석 공격, 서비스 계정 관리는 D5.5 프로비저닝 생애주기의 7절, SSO의 단일 실패점은 D5.2 식별·인증 전략의 6절에서 다룹니다.

    원본 연습문제 · D5.6-Q19

    Kerberos 에서 티켓 발급 티켓(TGT)은 무엇에 쓰이는가?

    1. 특정 애플리케이션 서버에 직접 접근하는 데.
    2. 최초 인증이 성공한 뒤 비밀번호를 다시 입력하지 않고 티켓 발급 서비스에서 서비스 티켓을 요청하는 데.
    3. 워크스테이션의 사용자 파일을 암호화하는 데.
    4. 클라이언트와 서버 사이의 시각을 동기화하는 데.
    정답과 해설 보기

    정답 B. TGT 는 "나는 이미 인증되었다" 는 증명이다. 이것으로 각 서비스에 대한 서비스 티켓을 받아 쓰므로 비밀번호가 네트워크를 반복해서 오가지 않는다. 이 구조 때문에 TGT 가 탈취되면 여러 서비스에 접근할 수 있고 골든 티켓 공격은 TGT 를 위조하는 것이다. 시각 동기화는 Kerberos 의 전제 조건이지만 TGT 의 용도는 아니다.

    • A · 직접 접근에는 서비스 티켓이 필요하다.
    • C · 파일 암호화와 무관하다.
    • D · 시각 동기화는 전제 조건이다.

    원본 연습문제 · D5.6-Q01

    한 도메인 컨트롤러를 통해 인증하는 사용자들이 갑자기 로그인에 실패하고 다른 컨트롤러는 정상 동작한다. 그 컨트롤러의 시각이 다른 컨트롤러보다 12분 어긋나 있다. 실패의 가장 가능성 높은 원인은?

    1. 사용자 비밀번호 해시가 그 컨트롤러로 복제되지 않았다.
    2. 그 컨트롤러의 LDAPS 인증서가 만료되었다.
    3. 그 컨트롤러의 서비스 주 이름 풀이 소진되었다.
    4. Kerberos 가 재생 방지에 타임스탬프를 사용하며 시각 차이가 허용 오차를 넘었다.
    정답과 해설 보기

    정답 D. Kerberos 는 인증자에 타임스탬프를 넣어 재생을 방지하므로 클라이언트와 KDC 의 시각 차이가 허용 오차(보통 5분)를 넘으면 인증이 실패한다. 시각 동기화는 Kerberos 의 필수 전제이며 전면 인증 실패의 가장 흔한 원인이다.

    • A · 해시 복제 문제라면 시각 차이와 무관한 다른 증상이 나타난다.
    • B · LDAPS 인증서는 디렉터리 조회 보호용이며 Kerberos 티켓 검증과 다르다.
    • C · 서비스 주 이름에는 그런 소진 개념이 없다.

    3RADIUS

    Remote Authentication Dial-In User Service. 네트워크 접근에 대한 AAA를 제공합니다.

    특징내용
    전송UDP(1812/1813, 레거시 1645/1646)
    암호화 범위비밀번호 속성만 암호화, 나머지 속성은 평문 → RADIUS over TLS(RadSec)나 IPsec으로 보호
    AAA인증과 인가가 하나의 교환에 결합
    용도무선(802.1X), VPN, 네트워크 접근 제어, ISP 가입자 인증
    확장동적 인가(RFC 5176)로 세션 중 권한 변경·강제 종료. NAC의 격리 VLAN 전환에 쓰임

    원본은 RADIUS가 디렉터리를 대체하지 않는다고 짚습니다. 보통 RADIUS 서버가 뒤에 있는 LDAP/AD에 질의해 자격증명을 검증합니다.

    연결NAC와 격리 VLAN은 D4.2 5절에서 다룹니다.

    원문 위치: D5.6.md §3 RADIUS

    4TACACS+

    Terminal Access Controller Access-Control System Plus. 시스코가 개발했고 네트워크 장비 관리 인증에 쓰입니다.

    구분RADIUSTACACS+
    전송UDPTCP(49)
    암호화비밀번호만페이로드 전체
    AAA결합분리 → 명령 단위 인가 가능
    대표 용도무선·VPN 사용자 인증라우터·스위치·방화벽 관리자 인증과 명령 통제

    “네트워크 장비에서 관리자가 실행할 수 있는 명령을 개별 통제해야 한다”면 TACACS+, “무선 사용자 인증”이면 RADIUS입니다.

    원문 사례 — TACACS+로 구현한 명령 단위 인가. 네트워크 운영팀 전원이 같은 특권 수준으로 장비에 접속하다 주니어 엔지니어의 실수로 핵심 라우터 설정이 바뀌어 장애가 났습니다. 역할을 나눠 주니어는 조회와 제한된 변경만 허용하고, 모든 명령 실행을 계정관리 기록으로 남겼습니다.

    보충장비가 네트워크에 들어와도 되는지 판단하는 일과 관리자에게 특정 설정 명령을 허용하는 일은 다른 문제입니다. 프로토콜 이름이 운영 정책을 만들어 주지는 않으므로, 실제 환경에서 무엇을 인증하고, 어떤 단위로 인가하며, 어떤 실행 기록이 필요한지를 먼저 적고 프로토콜을 고릅니다.

    원문 위치: D5.6.md §3 TACACS+, §7 사례 4

    5LDAP

    Lightweight Directory Access Protocol. 디렉터리 조회와 수정을 위한 프로토콜이며 인증 수단으로도 쓰입니다.

    항목내용
    구조계층적 트리(DIT)와 고유 이름(DN). 객체는 objectClass와 속성을 가짐
    단순 바인드DN과 비밀번호를 보냄. TLS 없이는 비밀번호가 평문 → LDAPS(636) 또는 StartTLS 필수
    익명 바인드인증 없는 조회 허용 시 디렉터리 전체가 정찰 대상. 비활성화가 원칙
    SASL 바인드외부 인증 메커니즘(Kerberos 등)을 쓰는 강한 바인드
    LDAP 인젝션사용자 입력을 검색 필터에 그대로 넣으면 인증 우회·정보 노출. 입력 검증, 이스케이프, 파라미터화

    원본은 디렉터리가 인증의 원천이자 인가의 원천이라는 점을 강조합니다. 디렉터리 쓰기 권한은 접근 통제 전체를 바꿀 수 있는 권한이므로 그룹 멤버십 변경을 감시 대상으로 둡니다.

    원문 사례 — 평문 LDAP 바인드. 레거시 앱이 TLS 없이 단순 바인드로 디렉터리에 인증해, 같은 세그먼트에서 트래픽을 수집하자 서비스 계정 DN과 비밀번호가 평문으로 드러났습니다. LDAPS/StartTLS 강제, 익명 바인드 비활성화, 디렉터리 측에서 평문 바인드 거부, 노출된 자격증명 교체로 대응했습니다.

    보충사용자 정보를 디렉터리에서 조회하는 일과 그 사용자로 로그인할 수 있는지 검증하는 일은 목적이 다릅니다. 인증 서비스가 LDAP 디렉터리를 쓰더라도 채널 보호, 조회 권한, 인증 흐름을 따로 검토합니다. 세그먼테이션으로 디렉터리를 옮기는 것만으로는 평문 바인드 문제가 사라지지 않습니다.

    원본 연습문제 · D5.6-Q07

    내부 세그먼트의 패킷 수집에서 디렉터리 인증 중 서비스 계정의 고유 이름과 비밀번호가 평문으로 드러났다. 이를 해소하는 변경 조합은?

    1. 디렉터리 서버를 다른 VLAN 으로 옮기고 세그먼테이션에 의존한다.
    2. 디렉터리를 모든 속성을 암호화하는 RADIUS 서버로 교체한다.
    3. LDAPS 또는 StartTLS 를 강제하고 디렉터리에서 평문 단순 바인드를 거부하며 익명 바인드를 비활성화하고 노출된 자격증명을 교체한다.
    4. 서비스 계정 비밀번호 길이를 늘리고 교체 주기를 연장한다.
    정답과 해설 보기

    정답 C. LDAP 단순 바인드는 TLS 없이는 DN 과 비밀번호를 평문으로 전송한다. LDAPS 나 StartTLS 를 강제하고 디렉터리 측에서 평문 바인드를 거부해야 하며 익명 바인드도 정찰을 막기 위해 비활성화한다. 이미 평문으로 노출된 자격증명은 교체가 필수다.

    • A · 세그먼테이션은 완화책이며 평문 전송 자체를 없애지 않는다.
    • B · RADIUS 는 비밀번호 속성만 암호화하고 디렉터리를 대체하지도 않는다.
    • D · 비밀번호를 길게 해도 평문 전송이면 그대로 노출된다.

    6802.1X와 EAP

    포트 기반 네트워크 접근 통제입니다. 유선 포트와 무선 연결에서 인증 전까지 네트워크를 열지 않습니다.

    Supplicant
    클라이언트
    →
    Authenticator
    스위치 / AP
    →
    Authentication Server
    보통 RADIUS

    EAP는 인증 방식을 담는 프레임워크이며 실제 방식은 EAP 메서드가 정합니다.

    EAP 메서드특징
    EAP-TLS양방향 인증서. 가장 강하고 피싱에 강함
    PEAPTLS 터널 안에서 비밀번호 인증
    EAP-TTLSTLS 터널 안에서 다양한 내부 방식
    EAP-MD5단방향, 취약. 사용하지 않음

    원본은 터널형 EAP(PEAP/TTLS)의 핵심 요건이 서버 인증서 검증이라고 강조합니다. 클라이언트가 서버 인증서를 검증하지 않으면 가짜 AP가 터널을 종단해 내부 자격증명을 수집할 수 있고, 실무 사고 대부분이 이 설정 누락에서 나옵니다.

    원문 사례 — 가짜 AP가 수집한 기업 자격증명. PEAP를 썼지만 클라이언트 프로파일에서 서버 인증서 검증이 꺼져 있었습니다. 같은 SSID의 가짜 AP에 단말들이 접속해 TLS 터널을 가짜 서버에 종단했고 자격증명이 노출되었습니다. 신뢰 CA와 서버 이름을 고정한 프로파일을 중앙 배포하고, 중장기적으로 EAP-TLS로 전환했습니다.

    MAB(MAC 인증 우회)는 802.1X를 지원하지 않는 기기(프린터, IP 카메라)를 MAC 주소로 허용하는 보조 수단입니다. MAC은 위조할 수 있으므로 약한 통제이며 전용 세그먼트와 프로파일링을 함께 씁니다.

    가상 예시병원 네트워크에 붙는 노트북은 802.1X와 기기 인증서(EAP-TLS)로 인증하지만, 오래된 의료 장비 일부는 802.1X를 지원하지 않아 MAB로 허용하고 있다고 합시다. 이 장비들은 MAC 주소만으로 들어오므로, 같은 MAC을 흉내 낸 노트북도 들어올 수 있습니다. 그래서 MAB 장비는 전용 세그먼트에 두고, 장비 유형 프로파일링으로 “프린터라던 MAC이 갑자기 웹 브라우징을 한다” 같은 이상을 잡도록 합니다.

    연결802.1X와 NAC는 D4.2 5절, 무선 보안 프로토콜은 D4.1 13절, 인증서 검증은 D3.6 암호 솔루션에서 다룹니다.

    7자격증명 저장과 전송 보호

    원칙내용
    복호화 불가능한 형태로 저장느린 전용 해시 함수와 사용자별 솔트, 가능하면 메모리 하드 알고리즘
    암호화 저장은 부적절복호화 키가 있으면 평문 복원 가능
    페퍼 pepper별도 보관소에 두면 DB 유출만으로는 크래킹이 어려워짐
    전송 보호모든 인증 트래픽은 TLS 또는 동등한 보호. 레거시 프로토콜은 터널로 감쌈

    보충“비밀번호를 암호화해서 저장했다”는 말이 안전하게 들리지만, 서버는 비밀번호를 되살릴 필요가 없습니다. 입력된 값을 같은 방식으로 해시해 비교하면 충분하므로, 되살릴 수 있는 형태(암호화)로 둘 이유가 없습니다. 해시를 일부러 느리게 만드는 이유는 정상 로그인 한 번에는 차이가 없지만, 유출된 해시로 수십억 번 대입해 보는 공격자에게는 비용이 크게 늘기 때문입니다.

    연결해시와 솔트의 원리는 D3.6 암호 솔루션, 해시 크래킹 공격은 D3.7 암호 분석 공격에서 다룹니다.

    8실패 처리, 로깅, 가용성, 레거시 정리

    실패 처리

    요건이유
    동일한 오류 메시지“아이디 없음”과 “비밀번호 틀림”을 구분하면 사용자 열거 가능
    속도 제한과 잠금계정별 잠금은 서비스 거부로 악용될 수 있음 → IP·기기 단위 제한, 점진적 지연 병행
    비밀번호 스프레이 대응여러 계정에 같은 비밀번호를 시도. 계정별 잠금으로 탐지 불가 → 조직 전체 실패율 모니터링
    타이밍 차이 제거없는 계정에서 응답이 더 빠르면 그 자체가 정보 노출

    원문 사례 — 계정 잠금을 회피한 스프레이. 공격자가 직원 3,000명의 계정에 흔한 비밀번호 하나씩만 시도해 계정별 실패 횟수가 잠금 임계값에 닿지 않았고, 일부 계정이 뚫렸습니다. 조직 전체 실패율과 단일 출처의 다수 계정 시도를 탐지 규칙에 넣고 MFA 범위를 넓혔습니다.

    원문 사례 — 사용자 열거가 가능한 로그인 화면. 실패 메시지가 구분되고 없는 계정은 응답이 눈에 띄게 빨라, 공격자가 유효 계정 목록을 모아 표적 피싱과 스프레이에 썼습니다. 메시지를 통일하고 응답 시간을 평준화했으며 재설정 화면에도 같은 처리를 했습니다.

    로깅과 탐지

    • 인증 성공과 실패를 모두 기록합니다. 실패만 기록하면 침해 뒤의 정상 로그인을 추적할 수 없습니다.
    • 기록 항목: 시각, 계정, 출처, 인증 수단, 결과, 세션 식별자. 비밀번호나 토큰 값은 기록하지 않습니다.
    • 탐지 신호: 불가능한 이동, 다수 계정에 같은 비밀번호 시도, 비정상 시간, 비정상 인증 수단 변경, MFA 등록 변경.

    가용성과 레거시 정리

    인증 시스템은 모든 접근의 전제입니다. KDC, RADIUS, IdP는 다중화하고 지역 분산을 고려합니다. 장애 때는 fail-secure를 기본으로 하되 비상 계정 경로를 설계합니다.

    약한 인증 프로토콜이 남아 있으면 공격자는 가장 약한 경로를 씁니다. NTLM류 레거시 인증, 평문 LDAP, EAP-MD5, 기본 인증 등은 사용 현황을 측정한 뒤 단계적으로 차단합니다. 측정 없이 차단하면 업무가 멈춥니다.

    연결세션 토큰의 엔트로피·재발급·만료 같은 세션 통제는 D5.2 식별·인증 전략의 9절, 로그 수집과 탐지는 D7.2 로깅·모니터링, 비상 계정과 IdP 장애는 D5.3 연합 식별의 9절에서 다룹니다.

    9종합 이해 확인

    종합 · 자작 상황 문제 (실제 시험 문제 아님)

    인증 인프라 점검 결과다. ㉠ 무선은 PEAP인데 단말 프로파일에서 서버 인증서 검증이 꺼져 있다. ㉡ 네트워크 장비에 운영팀 전원이 같은 특권으로 접속하며 명령 기록이 없다. ㉢ 한 레거시 앱이 TLS 없이 LDAP 단순 바인드를 쓴다. ㉣ 계정별 잠금만 있고 조직 전체 실패율은 보지 않는다. 가장 적절한 대책 묶음은?

    1. ㉠ SSID 숨김 / ㉡ RADIUS로 통일 / ㉢ 디렉터리를 다른 VLAN으로 / ㉣ 잠금 임계값을 1회로
    2. ㉠ EAP-MD5로 교체 / ㉡ 공유 관리자 계정 / ㉢ 비밀번호 교체 주기 단축 / ㉣ 로그 보존 연장
    3. ㉠ 신뢰 CA·서버 이름을 고정한 프로파일 배포, 장기적으로 EAP-TLS / ㉡ TACACS+로 역할별 명령 인가와 명령 기록 / ㉢ LDAPS·StartTLS 강제, 평문 바인드 거부, 노출 자격증명 교체 / ㉣ 조직 전체 실패율·다수 계정 시도 탐지, MFA 확대
    4. ㉠ MAB로 전환 / ㉡ 장비별 로컬 계정 / ㉢ 익명 바인드 허용 / ㉣ 오류 메시지를 상세히
    정답과 해설 보기

    정답 C. ㉠ 6절(터널형 EAP는 서버 인증서 검증이 핵심), ㉡ 4절(AAA 분리로 명령 단위 인가), ㉢ 5절(세그먼트 이동으로는 평문 해소 안 됨), ㉣ 8절(스프레이는 계정별 잠금으로 못 잡음, 임계값 1회는 서비스 거부를 부름). D의 “상세 오류 메시지”는 사용자 열거를 돕습니다.

    사용자 인증 후 필요한 세션 통제 묶음은?

    1. 사용자가 다시 로그인할 필요가 거의 없도록 장기 세션 토큰.
    2. 충분한 엔트로피를 가진 토큰을 권한 변경 시 재생성하고 안전하게 전송·저장하며 유휴 및 절대 시간 초과와 로그아웃 시 서버 측 무효화를 적용한다.
    3. 서버가 사용자를 식별할 수 있도록 쿠키에 사용자명을 저장한다.
    4. 추적이 쉽도록 사용자명에서 세션 식별자를 도출한다.
    정답과 해설 보기

    정답 B. 인증은 한 순간이고 그 뒤의 접근은 세션이 대신 증명한다. 따라서 세션 토큰은 추측할 수 없어야 하고 권한이 바뀌는 시점에 재생성해 세션 고정을 막아야 한다. 로그아웃 시 서버 측에서 무효화하지 않으면 클라이언트에서만 지워져 토큰이 계속 유효하다. 사용자명 기반 식별자는 예측 가능해 위조된다.

    • A · 장기 토큰은 탈취 시 노출 기간이 길다.
    • C · 사용자명 쿠키는 위조가 쉽다.
    • D · 예측 가능한 식별자는 위조된다.

    11핵심 요약

    1. 선택 기준: 어디서 누구를 인증하는가. 도메인=Kerberos, 네트워크 접속=802.1X+RADIUS, 장비 관리=TACACS+, 웹·제3자=SAML/OIDC.
    2. Kerberos: KDC(AS+TGS), TGT → 서비스 티켓, 비밀번호 비전송, 상호 인증, SSO, 수명 제한, 타임스탬프 재생 방지 → 시각 동기화 필수(보통 5분).
    3. KDC = 단일 실패점·최고가치 표적. 골든 티켓(krbtgt, 두 번 교체), 실버 티켓, Kerberoasting(오프라인 크래킹), Pass-the-Ticket, AS-REP Roasting, 무제한 위임.
    4. RADIUS: UDP, 비밀번호만 암호화, AAA 결합, 무선·VPN. 디렉터리를 대체하지 않음.
    5. TACACS+: TCP 49, 전체 암호화, AAA 분리 → 명령 단위 인가, 장비 관리.
    6. LDAP: 단순 바인드는 TLS 없으면 평문 → LDAPS/StartTLS. 익명 바인드 비활성화, LDAP 인젝션 방지. 디렉터리 = 인증·인가의 원천.
    7. 802.1X: Supplicant–Authenticator–인증 서버. EAP-TLS 최강, EAP-MD5 금지. 터널형 EAP는 서버 인증서 검증 필수. MAB는 약한 통제.
    8. 저장: 느린 해시 + 사용자별 솔트(+메모리 하드, 페퍼), 암호화 저장 부적절. 전송은 TLS.
    9. 실패 처리: 동일 메시지, 타이밍 평준화, IP·기기 단위 제한, 스프레이는 조직 전체 실패율로.
    10. 로깅: 성공·실패 모두, 비밀번호·토큰 값 금지, MFA 등록 변경 감시. 인증 시스템 다중화. 레거시는 측정 후 단계적 차단.
    원문 위치: D5.6.md §8 CISSP 시험 관점, §9 핵심 암기 요약. 원본의 “시험의 고전 문항”, “가장 흔한 답” 같은 출제 단정 표현은 판단 기준으로 바꿔 적었습니다.

    12주요 용어 (Glossary)

    영어 원어와 한국어 뜻 · English–Korean

    Kerberos · 티켓 기반 인증 프로토콜

    티켓 기반 대칭키 인증 프로토콜. 상호 인증과 SSO 를 제공한다.

    KDC (Key Distribution Center) · 키 배포 센터

    AS 와 TGS 를 호스팅하는 Kerberos 핵심 서버.

    TGT (Ticket Granting Ticket) · 서비스 티켓 발급을 위한 티켓

    AS 가 발급하는 티켓. 이후 서비스 티켓 요청에 사용된다.

    Service Ticket · 서비스 티켓

    TGS 가 발급하는 특정 서비스 접근용 티켓.

    Realm · 영역

    공통 KDC 를 공유하는 Kerberos 관리 영역.

    Golden Ticket · 골든 티켓

    krbtgt 키를 획득해 임의 사용자·권한의 TGT 를 위조하는 공격.

    Silver Ticket · 실버 티켓

    서비스 계정 키로 특정 서비스의 티켓을 위조하는 공격. KDC 를 거치지 않는다.

    Kerberoasting · 커버로스 서비스 계정 자격 증명을 노리는 유형

    서비스 티켓을 받아 오프라인에서 서비스 계정 비밀번호를 크래킹하는 공격.

    Pass-the-Ticket · 티켓 재사용 인증 공격

    메모리에서 탈취한 티켓을 재사용하는 공격.

    RADIUS — Remote Authentication Dial-In User Service · 원격 접속용 AAA 프로토콜

    UDP 기반 네트워크 접근 AAA 프로토콜. 비밀번호 속성만 암호화한다.

    TACACS+ — Terminal Access Controller Access-Control System Plus · 네트워크 장비 관리용 AAA 프로토콜

    TCP 기반 장비 관리 AAA 프로토콜. 페이로드 전체를 암호화하고 AAA 가 분리되어 명령 단위 인가가 가능하다.

    LDAP (Lightweight Directory Access Protocol) / LDAPS (LDAP over TLS) · 경량 디렉터리 접근 / TLS로 보호한 LDAP

    디렉터리 접근 프로토콜과 그 TLS 보호 형태.

    Simple Bind / SASL Bind · 단순 바인드 / SASL 기반 바인드

    DN 과 비밀번호로 하는 기본 바인드와 외부 메커니즘을 사용하는 강한 바인드.

    802.1X · 포트 기반 네트워크 접근 제어 표준

    포트 기반 네트워크 접근 통제 표준. Supplicant, Authenticator, Authentication Server 로 구성된다.

    EAP (Extensible Authentication Protocol) · 확장 인증 프로토콜

    인증 방식을 담는 프레임워크. EAP-TLS, PEAP, EAP-TTLS 등의 메서드가 있다.

    MAB (MAC Authentication Bypass) · MAC 주소 기반 대체 접근 확인

    802.1X 미지원 기기를 MAC 주소로 허용하는 보조 수단. MAC 위조 가능성 때문에 약한 통제다.

    User Enumeration · 사용자 열거

    오류 메시지나 응답 시간 차이로 계정 존재 여부를 알아내는 것.

    Password Spraying · 비밀번호 스프레이

    여러 계정에 같은 비밀번호를 시도해 계정 잠금을 회피하는 공격.

    3. 내부 세그먼트의 패킷 수집에서 디렉터리 인증 중 서비스 계정의 고유 이름과 비밀번호가 평문으로 드러났다. 이를 해소하는 변경 조합은?
    4. 인증 인프라 점검 결과다. ㉠ 무선은 PEAP인데 단말 프로파일에서 서버 인증서 검증이 꺼져 있다. ㉡ 네트워크 장비에 운영팀 전원이 같은 특권으로 접속하며 명령 기록이 없다. ㉢ 한 레거시 앱이 TLS 없이 LDAP 단순 바인드를 쓴다. ㉣ 계정별 잠금만 있고 조직 전체 실패율은 보지 않는다. 가장 적절한 대책 묶음은?

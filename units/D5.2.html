    사람이든 기기든 서비스든, 시스템에 들어오는 모든 주체는 “나는 누구다”라고 주장합니다. 이 단원은 그 주장을 어떻게 믿을 수 있게 만드는지를 다룹니다. 처음 등록할 때 신원을 확인하는 일, 로그인할 때 인증 요소를 고르는 일, 로그인 뒤 세션을 지키는 일, 여러 시스템과 조직 사이에서 한 번의 인증을 나눠 쓰는 일입니다.

    2인증 요소와 다중요소 인증

    세 가지 범주

    유형의미예시
    Type 1 — 지식 something you know알고 있는 것비밀번호, PIN, 보안 질문
    Type 2 — 소유 something you have가지고 있는 것토큰, 스마트카드, 휴대폰
    Type 3 — 생체 something you are고유한 신체·행동 특성지문, 홍채, 얼굴, 서명 패턴

    보조적으로 위치(somewhere you are)와 행동(something you do)을 더하기도 합니다.

    다중요소의 정의

    원본의 정의는 분명합니다. MFA는 서로 다른 유형의 요소를 둘 이상 쓰는 것이다.

    조합MFA인가
    비밀번호 + 보안 질문아니다(둘 다 Type 1)
    비밀번호 + OTP 토큰맞다(Type 1 + Type 2)
    지문 + 얼굴 인식아니다(둘 다 Type 3)
    스마트카드 + PIN맞다(Type 2 + Type 1)

    같은 유형을 두 번 쓰는 것은 2단계(two-step)일 뿐 다중요소가 아닙니다.

    원문 사례 — MFA가 아니었던 2단계 인증. 조직이 MFA를 적용했다고 보고했지만 실제로는 비밀번호 + 보안 질문이었습니다. 둘 다 지식 기반이라 다중요소가 아니었고, 유출된 개인정보로 보안 질문이 모두 뚫렸습니다.

    MFA 수단의 상대적 강도

    수단원본의 평가
    SMS OTP가장 약함. SIM 스와핑과 가로채기에 취약
    앱 기반 TOTP중간. 피싱으로 실시간 중계 가능
    푸시 알림편리하지만 MFA 피로 공격(반복 승인 요청으로 실수 유도)에 취약
    FIDO2/WebAuthn 하드웨어 키가장 강함. 피싱 저항성을 구조적으로 제공

    원본은 FIDO2가 피싱에 강한 이유를 인증이 출처(origin)에 묶이기 때문이라고 설명합니다. 가짜 사이트에서는 올바른 서명이 만들어지지 않습니다.

    원문 사례 — MFA 피로 공격. 공격자가 훔친 비밀번호로 밤새 푸시 알림을 수십 번 보냈고, 잠에서 깬 사용자가 알림을 멈추려고 무심코 승인했습니다. 번호 매칭과 시도 횟수 제한을 적용하고 장기적으로 FIDO2로 전환했습니다.

    보충강도 순서는 “공격자가 중간에 끼어들 수 있는가”로 이해하면 외울 필요가 없습니다. SMS·TOTP 코드는 사람이 읽고 입력하므로 가짜 사이트에도 입력할 수 있고, 공격자가 그 코드를 즉시 진짜 사이트에 넣으면 통과합니다. 푸시는 사람이 “승인”만 누르면 되므로 지쳐서 누르게 만들 수 있습니다. FIDO2는 기기가 접속한 사이트 주소를 직접 확인해 그 주소용 서명만 만들기 때문에, 사람이 속아도 기기는 속지 않습니다. 그래서 인증 수단을 하나의 순위로 외우기보다 “어떤 공격을 막아야 하는가”에 맞춰 고릅니다.

    연결크리덴셜 스터핑은 D3.7 암호 분석 공격, 사회공학의 심리 원리는 D1.12 인식·교육·훈련, MFA 피로 공격 사례는 D7.15 인원 안전, 디지털 서명 원리는 D3.6 암호 솔루션에서 다룹니다.

    원본 연습문제 · D5.2-Q01

    어떤 조직이 비밀번호와 보안 질문으로 다중요소 인증을 구현했다고 주장한다. 이것이 다중요소에 해당하지 않는 이유는?

    1. 비밀번호는 다른 어떤 인증 방법과도 결합할 수 없다.
    2. 보안 질문은 현대 디렉터리 서비스에서 지원되지 않는다.
    3. 다중요소 인증은 최소 세 가지 구별되는 요소를 요구한다.
    4. 둘 다 지식 요소이므로 한 가지 요소 유형만 사용되고 있다.
    정답과 해설 보기

    정답 D. 다중요소 인증은 서로 다른 유형의 요소를 둘 이상 사용하는 것이다. 비밀번호와 보안 질문은 모두 지식(Type 1) 요소이므로 2단계일 뿐 다중요소가 아니다. 유출된 개인정보로 보안 질문이 뚫리는 사례가 흔하며 소유(Type 2)나 생체(Type 3)를 추가해야 진정한 MFA 가 된다.

    • A · 비밀번호는 다른 요소와 결합할 수 있다.
    • B · 지원 여부가 아니라 요소 유형이 문제다.
    • C · 서로 다른 두 유형이면 충족된다.

    3생체 인증의 오류율

    지표의미오류 유형
    FRR False Rejection Rate정당한 사용자를 거부Type I
    FAR False Acceptance Rate부정한 사용자를 수락Type II
    CER / EER Crossover Error RateFAR과 FRR이 같아지는 지점정확도 비교 기준

    원본은 보안상 더 위험한 것은 FAR(Type II)이라고 정리합니다. 침입자를 들여보내기 때문입니다. FRR이 높으면 불편하지만 보안은 유지됩니다. 민감도를 높이면 FAR은 내려가고 FRR은 올라가며, 둘은 맞바꾸는 관계입니다. CER이 낮을수록 전반적으로 우수한 시스템입니다. 고보안 환경에서는 FAR을 낮추고, 늘어난 FRR은 대체 인증 수단으로 보완합니다.

    생체 인증의 고유 문제: 취소 불가(비밀번호는 바꿀 수 있지만 지문은 못 바꾼다), 프라이버시(생체 정보 자체가 민감 정보), 템플릿 보호(원본이 아닌 변환된 템플릿 저장), 위조(presentation attack) → 생체 검출(liveness detection).

    원문 사례 — 생체 민감도 조정. 출입 지문 인식기의 FRR이 높아 불만이 많아 민감도를 낮췄더니, FAR이 올라가 타인의 지문이 수락되는 일이 생겼습니다. 민감도를 되돌리고, FRR로 인한 불편은 사원증 병행(Type 2)으로 보완했습니다.

    보충Type I·II라는 이름을 헷갈리지 않으려면 “첫 번째 실수는 주인을 못 알아본 것, 두 번째 실수는 낯선 사람을 주인으로 착각한 것”으로 기억하면 됩니다. CER은 두 오류가 같아지도록 맞췄을 때의 값이라 제품끼리 비교하는 잣대일 뿐, 실제 운영에서 그 지점에 맞추라는 뜻은 아닙니다. 출입문과 고위험 관리자 접근은 감수할 수 있는 거부 비용이 다르므로 같은 장비라도 다른 민감도로 운영할 수 있습니다.

    원본 연습문제 · D5.2-Q19

    생체 인증 시스템에서 거짓 수락(false acceptance)이 뜻하는 것은?

    1. 센서가 판독에 실패한다.
    2. 정당한 사용자가 잘못 거부된다.
    3. 인가되지 않은 사람이 등록된 사용자로 잘못 수락된다. 두 오류 유형 중 보안상 더 치명적인 쪽이다.
    4. 등록된 템플릿이 만료되었다.
    정답과 해설 보기

    정답 C. 거짓 수락은 침입을 허용하는 오류이고 거짓 거부는 정당한 사용자를 막는 오류다. 보안 관점에서는 거짓 수락이 더 위험하므로 민감한 환경에서는 민감도를 높여 거짓 수락을 줄이는 쪽으로 조정한다. 그 대가로 거짓 거부가 늘어 사용성이 떨어진다. 두 오류율이 같아지는 지점을 교차 오류율(CER)이라 한다.

    • A · 판독 실패는 별개 상태다.
    • B · 거짓 거부의 정의다.
    • D · 템플릿 만료와 무관하다.

    신원 증명은 “이 사람이 정말 주장하는 그 사람인가”를 확인하는 과정이며, 신분증 확인, 대면 확인, 기존 관계 활용 등이 쓰입니다.

    NIST SP 800-63의 세 보증 수준

    수준대상의미
    IAL Identity Assurance Level신원 증명등록 시 신원 확인의 엄격함
    AAL Authentication Assurance Level인증로그인할 때 계정에 연결된 인증 수단을 실제로 통제하고 있다는 확신
    FAL Federation Assurance Level연합신원 제공자에서 서비스로 전달되는 인증 결과의 보호 수준

    세 수준은 각각의 위험을 평가해 따로 정합니다. 예를 들어 기본 신원 증명은 IAL1로 충분해도, 로그인 뒤 개인정보를 조회할 수 있다면 AAL2가 필요할 수 있습니다.

    확인 필요원본은 “익명으로 등록(IAL1)하되 강한 인증(AAL3)” 조합을 예로 들지만, 이것은 개정 전(SP 800-63-3) 기준입니다. 현행 SP 800-63A-4(2025년 7월 최종)에서 IAL1도 신원 증명 수준입니다. IAL1의 신원 증명은 주장한 신원이 실제로 존재함을 뒷받침하고, 핵심 속성을 권위 있는 출처와 대조합니다. 실세계 신원과 연결할 필요가 없는 서비스는 신원 증명 없이 운영할 수 있습니다. 또 AAL의 영문 명칭도 개정판 표기(Authentication Assurance Level)로 적었습니다. 두 내용은 NIST 웹 공개본(pages.nist.gov/800-63-4)에서 확인했습니다.

    등록·재설정 절차가 가장 약한 고리다

    원본은 헬프데스크를 통한 비밀번호 재설정이 가장 흔한 우회 경로라고 경고합니다. 사회공학으로 재설정을 유도하면 아무리 강한 인증도 무력화됩니다.

    원문 사례 — 헬프데스크를 통한 우회. 강한 MFA를 적용했지만 공격자가 헬프데스크에 전화해 MFA 재등록을 요청했고, 상담원은 생년월일 확인만으로 처리했습니다. 본인 확인 절차를 강화하고 관리자 승인과 콜백 검증을 추가했습니다.

    판단 순서계정 탈취 원인을 볼 때 ① 등록 때 신원 증빙을 잘못 받아들였나(IAL) ② 로그인에서 인증 수단이 약했나(AAL) ③ 다른 조직의 인증 결과를 받아들이는 과정에서 위조·재사용이 있었나(FAL) ④ 재설정·재등록 절차가 우회로였나를 나눠 봅니다. ④는 ①~③이 아무리 강해도 전체를 무너뜨립니다.

    연결사회공학과 별도 채널 콜백 확인은 D1.12 인식·교육·훈련, 헬프데스크 우회 사례는 D7.15 인원 안전, 계정 생애주기는 D5.5 프로비저닝 생애주기, 연합 흐름은 D5.3 연합 식별에서 다룹니다.

    1. EAL — 평가 보증 수준
    2. AAL — 인증 보증 수준
    3. IAL — 신원 보증 수준
    4. FAL — 연합 보증 수준
    정답과 해설 보기

    정답 C. 질문은 계정을 만들 때 신청자가 주장하는 사람인지 확인하는 절차를 묻습니다. 개인정보를 조회할 수 있는 서비스에서는 등록과 이후 로그인의 위험이 다르므로 IAL1과 AAL2를 함께 검토할 수 있습니다.

    • A · EAL은 Common Criteria에서 제품 보안 평가에 적용하는 수준입니다.
    • B · AAL은 로그인 시 계정에 연결된 인증 수단을 통제하는지 확인하는 수준입니다.
    • D · FAL은 인증 결과를 다른 서비스에 전달하는 연합 과정의 보호 수준입니다.
    원문 위치 · D5.2-Q07 · 지침 판과 설명은 SP 800-63-4에 맞춰 수정
    문제 목록으로 돌아가기
    원문 위치: D5.2.md §3 신원 증명과 등록, §7 사례 5 · 공식 개요 5.2 “Registration, proofing, and establishment of identity” · 외부 확인: NIST SP 800-63-4·63A-4·63B-4(2025-07) · 기존 문제 Q07 주제

    5그룹과 역할

    원본의 원칙은 개별 사용자에게 직접 권한을 주지 않는다입니다. 사용자 → 그룹/역할 → 권한 구조로 관리하면 관리가 단순해지고, 일관성이 생기며, 권한 검토가 쉬워지고, 입퇴사·전보를 빨리 반영할 수 있습니다.

    역할(Role)은 직무에 대응하고 그룹(Group)은 사용자 묶음입니다. 실무에서는 섞어 쓰지만 RBAC에서 역할은 권한의 집합이라는 의미가 강합니다. 원본은 역할 폭증(role explosion)을 주의시킵니다. 예외를 역할로 계속 만들면 관리가 불가능해집니다.

    연결RBAC와 다른 인가 모델은 D5.4 인가 메커니즘, 입퇴사·전보 처리는 D5.5 프로비저닝 생애주기·D1.8 인적 보안에서 다룹니다.

    원문 위치: D5.2.md §3 그룹과 역할 · 공식 개요 5.2 “Groups and Roles”

    6SSO — 한 번의 인증

    장점단점
    사용자 편의, 비밀번호 수 감소단일 실패점
    중앙 집중 정책침해 시 모든 시스템 노출
    감사 일원화가용성 의존, 초기 구축 복잡

    원본은 SSO를 “왕국의 열쇠(keys to the kingdom)”라고 부릅니다. 그래서 SSO 계정에는 강한 MFA가 필수이고, 세션 관리와 이상 탐지가 중요해집니다. 전통적 SSO의 대표가 Kerberos입니다.

    연결Kerberos의 동작은 D5.6 인증 시스템, Kerberos를 노리는 공격은 D3.7 암호 분석 공격에서 다룹니다.

    원문 위치: D5.2.md §3 SSO · 공식 개요 5.2 “Single sign-on (SSO)”

    7연합 신원 관리

    SSO가 한 조직 안이라면 연합(Federated Identity)은 서로 다른 신뢰 도메인 사이에서 신원을 공유합니다. 신원을 검증하고 주장을 발급하는 쪽이 IdP(Identity Provider), 그 주장을 믿고 접근을 허용하는 쪽이 SP/RP(Service Provider / Relying Party)입니다.

    프로토콜목적형식
    SAML 2.0인증 + 속성 전달(기업 웹 SSO 표준)XML
    OAuth 2.0인가(위임) — 인증이 아니다JSON/REST
    OIDCOAuth 위의 인증 계층(ID 토큰, JWT)JSON/JWT

    원본이 가장 강조하는 구분은 OAuth 2.0은 인가 프레임워크이지 인증 프로토콜이 아니다입니다. OAuth는 “이 앱이 내 사진에 접근해도 좋다”는 권한 위임을 다루고, “이 사람이 누구인가”는 알려 주지 않습니다.

    원문 사례 — OAuth를 인증으로 오용. 개발팀이 OAuth 액세스 토큰을 받으면 “로그인된 사용자”로 처리했는데, 토큰이 어느 사용자의 것인지 보장되지 않아 다른 앱에서 발급된 토큰을 제출하는 공격이 가능했습니다. OIDC의 ID 토큰으로 바꾸고 발급 대상(aud)과 발급자(iss)를 검증했습니다.

    연합의 신뢰 문제: SP는 IdP를 믿어야 하므로 IdP가 침해되면 연결된 모든 SP가 영향을 받습니다. 메타데이터 검증, 서명 확인, 주장 유효 기간 제한이 필요합니다.

    연결제3자 신원 서비스와 연합의 상세(신뢰 관계, JIT 프로비저닝, 장애 처리)는 D5.3 연합 식별에서 다룹니다.

    원문 위치: D5.2.md §3 연합 신원 관리, §7 사례 4 · 공식 개요 5.2 “Federated Identity Management (FIM)”

    8자격증명 관리 시스템과 패스워드리스

    비밀번호 금고와 PAM

    비밀번호 금고(Password Vault)는 자격증명을 암호화해 중앙에 보관하고, 꺼내 쓸 때 사용 이력을 기록해 공유 계정의 책임추적성을 보완합니다. PAM(Privileged Access Management)은 특권 계정에 특화된 금고로, 자격증명 자동 교체, 적시 권한 상승과 세션 중개, 세션 녹화와 명령 필터링, 사용 승인 워크플로를 제공합니다.

    보충금고를 도입해도 “누가 언제 무엇을 꺼냈는가”를 기록하지 못하거나 꺼낸 비밀을 교체하지 않으면 책임추적성은 그대로입니다. 대상별 소유자와 열람 권한을 정하고, 높은 권한의 비밀에는 승인·사용 기록·교체 시점을 붙이며, 서비스가 자동으로 받아 가는 자격증명도 같은 수명주기로 관리해야 합니다. 금고 자체가 가장 가치 있는 표적이 된다는 점도 함께 고려합니다.

    패스워드리스 인증

    방식설명
    FIDO2 / WebAuthn하드웨어 키나 플랫폼 인증기, 공개키 기반
    패스키 Passkey기기 사이에 동기화되는 FIDO 자격증명
    인증서 기반스마트카드, 기기 인증서
    매직 링크메일 링크(메일 계정 보안에 의존)

    비밀번호가 사라지면 재사용, 크리덴셜 스터핑, 피싱, 무차별 대입, 유출 목록 공격이 함께 사라집니다. 원본은 FIDO2의 동작을 이렇게 설명합니다. 등록 때 기기가 키 쌍을 만들고 공개키만 서버에 저장하며, 인증 때 개인키로 챌린지에 서명합니다. 개인키는 기기를 떠나지 않으므로 서버가 유출되어도 자격증명이 노출되지 않습니다.

    연결점프 서버는 D4.3 안전한 통신 채널, PAM 운영은 D7.4 기본 보안 운영 개념, 공개키 서명의 원리는 D3.6 암호 솔루션에서 다룹니다.

    원문 위치: D5.2.md §3 자격증명 관리 시스템, 패스워드리스 인증 · 공식 개요 5.2 “Credential management systems (e.g., password vault)”, “password-less authentication”

    9세션 관리

    인증 이후 상태를 유지하는 일도 인증 체계의 일부입니다.

    통제내용
    유휴 타임아웃일정 시간 사용하지 않으면 종료
    절대 타임아웃활동과 무관하게 최대 수명 제한
    재인증민감 작업 전 다시 확인
    토큰 보호안전한 저장, 전송 시 암호화
    세션 고정 방지인증 후 세션 ID 재발급
    동시 세션 제한비정상 다중 접속 탐지

    세션 고정(session fixation)은 공격자가 미리 만든 세션 ID를 피해자가 쓰게 한 뒤, 피해자가 로그인하면 그 세션을 가로채는 공격입니다. 로그인 시점에 세션 ID를 새로 발급하면 막을 수 있습니다. 원본은 제로 트러스트에서는 세션 내내 지속 평가한다고 덧붙입니다.

    원문 사례 — 세션 고정. 로그인 후에도 세션 ID가 그대로 유지되는 구현이라, 공격자가 특정 세션 ID가 담긴 링크를 보내고 피해자가 그 링크로 로그인하자 같은 세션으로 접근할 수 있었습니다.

    가상 예시관리자가 피싱에 강한 인증으로 로그인한 뒤, 병원 현장의 공용 지원 단말에 브라우저를 열어 두고 자리를 떴습니다. 두 시간 뒤에도 그 브라우저로 고위험 설정 변경을 할 수 있다면, 처음의 강한 인증은 의미가 줄어듭니다. 관리자 세션에는 유휴·절대 만료를 짧게 두고, 설정 변경 같은 고위험 작업 앞에는 재인증을 요구합니다. 인증의 강도와 세션의 수명은 함께 설계해야 합니다.

    연결지속 평가와 제로 트러스트는 D3.1 안전한 설계 원칙, 세션 관련 코드 취약점은 D8.5 안전한 코딩에서 다룹니다.

    원문 위치: D5.2.md §3 세션 관리, §7 사례 6 · 공식 개요 5.2 “Session management”

    10적시 접근 (Just-In-Time)

    유형설명
    JIT 권한 상승작업 시간에만 특권 부여
    JIT 프로비저닝첫 접속 시 계정 자동 생성(연합에서 흔함)
    JIT 접근 요청승인 워크플로 기반 임시 접근

    원본은 목표를 상시 특권 계정을 없애는 것으로 정리합니다. 권한이 없는 시간이 길수록 탈취될 기회도 줄어듭니다.

    연결최소권한의 “필요한 기간만”은 D3.1 안전한 설계 원칙, JIT 프로비저닝과 연합의 책임 경계는 D5.3 연합 식별에서 다룹니다.

    원문 위치: D5.2.md §3 적시 접근 · 공식 개요 5.2 “Just-In-Time”

    11종합 이해 확인

    종합 · 자작 상황 문제 (실제 시험 문제 아님)

    점검 결과다. ㉠ 원격 접속에 비밀번호 + 보안 질문을 쓰며 이를 MFA라고 부른다. ㉡ 푸시 승인 MFA에 피로 공격이 성공했다. ㉢ 헬프데스크가 생년월일만으로 MFA를 재등록해 준다. ㉣ 로그인 후에도 세션 ID가 바뀌지 않는다. 가장 적절한 대책 묶음은?

    1. ㉠ 다른 유형의 요소(소유·생체) 추가 / ㉡ 번호 매칭·시도 제한, 장기적으로 FIDO2 / ㉢ 콜백·관리자 승인 등 강화된 본인 확인 / ㉣ 로그인 시 세션 ID 재발급
    2. ㉠ 보안 질문을 하나 더 / ㉡ 사용자 교육만 / ㉢ 생년월일 + 주소 / ㉣ 세션 시간 연장
    3. ㉠ 비밀번호 길이 확대 / ㉡ SMS OTP로 교체 / ㉢ 재등록 금지 / ㉣ 쿠키 삭제 안내
    4. ㉠ 지문 + 얼굴 / ㉡ 푸시 알림 끔 / ㉢ 이메일로 처리 / ㉣ 동시 세션 허용
    정답과 해설 보기

    정답 A. ㉠ 2절(같은 유형 두 개는 MFA가 아님 — D의 지문+얼굴도 같은 이유로 틀림), ㉡ 2절(원문 사례 2), ㉢ 4절(재설정이 가장 약한 고리), ㉣ 9절(세션 고정).

    관리되는 노트북을 사내 네트워크에 인증시키는 적절한 방식은?

    1. 모든 사내 노트북에 설정된 공유 사전 공유 키.
    2. 사용자가 이미 인증되었으므로 사용자 자신의 비밀번호.
    3. 사내 PKI 가 발급한 기기 인증서를 가능한 경우 하드웨어에 저장하고 802.1X 로 검증하며 인증서 생애주기와 폐기를 관리한다.
    4. 기기마다 고유한 하드웨어 주소가 있으므로 MAC 주소 허용 목록.
    정답과 해설 보기

    정답 C. MAC 주소는 쉽게 위조되므로 인증 수단이 아니다. 공유 키는 한 기기에서 유출되면 전체가 뚫린다. 사용자 비밀번호는 사용자를 증명하지 기기를 증명하지 않으므로 비관리 기기에서의 접근을 구분하지 못한다. 기기별 인증서를 하드웨어에 보관하고 폐기 체계를 갖추는 것이 표준적 방식이다.

    • A · 공유 키는 단일 유출로 전체가 무력화된다.
    • B · 사용자 인증은 기기 인증을 대체하지 않는다.
    • D · MAC 주소는 위조가 쉽다.

    12핵심 개념을 내 말로 설명하기

    복습

    신원 증명, 인증, 세션 만료는 각각 어느 순간을 보호하나요?

    설명 확인하기

    신원 증명은 계정을 실제 주체에게 연결하는 등록 과정입니다. 인증은 현재 요청자가 등록한 인증 수단을 보유하는지 확인합니다. 세션 만료는 인증 뒤 그 권한이 계속 쓰이는 시간을 제한합니다.

    13핵심 요약

    1. 식별 = 주장, 인증 = 검증. AAA = 인증·인가·계정 관리(감사). IAAA = 식별 + AAA.
    2. 인증 요소: Type 1 지식 / Type 2 소유 / Type 3 생체. MFA = 서로 다른 유형 둘 이상. 같은 유형 두 번은 2단계일 뿐.
    3. MFA 강도: SMS(SIM 스와핑) < TOTP(중계) < 푸시(피로 공격) < FIDO2(출처에 묶여 피싱 저항).
    4. FRR = Type I(정당 사용자 거부), FAR = Type II(부정 사용자 수락) — 보안상 FAR이 더 위험. 민감도↑ → FAR↓ FRR↑. CER 낮을수록 우수. 생체는 취소 불가.
    5. 신원 증명 → 등록 → 발급 → 사용 → 폐기. IAL(증명) / AAL(인증) / FAL(연합)은 따로 정한다. 현행 800-63-4는 IAL1에도 신원 확인 포함.
    6. 헬프데스크 재설정이 가장 흔한 우회 경로.
    7. 권한은 그룹·역할로. 역할 폭증 주의.
    8. SSO = 편의 + 단일 실패점(왕국의 열쇠) → 강한 MFA.
    9. 연합: IdP(주장 발급) / SP·RP(신뢰). SAML = 인증+속성(XML), OAuth 2.0 = 인가(위임, 인증 아님), OIDC = OAuth 위 인증(ID 토큰).
    10. 금고(사용 이력), PAM(자동 교체, JIT, 세션 녹화). 패스워드리스(FIDO2·패스키): 개인키는 기기를 떠나지 않는다.
    11. 세션: 유휴·절대 타임아웃, 재인증, 로그인 시 세션 ID 재발급(세션 고정 방지). JIT로 상시 특권 제거.
    원문 위치: D5.2.md §8 CISSP 시험 관점, §9 핵심 암기 요약. 원본의 “시험 포인트” 같은 출제 단정 표현은 판단 기준으로 바꿔 적었습니다.

    14주요 용어 (Glossary)

    영어 원어와 한국어 뜻 · English–Korean

    AAA — Authentication, Authorization, Accounting / IAAA — Identification, Authentication, Authorization, Accountability · 인증·인가·활동 기록 / 식별을 포함한 접근 확인과 책임추적

    인증·인가·계정관리, 그리고 앞에 식별을 더한 네 단계.

    Type 1 / 2 / 3 Factor · 지식 / 소유 / 생체 특성 요소

    지식(아는 것), 소유(가진 것), 생체(고유 특성).

    MFA — Multi-Factor Authentication · 다중 요소 인증

    서로 다른 유형의 인증 요소를 둘 이상 사용하는 것. 같은 유형 둘은 다중요소가 아니다.

    FRR / FAR / CER — False Rejection Rate / False Acceptance Rate / Crossover Error Rate · 오거부율 / 오수락률 / 교차 오류율

    정당한 사용자 거부율(Type I), 부정한 사용자 수락률(Type II), 두 값이 같아지는 교차 오류율.

    Identity Proofing · 신원 증명

    등록 시점에 주장한 신원이 실제인지 확인하는 과정.

    IAL / AAL / FAL — Identity Assurance Level / Authentication Assurance Level / Federation Assurance Level · 신원 확인 / 인증 / 연합 보증 수준

    NIST SP 800-63 의 신원 증명·인증·연합 보증 수준. 독립적으로 선택한다.

    SSO — Single Sign-On · 단일 로그인

    한 번 인증으로 여러 시스템에 접근하는 방식. 단일 실패점이 되기도 한다.

    Federation · 연합

    서로 다른 신뢰 도메인 간에 신원을 공유하는 체계.

    Identity Provider (IdP) / Service Provider (SP) / Relying Party (RP) · 신원 제공자 / 서비스 제공자 또는 신뢰 당사자

    신원을 검증해 주장을 발급하는 주체와, 그 주장을 신뢰해 접근을 허용하는 주체.

    SAML 2.0 — Security Assertion Markup Language · 보안 주장 마크업 언어 2.0

    XML 기반 인증·속성 전달 표준. 기업 웹 SSO 에 널리 쓰인다.

    OAuth 2.0 · 위임 인가 프레임워크

    권한 위임을 위한 인가 프레임워크. 인증 프로토콜이 아니다.

    OIDC — OpenID Connect · 오픈아이디 연결 인증 계층

    OAuth 2.0 위에 인증 계층을 더한 규격. ID 토큰으로 신원을 전달한다.

    FIDO2 / WebAuthn · 피싱 저항 인증 표준 계열 / 웹 인증 API

    공개키 기반 패스워드리스 인증 표준. 출처에 묶여 피싱 저항성을 제공한다.

    Passkey · 패스키

    기기 간 동기화되는 FIDO 자격증명.

    Session Fixation · 세션 고정

    공격자가 지정한 세션 ID 를 피해자가 사용하게 해 세션을 탈취하는 공격.

    JIT — Just-In-Time · 적시 접근 권한 부여

    필요한 순간에만 권한이나 계정을 제공하고 회수하는 방식.

    MFA Fatigue · MFA 피로 공격

    반복적인 푸시 승인 요청으로 사용자의 실수 승인을 유도하는 공격.

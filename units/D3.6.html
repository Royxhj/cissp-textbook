    연습문제 5개 바로가기

    표시 없는 본문은 원본 정리 파일의 내용 · 보충은 원본에 없어 더한 설명 · 가상 예시는 지어낸 상황 · 연결은 다른 단원과의 관계 · 확인 필요는 그대로 확정하지 않은 부분

    암호는 보안의 많은 부분을 떠받치지만, 실제 사고는 알고리즘이 깨져서가 아니라 키를 잘못 다루거나 모드를 잘못 고르거나 인증서를 확인하지 않아서 일어납니다. 이 단원은 암호를 “고르고 쓰고 바꾸는” 판단을 다룹니다. 어떤 문제에 대칭을, 어떤 문제에 비대칭을 쓰는지, 왜 둘을 섞는지, 양자 컴퓨터가 무엇을 바꾸는지, 그리고 공개키를 믿게 해 주는 PKI입니다.

    1암호가 주는 것과 주지 않는 것

    암호는 기밀성·무결성·진정성·부인방지를 제공하는 수단이며, 가용성은 제공하지 않습니다. 오히려 키를 잃으면 데이터를 쓸 수 없게 되므로 가용성을 해칠 수도 있습니다.

    케르크호프스 원칙(Kerckhoffs's Principle) — 시스템의 안전성은 알고리즘의 비밀이 아니라 키의 비밀에 기대야 합니다. 알고리즘이 공개되어도 안전해야 합니다. 원본은 그 실무적 귀결로 직접 만든 암호(roll-your-own crypto)는 쓰지 않는다를 듭니다. 그리고 다시 강조합니다. 실패의 대부분은 알고리즘이 아니라 키 관리와 구현에서 일어난다.

    보충알고리즘을 공개하는 쪽이 더 안전한 이유는 검증 때문입니다. 공개된 알고리즘은 전 세계 연구자가 오랫동안 공격해 보고 살아남은 것이고, 비밀 알고리즘은 만든 사람 몇 명만 검토한 것입니다. 또 알고리즘은 제품에 들어가는 순간 분석될 수 있으므로 비밀로 유지하기 어렵고, 들키면 바꾸기도 어렵습니다. 키는 다릅니다. 짧고, 바꾸기 쉽고, 장치별·사용자별로 다르게 할 수 있습니다. 그래서 비밀은 바꾸기 쉬운 곳(키)에 두라는 것이 이 원칙입니다.

    원문 위치: D3.6.md §2 · 공식 개요 3.6 “Select and determine cryptographic solutions”

    2암호 수명주기

    공식 개요 3.6의 첫 세부 항목이 암호 수명주기(키, 알고리즘 선정)입니다.

    1. 요구사항 정의 — 무엇을, 얼마나 오래 보호할 것인가
    2. 알고리즘 선정 — 승인된 알고리즘과 적정 키 길이
    3. 키 생성 — 고품질 난수
    4. 키 분배 — 안전한 전달
    5. 키 저장 — HSM, 키 관리 시스템
    6. 사용 — 용도 분리
    7. 교체(rotation) — 주기적 갱신
    8. 폐기·소멸 — 안전한 파기
    9. 복구·에스크로 — 키 손실 대비

    원본의 핵심 판단 기준은 보호 기간입니다. 데이터를 10년 보호해야 한다면 10년 뒤에도 안전한 알고리즘과 키 길이를 골라야 합니다. 오늘 안전한 것으로는 부족합니다.

    암호 민첩성(Crypto-agility)은 알고리즘이 깨졌을 때 빨리 바꿀 수 있는 설계입니다. 알고리즘을 코드에 박지 않고 설정으로 분리하며, 인증서와 키의 인벤토리를 유지합니다. 원본은 양자 내성 암호로의 전환을 앞두고 특히 중요해졌다고 설명합니다.

    가상 예시현장에 10년 이상 설치되는 장비가 통신에 특정 서명 알고리즘을 쓰도록 펌웨어에 고정되어 있다면, 그 알고리즘이 약해졌다고 판정되어도 바꾸려면 모든 장비의 펌웨어를 교체해야 합니다. 설계 단계에서 “알고리즘 식별자 + 키”를 설정으로 받을 수 있게 하고, 장비별로 어떤 알고리즘과 인증서를 쓰는지 목록을 유지하면, 전환 시점에 영향 범위를 바로 알고 단계적으로 바꿀 수 있습니다. 장비 수명이 길수록 암호 민첩성의 가치가 커집니다.

    연결보호 기간과 키 수명주기의 권고는 원본이 드는 NIST SP 800-57, 알고리즘·키 길이 전환 지침은 SP 800-131A에 있습니다. 인증서·키 인벤토리는 D2.3 안전한 프로비저닝의 인벤토리, 장기 보존 데이터의 키 보존은 D2.5 자산 보존 (EOL·EOS)에서 다뤘습니다.

    원문 위치: D3.6.md §3 암호 수명주기, §6 NIST SP 800-57·800-131A · 공식 개요 3.6 “Cryptographic life cycle (e.g., keys, algorithm selection)”

    3대칭키 암호

    쉬운 설명

    송신자와 수신자가 같은 키를 공유합니다.

    특징내용
    속도빠름 — 대량 데이터 암호화에 적합
    제공기밀성, (MAC와 결합하면) 무결성·진정성
    제공하지 않음부인방지 — 같은 키를 둘이 가지므로 누가 만들었는지 제3자에게 증명할 수 없다
    과제키 분배와 키 개수

    키 개수 공식

    n명이 서로 통신하려면 필요한 대칭키 수는 n(n−1)/2입니다. 100명이면 100 × 99 / 2 = 4,950개입니다. 비대칭키는 각자 공개키·개인키 한 쌍이면 되므로 2n개, 100명이면 200개입니다.

    원문 사례 — 키 개수 계산. 지사 50곳이 서로 안전하게 통신하려면 대칭키만으로는 50 × 49 / 2 = 1,225개의 키가 필요하고, 지사가 하나 늘 때마다 50개가 추가됩니다. PKI를 도입해 각 지사가 키 쌍 하나씩만 갖자 관리 대상이 100개로 줄었습니다.

    보충공식이 n(n−1)/2인 이유는 악수 횟수와 같습니다. n명 각자가 나머지 n−1명과 키를 하나씩 나누면 n(n−1)개인데, A-B와 B-A는 같은 키이므로 2로 나눕니다. 새 사람이 한 명 들어오면 기존 n명 모두와 새 키가 필요하므로 n개가 늘어납니다(사례의 “하나 늘 때마다 50개”). 이 증가 속도가 대칭키만으로는 규모를 키우기 어려운 이유이고, 비대칭 암호가 해결한 문제입니다.

    주요 알고리즘과 블록·스트림

    알고리즘상태
    DES (56비트)폐기 — 키가 너무 짧다
    3DES폐기 권고 — 느리고 블록 크기가 작다
    AES (128/192/256)현행 표준(FIPS 197)
    ChaCha20스트림 암호, 모바일에서 효율적
    • 블록 암호 — 고정 크기 블록 단위로 처리(AES는 128비트 블록)
    • 스트림 암호 — 비트·바이트 단위로 처리. 빠르고 실시간 통신에 적합. 키 스트림 재사용은 치명적이다
    원본 연습문제 · D3.6-Q01

    지사 50곳이 대칭 암호만으로 서로 안전하게 통신해야 한다. 필요한 고유 대칭키 수는?

    1. 1,225개
    2. 100개
    3. 2,500개
    4. 50개
    정답과 해설 보기

    정답 A. n 명이 서로 통신할 때 필요한 대칭키 수는 n(n-1)/2 다. 50 × 49 / 2 = 1,225 개가 된다. 비대칭 방식이라면 각자 키 쌍 하나씩 2n = 100 개로 충분해 대칭 방식의 확장성 문제가 드러난다.

    • B · 비대칭 방식에서 필요한 키 수(2n)다.
    • C · n² 로 잘못 계산한 값이다.
    • D · 각 지사당 1개로 계산한 값이며 쌍별 키가 아니다.

    4블록 암호 운영 모드

    같은 알고리즘이라도 모드에 따라 안전성이 크게 달라집니다.

    모드특징
    ECB블록마다 독립 암호화. 같은 평문 → 같은 암호문. 패턴이 드러나 쓰지 않는다
    CBC이전 블록과 XOR. IV 필요. 순차 처리
    CTR카운터를 암호화해 스트림처럼 사용. 병렬 처리 가능
    GCMCTR + 인증. 기밀성과 무결성을 함께 제공(AEAD)

    원문 사례 — ECB 모드가 드러낸 이미지. 개발자가 이미지 파일을 AES-ECB로 암호화했는데, 암호화된 파일을 이미지로 표시하자 원본의 윤곽이 그대로 보였습니다. 같은 평문 블록이 같은 암호문 블록이 되므로 반복 패턴이 남은 것입니다. GCM으로 바꿔 기밀성과 무결성을 함께 확보했습니다.

    원본은 GCM 같은 AEAD 모드가 현대의 기본 선택이라고 정리합니다. 암호화와 무결성 검증을 따로 구현하면 실수하기 쉽기 때문입니다.

    IV / Nonce는 같은 키로 같은 평문을 암호화해도 다른 암호문이 나오게 하는 값이며, 재사용하면 안 됩니다. 원본은 CTR·GCM에서 nonce를 재사용하면 키 노출로 이어질 수 있다고 경고합니다.

    보충ECB가 위험한 이유를 한 문장으로 하면 “암호화했는데 같은 것끼리 같아 보인다”입니다. 데이터베이스의 같은 값(예: 같은 진단 코드)이 같은 암호문이 되면, 내용은 몰라도 “이 두 환자는 같은 진단”이라는 정보가 샙니다. IV와 nonce는 매번 다른 출발점을 줘서 이 문제를 없앱니다. 그래서 재사용하면 ECB와 비슷한 패턴 노출이 생기고, CTR·GCM에서는 그보다 더 나쁜 결과가 됩니다.

    연결모드와 nonce의 잘못된 사용을 노리는 공격은 D3.7 암호 분석 공격에서 다룹니다.

    원문 위치: D3.6.md §3 블록 암호 운영 모드, §7 사례 1

    5비대칭키 암호와 타원곡선

    방향이 핵심이다

    공개키와 개인키 쌍을 씁니다.

    목적사용하는 키
    기밀성(암호화)받는 사람의 공개키로 암호화 → 받는 사람의 개인키로 복호화
    부인방지·진정성(서명)보내는 사람의 개인키로 서명 → 보내는 사람의 공개키로 검증

    원본의 요약은 암호화는 받는 사람의 공개키로, 서명은 보내는 사람의 개인키로입니다.

    보충방향은 “누구만 할 수 있어야 하는가”로 생각하면 헷갈리지 않습니다. 암호화에서 지키고 싶은 것은 “받는 사람만 열 수 있다”이므로, 받는 사람만 가진 개인키로 열리게 하려면 그 짝인 받는 사람의 공개키로 잠급니다. 서명에서 지키고 싶은 것은 “보낸 사람만 만들 수 있다”이므로, 보낸 사람만 가진 개인키로 서명하고 누구나 가진 공개키로 확인합니다. 개인키는 언제나 “그 사람만 할 수 있는 일”에 쓰입니다.

    주요 알고리즘

    알고리즘기반용도
    RSA소인수분해암호화·서명
    Diffie-Hellman이산대수키 교환 전용(암호화 불가)
    ECC타원곡선 이산대수암호화·서명·키 교환
    ElGamal이산대수암호화·서명
    DSA / ECDSA이산대수서명 전용

    단점은 대칭키보다 수백~수천 배 느리다는 것입니다. 그래서 대량 데이터를 직접 암호화하지 않습니다.

    타원곡선 암호 (ECC)

    공식 개요 3.6이 암호 방식의 예로 elliptic curves를 따로 듭니다. ECC는 같은 보안 강도를 훨씬 짧은 키로 달성합니다.

    보안 강도RSA 키 길이ECC 키 길이
    128비트 수준3072비트256비트
    192비트 수준7680비트384비트

    키·서명 크기가 작고 연산이 빠르며 전력 소비가 적어 모바일, IoT, 임베디드 환경에 특히 적합합니다.

    확인 필요위 표에서 보듯 키 길이의 숫자만으로 알고리즘 사이의 강도를 비교할 수 없습니다. RSA 3072비트와 ECC 256비트가 비슷한 강도입니다. 알고리즘을 고를 때는 용도(서명인지 키 합의인지)를 먼저 구분하고, 조직이 승인한 강도·구현·호환성과 키 수명을 함께 봅니다. 표의 대응값은 원본의 수치이며 NIST SP 800-57의 비교표와 같은 계열의 값입니다.

    원문 위치: D3.6.md §3 비대칭키 암호, 타원곡선 암호, §5 둘째 표 · 공식 개요 3.6 “asymmetric, elliptic curves”

    6하이브리드 구조와 순방향 비밀성

    실제 시스템은 대칭과 비대칭을 함께 씁니다.

    1. 비대칭세션키(대칭키)를 안전하게 교환·합의
    →

    완전 순방향 비밀성 (PFS)

    PFS(Perfect Forward Secrecy)는 세션마다 임시(ephemeral) 키 쌍을 써서, 장기 개인키가 나중에 유출되어도 과거 세션을 복호화할 수 없게 합니다. DHE, ECDHE가 이를 제공합니다. 정적 RSA 키 교환은 PFS를 제공하지 않아, 개인키가 유출되면 저장해 둔 과거 트래픽이 모두 복호화됩니다. 원본은 이것이 “지금 수집하고 나중에 복호화한다(harvest now, decrypt later)” 공격에 대한 방어이기도 하다고 설명합니다.

    원문 사례 — PFS가 없어 과거 트래픽이 복호화된 경우. 서버 개인키가 유출되자 공격자는 수년간 모아 둔 암호화 트래픽을 모두 복호화했습니다. 정적 RSA 키 교환이라 세션키가 서버 개인키로 보호되고 있었기 때문입니다. ECDHE 기반 PFS를 적용한 뒤로는 장기 키가 유출되어도 과거 세션을 풀 수 없게 되었습니다.

    보충차이는 “세션키를 무엇으로 감쌌는가”입니다. 정적 RSA에서는 세션키를 서버의 장기 공개키로 암호화해 보내므로, 그 장기 개인키가 모든 과거 세션키의 열쇠가 됩니다. ECDHE에서는 양쪽이 세션마다 새 임시 키로 세션키를 합의하고 끝나면 버리므로, 장기 키는 “상대가 진짜 서버인가”를 확인하는 서명에만 쓰입니다. 장기 키가 털려도 과거의 임시 키는 이미 사라졌습니다. 그래서 설계 검토에서는 데이터 보호(대칭), 세션키 합의(임시 키), 상대 인증(장기 키 서명)을 각각 따로 확인합니다.

    연결TLS·IPSec·VPN의 실제 구성은 D4.3 안전한 통신 채널에서 다룹니다.

    원본 연습문제 · D3.6-Q05

    서버의 장기 개인키가 유출된 후 공격자가 수년간 수집해 둔 TLS 트래픽을 복호화했다. 이를 막았을 성질은?

    1. 서버에서 OCSP 스테이플링 활성화.
    2. ECDHE 같은 임시 키 교환을 사용하는 완전 순방향 비밀성.
    3. 클라이언트 측 인증서 고정.
    4. 서버 인증서의 더 긴 RSA 키 길이.
    정답과 해설 보기

    정답 B. 정적 RSA 키 교환에서는 세션키가 서버 개인키로 보호되어 개인키가 유출되면 저장된 과거 트래픽을 모두 복호화할 수 있다. DHE/ECDHE 는 세션마다 임시 키 쌍을 사용해 장기 키가 유출되어도 과거 세션을 복호화할 수 없게 한다.

    • A · OCSP 스테이플링은 폐기 상태 확인 방식이다.
    • C · 인증서 고정은 중간자 공격 대응이며 과거 트래픽 보호와 무관하다.
    • D · 키를 늘려도 유출되면 같은 문제가 발생한다.

    7해시, MAC, 디지털 서명

    해시 함수

    임의 길이 입력을 고정 길이 출력으로 바꾸는 단방향 함수이며 복원할 수 없습니다. 요구 속성은 셋입니다.

    • 역상 저항성 — 해시값에서 입력을 찾을 수 없다
    • 제2 역상 저항성 — 주어진 입력과 같은 해시를 갖는 다른 입력을 찾을 수 없다
    • 충돌 저항성 — 같은 해시를 갖는 임의의 두 입력을 찾을 수 없다

    생일 공격(Birthday Attack)은 충돌을 찾는 공격입니다. 생일 역설 때문에 n비트 해시의 충돌 저항성은 n/2비트에 불과합니다. 256비트 해시의 충돌 저항성은 128비트 수준입니다.

    SHA-3현행, 다른 구조(스펀지)

    디지털 서명은 메시지 해시 → 송신자 개인키로 서명하는 구조입니다. 원본은 MAC·HMAC가 부인방지를 제공하지 않는다는 점을 강조합니다.

    비밀번호 저장에는 일반 해시가 아니라 전용 함수를 씁니다. bcrypt, scrypt, Argon2, PBKDF2처럼 일부러 느리고 솔트를 쓰는 함수여야 무차별 대입에 견딥니다.

    판단 순서배포 파일을 보호하는 수단을 고를 때 ① “내용이 바뀌었는가”만 확인하면 되나 → 신뢰할 경로로 받은 해시와 비교 ② “키를 공유한 상대가 보냈는가”까지 확인하나 → MAC(단, 공유한 두 주체 중 누가 만들었는지는 구별 못 함) ③ “누구나 발행자와 무결성을 검증하고, 발행자가 부인할 수 없어야” 하나 → 디지털 서명. 소프트웨어 배포처럼 받는 쪽이 불특정 다수면 ③이 답입니다.

    연결해시·MAC·서명이 CIA와 부인방지 중 무엇을 제공하는지는 D1.2 보안 개념 (CIA 등), 해싱과 토큰화·암호화의 비교는 D2.6 데이터 보안 통제, 생일 공격과 비밀번호 해시 공격은 D3.7 암호 분석 공격에서 다룹니다. 원본은 디지털 서명 표준으로 FIPS 186을 들며, 현행판은 FIPS 186-5(2023년 2월)입니다.

    원본 연습문제 · D3.6-Q14

    해싱과 암호화를 구분하는 것은?

    1. 둘 다 입력과 같은 길이의 출력을 만든다.
    2. 해싱이 기밀성을, 암호화가 무결성을 보호한다.
    3. 해싱은 키를 쓰고 암호화는 쓰지 않는다.
    4. 암호화는 올바른 키로 되돌릴 수 있도록 설계되고 해싱은 무결성 검증에 쓰이는 고정 길이 값을 만드는 단방향 함수다.
    정답과 해설 보기

    정답 D. 암호화의 목적은 되돌리는 것이고 해싱의 목적은 되돌릴 수 없는 것이다. 그래서 비밀번호 저장에는 해싱을 쓰고 통신 내용 보호에는 암호화를 쓴다. 해시는 입력 길이와 무관하게 고정 길이 출력을 만들며 같은 입력은 항상 같은 해시를 내므로 변경 여부를 검증할 수 있다.

    • A · 해시는 고정 길이 출력을 만든다.
    • B · 보호 속성이 뒤바뀌었다.
    • C · 키 사용 설명이 뒤바뀌었다.

    8양자 컴퓨팅의 영향

    대칭과 비대칭에 미치는 영향이 다르다

    원본이 이 단원에서 가장 중요한 구분으로 꼽는 부분입니다.

    대상양자 알고리즘영향대응
    RSA, DH, ECCShor사실상 완전 무력화알고리즘 교체(PQC)
    AES 등 대칭키Grover탐색 속도가 제곱근으로 단축 → 유효 강도 절반키 길이 확대(AES-256)
    해시Grover저항성 일부 감소충분한 출력 길이

    원본의 결론입니다. 비대칭 암호는 교체가 필요하다. 대칭 암호는 키 길이를 늘리면 된다. AES-128은 유효 64비트가 되지만 AES-256은 유효 128비트로 여전히 안전합니다.

    PQC와 QKD

    기술성격인프라
    PQC Post-Quantum Cryptography 양자 내성 암호양자 컴퓨터로도 풀기 어려운 수학 문제에 기반한 알고리즘. 고전 컴퓨터에서 동작기존 인프라
    QKD Quantum Key Distribution 양자 키 분배양자 물리로 키를 분배. 도청하면 양자 상태가 교란되어 도청 사실이 탐지된다전용 광 인프라, 거리 제약

    원본은 QKD는 암호화 알고리즘이 아니라 키 분배 방식이며 PQC와도 다르다고 주의시킵니다. 공식 개요는 QKD를 PKI 항목의 예로 듭니다.

    원문 사례 — 양자 대비 전환 계획. 보호 기간이 20년인 의료 기록을 다루는 조직이 대칭은 AES-128 → AES-256, 비대칭은 RSA-2048 → NIST 표준 PQC 알고리즘으로 전환하는 로드맵을 세우고, 알고리즘을 설정으로 분리하고 인증서 인벤토리를 만들어 암호 민첩성을 확보했습니다. 원본은 “지금 수집하고 나중에 복호화” 위협 때문에 보호 기간이 긴 데이터일수록 전환이 시급하다고 정리합니다.

    확인 필요원본은 “NIST가 2024년 PQC 표준을 발표했다(격자 기반 등)”까지만 적습니다. 2024년 표준은 FIPS 203(ML-KEM, 키 확립), FIPS 204(ML-DSA, 서명), FIPS 205(SLH-DSA, 서명)입니다(일반 지식에 근거). 그 뒤 NIST는 2026년 10월 27일 IR 8547(양자 내성 암호 표준으로의 전환) 최종판을 발행했습니다(NIST CSRC 문서 이력: 2024-11-12 초안, 2026-10-27 최종). 2차 자료가 전하는 최종판 표에 따르면 RSA·ECDSA·ECDH 같은 양자 취약 공개키 알고리즘은 키 크기와 관계없이 2030년 이후 사용 중단 권고(deprecated), 2035년 이후 허용 안 함(disallowed)이며, 2024년 초안에서 2035년까지 허용되던 RSA-3072·P-256 등도 2030년 이후 중단 권고로 바뀌었습니다(Cloud Security Alliance 연구 노트, postquantum.com 보도). 최종 발행 사실은 NIST CSRC에서 확인했고, 알고리즘별 일정표는 NIST 원문 PDF가 아니라 위 2차 자료로 확인한 것입니다. 시험 개요(2024판) 기준 수험서는 이 일정을 다루지 않을 수 있습니다.

    가상 예시장비가 수집해 회사로 보내는 데이터 중 오래 비밀이어야 하는 것(설계 정보, 환자 관련 정보)이 있고 장비 수명이 15년이라면, 이 장비들은 2035년 이후에도 현장에 있습니다. 지금 RSA 키 교환으로 보낸 트래픽은 누군가 모아 두었다가 나중에 풀 수 있습니다. 그래서 새로 설계하는 장비는 ① 통신 키 합의부터 양자 내성 방식(또는 기존 방식과 섞은 하이브리드)으로 바꿀 수 있게 하고 ② 대칭 암호는 AES-256을 쓰며 ③ 펌웨어 서명 알고리즘을 나중에 바꿀 수 있게 설계합니다. 이것이 2절의 암호 민첩성이 실제로 필요한 장면입니다.

    CISSP 관점양자 대비를 묻는 상황에서는 ① 대상이 대칭인지 비대칭인지 먼저 가리고 ② 대칭이면 키 길이 확대(AES-256), 비대칭이면 PQC로 전환을 고르며 ③ PQC(수학 기반 알고리즘)와 QKD(물리 기반 키 분배)를 섞은 선택지를 경계합니다. “보호 기간이 긴 데이터”가 나오면 지금 수집해 나중에 복호화하는 위협을 떠올립니다.

    원본은 지식 분할과 이중 통제가 함께 쓰인다고 설명합니다. 키를 조각내 나눠 갖고(지식 분할), 쓰려면 모두 모여야 합니다(이중 통제).

    보충용도 분리가 필요한 이유는 키마다 수명과 보관 요구가 다르기 때문입니다. 암호화 키는 잃으면 데이터를 못 읽으므로 에스크로(복구 사본)가 필요할 수 있지만, 서명 키를 남이 보관하면 그 사람이 서명을 위조할 수 있어 부인방지가 무너집니다. 그래서 서명 키는 보통 에스크로하지 않습니다. 또 키를 교체해도 이전 키로 암호화된 보관 자료를 읽어야 한다면 이전 키를 복호화 전용으로 남겨 두는 계획이 필요하고, 더 이상 읽어서는 안 되는 자료라면 보존 정책에 따라 키를 파기합니다(암호 소거).

    용어 주의원본 D3.6의 ‘분할 지식’, D1.8의 ‘2인 통제’는 이 교재에서 각각 지식 분할(Split Knowledge), 이중 통제(Dual Control)로 통일합니다.

    연결직무 분리·이중 통제와의 관계는 D1.8 인적 보안, HSM과 키 소멸은 D3.4 시스템 보안 기능, 암호 소거는 D2.4 데이터 생애주기, 장기 보존 데이터의 키 에스크로는 D2.5 자산 보존 (EOL·EOS), 운영 중 키·인증서 관리는 D7.5 자원 보호에서 다룹니다.

    원본 연습문제 · D3.6-Q10

    키를 여러 보관자가 나눠 보관하고 사용하려면 모두 모여야 한다. 이 조합이 나타내는 통제는?

    1. 키 에스크로와 인증서 고정
    2. 지식 분할과 이중 통제
    3. 암호 민첩성과 소멸
    4. 순방향 비밀성과 키 교체
    정답과 해설 보기

    정답 B. 지식 분할(split knowledge)은 키를 조각내어 여러 사람이 나눠 보관하는 것이고 이중 통제(dual control)는 사용하려면 둘 이상이 동시에 참여해야 하는 것이다. 두 통제는 함께 쓰이며 D1.8 의 직무 분리·이중 통제와 같은 원리다.

    • A · 키 에스크로는 복구를 위한 제3자 보관이다.
    • C · 암호 민첩성은 교체 용이성, 소멸은 사용 후 제거다.
    • D · 순방향 비밀성과 키 교체는 별개의 개념이다.

    10공개키 기반구조 (PKI)

    왜 필요한가

    비대칭 암호는 “받는 사람의 공개키로 암호화”하라고 하지만, 그 공개키가 정말 그 사람의 것인지는 어떻게 알까요. 공격자가 자기 공개키를 남의 것이라고 속이면 암호화는 공격자를 위해 하게 됩니다. PKI는 공개키와 주체를 묶어 보증하는 체계입니다.

    요소역할
    CA 인증기관인증서 발급·서명·폐기
    RA 등록기관신원 확인과 등록 요청 처리
    인증서 저장소인증서와 폐기 목록 게시
    최종 개체인증서를 쓰는 주체

    원본은 루트 CA는 오프라인으로 보관하는 것이 원칙이라고 합니다. 루트가 침해되면 그 아래 전체 신뢰가 무너지기 때문입니다.

    폐기 확인과 검증 항목

    방식특징
    CRL 폐기 목록주기적으로 내려받는다. 크기가 커지고 시차가 생긴다
    OCSP 온라인 상태 확인실시간 조회. 프라이버시 문제와 가용성 의존
    OCSP Stapling서버가 응답을 미리 받아 첨부. 둘의 단점을 보완

    인증서를 검증할 때 확인할 것: 서명 유효성과 신뢰 체인, 유효 기간, 폐기 여부, 용도(Key Usage)와 이름 일치.

    원문 사례 — 인증서 검증을 생략한 모바일 앱. 앱이 TLS를 썼지만 개발 편의로 넣은 코드 때문에 인증서 검증이 꺼진 채 운영에 나갔습니다. 공격자가 자체 서명 인증서로 중간자 공격을 해 모든 통신을 평문으로 보았습니다. 원본의 결론은 TLS는 인증서 검증이 작동해야 의미가 있다. 암호화 자체보다 상대가 진짜인지 확인하는 것이 핵심이다입니다.

    보충검증 항목 중 “이름 일치”가 자주 빠집니다. 신뢰하는 CA가 발급한 유효한 인증서라도, 장비가 접속하려는 서버 이름과 인증서에 적힌 이름이 다르면 그 인증서는 “다른 서버가 진짜”라는 것만 증명합니다. 서명·체인·기간·폐기만 보고 이름을 안 보면, 공격자가 정상 발급받은 자기 도메인 인증서로도 중간자 공격이 가능합니다. 사설 CA를 쓰는 장비라면 그 루트 인증서를 어떻게 배포하고 교체할지도 설계에 들어가야 합니다.

    연결TLS와 VPN의 구성은 D4.3 안전한 통신 채널, 인증서 기반 사용자·기기 인증은 D5.6 인증 시스템, 중간자 공격은 D3.7 암호 분석 공격·D4.1 네트워크 아키텍처에서 다룹니다. 원본은 RFC 5280(X.509 인증서와 CRL)과 RFC 6960(OCSP)을 듭니다.

    2. ㉠ 그대로 / ㉡ 그대로 / ㉢ 그대로 / ㉣ 그대로
    3. ㉠ ECB 모드로 속도 확보 / ㉡ MD5로 교체 / ㉢ RSA 키 길이만 늘림 / ㉣ QKD 도입
    4. ㉠ 해시로 암호화 / ㉡ 해시만 사용 / ㉢ OCSP 사용 / ㉣ AES-128 유지

    정답 A.

    복습

    TLS가 대칭키와 공개키 기술을 함께 사용하는 이유를 어떻게 설명하나요?

    설명 확인하기

    연결에서 상대의 신원을 확인하고 세션 키를 합의할 때 공개키 기술을 쓸 수 있습니다. 연결 후 많은 데이터를 보호할 때는 합의한 비밀로 효율적인 대칭키 암호를 사용합니다. 두 단계의 실패 조건이 다릅니다.

    13핵심 요약

    1. 암호는 기밀성·무결성·진정성·부인방지를 제공, 가용성은 제공하지 않는다. 케르크호프스 원칙: 비밀은 키에. 자체 제작 암호 금지.
    2. 수명주기: 요구 → 알고리즘 → 생성 → 분배 → 저장 → 사용 → 교체 → 폐기 → 복구. 기준은 보호 기간. 암호 민첩성.
    3. 대칭: 빠름, 부인방지 불가, 키 분배 과제. 키 수 n(n−1)/2(100명 4,950개) vs 비대칭 2n. AES 현행, DES 폐기, 3DES 폐기 권고.
    4. 모드: ECB는 패턴 노출로 금지, CBC, CTR, GCM = AEAD(기밀성 + 무결성). IV/nonce 재사용 금지.
    5. 암호화는 받는 사람의 공개키, 서명은 보내는 사람의 개인키. DH = 키 교환 전용, DSA/ECDSA = 서명 전용.
    6. ECC: 같은 강도를 짧은 키로(RSA 3072 ≈ ECC 256). 모바일·IoT에 적합.
    7. 하이브리드: 비대칭으로 세션키 합의 → 대칭으로 데이터. PFS = 세션마다 임시 키(DHE/ECDHE), 정적 RSA는 PFS 없음.
    8. 해시: 역상·제2 역상·충돌 저항성. 생일 공격 → 충돌 저항성 n/2비트. MD5·SHA-1 파기, SHA-2·SHA-3 현행.
    9. MAC/HMAC는 부인방지 없음, 디지털 서명은 무결성·진정성·부인방지. 비밀번호는 bcrypt·scrypt·Argon2·PBKDF2.
    10. Shor → RSA·DH·ECC 무력화 → PQC로 교체. Grover → 대칭 유효 강도 절반 → AES-256. PQC = 수학 알고리즘, QKD = 물리 기반 키 분배.
    11. 키 관리: 용도 분리, 주기적 교체, HSM/KMS 보관, 지식 분할 + 이중 통제, 에스크로, 소멸.
    12. PKI: CA(발급·폐기), RA(신원 확인), 루트 CA 오프라인. 폐기 확인: CRL / OCSP / OCSP Stapling. 검증: 서명·체인, 기간, 폐기, 용도·이름 일치. 검증 생략은 중간자 공격을 부른다.
    원문 위치: D3.6.md §8 CISSP 시험 관점, §9 핵심 암기 요약. 원본의 “계산 문제로 자주 나온다”, “시험 단골” 같은 출제 단정 표현은 판단 기준으로 바꿔 적었습니다. 원본 §6의 FIPS 140-2/140-3(암호 모듈)은 D3.4 시스템 보안 기능에 있습니다.

    14주요 용어 (Glossary)

    영어 원어와 한국어 뜻 · English–Korean

    Kerckhoffs's Principle · 케르크호프스 원칙

    시스템의 안전성은 알고리즘의 비밀이 아니라 키의 비밀에 의존해야 한다는 원칙.

    Crypto-agility · 암호 민첩성

    알고리즘이 깨졌을 때 신속히 교체할 수 있도록 하는 설계 속성.

    Symmetric / Asymmetric · 대칭 / 비대칭

    같은 키를 공유하는 방식과 공개키·개인키 쌍을 쓰는 방식.

    ECB / CBC / CTR / GCM — Electronic Codebook / Cipher Block Chaining / Counter / Galois/Counter Mode · 전자 코드북 / 암호 블록 연쇄 / 카운터 / 갈루아 카운터 모드

    블록 암호 운영 모드. ECB 는 패턴이 드러나 사용 금지, GCM 은 기밀성과 무결성을 함께 제공한다.

    AEAD — Authenticated Encryption with Associated Data · 연관 데이터가 있는 인증 암호

    암호화와 무결성 검증을 함께 수행하는 방식. GCM 이 대표적이다.

    IV / Nonce · 초기화 벡터 / 논스

    같은 키로 같은 평문을 암호화해도 다른 결과가 나오게 하는 값. 재사용하면 안 된다.

    Diffie-Hellman · 디피–헬먼 키 합의

    키 교환 전용 알고리즘. 데이터를 직접 암호화하지 않는다.

    ECC — Elliptic Curve Cryptography · 타원곡선 암호

    짧은 키로 동등한 보안 강도를 제공하는 비대칭 암호. 모바일·IoT 에 적합하다.

    Hybrid Cryptosystem · 하이브리드 암호 시스템

    비대칭으로 세션키를 교환하고 대칭으로 데이터를 암호화하는 구조. TLS 가 대표적이다.

    PFS — Perfect Forward Secrecy · 완전 순방향 비밀성

    세션마다 임시 키를 사용해 장기 키가 유출되어도 과거 세션이 복호화되지 않게 하는 성질. DHE/ECDHE 가 제공한다.

    Birthday Attack · 생일 공격

    해시 충돌을 찾는 공격. n비트 해시의 충돌 저항성은 n/2 비트다.

    Split Knowledge / Dual Control · 지식 분할 / 이중 통제

    키를 나눠 보관하고 사용 시 여러 명이 동시에 참여하게 하는 통제.

    Key Escrow · 키 에스크로

    키 손실에 대비해 제3자가 키를 보관하는 체계.

    Zeroization · 소멸

    사용 후 메모리나 저장소에서 키를 안전하게 제거하는 것.

    Shor's Algorithm · 쇼어 알고리즘

    양자 컴퓨터에서 소인수분해와 이산대수를 효율적으로 푸는 알고리즘. RSA·DH·ECC 를 무력화한다.

    Grover's Algorithm · 그로버 알고리즘

    양자 탐색 알고리즘. 대칭키의 유효 강도를 절반으로 줄인다.

    PQC — Post-Quantum Cryptography · 양자 내성 암호

    양자 컴퓨터로도 풀기 어려운 문제에 기반한 알고리즘. 고전 컴퓨터에서 동작한다.

    QKD — Quantum Key Distribution · 양자 키 분배

    양자역학 원리로 키를 분배하는 방식. 도청 시도가 탐지된다. 암호 알고리즘이 아니다.

    CA / RA — Certification Authority / Registration Authority · 인증 기관 / 등록 기관

    인증기관과 등록기관. CA 는 인증서를 발급·서명하고 RA 는 신원 확인을 담당한다.

    CRL / OCSP — Certificate Revocation List / Online Certificate Status Protocol · 인증서 폐기 목록 / 온라인 인증서 상태 프로토콜

    인증서 폐기 목록과 온라인 인증서 상태 확인 프로토콜.

    연습문제 5개 바로가기

    표시 없는 본문은 원본 정리 파일의 내용 · 보충은 원본에 없어 더한 설명 · 가상 예시는 지어낸 상황 · 연결은 다른 단원과의 관계 · 확인 필요는 그대로 확정하지 않은 부분

    원본의 첫 문장이 이 단원의 전부를 말합니다. 시험되지 않은 계획은 계획이 아니라 가정이다. 문서상 완벽한 계획이 실제로 작동하는지는 시험으로만 알 수 있습니다. 공식 개요 7.12는 다섯 가지 시험 유형과 함께 소통을 별도 항목으로 듭니다. 실제 시험에서 가장 자주 실패하는 영역이기 때문입니다. 그리고 원본은 한 가지 역설을 강조합니다. 시험은 실패해야 가치가 있다.

    낭독·테이블탑과 워크스루

    낭독(read-through, checklist review)은 담당자가 계획과 체크리스트를 읽고 자기 역할과 필요 자원을 확인하고, 테이블탑은 관계자가 모여 “이 상황에서 어떻게 할 것인가”를 논의합니다. 문서 오류, 오래된 연락처, 역할 공백, 서로 다른 이해, 비현실적 가정을 찾지만, 실제 수행 능력과 기술적 작동은 검증하지 못합니다. 비용이 거의 없어 자주 할 수 있고, 신규 인력 교육과 계획 갱신 직후에 적합합니다.

    워크스루는 계획의 각 단계를 순서대로 따라가며 전제, 필요 자원, 소요 시간, 선행 조건을 확인합니다. 단계 간 순서 오류, 누락된 선행 작업, 의존성 간과를 찾으며 절차 순서 검증에 더 초점이 있습니다.

    시뮬레이션

    가상의 재해 시나리오를 제시하고 참여자가 실제로 역할을 수행합니다. 진행자가 상황을 단계적으로 주입(inject)합니다(“주 사이트 전원 완전 상실”, “핵심 담당자 연락 두절”). 의사결정 지연, 소통 혼선, 권한 불명확을 찾아내며, 원본은 운영 위험 없이 의사결정 품질을 볼 수 있는 가장 좋은 수단이라고 평가합니다. 예상하지 못한 상황 주입이 가치를 높입니다.

    원문 사례 — 시뮬레이션이 드러낸 의사결정 공백. “주 데이터센터 전원 완전 상실”을 주입했더니 참여자들은 기술 절차는 잘 알았지만 누가 DR 발동 권한이 있는지 서로 다르게 답했고, 발동 결정에 모의 시간 2시간이 걸렸습니다.

    병행 처리와 전면 중단

    병행 처리는 대체 사이트를 실제로 가동해 실제 처리를 수행하고 결과를 비교하며, 주 사이트는 계속 서비스합니다. 데이터 동기화 지연, 용량 부족, 설정 불일치, 실제 RTO·RPO를 찾습니다. 네트워크 충돌, 중복 처리, 외부 시스템 이중 전송에 주의해야 하지만, 원본은 실무에서 가장 균형 잡힌 선택으로 평가합니다.

    원문 사례 — 병행 처리가 찾은 용량 부족. 대체 사이트에서 실제 거래를 처리하자 주 사이트의 40% 수준 처리량에서 응답 시간이 기준을 넘었습니다. 대체 사이트 용량이 평시 부하 기준으로만 산정되어 있었습니다.

    전면 중단은 가장 현실적이고 가장 많이 발견하지만, 전환이 실패하면 실제 장애가 됩니다. 전제는 하위 단계 시험 통과, 경영진 승인, 고객 고지, 복귀 계획, 중단 기준이며, 결산·성수기를 피합니다. 많은 조직이 수행하지 못해 병행 처리로 대체하고 일부 서비스에 한정합니다.

    원본의 원칙: 시험 수준을 점진적으로 올린다. 테이블탑도 통과하지 못하는 조직이 전면 중단을 하면 실제 장애만 만들고 배우는 것이 없습니다(레드팀 전에 기본 위생이 먼저인 것과 같은 논리).

    원문 사례 — 전면 중단 시험 실패. 하위 단계를 충분히 거치지 않고 전면 중단을 시도했다가 전환이 실패해 실제 장애가 6시간 이어졌는데, 발견된 결함은 워크스루에서 찾을 수 있었던 기본 문제들이었습니다.

    보충시험 유형은 “무엇을 알고 싶은가”에 맞춰 고릅니다. 테이블탑은 의사결정과 연락 흐름을 보는 데 유용하지만, 실제 복원 시간을 알아야 한다면 복원을 실제로 수행해 시간을 잴 수 있는 방식(병행 처리, 부분 복원 시험)이 필요합니다. 의료기관이라면 진료 시스템 전면 중단 시험은 현실적으로 어렵기 때문에, 병행 처리와 다운타임 수기 절차 훈련을 조합하는 경우가 많습니다.

    연결레드팀의 전제는 D6.2 보안 통제 테스트의 3절, 발동 권한과 대리 순서는 D7.11 재해 복구 프로세스의 2절, 복구 사이트 용량 보장은 D7.10 복구 전략의 4절에서 다룹니다.

    원본 연습문제 · D7.12-Q01

    운영 시스템에 아무 위험 없이 직원이 압박 속에서 올바른 결정을 내릴 수 있는지 검증하는 재해 복구 시험 유형은?

    1. 시스템을 전환하지 않고 전개되는 시나리오에 맞춰 참여자가 자기 역할을 수행하는 시뮬레이션.
    2. 대체 사이트가 실제 거래를 처리하는 병행 처리 시험.
    3. 각 담당자가 계획을 읽고 자기 역할을 확인하는 체크리스트 검토.
    4. 주 사이트를 실제로 중단하는 전면 중단 시험.
    정답과 해설 보기

    정답 A. 시뮬레이션은 가상 시나리오를 단계적으로 주입하며 참여자가 실제로 역할을 수행하지만 시스템은 전환하지 않는다. 따라서 운영 위험 없이 의사결정 지연과 소통 혼선, 권한 불명확 같은 사람과 절차의 문제를 드러내는 데 가장 효과적이다.

    • B · 병행 처리는 기술적 작동을 검증하며 운영 위험이 일부 존재한다.
    • C · 체크리스트 검토는 문서와 이해만 확인하고 수행을 보지 않는다.
    • D · 전면 중단은 운영 위험이 가장 크다.
    원문 위치 · D7.12-Q01
    문제 목록으로 돌아가기
    원본 연습문제 · D7.12-Q10

    병행 처리 시험에서 대체 사이트가 실제 거래를 처리했고 주 사이트 처리량의 40% 수준에서 응답 시간이 기준을 초과했다. 이 시험 유형의 가치에 대해 이것이 보여주는 것은?

    1. 병행 처리 시험은 위험이 너무 커서 테이블탑 훈련으로 대체해야 한다.
    2. 설비가 존재한다는 것과 실제로 부하를 감당한다는 것을 주 서비스를 유지하면서 검증한다.
    3. 용량 문제는 전면 중단 시험으로만 찾을 수 있다.
    4. 비용과 무관하게 대체 사이트를 항상 주 사이트와 동일하게 구성해야 한다.
    정답과 해설 보기

    정답 B. 설비가 있다는 것과 실제 부하를 감당한다는 것은 다르다. 병행 처리는 대체 사이트를 실제 가동해 처리 결과와 성능을 확인하면서 주 서비스를 계속 제공하므로 운영 위험이 제한적이다. 그래서 실무에서 가장 균형 잡힌 선택으로 평가된다.

    • A · 테이블탑은 용량 문제를 전혀 드러내지 못한다.
    • C · 병행 처리로도 용량 문제를 찾을 수 있고 위험이 더 낮다.
    • D · 동일 구성은 비용 측면에서 비현실적이며 요구 용량 산정이 핵심이다.

    2소통 검증 (Communications)

    공식 개요가 소통을 별도 항목(이해관계자, 시험 상태, 규제 기관)으로 명시한 이유는 시험에서 가장 자주 실패하는 영역이기 때문입니다.

    검증 항목확인할 것
    연락망의 유효성번호와 메일이 실제로 연결되는가. 연락 성공률 측정
    대역 외 채널사내 수단이 없을 때의 대체 경로
    대량 통지 시스템실제 발송과 수신 확인
    에스컬레이션단계별 보고가 제때 이루어지는가
    외부 통지규제 기관, 고객, 공급자, 보험사 통지 절차와 담당자
    상태 페이지별도 인프라에서 실제로 갱신되는가
    이해관계자별 메시지사전 템플릿이 적절한가

    시험 중 소통 자체의 관리

    • 시험임을 명확히 표시: 모든 소통에 “훈련” 표기. 그렇지 않으면 실제 사고로 오인합니다.
    • 외부 대상은 사전 합의: 규제 기관이나 고객에게 실제 통지를 보내지 않고 절차만 검증합니다.
    • 시험 상태 보고: 참여자와 관찰자에게 진행 상황을 알립니다.

    원문 사례 — 훈련 표기 누락으로 생긴 혼선. 시뮬레이션 중 참여자가 “훈련” 표기 없이 실제 운영팀에 연락했고, 운영팀은 실제 재해로 오인해 비상 대응을 발동하고 고객 공지 초안을 준비했습니다.

    원문 사례 — 연락 성공률 54%. 훈련에서 연락망을 실제로 써 보니 연락 성공률이 54%였습니다(퇴사자 번호, 변경된 번호, 무응답). 연락망 갱신을 인사 변동에 자동 연동하고, 연락 성공률을 필수 측정 항목으로 넣고, 분기별 연락 확인을 했습니다.

    연결DR 소통 수단과 원칙은 D7.11 재해 복구 프로세스의 4절, 사고 시 대외 소통은 D7.6 사고 관리의 6절에서 다룹니다.

    원문 위치: D7.12.md §3 소통 검증, §7 사례 5, 사례 6 · 공식 개요 7.12 “Communications (e.g., stakeholders, test status, regulators)”

    3시험 설계

    요소요점
    목표“DR 훈련 수행”이 아니라 “DB 복원이 RTO 4시간 안에 가능한지 확인”
    범위어떤 업무, 시스템, 사이트
    성공 기준사전에 정의. 없으면 결과 해석이 주관
    측정 항목실측 RTO·RPO, 발동까지 시간, 단계별 소요, 연락 성공률
    시나리오위험 평가에서 도출, 난도 조절, 예상하지 못한 요소 주입(담당자 부재, 대체 사이트 일부 장애, 공급자 동시 영향), 변형(같은 시나리오 반복은 암기한 대응만 확인)
    참여자대리자를 주 수행자로, 업무 부서 참여, 별도 관찰자·기록자, 핵심 공급자
    안전 장치중단 기준, 롤백 계획, 사전 백업, 경영진 승인과 고지

    원문 사례 — 업무 부서 없이 수행한 훈련. DR 훈련에 IT만 참여해 시스템은 복구되었지만, 실제 재해에서 업무 재개 절차(수동 대체 처리, 고객 응대, 거래 재처리)가 전혀 검증되지 않았음이 드러났습니다. 원본은 IT 복구만 검증하면 업무 재개(WRT)가 검증되지 않는다고 정리합니다.

    원문 사례 — 같은 시나리오 반복. 5년간 데이터센터 화재 시나리오로만 훈련해 참여자들이 대응을 암기했는데, 실제 재해는 랜섬웨어로 인한 데이터 무결성 상실이었고 복구 지점 판단과 재감염 방지라는 전혀 다른 문제를 다뤄야 했습니다. 랜섬웨어, 공급자 장애, 핵심 인력 부재, 클라우드 리전 장애를 순환시켰습니다.

    연결RTO + WRT ≤ MTD는 D7.10 복구 전략의 1절, 랜섬웨어 복구 지점 판단은 D7.6 사고 관리의 7절에서 다룹니다.

    원본 연습문제 · D7.12-Q06

    재해 복구 훈련에 IT 만 참여했다. 시스템은 성공적으로 복구되었으나 실제 재해에서 수동 대체 처리 절차와 고객 응대, 거래 재처리가 한 번도 시험되지 않았음이 드러났다. 공백은?

    1. 복구 목표 시간을 더 단축해야 했다.
    2. 업무 부서가 참여해야 한다. 그렇지 않으면 업무 복구 시간과 업무 재개 절차가 전혀 검증되지 않는다.
    3. 병행 처리가 아니라 전면 중단을 사용해야 했다.
    4. IT 가 업무 부서를 대신해 업무 절차를 문서화해야 했다.
    정답과 해설 보기

    정답 B. IT 복구만 검증하면 복구 후 업무 정상화에 걸리는 시간과 수동 대체 처리, 고객 응대, 거래 재처리 절차가 검증되지 않는다. RTO 와 WRT 의 합이 MTD 안에 들어와야 하므로 업무 부서를 필수 참여자로 포함하고 업무 재개까지를 시험 범위로 확장해야 한다.

    • A · 시간 목표 단축은 업무 재개 절차 미검증을 해결하지 않는다.
    • C · 시험 유형이 아니라 참여 범위가 문제다.
    • D · IT 가 대신 작성한 업무 절차는 실제 수행 가능성을 보장하지 않는다.

    5시험은 실패해야 가치가 있다

    원본의 정리: 모든 시험이 성공하면 시험이 너무 쉬운 것이다.

    • 시험의 목적은 “우리가 잘한다”를 확인하는 것이 아니라 결함을 찾는 것입니다.
    • 결함 0건 보고는 의심 대상입니다. 시나리오가 쉬웠거나, 범위가 좁았거나, 결함을 기록하지 않은 것입니다.
    • 성공 지표를 “통과 여부”로 두면 쉬운 시험을 설계하게 됩니다. 지표는 도출된 결함 수와 조치 완료율이어야 합니다.
    • 조직 문화가 실패를 학습으로 다루지 않으면 시험이 형식화됩니다.

    원문 사례 — 결함 0건 보고의 함정. 3년간 훈련 보고서의 도출 결함이 모두 0건이었는데, 검토해 보니 시나리오가 계획 문서 그대로였고, 참여자가 사전에 각본을 받았으며, 관찰자가 없어 결함이 기록되지 않았습니다. 사전 각본 없는 상황 주입과 별도 관찰자 지정을 의무화했습니다.

    원문 사례 — 체크리스트 검토만 반복한 조직. DR 훈련을 매년 했다고 보고했지만 전부 체크리스트 검토였고, 실제 장애에서 대체 사이트 동기화 지연이 11시간이라 RPO 1시간을 전혀 달성할 수 없었습니다.

    가상 예시복구 시험 보고서에 “문제 없이 성공”만 적혀 있습니다. 확인해 보니 담당자들이 실습 답안을 이미 알고 있었고, 새 복원본이 아니라 미리 준비된 데이터를 썼습니다. 보고서를 검증 가능하게 고치려면 시나리오 출처, 복원에 쓴 백업 시점, 단계별 실측 시간, 관찰자가 기록한 지연과 혼선, 그리고 각 결함의 조치 책임자를 적어야 합니다. ISO 22301 심사에서 연습 결과의 “근거”를 볼 때와 같은 기준입니다.

    원본 연습문제 · D7.12-Q15

    DRP 시험이 매번 성공해도 조직이 준비되지 않은 상태로 남을 수 있는 이유는?

    1. 사전 예고되고 업무 시간에 전원이 참석하며 데이터가 미리 준비된 시험은 핵심 인력 부재나 인프라 성능 저하, 동시 장애 같은 실제 재해의 조건을 검증하지 못할 수 있기 때문이다.
    2. 성공한 시험은 항상 참가자들이 조작하기 때문이다.
    3. 대부분의 표준에서 시험 결과는 30일 후 만료되기 때문이다.
    4. 전체 중단 시험만 유효한 결과를 산출하기 때문이다.
    정답과 해설 보기

    정답 A. 시험이 쉬운 조건으로만 수행되면 계획의 실제 강건성을 알 수 없다. 예고 없는 시점, 핵심 담당자 부재, 일부 자원만 가용한 상황, 동시 다발 장애 같은 가정을 점진적으로 도입해 시험의 난도를 높여 가야 실제 대비 수준이 드러난다.

    • B · 조작을 전제하는 설명은 근거가 없다.
    • C · 결과 만료 규정은 존재하지 않는다.
    • D · 하위 시험도 각자 유효한 검증 목적을 가진다.

    6주기와 트리거

    • 정기 주기: 유형별로 다릅니다. 테이블탑은 자주, 전면 중단은 드물게.
    • 규제 요구: 산업별 최소 주기.
    • 변경 트리거: 주요 시스템 변경, 사이트 이전, 조직 개편, 공급자 변경 뒤에는 주기와 무관하게.

    8핵심 개념을 내 말로 설명하기

    복습

    탁상 훈련을 끝낸 팀이 실제 RTO 달성을 입증하려면 무엇을 더 해야 하나요?

    설명 확인하기

    연락과 의사결정은 문서 기반 훈련에서 확인할 수 있습니다. 실제 복원 시험에서는 정한 기산 시각부터 서비스나 거래가 성공한 시각까지를 측정하고 시험 범위를 함께 남깁니다.

    9핵심 요약

    1. 시험되지 않은 계획은 가정이다. 목적: 유효성, 결함 발견, 역량, 실측값, 역할 숙지.
    2. 시험(합격·불합격) / 훈련(역할 연습) / 교육(지식). “했다”가 아니라 어떤 수준으로 무엇을 발견했나.
    3. 다섯 유형(낮은 위험 → 높은 현실성): 낭독·테이블탑 → 워크스루 → 시뮬레이션 → 병행 처리 → 전면 중단.
    4. 테이블탑: 문서·역할 오류, 기술 작동은 검증 못 함. 워크스루: 절차 순서. 시뮬레이션: 위험 없이 의사결정 품질.
    5. 병행 처리: 실제 가동, 주 서비스 유지 — 가장 균형. 전면 중단: 가장 현실적, 가장 위험, 하위 단계 통과가 전제.
    6. 점진적으로 올린다.
    7. 소통: 연락 성공률, 대역 외 채널, 외부 통지 절차, 상태 페이지. 모든 소통에 “훈련” 표기, 외부는 사전 합의.
    8. 설계: 구체적 목표·성공 기준, 위험 기반·변형 시나리오, 예상 못한 주입, 대리자·업무 부서·관찰자, 안전 장치.
    9. 결과: hot wash, 비난 없는 검토, 계획 갱신, 조치 추적, 증거 보존.
    10. 시험은 실패해야 가치가 있다. 결함 0건은 의심, 지표는 결함 수와 조치율. 변경 트리거로 재시험.
    원문 위치: D7.12.md §8 CISSP 시험 관점, §9 핵심 암기 요약. 원본의 출제 단정 표현은 판단 기준으로 바꿔 적었습니다.

    10주요 용어 (Glossary)

    영어 원어와 한국어 뜻 · English–Korean

    Read-through / Checklist Review · 낭독 / 체크리스트 검토

    담당자가 계획 문서와 체크리스트를 읽고 역할과 자원을 확인하는 가장 간단한 시험.

    Tabletop Exercise · 테이블탑 훈련

    관계자가 모여 시나리오를 놓고 대응을 논의하는 훈련.

    Structured Walk-through · 워크스루

    계획의 각 단계를 순서대로 따라가며 전제와 자원, 순서를 검증하는 활동.

    Simulation · 시뮬레이션

    가상 시나리오를 제시해 참여자가 실제로 역할을 수행하는 훈련. 시스템은 전환하지 않는다.

    Inject · 상황 주입

    훈련 중 진행자가 단계적으로 제시하는 새로운 상황 정보.

    Parallel Test · 병행 처리 시험

    대체 사이트를 실제 가동해 주 사이트와 병행 운영하며 결과를 비교하는 시험.

    Full Interruption Test · 전면 중단 시험

    주 사이트를 실제 중단하고 대체 사이트로 전환하는 가장 현실적인 시험.

    Facilitator · 진행자

    훈련 시나리오를 운영하고 상황을 주입하는 역할.

    Hot Wash / Debriefing · 디브리핑

    훈련 종료 직후 즉시 수행하는 결과 공유와 결함 도출.

    Abort Criteria · 중단 기준

    운영에 실제 영향이 발생할 때 시험을 중단하는 기준.

    Success Criteria · 성공 기준

    시험 전에 정의하는 합격 조건.
